# Architecture Decision Records — 책 집필 하네스

## 철학
출처에 없는 사실을 쓰지 않는다. 장 단위로 작게 쓰고, 덮어쓰기 생성기는 승인 게이트 뒤에 둔다.

---

### ADR-001: 기본 원고 대상은 ztcfbook
**결정**: 하네스 기본 write target = `../ztcfbook`
**이유**: 이미 32장+부록 구조·목차·출처 색인 계약이 있다.
**트레이드오프**: 입문/Master는 별도 승인 후 `-m`/`-h`로 미러링한다.

### ADR-002: PDMP 실행 하네스 골격 재사용
**결정**: `phases/` + `execute.py` + `/harness` 워크플로를 유지하고 도메인만 집필로 교체한다.
**이유**: 팀의 운영 습관(step 자기완결·재시도·브랜치)을 그대로 쓸 수 있다.
**트레이드오프**: npm lint/build Stop hook은 문서 하네스에 맞지 않아 비활성/교체한다.

### ADR-003: 생성 스크립트는 덮어쓰기 Gate
**결정**: `node _gen-book-*.cjs`는 사용자 명시 승인 없이 실행 금지.
**이유**: 집필 완료 본문을 한 번에 날릴 수 있다 (`ztcfbook/README` 경고).
**트레이드오프**: 스캐폴드 재생성 속도는 떨어지지만 원고 안전이 우선이다.

### ADR-005: 목차 항목 = 풍부한 책 본문 단위 (IN/OUT 폐기)
**결정**: `TOC` 항목 1개당 `ztcfbook` 장을 **자세하고 풍부하게** 쓴다. `chapters/{id}/IN|OUT` 작업장 패턴은 쓰지 않는다.
**이유**: 제품은 독자가 읽는 책이지 핸드오프 메모가 아니다.
**트레이드오프**: 증적은 git diff·toc status·본문 출처 색인에 남긴다.
