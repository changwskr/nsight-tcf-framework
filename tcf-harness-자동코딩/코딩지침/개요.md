# NSIGHT 자동 하네스 상세설계 패키지

Harness Orchestrator 상세설계를 실제 구현에서 사용할 수 있도록 **모듈·패키지 구조, Oracle DB 정의, REST API, JSON Schema, Workflow YAML, Gate Rule YAML**로 분리했습니다.

기존 요구사항의 승인형 자동화, Source Evidence, 단계별 작업공간, Evidence 기반 Gate, 요구사항–ServiceId–프로그램–SQL–테스트 추적성 기준을 반영했습니다. Architecture Gate 역시 문서 존재 여부가 아니라 설계·소스·OM 정보·시험·운영 증적의 정합성을 판정하도록 구성했습니다.

## 3. REST API 명세

[REST API 상세명세](sandbox:/mnt/data/NSIGHT_Auto_Harness_Design_Package/api/rest-api-spec.md)

[OpenAPI 3.1 계약](sandbox:/mnt/data/NSIGHT_Auto_Harness_Design_Package/api/openapi.yaml)

총 **17개 Operation**을 정의했습니다.

```text
Run 등록·조회·중지·재개·취소
```

외부 Control API와 내부 Agent API를 분리하고 다음 통제를 포함했습니다.

- `Idempotency-Key`
- `If-Match` 기반 낙관적 동시성
- JWT 사용자 인증
- Agent Worker 전용 Token
- `application/problem+json`
- Task Lease와 중복 Claim 방지
- 승인 없는 상태 변경 차단

Rule은 다음 유형으로 구분했습니다.

```text
HARD
→ 실패 시 예외 없이 Gate FAIL

REQUIRED
→ 필수 기준 미충족 시 FAIL

SCORED
→ 품질점수에 반영

ADVISORY
→ 경고와 개선사항 기록

HUMAN
→ 지정 역할의 사람 승인 필수
```
