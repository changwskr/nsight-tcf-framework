TCF ON 기준으로, **요청(온라인 거래) 흐름**과 **DB 트랜잭션**을 겹쳐 보면 아래와 같습니다.

## 1. 한눈에 보는 컴포넌트 흐름

```text
[브라우저]
    │
    ▼
[pdmg-ui]  POST /api/relay/{serviceId}   { hdr_nhnis, dto }
    │
    ▼
[pdmg-service + pdmg-fw]
────────────────────────────────────────────────────────────
 │ 업무 DB TX 밖 (시스템 구간)
 │
 │  ① DefaultFilter
 │       Body 캐시 · JWT(비-local) · hdr_nhnis · ServiceContext · MDC
 │  ② ServicePreventionInterceptor.preHandle
 │       요청전문 로그 · ImageLog INSERT
 │  ③ OnlineTransactionController
 │  ④ TcfFacade → Dispatcher
 │
 │──────────────── 진입 ────────────────
 │  ⑤ Handler (entry.handler)
 │       serviceId → Facade 메서드만
 │
 │╔════════════ DB TX 경계 ══════════════════════════════╗
 │║ ⑥ Facade (application.facade)                        ║
 │║      @Transactional(rdwTransactionManager)  BEGIN     ║
 │║         │                                             ║
 │║         ▼                                             ║
 │║  ⑦ BizPrePostAspect  [업무 선처리]                    ║
 │║  ⑧ Service (application.service)                      ║
 │║  ⑨ DAO → Mapper(rdw.mg.co.a) → DB                     ║
 │║  ⑩ BizPrePostAspect  [업무 후처리]                    ║
 │║                                                       ║
 │║      Facade 반환 → COMMIT (예외 시 ROLLBACK)          ║
 │╚═══════════════════════════════════════════════════════╝
 │
 │  ⑪ ResponseBodyAdvice
 │       응답 봉투 { hdr_nhnis, dto } · 응답전문 로그
 │  ⑫ Interceptor.afterCompletion
 │       ImageLog UPDATE / exceptionImagelog
────────────────────────────────────────────────────────────
    │
    ▼
[브라우저]  성공 dto / 실패 NH_NIS_ERR_DTO
```

## 2. 계층 · 컴포넌트 · TX

| #     | 컴포넌트                                    | 패키지/모듈                       | DB TX                   |
| ----- | ------------------------------------------- | --------------------------------- | ----------------------- |
| 1     | `DefaultFilter`                             | `pdmg-fw` commons                 | 밖                      |
| 2     | `ServicePreventionInterceptor`              | `pdmg-fw`                         | 밖                      |
| 3–4   | `OnlineTransactionController` / `TcfFacade` | `pdmg-fw` tcf                     | 밖                      |
| 5     | `*Handler`                                  | `entry.handler`                   | 밖                      |
| **6** | `*Facade`                                   | `application.facade`              | **경계 (BEGIN/COMMIT)** |
| 7·10  | `BizPrePostAspect`                          | `entry.aspect`                    | **안** (Facade TX 참여) |
| 8     | `*Service`                                  | `application.service`             | 안                      |
| 9     | `*DAO` + XML                                | `persistence.dao` / `rdw.mg.co.a` | 안                      |
| 11    | `ResponseBodyAdvice`                        | `pdmg-fw`                         | 밖                      |
| 12    | Interceptor `afterCompletion`               | `pdmg-fw`                         | 밖                      |

## 3. DB 트랜잭션만 확대

```text
Handler
  └─ Facade 프록시
        │  ★ @Transactional 시작
        ├─ [업무 선처리]  Service 진입 직전
        ├─ Service
        │     └─ DAO / SQL
        ├─ [업무 후처리]  Service 반환 직후
        │  ★ COMMIT (또는 ROLLBACK)
        └─ 반환 → Handler → 시스템 후처리
```

핵심: **TX는 Facade만**, 업무 선후처리는 **Service Pointcut**이라 Facade TX **안**에서 돈다.

## 4. 의존 방향 (구조)

```text
UI ──► FW(Filter/Interceptor/OnlineController/TcfFacade)
         ──► Handler
              ──► Facade ★TX
                   ──► Service
                        ──► DAO ──► DB
         ◄── ResponseBodyAdvice / ImageLog (TX 밖)
```

금지에 가까운 우회: `Handler → Service/DAO` 직호출 (TX·선후처리 깨짐).

## 5. 두 가지 “트랜잭션” 구분

| 말               | 의미                    | 컴포넌트                      |
| ---------------- | ----------------------- | ----------------------------- |
| 온라인 거래 흐름 | 요청 1건의 라이프사이클 | Filter → … → ImageLog         |
| DB 트랜잭션      | commit/rollback         | **Facade `@Transactional`만** |
