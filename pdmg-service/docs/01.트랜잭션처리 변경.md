# 01. 트랜잭션처리 변경 (PDMG)

기준일: 2026-08-09  
대상: `pdmg-service` / `pdmg-fw`  
관련 소스: `BizPrePostAspect`, Business Facade(`nhnis.mg.entry.facade`)

## 결론

`BizPrePostAspect` Pointcut을 **Service**로 두면, 업무 선처리·후처리가 **Facade `@Transactional` 안**에서 실행된다.

```text
TX BEGIN   ← Facade 프록시 진입
├─ 업무 선처리          ← Service 프록시 @Before
├─ Service
├─ DAO / SQL
└─ 업무 후처리          ← Service 프록시 @AfterReturning
TX COMMIT  ← Facade 반환
```

검증 로그 키:

```text
[업무 선처리] 호출: mgcoa5530Service.mgcoa5530S0
```

## 변경 전 / 후

### 변경 전 (Controller ‖ Facade Pointcut)

Advisor `@Order`에 따라 업무 후처리가 TX **밖**에 있을 수 있었다.

```text
업무 선처리
→ TX 시작
→ Facade / Service / DAO
→ TX Commit
→ 업무 후처리          ← Commit 이후일 수 있음
```

### 변경 후 (Service Pointcut) — 현재

Facade TX가 먼저 열리고, 그 안에서 Service Aspect가 돈다. TX Advisor와 Biz Aspect의 순서 경쟁을 피한다.

```text
Handler
→ Facade 프록시
   → @Transactional 시작
   → Service 프록시
      → 업무 선처리
      → Service
      → DAO / SQL
      → 업무 후처리
   → Service 반환
→ Facade 반환
→ Commit
```

## 현재 Pointcut

파일: `nhnis.mg.entry.aspect.BizPrePostAspect`

```java
@Pointcut("execution(public * nhnis.mg.application.service..*(..))")
public void mgBizBoundary() {
}
```

- `@Transactional` 위치: **Business Facade** (`rdwTransactionManager`)
- 업무 선후처리 위치: **Service** (`BizPrePostAspect`)

## 런타임 전체 흐름 (TCF ON)

상세: [pdmg-service 트랜잭션흐름.md](./pdmg-service%20트랜잭션흐름.md)

```text
Filter → 시스템 선처리(ImageLog INSERT)
  → OnlineTransactionController → TcfFacade → Handler
  → Facade(@Transactional)
       → [업무 선처리] → Service → DAO → [업무 후처리]
  → 시스템 후처리(응답 봉투) → ImageLog UPDATE
```

공통 Controller 1개(`OnlineTransactionController`) + Handler/Facade/Service.  
거래별 Controller는 `nhnis.fw.tcf.enabled=true` 일 때 비활성.

## Service Pointcut 부작용

| 항목 | 내용 |
|------|------|
| Facade가 Service를 N회 호출 | 선후처리 로그 N회 |
| 배치/스케줄이 Service 직접 호출 | 선후처리 실행됨 |
| Facade DTO 변환 실패 | Service 미도달 → 업무 선처리 없음 |
| Service → Service 호출 | 중첩 선후처리 가능 |
| self-invocation | 프록시 미통과 → Aspect 미실행 |

거래당 선후처리를 **정확히 1회**만 보장하려면 Facade Pointcut + TX Advisor 순서 조정이 개념적으로 더 맞다.  
**Service 실행을 같은 TX로 확실히 감싸는 것**이 우선이면 현재 Service Pointcut이 적절하다.

## 잔여 개선

- 로그 `BRC: null`: DTO에 지점코드가 없을 때 `ServiceContext` 헤더 `tr_brc`로 보완 가능
- IDE 실행 시 `pdmg-service` 변경은 `classes` 재컴파일·재시작 필요. `pdmg-fw` 변경은 jar 재빌드 후 재시작
