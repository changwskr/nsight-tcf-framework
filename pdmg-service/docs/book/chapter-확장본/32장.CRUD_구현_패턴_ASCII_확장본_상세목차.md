# 제32장. CRUD 구현 패턴 — ASCII 확장본 상세목차

> **집필 기준**
>
> 이 장은 `32장.CRUD 구현 패턴.md`, `32-CRUD-구현-패턴-집필-프롬프트.md`, `32.범용CRUD프롬프트.md`, `CRUD서비스프롬프트가이드.md`, `범용CRUD프롬프트.md`와 Service/DAO/Mapper/DTO/예외/페이징 재분석 자료를 기준으로 작성한다.
>
> **현재 사실 기준**
>
> - 실전 기준 프로그램은 `mgcoa9001` 거래통제다.
> - 현재 해당 Program은 S0 목록, C0 등록, U0 수정, D0 삭제가 확인되고 상세 전용 S1은 없다.
> - S0 AS-IS는 pageNo 1, pageSize 20/max100, count/list 공통 WHERE, Oracle ROWNUM offset 방식이다.
> - C0 AS-IS에는 exists→insert race window와 insert `cnt==1` 엄격검증 Gap이 있다.
> - U0 AS-IS는 7-key WHERE, 0건 실패, `cnt>1` 미검증, version 조건 부재로 lost update 가능성이 있다.
> - D0 AS-IS는 물리 DELETE이며 changeReason은 검증하지만 업무 삭제이력으로 보존하지 않는다.
> - Timeout ON에서는 Worker `TransactionTemplate`이 outer DB TX이며 Facade/Service Transaction Annotation은 REQUIRED 참여자가 될 수 있다.
> - Legacy current Service 중에는 `RSLT_CD` 정상반환형 실패가 있어 신규 BizException 표준과 구분한다.
> - ImageLog는 업무 삭제감사의 대체물이 아니다.
>
> **장 경계**
>
> - 제31장의 Program/파일 생성 절차를 반복하지 않는다.
> - 제32장은 CRUD 행위별 불변조건·동시성·삭제전략·row count·Transaction·오류를 심화한다.
> - 제33장의 전체 Test/품질 Gate 구현 상세를 과도하게 선점하지 않는다.
