## A.5 KPI 카드 정의 `[설계반영]` + `[확인필요]`

| KPI ID | 표시명 | 산정식(초안) | Drill-down 파라미터 |
|--------|--------|--------------|---------------------|
| KPI-TOTAL | 총 자원 | 관리대상 자원 Instance 수 (사용중) | (필터만) |
| KPI-RISK-STATUS | 위험 상태 | **[확인필요 CONF-001]** 임시: `현재상태 IN (경고,위험)` OR `위험등급 IN (Critical,High)` 중 **정책코드 `KPI_RISK_STATUS_MODE`** 로 선택 | `eosStatus` 또는 `riskLevel` |
| KPI-CRIT | Critical | `위험등급 = Critical` | `riskLevel=Critical` |
| KPI-HIGH | High | `위험등급 = High` | `riskLevel=High` |
| KPI-EXC-NEED | 예외 필요 | Critical/High 이고 조치계획 없거나 조치불가·예외미승인 | `exceptionNeed=Y` |
| KPI-INPROG | 진행중 | 조치상태 IN (계획수립,진행중,테스트중) | `actionStatus=IN_PROGRESS` |
| KPI-MONTH | 금월 목표조치 | 목표조치일 ∈ 당월 AND 미완료 | `targetYm=YYYYMM` & `incomplete=Y` |

> 샘플 Excel의 `위험 상태=27` vs 등급합=36 불일치는 **산정식 정책화**로 해결 (`RULE-192`). 원본 수치는 Issue로만 기록하고 조용히 교정하지 않음.

## A.7 Grid — 우선조치 Top 10

선정 Rule `[설계반영]`:

```text
1순위 위험등급 Critical > High > Medium > Low
2순위 EOS 잔여일수 오름차순 (과거=최우선)
3순위 조치목표일 임박/초과
4순위 예외만료 임박
```

| 컬럼 | 비고 |
|------|------|
| 순위, 자원ID, 제품명, 현재버전 | |
| EOS일자, 잔여일수, 현재상태 Badge | |
| 위험등급 Badge | |
| 조치유형/상태 | 없으면 `-` |
| 담당조직 | |
| [상세] | → EOS-030 |

목록에 원장 전체 컬럼을 넣지 않음 (`AGENT` §17).
