## 2. 문제·목적 요약

### 2.1 현행 문제 (Excel)

- 동일 자원 정보가 시트별 분산 → 중복 입력·EOS 일자 변경 시 다수 수정
- 위험도 수기 산정, Dashboard·원장 불일치, 예외 만료·월간보고 수작업
- 벤더 근거·설치버전 조사 반복

### 2.2 시스템 목적

기술자원의 **EOS/EOL/계약종료**를 통합 관리하고, 위험 식별 → 조치계획 → 예외승인 → 종료·보고까지 추적한다.

```text
사용 자원 → 현재버전 → 지원종료일 → 위험도
  → 전환계획 → 조치일정 → (불가 시) 예외승인 → 완료검증·보고
```

### 2.3 관리대상 범위

서버만이 아니라 **채널·네트워크·WEB/WAS/OS/JDK/Framework/DB/MW/보안/라이브러리/DevOps 도구**까지 포함하는 기술 Lifecycle 모델.

자원구분 코드: `CHANNEL | NET | WEB | WAS | OS | JDK | FMW | DBMS | MW | ETL | SEC | LIB | TOOL` (+ 코드 확장)

## 3. 핵심 아키텍처 판단

### 3.1 금지 패턴

Excel 시트 = 독립 메뉴·독립 테이블로 쪼개지 않는다.

### 3.2 목표 도메인 모델 `[추가제안·핵심]`

Excel의 `자원ID` 한 행은 실제로는 다음이 혼합되어 있다. 시스템은 분리한다.

```text
PRODUCT                (예: Apache Tomcat)
  └─ PRODUCT_VERSION   (예: 8.5.x)  ← EOS/EOL/근거는 여기에
       └─ RESOURCE INSTANCE (예: sv-ap-prd-01 설치분)
            ├─ Risk Assessment
            ├─ Action Plan (+ Transition / Rollback)
            ├─ Exception (+ 월간점검)
            ├─ Monthly Check / Report Snapshot
            ├─ Evidence
            └─ Change History
```

EOS 일자 1회 변경 → 해당 버전을 쓰는 **모든 Instance**의 상태·영향이 함께 갱신되어야 한다.

### 3.3 업무 흐름 (E2E)

```text
자원 조사/등록 → 제품·버전 확인 → EOS/EOL/계약일
  → 잔여일 자동계산 → 현재상태 자동판정 → 위험도 평가
  → (위험) 조치계획 → Upgrade 등 전환·Rollback 또는 예외신청
  → 승인/보완통제/월간점검 → 완료검증 → EOS 종료 · Dashboard/월간보고
```

## 4. 요건 영역별 정리

### 4.1 ID 접두어 맵

| 접두 | 영역 | 결과본 규모(대략) |
|------|------|-------------------|
| `EOS-RSC` | 자원 등록 | 014 |
| `EOS-LFC` | Lifecycle | 009 |
| `EOS-STS` | 상태 자동판정 | 006 |
| `EOS-RSK` | 위험도 평가 | 010 |
| `EOS-ACT` | 조치계획 | 014 |
| `EOS-TRN` | 전환·Rollback | 007 |
| `EOS-EXC` | 예외승인 | 015 |
| `EOS-RPT` | 월간보고 | 010 |
| `EOS-COL` | 점검·수집 | 008 |
| (코드/알림/권한/이력/검색/Gate) | 기준·운영 | 서술형 + 표 |

### 4.2 상태 Rule (샘플 기준 → 정책화)

| 현재상태 | 기준 |
|----------|------|
| 정상 | EOS까지 ≥12개월 |
| 주의 | 6~12개월 |
| 경고 | 3~6개월 |
| 위험 | EOS 도래 또는 &lt;3개월 |
| 예외 | 승인 유효 기간 |

임계값은 코드/정책으로 변경 가능 (`EOS-STS-003`). 예외 만료 시 위험 환원 (`EOS-STS-006`, `EOS-EXC-014`).

### 4.3 위험도 Rule (샘플 기준 → 정책화)

- 7항목 × 1~5점 → 총점 자동합산  
  (업무중요도, 운영환경, 외부노출, 보안취약점, 장애영향도, 대체난이도, EOS상태)
- Critical ≥32 / High 26~31 / Medium 20~25 / Low ≤19
- Critical → 즉시 개선계획, High → 3개월 이내 계획 (`EOS-RSK-009/010`)

### 4.4 조치·전환

- 조치유형: Upgrade / Replace / Remove / Extended Support / Isolation / Exception  
- 진행상태: 미착수 ~ 완료 / 보류 / 예외관리  
- 전환: Rolling / Blue-Green / DR 사전검증 / Rollback 필수 (`EOS-TRN-*`, `EOS-ACT-009`)

### 4.5 예외승인

단순 보류가 아님. **기간 + 사유 + 불가사유 + 보완대책 + 최종전환계획/일 + 월간점검 + 종료기준 + 승인/조건부/반려**.  
연장 = 재승인. 신청자≠승인자 분리.

### 4.6 Dashboard / 월간보고

- KPI: 총자원, 위험상태, Critical/High, 예외필요, 진행중, 금월목표조치 등  
- 영역별 집계 + 우선조치 Top N + Drill-down  
- 월간 Snapshot·전월대비·Excel 출력

### 4.7 수집·기준정보·알림·권한

- 자원구분별 점검명령·결과 저장·버전 Drift 표시 (`EOS-COL-*`)
- 코드·평가기준·임계값·알림기준 **하드코딩 금지**
- EOS D-12/6/3개월, Critical, 목표일 초과, 예외만료 등 알림
- RBAC + SoD(신청≠승인, 평가≠최종승인, 완료등록≠검증승인) + 전체 감사이력

### 4.8 품질 Gate (등록/변경 시)

자원ID 중복 금지, Critical+계획없음, 예외 필수항목, 점수 1~5, 총점 자동계산, 완료 시 완료일·증빙, PROD 담당조직 필수 등.

## 5. 데이터 품질 Issue (샘플에서 확인 → 시스템 검증 필수)

| Issue | 내용 | 시스템 대응 |
|-------|------|-------------|
| Dashboard `위험 상태` 27 vs 등급합 36 | KPI 정의 모호 | KPI 산정식 기준정보화 |
| `금월 목표조치` → `1899-12-31` | 날짜/건수 혼동 | 타입 분리·검증 |
| 예외 `2026-07-01 ~ 2026-06-30` | 종료&lt;시작 | `종료일 ≥ 시작일` |
| EOS vs 조치목표일 | 선후 불일치 가능 | 날짜 정합성 Gate |

마스터 프롬프트 원칙: **원본을 조용히 고치지 말고 Issue로 보고**한 뒤 검증 Rule로 승격.

## 6. 화면·단계적 구축

### 6.1 권장 화면 (결과본 §23)

| 우선 | 화면 |
|------|------|
| **P0** | EOS-010 Dashboard, 020 통합조회, 030 등록·상세, 040 Product Lifecycle, 050 위험평가, 060 조치계획, 070/080 예외신청·승인, 090 예외·월간점검, 140 코드·정책, 150 변경이력 |
| **P1** | EOS-100 월간보고, 110 Calendar, 120 점검결과 |
| **P2** | EOS-130 자동수집 현황 |

### 6.2 로드맵 (프롬프트 §24 ∩ 결과본 §24)

| Phase | 범위 |
|-------|------|
| **P0** | 자원원장 + Product/Lifecycle + 상태자동판정 + 위험도 + 조치 + 예외 + Dashboard + 기준정보 + 이력 + 핵심 Gate *(월간보고는 결과본 1차에 포함, 화면은 P1로도 표기 — 구현 시 P0 최소 Snapshot 권장)* |
| **P1** | 월간 Snapshot/보고, 알림, 예외 월간점검, 증빙, Calendar, 완료검증 |
| **P2** | 점검명령 자동수집, Agent/API, SBOM/SCA, Drift, 벤더 Lifecycle 연계 |
| **P3** | System→Service→App→WAR→Tomcat/JDK→OS→DB 영향도 |

### 6.3 최우선 확정 과제 (결과본 §26)

1. 자원ID ↔ Product / Version / Instance 모델  
2. EOS 현재상태 산정 Rule  
3. 위험점수 산정 Rule  
4. 예외 승인 Workflow

## 7. 비기능 요약

목록조회 ~3초, 업무시간 가용성, RBAC·감사로그, 첨부(Lifecycle 근거) ACL, Dashboard=원장 실시간 일치, 일 Batch 잔여일·상태 재계산, Export, 과거 시점 재현.

## 9. 한 줄 정의

```text
EOS 자원관리 시스템
= 기술자원 원장
+ Product Lifecycle
+ 상태·위험 자동판정
+ 조치·전환·Rollback
+ 예외승인·월간점검
+ Dashboard/월간보고
+ 감사·이력
(+ 이후 자동수집·업무영향도)
```

Excel을 Web으로 옮기는 것이 아니라, **단일 원장 중심 Lifecycle 플랫폼**으로 재설계하는 것이 두 문서의 공통 결론이다.
