## 1. 한 줄 요약

선·후 처리는 **기능(세부업무)을 중심**으로 **5중 중첩 범위** — 시스템 → 공통 → 어플리케이션 → 업무 → 기능 — 에 걸쳐 적용된다. 좌측 **[마케팅플랫폼 MP]**·우측 **[BI포탈 BL]** 두 사례가 **동일 계층 패턴**을 보여 주며, 최하위 기능 내부는 **Controller → Service → DAO → DB** 스택이다.

## 3. 선/후 처리 범위 TEXT 표그림

원본 이미지의 **바깥→안쪽 5계층**과 **좌(MP)·우(BL) 대칭 배치**를 TEXT 표·ASCII로 변환한 것이다.

### 3.1 5계층 범위 요약

| Level | 계층명 | Scope | MP 예시 (좌) | BL 예시 (우) | 거래 처리 구조 대응 |
|---:|---|---|---|---|---|
| **L1** | 시스템 선/후 처리 | 어플리케이션 **그룹** (대구분) | 마케팅플랫폼 (MP) | BI포탈 (BL) | ① 시스템 선 · ⑧ 시스템 후 |
| **L2** | 공통 선/후 처리 | 어플리케이션 **그룹** 내 공통 | 캠페인 **공통** | 신용실적 **공통** | ② 공통 선 · ⑦ 공통 후 |
| **L3** | 어플리케이션 | **업무구분** | CM (캠페인) | CR (신용실적) | 업무구분(co/cm/cr …) |
| **L4** | 업무 선/후 처리 | **기능** 직전·직후 (브래킷) | A 업무 선/후 | E 업무 선/후 | ③ 업무 선 · ⑥ 업무 후 |
| **L5** | 기능 (세부업무구분) | Controller Method | A 업무 | E 업무 | ④ Controller · ⑤ Service |

### 3.2 좌(MP) · 우(BL) 대칭 배치 표

| 구역 | [마케팅플랫폼] MP (좌) | [BI포탈] BL (우) |
|---|---|---|
| L1 시스템 | **마케팅플랫폼** 시스템 선/후 처리 | **BI포탈** 시스템 선/후 처리 |
| L2 공통 | **캠페인 공통** 선/후 처리 | **신용실적 공통** 선/후 처리 |
| L3 어플리케이션 | **CM** (캠페인) | **CR** (신용실적) |
| L4 업무 | `[ A 업무 선/후 처리 ]` | `[ E 업무 선/후 처리 ]` |
| L5 기능 | **A 업무** — `Controller.method()` | **E 업무** — `Controller.method()` |
| 내부 스택 | Service → DAO → **TB_MPCMA\*** | Service → DAO → **TB_BLCRE\*** |

### 3.3 기능(L5) 내부 3-Tier 표

| 계층 | MP (CM · A) | BL (CR · E) | 역할 |
|---|---|---|---|
| Controller | `method()` | `method()` | 서비스ID 진입 · 흐름 제어 |
| Service | Service | Service | Biz Logic |
| DAO | DAO | DAO | DB Access (SQL ID) |
| DB | TB_MPCMA* | TB_BLCRE* | 물리 테이블 (명명규칙 연계) |

### 3.5 MP · BL 나란히 ASCII

```text
[마케팅플랫폼 MP]                    [BI포탈 BL]
─────────────────                    ─────────────
L1  MP 시스템 선/후                  L1  BL 시스템 선/후
L2  캠페인 공통 선/후                L2  신용실적 공통 선/후
L3  CM (캠페인)                      L3  CR (신용실적)
L4  [ A 업무 선/후 ]                 L4  [ E 업무 선/후 ]
L5  A → Controller→Service→DAO      L5  E → Controller→Service→DAO
    → TB_MPCMA*                          → TB_BLCRE*
```

| 이미지 표기 | 분류 | 패키지/테이블 패턴 |
|---|---|---|
| MP | 어플리케이션 그룹 (대구분) | `nhnis.mp.*` |
| BL | 어플리케이션 그룹 (대구분) | `nhnis.bl.*` (BI포탈) |
| CM | 업무구분 | `nhnis.mp.cm.*` |
| CR | 업무구분 | `nhnis.bl.cr.*` |

| TB_MPCMA* | DB 테이블 | MP + CM + A 업무 |
| TB_BLCRE* | DB 테이블 | BL + CR + E 업무 |

## 4. 계층별 구조 분석

### 4.1 L1 · L2 — 시스템·공통 선/후

| 계층 | 적용 범위 | 특성 |
|---|---|---|
| L1 시스템 | 어플리케이션 그룹 전체 (MP 또는 BL) | NH Cloud Framework · 그룹 단위 횡단 |
| L2 공통 | 그룹 내 도메인 공통 (캠페인 공통 / 신용실적 공통) | 여러 어플리케이션(CM, …)에 공유 |

**해석**: L1은 **거래 처리 ①⑧**, L2는 **거래 처리 ②⑦**과 범위가 대응한다. 다만 L2는 이미지상 **“캠페인 공통”**처럼 **업무군 공통**으로 한 단계 더 세분화되어 있다.

### 4.2 L3 — 어플리케이션 (업무구분)

| MP | BL |
|---|---|
| CM = 캠페인 | CR = 신용실적 |

**해석**: [온라인 프레임워크 패키지 계층](./온라인_프레임워크_패키지_계층_분석.md)의 **업무구분(co, cm, cr …)** 레벨과 일치.

### 4.3 L4 — 업무 선/후 (브래킷)

- **A 업무** / **E 업무** 직전·직후에만 적용
- 이미지상 **브래킷 `[ ]`** 으로 L5 기능을 감쌈

**해석**: **거래 처리 ③⑥**(서비스ID 단위)과 동일 Scope. 기능별 Extension Point.

### 4.4 L5 — 기능 · 3-Tier

| 구성 | 역할 |
|---|---|
| Controller.method() | 서비스ID 1:1 · 본 처리 진입 |
| Service | Biz Logic |
| DAO | SQL · OR Mapper |
| DB Table | 영속 데이터 |

## 6. 아키텍처 관점 핵심 정리

| 관점 | 확인되는 구조 |
|---|---|
| Scope Nesting | 5중 중첩 — 바깥일수록 넓은 선/후 처리 |
| Separation of Concerns | 시스템 / 공통 / 업무 / 기능 책임 분리 |
| Symmetry | MP·BL 동일 패턴 · 도메인 코드만 상이 |
| Implementation | L5 = Controller-Service-DAO-DB |
| Naming | TB_{그룹}{업무}{기능}* 테이블 명명 |
| Extension | L2·L4 = 선택적 선/후 훅 (필요 시 구현) |

## 7. PDMG/TCF 프레임워크 연관 시사점

| Level | TCF/PDMG 대응 | 비고 |
|---|---|---|
| L1 | Filter, `stf`/`etf`, Application Group 설정 | MP vs BL 별도 Bean 가능 |
| L2 | Domain 공통 Pre/Post (AOP·Interceptor) | 캠페인 공통 / 신용실적 공통 |
| L3 | 패키지 `mp.cm`, `bl.cr` | 업무구분 단위 배치 |
| L4 | 서비스ID·Handler Pre/Post | Controller Method Scope |
| L5 | Controller → Facade → Service → DAO | 표준 4계층 |

**설계 시사점**: 선/후 처리를 **어느 Level에 두느냐**가 영향 범위(Impact Radius)를 결정한다. L1에 넣으면 MP 전체, L4에 넣으면 A 업무만.
