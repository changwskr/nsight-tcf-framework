# 05. 시스템 표준 정의 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)

> **방법론 폴더**: `04-PHYSICAL (시스템표준*)`
> **작성일**: 2026-08-26

## 1. 목적

서버 호스트 명명, 파일시스템, 사용자 계정, 서버 포트 등 운영·구축 공통 표준을 설계·준수 기준으로 제공한다.

## 2. 적용 범위

- **포함**: Hostname 규칙(12자리·소문자), Linux FS 표준, AP/DB 디렉터리 분류, 계정, 포트 현황
- **제외**: 앱 패키지 명명(8장), 거래/GUID(8장)
- **적용**: 전 환경 서버 신설·변경 시 필수

## 3. 설계 원칙

1. **단일 명명 규칙**: Hostname은 12자리 소문자 규칙을 예외 없이 적용한다(업무 특성 예외는 변경관리).
2. **FS 표준 우선**: OS 표준 FS를 따르고, 업무별 변경은 명시적 사유와 함께만 허용한다.
3. **AP/DB 디렉터리 3분류**: AP·DB 서버 디렉터리는 표준 3분류를 기본으로 한다.
4. **계정·포트 가시화**: 계정·포트는 인벤토리와 동기화하고 무단 변경을 금지한다.
5. **물리·표준 정합**: 3장 목록의 Hostname이 본 장 규칙을 만족해야 한다.

## 4. 설계 기준 (결정 규칙)

- 신규 서버는 명명 규칙 검증 후 인벤토리에 등록한다.
- FS·마운트·용량 할당은 표준표 + 업무 예외표를 함께 관리한다.
- 포트는 서비스 역할별로 중복·충돌 검사 후 할당한다.
- 계정은 환경(운영/DR/개발/선도)·역할(앱/DB/배치)로 분리한다.

## 5. 구성·경계

```text
시스템 표준
├─ 호스트 명명 (12자리, 소문자)
├─ 파일시스템 (OS 표준 + AP/DB 3분류)
├─ 사용자 계정
└─ 서버 포트
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 규칙표에 맞는 Hostname만 등록 | 임의 길이·대문자·비표준 접두 사용 |
| 계정·포트를 인벤토리와 동기화 | 서버 로컬에만 존재하는 비공식 계정/포트 |
| FS 예외를 문서화 | 표준 없이 디렉터리를 임의 생성 |

## 7. 설계 체크리스트

- [ ] Hostname이 12자리 소문자 규칙을 만족하는가?
- [ ] AP/DB FS·디렉터리 분류가 표준과 맞는가?
- [ ] 계정·포트 현황표가 최신인가?
- [ ] 3장 물리 목록과 표준이 교차 검증되었는가?
