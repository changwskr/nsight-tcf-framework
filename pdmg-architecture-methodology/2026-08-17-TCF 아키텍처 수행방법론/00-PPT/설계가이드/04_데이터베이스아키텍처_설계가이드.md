# 04. 데이터베이스 아키텍처 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)

> **방법론 폴더**: `04-PHYSICAL (DB*)`
> **작성일**: 2026-08-26

## 1. 목적

정보계 DW(RDW/ADW)의 구성·이중화·CDC/OGG 중계·OLTP와 대용량 배치 공존 방안을 설계한다.

## 2. 적용 범위

- **포함**: DB 구성도, RAC 이중화, OGG/CDC 중계(Downstream), 서버별 DB 접근, OLTP·배치 수행 방안
- **제외**: 주제영역 의미 정의(1장), ETL 업무 매핑 상세(데이터 영역 가이드), 호스트 명명(5장)
- **핵심 플랫폼**: RDW, ADW (EXADATA RAC)

## 3. 설계 원칙

1. **고가용성 우선**: RDW/ADW는 RAC(Active-Active) 이중화로 설계한다.
2. **원천 부하 최소화**: 계정계 Source → 중계(Downstream) → 정보계 경로로 원천 DB 부하를 분산한다.
3. **OLTP·배치 분리 의식**: 실시간 거래와 대량 배치가 동일 자원에서 충돌하지 않도록 수행 방안을 명시한다.
4. **접근 경로 표준화**: 서버/앱별 DB 접근 방안을 표로 고정한다.
5. **복제 책임 분리**: CDC(실시간)·ETL(배치/BCV)·RDW→ADW 동기화 목적을 혼동하지 않는다.

## 4. 설계 기준 (결정 규칙)

- RDW·ADW는 EXADATA RAC 구성(노드 수·식)을 설계서에 명시한다.
- OGG/CDC 중계서버 역할을 구성도에 포함한다.
- 계정계 BCV→ETL, CDC 실시간, RDW→ADW ETL 경로를 IF(6장)와 용어를 맞춘다.
- 배치 윈도우·자원 분리 정책을 OLTP 영향 관점에서 기술한다.

## 5. 구성·경계

```text
계정계(Source) ─CDC/OGG─▶ 중계(Downstream) ─▶ 정보계 RDW
코어 BCV ─ETL─▶ RDW
RDW ─ETL─▶ ADW
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 중계서버를 두어 계정계 직접 부하를 줄임 | 계정계에 정보계 배치·조회를 직접 과다 연결 |
| RAC·이중화 토폴로지를 도식으로 고정 | 단일 노드 가정으로 용량·가용성 설계 |
| OLTP/배치 수행 방안을 문서화 | 동일 피크에 대량 ETL과 온라인 조회를 무계획 병행 |

## 7. 설계 체크리스트

- [ ] RDW/ADW RAC 구성이 명시되었는가?
- [ ] 이중화·OGG/CDC 중계도가 존재하는가?
- [ ] 서버별 DB 접근 방안이 정의되었는가?
- [ ] OLTP·대용량 배치 공존 방안이 있는가?
- [ ] 6장 데이터 IF 표준과 용어·경로가 일치하는가?
