# 08. 아키텍처 표준화 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)
> **PPT 장**: 8장 · 슬라이드 109~138
> **방법론 폴더**: `05-MECHANISM`
> **작성일**: 2026-08-26

---

## 1. 목적

어플리케이션 계층·전문·GUID·캐릭터셋·거래 처리 구조 등 개발이 공유하는 아키텍처 표준을 설계·준수한다. PPT 8장 반복 블록은 단일 표준본으로 관리한다.

## 2. 적용 범위

- **포함**: 단말/온라인 패키지·계층, 거래 처리 구조, 전문 표준화, GUID, 캐릭터셋
- **제외**: Upload/RD/Inbound/SSO 등 구성 요소 상세(9장) — 표준과의 인터페이스만 본 장
- **주의**: 슬라이드 110~123과 125~138 반복 → 방법론 MD를 Single Source of Truth로 사용

## 3. 설계 원칙

1. **계층 고정**: 앱 그룹 → 앱 → 기능 → Controller/Service/DAO 계층을 표준으로 한다.
2. **표준전문 기본**: 온라인 거래는 표준전문을 쓰고, 패키지 UI 등 예외만 개별 처리한다.
3. **GUID 일관**: 거래 추적은 GUID 관리 체계를 따른다.
4. **캐릭터셋 통일**: 연계·저장·화면 구간의 캐릭터셋 정의를 준수한다.
5. **중복 장표 금지**: 동일 표준을 PPT에 이중 유지하지 말고 메커니즘 문서로 통합한다.

## 4. 설계 기준 (결정 규칙)

- 신규 기능은 분류체계 코드·패키지 경로·resource 명명 규칙을 따른다.
- 거래 처리 구조도(진입→선후처리→서비스→응답)를 표준에서 벗어나지 않는다.
- 전문 적용 범위(통합업무·채널·MCA 등)와 예외(Package UI)를 설계서에 명시한다.
- 업무 간 호출은 `메커니즘-아키텍처표준-업무간_호출구조_개발가이드`를 따른다.

## 5. 구성·경계

```text
표준화 축
├─ 어플리케이션 계층 구조
├─ 전문 표준화
├─ GUID 관리
├─ 캐릭터셋
└─ 거래 처리 구조
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 표준전문·GUID·캐릭터셋을 거래 설계서에 기입 | 연계마다 임의 전문 포맷 발명 |
| 패키지 계층·resource 규칙 준수 | 그룹/앱 경계를 무시하는 패키지 배치 |
| 방법론 MD를 개정 후 PPT 반영 | PPT 반복본만 수정해 문서 분기 |

## 7. 설계 체크리스트

- [ ] 계층·패키지 구조가 표준과 일치하는가?
- [ ] 전문 적용/예외 범위가 명시되었는가?
- [ ] GUID·캐릭터셋 규칙이 반영되었는가?
- [ ] 거래 처리 구조가 표준 구조도와 같은가?
- [ ] 8장 중복 내용이 단일 문서로 정리되었는가?
