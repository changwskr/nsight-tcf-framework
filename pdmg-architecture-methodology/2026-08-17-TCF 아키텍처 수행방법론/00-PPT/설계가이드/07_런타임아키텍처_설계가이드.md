# 07. 런타임 아키텍처 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)
> **PPT 장**: 7장 · 슬라이드 101~108
> **방법론 폴더**: `06-RUNTIME`
> **작성일**: 2026-08-26

---

## 1. 목적

업무 처리 유형(6종)에 따라 요청이 채널·연계·이벤트·분석·파일·배치로 흐르는 런타임 경로를 설계하고 검증한다.

## 2. 적용 범위

- **포함**: 채널, 연계, 마케팅 이벤트, 데이터 분석/제공, 파일 연계, 배치; 단말 거래·미니싱글뷰 관점
- **제외**: FW 패키지 구조(8~9장), IF 매체 선정(6장) — 단, 런타임은 표준 매체를 전제
- **검증**: FAST/DEEP/NFR VALIDATION, RUNTIME-SCENARIOS

## 3. 설계 원칙

1. **유형 먼저**: 신규 업무는 6종 유형 중 어디에 속하는지 먼저 결정한다.
2. **채널은 HTTP 웹 거래**: 정보단말·미니싱글뷰·싱글뷰는 웹 요청 거래로 모델링한다.
3. **연계는 대내·대외·타법인 경계**: 6장 표준 매체를 런타임 스텝에 명시한다.
4. **이벤트는 수집→규칙→접점 실행**: 마케팅 이벤트 파이프라인을 단계로 나눈다.
5. **배치·파일은 스케줄·전송 계약**: Control-M/FOS 등 운영 계약을 런타임 설계에 포함한다.

## 4. 설계 기준 (결정 규칙)

- 유형별 시퀀스(액터·서비스·FW·저장소)를 그린다.
- 타임아웃·재시도·멱등·보상은 유형 특성에 맞게 기입한다.
- 미니싱글뷰·UMS 통지 등은 해당 유형 하위 시나리오로 연결한다.
- NFR(응답·처리량·가용성) 검증 항목을 유형별로 연결한다.

## 5. 구성·경계

```text
업무 처리 유형 6종
1. 채널
2. 연계
3. 마케팅 이벤트
4. 데이터 분석/제공
5. 파일 연계
6. 배치
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 유형 태그 없이 거래를 신설하지 않음 | 유형 혼재(채널+배치)를 한 시퀀스에 무분별 혼합 |
| 런타임 시나리오·검증 문서와 동기화 | 장표만 있고 실패/지연 시나리오 없음 |
| 6장 IF 표준을 런타임 스텝에 표기 | 비표준 직접 연결을 런타임 정상 경로로 기술 |

## 7. 설계 체크리스트

- [ ] 6종 유형 중 분류가 명확한가?
- [ ] 유형별 상세분석·시퀀스가 존재하는가?
- [ ] 타임아웃·예외·재처리가 정의되었는가?
- [ ] NFR/시나리오 검증과 연결되어 있는가?
- [ ] 단말·미니싱글뷰 경로가 채널 유형과 정합한가?
