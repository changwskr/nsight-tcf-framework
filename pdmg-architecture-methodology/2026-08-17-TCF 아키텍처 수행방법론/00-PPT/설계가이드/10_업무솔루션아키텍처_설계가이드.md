# 10. 업무 솔루션 아키텍처 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)
> **PPT 장**: 10장 · 슬라이드 목차만(본문 약함)
> **방법론 폴더**: `03-LOGICAL · 06-RUNTIME`
> **작성일**: 2026-08-26

---

## 1. 목적

SELF-BI/OLAP/EBM 등 업무 솔루션·패키지 영역의 논리·IF·런타임 설계 기준을 제공한다. PPT 10장 본문이 약하므로 방법론 레이어드·IF·런타임 문서로 보완한다.

## 2. 적용 범위

- **포함**: BI/마케팅 솔루션 배치, 패키지 UI(MSTR 등), 신용실적·분석 제공, 마케팅 이벤트 실행과 솔루션 경계
- **제외**: 솔루션 벤더 기능 매뉴얼 전체, 일반 온라인 CRUD(8~9장 표준으로 처리)
- **상태**: PPT Gap → 본 가이드 + 방법론이 실질 설계 기준

## 3. 설계 원칙

1. **플랫폼 소속 명확화**: 솔루션은 BI포탈·마케팅플랫폼·데이터플랫폼 중 소속 그룹을 반드시 지정한다.
2. **IF 예외 최소화**: 패키지 UI 직접 경로·FOS 등 표준표 예외만 허용하고 신규한다.
3. **런타임 유형 정렬**: 분석 제공·마케팅 이벤트·채널 패키지 호출을 7장 유형에 매핑한다.
4. **데이터 계약**: 솔루션이 읽는 DW/마트/메타(비즈메타) 소유권을 명시한다.
5. **보안·권한**: 포탈·패키지 SSO(9장)와 역할 모델을 맞춘다.

## 4. 설계 기준 (결정 규칙)

- 솔루션 도입·변경 시 논리 레이어드(WEB/WAS/저장소) 위치를 갱신한다.
- 신용실적·비즈메타 등 특수 IF는 전용 분석 MD를 설계 입력으로 사용한다.
- OLAP/SELF-BI 조회는 데이터 분석/제공 런타임 유형으로 시퀀스를 작성한다.
- EBM/캠페인 실행은 마케팅 이벤트 유형과 접점(SMS/PUSH/메일 등)을 연결한다.

## 5. 구성·경계

```text
업무 솔루션 (설계 시 필수 기입)
├─ 소속 시스템 그룹 (BI / MP / RD / 거버넌스)
├─ UI 유형 (패키지 UI / 포탈 / 단말)
├─ IF 표준 행 (온라인·파일·데이터)
├─ 런타임 유형 (6종 중)
└─ 데이터 소유·권한
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 소속 그룹·IF·런타임 유형을 설계서 헤더에 기입 | 솔루션을 ‘기타’로만 두고 경계 미정의 |
| 비즈메타·신용실적 등 기존 IF 분석 재사용 | 동일 연계를 솔루션별로 중복 설계 |
| 패키지 예외를 표준표에 등재 | 예외를 암묵 운영 |

## 7. 설계 체크리스트

- [ ] 솔루션의 시스템 그룹·Zone이 정의되었는가?
- [ ] 패키지 UI/IF 예외가 6장 표준표에 있는가?
- [ ] 런타임 유형(분석/이벤트 등)이 매핑되었는가?
- [ ] 데이터 소유·메타(비즈메타) 관계가 명시되었는가?
- [ ] SSO·권한 모델이 9장과 정합한가?

## 8. 보완 노트 (PPT Gap)

PPT 통합본은 10장 목차만 있고 본문 장표가 약하다. 설계 시 본 가이드를 헤더로 쓰고, 위 방법론 MD를 본문으로 삼아 산출물을 작성한다. 추후 PPT 보강 시 본 가이드 §구성·체크리스트를 장표 목차로 사용한다.
