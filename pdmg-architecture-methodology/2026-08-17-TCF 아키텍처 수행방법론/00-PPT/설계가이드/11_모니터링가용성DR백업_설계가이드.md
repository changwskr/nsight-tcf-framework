# 11. 기타(모니터링·가용성·확장·DR·백업) — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)
> **PPT 장**: 11장 · 슬라이드 목차만(본문 약함)
> **방법론 폴더**: `01-VISION · 04-PHYSICAL · 06-RUNTIME`
> **작성일**: 2026-08-26

## 1. 목적

모니터링, 가용성, 확장, DR, 백업에 대한 설계 기준을 제공한다. PPT 11장 본문이 약하므로 NFR/SLA·HA-DR·인벤토리·NFR-VALIDATION으로 보완한다.

## 2. 적용 범위

- **포함**: NFR/SLA 목표, HA·DR 전환, 백업·복구, 모니터링·확장 관점, 검증 게이트
- **제외**: 업무 기능 모니터링 대시보드 UX 상세, 솔루션별 KPI 정의 전체
- **상태**: PPT Gap → 본 가이드 + NFR/HA-DR이 실질 설계 기준

## 3. 설계 원칙

1. **목표 선행**: 가용성·RPO/RTO·성능 SLA를 먼저 고정한 뒤 토폴로지를 정한다.
2. **DR은 운영 대응**: 3장 물리 대응표·4장 DB 이중화와 DR 런북을 일치시킨다.
3. **백업은 데이터·설정 구분**: DB·파일·설정·이미지 백업 대상을 분리해 정의한다.
4. **관측 가능성**: 거래로그·GUID·인프라 메트릭을 상관할 수 있게 설계한다.
5. **확장 축 명시**: 스케일아웃(WEB/WAS)·데이터 용량·이벤트 처리 중 어떤 축인지 밝힌다.

## 4. 설계 기준 (결정 규칙)

- NFR.md / SLA.md 목표치를 설계서에 인용한다.
- HA-DR.md의 전환 절차·대상 시스템을 환경(운영↔DR)과 매핑한다.
- 용량·인벤토리 문서로 확장 트리거(임계치)를 정한다.
- NFR-VALIDATION·FAST/DEEP 검증 항목을 릴리스 게이트에 연결한다.
- 모니터링 대상(앱/인프라/배치/IF)과 알람 책임을 표로 남긴다.

## 5. 구성·경계

```text
기타(운영 품질) 설계 축
├─ NFR / SLA
├─ HA / DR 전환
├─ 백업 / 복구
├─ 모니터링 / 관측
└─ 확장 (Scale) 정책
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| RPO/RTO·가용성 목표를 수치로 기입 | ‘고가용’만 적고 전환 절차 없음 |
| DR 서버·DB 이중화·런북을 한 세트로 관리 | 물리 DR만 있고 앱/배치 전환 누락 |
| 검증 문서를 게이트에 연결 | 장애 후에만 모니터링 항목을 추가 |

## 7. 설계 체크리스트

- [ ] NFR/SLA 목표가 설계에 인용되었는가?
- [ ] HA-DR 전환 대상·순서가 정의되었는가?
- [ ] 백업 대상·주기·복구 검증이 있는가?
- [ ] 모니터링·알람 책임이 할당되었는가?
- [ ] 확장 축·임계치가 용량 문서와 연결되었는가?
- [ ] NFR-VALIDATION 등 검증 게이트가 있는가?

## 8. 보완 노트 (PPT Gap)

PPT 통합본은 11장 목차만 있고 본문 장표가 약하다. 운영 품질·DR·백업 설계는 본 가이드와 NFR/HA-DR/용량/검증 문서를 세트로 사용한다.
