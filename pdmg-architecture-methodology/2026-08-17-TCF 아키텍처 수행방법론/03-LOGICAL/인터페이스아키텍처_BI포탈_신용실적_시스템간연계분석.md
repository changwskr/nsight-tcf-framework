# 인터페이스 아키텍처 — BI포탈 신용실적 시스템 간 연계 분석

## 1. 분석 개요

첨부 장표의 **BI포탈 신용실적** 구성을 기준으로, 웹정형보고서(신용실적) 모듈과 BI포탈·데이터거버넌스·하위 저장소 사이의 **연계 경계·산출물 유형·데이터 의존**을 분석한다.

장표 중심에는 **BI포탈 웹정형보고서 (신용실적)** 가 있고, 하단에 **BI포탈/비즈메타 · ADW · RDW** 저장소가 배치된다. 좌측 **BI포탈**과는 **보고서**, 우측 **데이터거버넌스**와는 **대시보드** 라벨의 양방향 점선으로 연결된다.

BI포탈 시스템구조도·데이터거버넌스 비즈메타 연관도와 맞물려, 본 장표는 **신용실적 정형보고서라는 단일 업무 산출물이 포탈·거버넌스에 어떻게 소비되는지**를 축약한 연계도이다.

> 이 문서는 이미지에서 판독한 논리 구조를 분석한 것이다. “보고서/대시보드”가 UI Link·임베드·API·배치 중 어느 매체인지, ADW/RDW 조회 경로, `BI포탈/비즈메타` 강조의 의미(주 의존 vs 권한·메타)는 구축 명세에서 확인해야 한다.

## 2. 핵심 결론

- **신용실적 = 웹정형보고서 모듈**: 범용 BI포탈과 분리된 **도메인 특화 정형보고서**로 표현된다.
- **소비 경로 이원화**: 동일 모듈이 **BI포탈에는 보고서**, **데이터거버넌스에는 대시보드**로 연계된다.
- **저장소 삼중 의존**: `BI포탈/비즈메타`(강조) · ADW · RDW 를 하단에 두어, 메타·분석DW·관계형DW를 함께 참조한다.
- **비즈메타 강조**: 세 저장소 중 `BI포탈/비즈메타`만 청색으로 강조되어, 신용실적 연계에서 **메타·용어·권한·계보** 의존이 크다는 신호로 읽힌다.
- **양방향 점선**: 보고서·대시보드 화살표가 양방향이므로, **단순 단방향 게시**가 아니라 호출·임베드·문맥 왕복 가능성이 있다.
- **포탈 vs 거버넌스 역할 분리**: 포탈은 업무 사용자용 **보고서**, 거버넌스는 품질·메타·모니터링 성격의 **대시보드** 소비로 해석된다.

## 3. 장표 구성요소 전사

### 3.1 중심 — BI포탈 웹정형보고서 (신용실적)

| 구성요소 | 표기 | 역할(해석) |
|---|---|---|
| 애플리케이션 모듈 | BI포탈 웹정형보고서 (신용실적) | 신용실적 정형 리포트 생성·조회·게시 로직 |

### 3.2 하단 저장소

| 저장소 | 강조 | 역할(해석) |
|---|---|---|
| BI포탈/비즈메타 | 청색(강조) | 포탈·비즈메타 공존 저장소. 메타·카탈로그·권한·용어 |
| ADW | 회색 | 분석용 DW. 집계·실적 분석 데이터 |
| RDW | 회색 | 관계형/정보계 DW. 정형 실적·원장성 데이터 |

> ADW/RDW의 정식 명칭(예: Analytical / Reporting DW)과 스키마 소유권은 데이터플랫폼·정보계 표준과 대조해 확정한다.

### 3.3 좌·우측 연계 시스템

| 방향 | 대상 | 라벨 | 역할(해석) |
|---|---|---|---|
| 좌 | BI포탈 | 보고서 | 포탈 메뉴·프레임에서 신용실적 정형보고서 소비 |
| 우 | 데이터거버넌스 | 대시보드 | 거버넌스 화면에서 신용실적 지표·상태 대시보드 소비 |

## 5. 인터페이스 매핑 (시스템 간)

| # | 출발 | 연계 유형(장표) | 도착 | 설계 의미 |
|---|---|---|---|---|
| 1 | BI포탈 | 보고서 | 웹정형보고서(신용실적) | 포탈 UX에서 신용실적 정형 리포트 진입·조회 |
| 2 | 웹정형보고서(신용실적) | 보고서 | BI포탈 | 리포트 결과·메뉴·권한 문맥을 포탈에 반영(양방향 해석) |
| 3 | 데이터거버넌스 | 대시보드 | 웹정형보고서(신용실적) | 거버넌스 UX에서 신용실적 대시보드 진입·조회 |
| 4 | 웹정형보고서(신용실적) | 대시보드 | 데이터거버넌스 | 지표·품질·메타 문맥을 거버넌스에 반영(양방향 해석) |
| 5 | 웹정형보고서(신용실적) | (내부) | BI포탈/비즈메타 | 메타·카탈로그·용어·권한 조회 |
| 6 | 웹정형보고서(신용실적) | (내부) | ADW | 분석·집계 실적 데이터 |
| 7 | 웹정형보고서(신용실적) | (내부) | RDW | 정형·원장성 실적 데이터 |

### 5.1 매핑에서 읽히는 설계 의도

1. **동일 실적 도메인을 소비자별로 다른 산출물 타입**(보고서 vs 대시보드)으로 노출한다.
2. **실행 데이터(ADW/RDW)** 와 **설명·통제 데이터(비즈메타)** 를 한 모듈 경계 안에서 함께 참조한다.
3. BI포탈과 데이터거버넌스를 **형제 소비자**로 두고, 신용실적 모듈을 공유 서비스로 둔다.
4. 장표에 Rest/Batch/UI Link 문자열이 없으므로, 보고서·대시보드는 **UI 임베드·메뉴 연동·포탈 프레임** 가능성이 높다(명세 확인).

## 6. 주요 처리 흐름

### 6.1 BI포탈 ←→ 신용실적 (보고서)

```text
사용자(BI포탈)
  → 보고서 연계(메뉴/프레임/임베드 등)
  → BI포탈 웹정형보고서 (신용실적)
  → BI포탈/비즈메타(메타·권한) + ADW/RDW(실적)
  → 정형보고서 화면·파일·조회 결과
  → BI포탈로 문맥·결과 반환
```

- SSO·메뉴 권한·리포트 파라미터가 포탈과 모듈 간 일치해야 한다.
- 대량 조회 시 포탈 세션 타임아웃·다운로드 정책을 정형보고서 모듈과 공유한다.

### 6.2 데이터거버넌스 ←→ 신용실적 (대시보드)

```text
사용자(데이터거버넌스)
  → 대시보드 연계
  → BI포탈 웹정형보고서 (신용실적) 또는 동일 데이터 기반 대시보드 뷰
  → 비즈메타(계보·오너·품질 문맥) + ADW/RDW(지표)
  → 거버넌스 대시보드에 표시
```

- 거버넌스 측 대시보드가 **동일 리포트 엔진 재사용**인지, **별도 뷰·위젯**인지를 명세로 구분한다.
- 품질·메타 지표와 신용실적 수치의 **신선도 SLA**를 맞춘다.

### 6.3 저장소 조회 (모듈 내부)

```text
웹정형보고서(신용실적)
  ├── BI포탈/비즈메타  → 용어·테이블·리포트 정의·권한
  ├── ADW             → 분석 집계·OLAP성 실적
  └── RDW             → 정형 상세·관계형 실적
```

- ADW/RDW 직접 JDBC vs 정보계 API/배치 적재 경로는 데이터플랫폼 표준과 맞춘다.
- 비즈메타 강조는 **정의 없이 수치만 보여주는 리포트 금지**에 가깝다.

## 7. 인터페이스 설계 원칙

1. **신용실적 정형보고서는 BI포탈·거버넌스에 각각 다른 소비 계약**(보고서 / 대시보드)을 제공한다.
2. **실적 수치(ADW/RDW)와 메타(비즈메타)를 한 조회 트랜잭션 문맥에서 정합**시킨다.
3. 포탈·거버넌스 사용자는 **원천 DW에 직접 접속하지 않고** 웹정형보고서 모듈을 경유한다.
4. 양방향 연계라도 **쓰기 권한·게시 권한**은 모듈·역할별로 명시한다(단순 조회 vs 리포트 등록).
5. 동일 지표가 보고서·대시보드에 동시에 노출될 때 **정의·집계식·기준일을 단일 소스(비즈메타)** 로 관리한다.
6. 추적 가능하도록 리포트/대시보드 호출에 **GUID·사용자·리포트ID**를 남긴다.
7. BI포탈 시스템구조도·비즈메타 연관도의 **Storage/배치/APIM 경로**와 본 도의 UI성 연계를 혼동하지 않는다.

## 8. 산출물·의존 특성 요약

| 구분 | 장점 | 위험 | 통제 포인트 |
|---|---|---|---|
| 보고서(↔BI포탈) | 업무 사용자 UX 일관 | 포탈-모듈 배포 결합 | 메뉴·권한·버전 동기화 |
| 대시보드(↔거버넌스) | 거버넌스 관점 모니터링 | 지표 정의 불일치 | 비즈메타 단일 정의 |
| BI포탈/비즈메타 | 용어·권한·계보 | DB 공유 장애 전파 | 스키마·계정 경계 |
| ADW | 분석 집계 성능 | 지연·재집계 | SLA·배치 완료 게이트 |
| RDW | 상세·정형 실적 | 대량 조회 부하 | 쿼리 가드·타임아웃 |

## 9. 품질·위험과 개선 권고

| 위험 | 영향 | 개선 권고 |
|---|---|---|
| 보고서 vs 대시보드 정의 분기 | 동일 실적의 수치 불일치 | 비즈메타 지표 정의 공유·회귀 비교 |
| ADW/RDW 기준일 불일치 | 보고서 신뢰 하락 | 기준일·마감 플래그 통일 |
| 비즈메타만 강조된 채 실적 경로 모호 | 구현 누락 | ADW/RDW 접근 계약(SQL/API) 명시 |
| 양방향 쓰기 범위 미정 | 권한 사고 | 조회-only vs 게시/등록 분리 |
| 포탈·거버넌스 이중 배포 | 버전 스큐 | 공통 모듈 버전·호환 매트릭스 |
| UI 임베드만으로 권한 위임 | 데이터 유출 | 모듈에서 권한 재검증 |
| 대량 다운로드 | 성능·개인정보 | 마스킹·용량 제한·감사 |

## 10. 점검 체크리스트

- [ ] “보고서”·“대시보드” 연계 매체가 UI Link / 임베드 / Rest / 배치인지 정의되어 있는가?
- [ ] BI포탈 메뉴·권한과 신용실적 리포트 권한이 동기화되는가?
- [ ] 데이터거버넌스 대시보드가 동일 엔진 재사용인지 별도 뷰인지 문서화되어 있는가?
- [ ] `BI포탈/비즈메타`·ADW·RDW 각각의 소유 팀·접속 계정·SLA가 있는가?
- [ ] 지표 정의·집계식이 비즈메타에 등록되고 보고서·대시보드가 이를 참조하는가?
- [ ] ADW/RDW 마감·재집계 완료 전 조회 차단 또는 경고가 있는가?
- [ ] 호출 추적(GUID·리포트ID·사용자)이 남는가?
- [ ] BI포탈 시스템구조도·비즈메타 연관도와 용어·DB 표기가 정합하는가?

## 11. 종합 평가

이 장표의 신용실적 연계는 **웹정형보고서 모듈을 중심에 두고, BI포탈에는 보고서·데이터거버넌스에는 대시보드로 이원화 소비하며, 하단에 비즈메타·ADW·RDW를 둔 구조**다. 비즈메타 강조는 실적 수치뿐 아니라 **메타·정의·권한**이 연계 품질의 핵심임을 보여 준다.

운영 품질은 **산출물 타입별 계약 명확화, ADW/RDW·메타 정합, 양방향 권한 범위, 포탈·거버넌스 버전 동기화**에 좌우된다. BI포탈·데이터거버넌스 레이어드/시스템구조 문서와 함께 읽어야 정보계 전체에서의 위치가 닫힌다.
