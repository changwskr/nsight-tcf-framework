쉽게 말하면 **`40-TEST/conformance-result.json`은 “아키텍처 규칙 검사 성적표”**입니다.

앞의 3개 단계를 학교 시험처럼 생각하면 가장 쉽습니다.

```text
20-MODEL
=
"우리 시스템은 이렇게 생겼다"
설계도

        ↓

30-CONFORMANCE
=
"이 규칙을 지켜야 한다"
시험문제 / 채점기준

        ↓

40-TEST/conformance-result
=
"실제로 검사해 보니 결과가 어땠다"
시험 성적표
```

예를 들어 `30-CONFORMANCE/reference-rules.json`에 이런 규칙이 있다고 하겠습니다.

| 규칙                           | 의미                                 |
| ------------------------------ | ------------------------------------ |
| ServiceId 중복 금지            | 같은 ServiceId가 2개 있으면 안 됨    |
| Handler 없는 ServiceId 금지    | 모든 ServiceId에 Handler가 있어야 함 |
| Handler → DAO 직접호출 금지    | Handler는 DAO를 바로 부르면 안 됨    |
| Controller → DAO 직접호출 금지 | Controller도 DAO를 바로 부르면 안 됨 |

그러면 `40-TEST`에서는 실제 `pdmg-service` 소스를 뒤집니다.

예를 들어:

```text
mgcoa9001S0
     ↓
mgcoa9001Handler
     ↓
mgcoa9001Facade
     ↓
mgcoa9001Service
     ↓
mgcoa9001DAO
```

이렇게 되어 있으면:

```text
ServiceId 존재             PASS
Handler 존재               PASS
Handler → Facade           PASS
Handler → DAO 직접호출 없음 PASS
```

입니다.

그래서 `conformance-result.json`에는 개념적으로 이런 결과가 들어갑니다.

```json
{
  "rule": "Handler → DAO 직접호출 금지",
  "result": "PASS"
}
```

반대로 실제 소스가:

```text
SomeHandler
    ↓
SomeDAO
```

로 되어 있으면:

```json
{
  "rule": "Handler → DAO 직접호출 금지",
  "result": "FAIL"
}
```

이 됩니다.

### `PASS`, `FAIL`, `HOLD`도 아주 간단합니다

| 결과     | 의미                      |
| -------- | ------------------------- |
| **PASS** | 검사했고 규칙을 지켰음    |
| **FAIL** | 검사했는데 규칙을 위반함  |
| **HOLD** | 아직 검사할 자료가 부족함 |

특히 `HOLD`가 중요합니다.

예를 들어:

```text
"빌드가 성공해야 한다"
```

라는 검사에서 실제 Gradle Build를 실행하지 않았다면,

```text
성공인지 실패인지 모름
        ↓
HOLD
```

입니다.

즉 **모른다고 PASS를 주면 안 됩니다.**

---

### 자동차 검사로 비유하면 더 쉽습니다

```text
20-MODEL
자동차 설계도
"브레이크가 있고, 안전벨트가 있고..."

30-CONFORMANCE
자동차 검사 기준
"브레이크가 정상이어야 한다"
"안전벨트가 있어야 한다"

40-TEST
실제 자동차 검사
"브레이크 정상 → PASS"
"안전벨트 정상 → PASS"
"에어백 검사는 못 함 → HOLD"

conformance-result.json
=
자동차 검사 결과표
```

PDMG로 다시 바꾸면:

```text
검사기준
─────────────────────────
ServiceId 중복 금지
Handler 존재
DAO 직접호출 금지
Package 규칙 준수
JWT Private Key 노출 금지

        ↓ 실제 소스 검사

검사결과
─────────────────────────
ServiceId 중복       PASS
Handler Mapping      PASS
Handler→DAO          PASS
Package Naming       PASS
Private Key          PASS
Build                HOLD
Test                 HOLD
```

이 전체 검사 결과를 저장하는 것이 **`conformance-result.json`**입니다.

따라서 세 파일만 기억하시면 됩니다.

```text
20-MODEL
"어떻게 생겼나?"

30-CONFORMANCE
"어떤 규칙을 지켜야 하나?"

40-TEST
"그래서 실제로 지켰나?"
```

**한 문장으로 정리하면:**

> `40-TEST/conformance-result.json` = **PDMG 실제 소스를 아키텍처 규칙으로 검사한 PASS/FAIL/HOLD 성적표**입니다.
