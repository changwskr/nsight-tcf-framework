# 1. 전체 Big Picture 요약

이 구성도는 차세대 정보계 전체를 다음 7개 영역으로 배치한다.

| No | 영역 | 핵심 구성 |
|---:|---|---|
| 1 | 채널 | 계정 단말 UI, 정보계 단말 UI, Package UI, Web 채널 UI, Mobile 채널 UI, SMS/PUSH/MAIL |
| 2 | 채널통합/연계 | MCA, JSON, 단위거래, Event, Noti, PUSH |
| 3 | 정보계 어플리케이션 서비스 | 마케팅플랫폼, BI포탈, 단말관리, 단말배포 |
| 4 | 마케팅 이벤트 처리 | Wise Collector, Kafka, 행동정보처리서버, 실시간처리서버, EBM, 고객행동데이터, 이벤트정보 |
| 5 | 데이터플랫폼 | RDW, ADW, JDBC, Agent, Polling, ETL |
| 6 | 데이터 거버넌스 | 비즈메타, 데이터 품질관리, 데이터 흐름관리 |
| 7 | 유관/외부 시스템 | 계정계, 정보계 유관 단위업무, Big Data, 계열사, 외부기관 |

아래 표는 원본 그림의 **좌 → 우 배치와 상 → 하 데이터 흐름**을 가능한 한 유지하여 TEXT 표로 변환한 것이다.

| 구역 | 채널 / 채널통합 | 정보계 어플리케이션 서비스 | 유관 시스템 / API | 데이터플랫폼 | 정보계 유관 / 외부 |
|---|---|---|---|---|---|
| 상단 온라인 | **계정 단말 UI** → 계정거래 → `MCA` / 단위거래<br>**정보계 단말 UI**, **Package UI** → `JSON` | **마케팅플랫폼 Web** → 마케팅플랫폼<br>**BI포탈 Web** → BI포탈<br>단말관리 / 단말배포 | 계정거래 → `MCA` → **계정코어**<br>`CDC` → 계정정보 → CDC중계<br>**API Gateway (CruzAPIM)** | `JDBC` 기반 접근 | 계정코어 / 계정계연계 / 경영관리 / 리스크관리<br>배치정보 → `MFT` / `FOS` |
| 업무 서비스 | 채널 요청 → JSON/서비스 | **마케팅플랫폼**: 공통, 통합고객, 개인고객, 기업고객, 상담판매, 통합상품, 캠페인, 컨텐츠, 메시지, 영업지원, CS, 미니싱글뷰, 실시간처리, 행동정보처리, 고객행동데이터, EBM | API Gateway 경유 연계 | **RDW** / **ADW** | 정보계 단위업무 / Big Data |
| 분석 서비스 | 정보계 단말/서비스 | **BI포탈**: BI포탈, 신용실적, OLAP, Self BI, 신BI포털UIUX | `JDBC` | RDW/ADW 조회·분석 | 분석 결과 활용 |
| 이벤트 수집 | Web 채널 UI / Mobile 채널 UI → `Event` | **마케팅 이벤트 처리** | - | Agent/JDBC 연계 | - |
| 행동 데이터 | 고객행태 → Event → Wise Collector Proxy | 행동정보처리서버 / 고객행태<br>Wise Collector 수집 → 고객행동데이터 Kafka | `Agent` | RDW의 마케팅정보 등으로 연계 | - |
| 실시간 이벤트 | Web/Mobile/Event | Kafka → 실시간처리서버 → EBM → 이벤트정보 | `API` | 실시간 데이터 연계 | UMS / PUSH |
| 데이터 수집·처리 | - | 데이터 수집 / 데이터 분석 | CDC / JDBC / Agent | **RDW**: 실시간 계열<br>**ADW**: 분석 계열 | 정보계 유관, Big Data |
| 거버넌스 | - | - | File / JDBC / Polling | **데이터 거버넌스**: 비즈메타, 데이터 품질관리, 데이터 흐름관리 | 정보계 유관/외부와 메타·파일 연계 |
| 배치/파일 | - | - | `ETL`, `FOS`, `MFT`, `대외 MCA` | RDW ↔ ADW 및 외부 데이터 이동 | 계정계 / 단위업무 / 계열사 / 외부기관 |

# 8. 아키텍처 분석

## 8.1 가장 큰 구조

이 그림의 중심축은 다음과 같다.

```text
Channel
   ↓
Application Service
   ↓
Data Platform
   ↓
Governance / External Integration
```

동시에 실시간 이벤트 업무는 별도의 병렬 축을 가진다.

```text
Web / Mobile Event
   ↓
Wise Collector
   ↓
Kafka
   ↓
Real-time Processing / EBM
   ↓
Customer Notification / Marketing Action
```

따라서 전체 시스템은 **온라인 업무 처리 축 + 실시간 행동/이벤트 처리 축 + 데이터 분석 축 + 배치/파일 연계 축**을 동시에 가진다.

## 8.2 RDW와 ADW의 역할 분리

이미지에서 RDW와 ADW는 물리적으로 별도의 데이터 영역으로 표시된다.

- **RDW**: 실시간SoR, 준실시간 집계, 준실시간 보고서마트, 마케팅정보
- **ADW**: 분석SoR, 분석통합/요약/집계, 분석단위업무마트, 분석보고서마트, 분석지원

즉 원본 구조는 **운영·준실시간 데이터와 분석성 데이터를 분리**하는 아키텍처다.

## 8.3 실시간 처리 구조

실시간 마케팅/고객행동 처리에는 `Event → Wise Collector → Kafka → 실시간 처리 → EBM`의 별도 파이프라인이 보인다.

이는 일반 온라인 JSON/JDBC 흐름과 분리된 이벤트 기반 처리 경로다.

## 8.4 연계 방식 다중화

그림에는 목적별로 연계 기술이 다르게 배치되어 있다.

- 온라인: `JSON`, `MCA`, `API Gateway`
- 실시간 데이터: `CDC`, `Kafka`, `Agent`
- DB 접근: `JDBC`
- 배치/대량 데이터: `ETL`
- 파일: `FOS`, `MFT`
- 대외기관: `대외 MCA`, `MFT`
- 알림: `API`, `PUSH`

즉 단일 인터페이스 기술로 통합하지 않고 **업무 특성과 데이터 특성에 맞게 연계 메커니즘을 분리**한다.

## 8.5 거버넌스 위치

데이터 거버넌스가 애플리케이션 내부가 아니라 데이터플랫폼 하단에 별도 횡단영역으로 존재한다.

이는 다음을 데이터 공통 관리기능으로 본다는 의미다.

- 비즈메타
- 데이터 품질
- 데이터 흐름

## 8.6 대내외 경계

상단의 `API Gateway(CruzAPIM)`와 하단의 `ETL/FOS/MFT/대외 MCA`가 서로 다른 성격의 경계 역할을 한다.

- API Gateway: 온라인/API 경계
- ETL/FOS/MFT: 데이터/파일 경계
- MCA: 계정·대외 거래 경계
