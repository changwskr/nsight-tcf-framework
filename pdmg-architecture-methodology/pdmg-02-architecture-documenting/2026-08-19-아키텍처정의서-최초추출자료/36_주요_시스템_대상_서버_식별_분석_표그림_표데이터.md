# 1. 원본 핵심 문구

**정보계 차세대 시스템은 주요 시스템 영역에 대해 논리적 대상 서버군을 각각 식별 함**

# 4. 시스템 영역별 상세 표데이터

## 4.1 마케팅플랫폼

| 순번 | 대상 서버 | 역할 해석 |
|---:|---|---|
| 1 | 마케팅플랫폼 서버 | 마케팅플랫폼의 일반 온라인 업무 처리 영역 |
| 2 | 미니 싱글뷰 서버 | 미니 싱글뷰 전용 업무 처리 영역 |
| 3 | 실시간처리 서버 | 실시간 이벤트/업무 처리 영역 |
| 4 | 행동처리 서버 | 고객 행동정보 처리 영역 |
| 5 | 고객행동데이터 서버 | 고객 행동 데이터 수집·처리 영역 |

### TEXT 구조

```text
마케팅플랫폼
├─ 마케팅플랫폼 서버
├─ 미니 싱글뷰 서버
├─ 실시간처리 서버
├─ 행동처리 서버
└─ 고객행동데이터 서버
```

### 분석

이미지에서는 마케팅플랫폼을 하나의 서버군으로 단순화하지 않고 다음처럼 성격이 다른 실행영역으로 나눈다.

- 일반 온라인 마케팅 업무
- 미니 싱글뷰
- 실시간 이벤트 처리
- 고객 행동 처리
- 고객 행동 데이터 처리

즉 **동기 온라인 업무와 이벤트/행동 데이터 처리 영역을 논리적으로 분리**하는 방향이다.

## 4.2 데이터플랫폼

| 순번 | 대상 서버 | 역할 |
|---:|---|---|
| 1 | ADW | Analytical Data Warehouse |
| 2 | RDW | Real-time Data Warehouse |

### TEXT 구조

```text
데이터플랫폼
├─ ADW
└─ RDW
```

### 분석

데이터플랫폼은 다음 두 데이터 처리 성격을 분리한다.

| 영역 | 데이터 처리 성격 |
|---|---|
| RDW | 실시간/준실시간 데이터 저장 및 서비스 |
| ADW | 분석용 데이터 저장·집계·마트·분석 지원 |

따라서 Big Picture에서 확인된 **RDW/ADW 이원화 구조가 서버 식별 기준에도 그대로 반영**된다.

| 3 | OLAP 서버 | 정형/비정형 분석 |

- OLAP
- Self BI

이는 업무 특성, 솔루션 특성, 자원 사용 패턴이 다른 분석 서비스를 **논리적 서버군 단위로 독립 관리**하려는 구조로 볼 수 있다.

# 8. 아키텍처 관점 분석

## 8.1 시스템 영역과 서버군을 1:1로 보지 않는다

이 페이지의 핵심은 하나의 시스템 영역에 하나의 서버만 할당하는 구조가 아니라는 점이다.

예를 들어 마케팅플랫폼은 다음 5개 서버 유형으로 분리된다.

```text
Marketing Platform
   │
   ├─ 일반 온라인
   ├─ Mini Single View
   ├─ Real-time Processing
   ├─ Behavior Processing
   └─ Customer Behavior Data
```

따라서 **업무 특성과 처리 성격에 따라 실행 서버군을 분리**한다.

## 8.2 데이터 워크로드 분리

데이터플랫폼은 RDW와 ADW로 분리된다.

```text
RDW = 실시간/준실시간
ADW = 분석/집계/마트
```

이는 운영성/실시간 데이터와 분석성 데이터의 자원 경합을 줄이기 위한 논리 분리 기준으로 해석할 수 있다.

## 8.3 BI 솔루션별 독립 서버군

BI 영역은 BI포탈, 신용실적, OLAP, Self BI로 구분된다.

이는 각각 다른 기능/솔루션 및 자원 패턴을 가질 수 있으므로 운영·장애·용량 관점에서 서버군을 분리하는 구조다.

## 8.4 데이터 거버넌스의 독립성

비즈메타/데이터품질과 데이터흐름을 별도 서버군으로 식별한다.

즉 데이터 거버넌스는 단순 관리 화면이 아니라 **독립적인 기술 서비스 영역**으로 취급된다.

## 8.5 공통 지원 인프라의 분리

IT서비스 및 인프라 지원에는 사용자 업무 처리와 직접 관련되지 않는 다음 서버들이 별도 식별된다.

- Source Management
- Deployment
- Batch
- CDC
- ETL
- Terminal Management
- Report

이 구조는 개발·배포·운영·데이터 이동 책임을 업무 WAS와 분리한다.

## 8.6 임시 인프라의 Lifecycle 분리

데이터 이행과 SQL 품질관리 서버는 `기타(임시)`로 별도 표시된다.

따라서 본 서버군은 운영 Baseline과 분리하여 **구축 단계 Lifecycle 자산**으로 관리하는 것이 원본 구조에 부합한다.

---

# 9. 관리 기준으로 변환한 표

이 장표를 실제 서버 인벤토리/Physical Architecture 관리 기준으로 확장하면 다음 컬럼 구조가 적절하다.

| 관리 계층 | 예 |
|---|---|
| Application Group | MP / RD / AD / BI / DG / IM |
| System Group | 마케팅플랫폼 / 데이터플랫폼 / BI포탈 / 데이터거버넌스 / IT서비스 |
| Logical Server Type | 마케팅플랫폼 서버 / RDW / OLAP / ETL 등 |
| Server Role | WEB / WAS / AP / DB / ETL / CDC 등 |
| Physical/VM Instance | 실제 Hostname |
| HA Group | #01/#02 등 |
| DR Group | #51/#52 등 |
| Software | Apache / Tomcat / GitLab / OGG / DataStage 등 |
| Capacity | CPU / MEM / Disk / tpmC / TPS |
| Runtime | JVM / Thread / Pool |
| Lifecycle | 운영 / 개발 / DR / 임시 |

> 이 확장 컬럼은 이번 이미지에 직접 모두 적혀 있는 값은 아니며, **장표의 논리적 대상 서버 식별을 실제 인벤토리로 연결할 때 사용할 관리 구조**이다.

# 10. 핵심 결론

이번 장표에서 확정적으로 읽을 수 있는 핵심은 다음과 같다.

1. 차세대 정보계의 주요 시스템 영역은 **마케팅플랫폼, 데이터플랫폼, BI포탈, 데이터거버넌스, IT서비스 및 인프라지원, 기타(임시)**로 나뉜다.
2. 각 영역은 하나 이상의 **논리적 대상 서버군**으로 세분화된다.
3. 이미지에서 총 **23개 논리적 서버 유형**을 식별할 수 있다.
4. 마케팅플랫폼은 일반 온라인과 실시간/행동처리를 분리한다.
5. 데이터플랫폼은 RDW와 ADW를 분리한다.
6. BI포탈은 BI포탈/신용실적/OLAP/Self BI를 분리한다.
7. 데이터거버넌스는 메타·품질과 데이터흐름을 분리한다.
8. IT서비스는 단말, 배치, CDC, ETL, 출력, Source/Deploy 기능을 별도 서버군으로 둔다.
9. 데이터 이행 및 SQL 품질관리는 운영계가 아닌 **임시 서버군**으로 구분한다.

# 11. 원본 판독 주의사항

- 이 장표의 `대상서버`는 **논리적 서버 유형**을 의미하며 실제 장비 대수와 동일하지 않다.
- WEB/WAS/AP/DB별 실제 서버 수, HA/DR 노드 수, CPU/MEM/Disk 등은 이 이미지에서 확인되지 않는다.
- `Git Lab`, `Gitlab Runner` 표기는 원본 장표의 표기를 유지하였다.
- 마케팅플랫폼의 `행동처리 서버`는 원본 우측 목록 기준으로 기록하였다.
