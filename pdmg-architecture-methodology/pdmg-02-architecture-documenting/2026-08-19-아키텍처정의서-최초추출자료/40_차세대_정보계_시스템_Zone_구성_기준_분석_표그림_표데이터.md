# 1. 원본 핵심 문구

**전사 IT Zone 체계는 운영·개발·DR 전 환경에 공통 적용되며, 차세대 정보계 시스템은 각 환경별 구축 대상 시스템 목적에 따라 서비스 제공 Zone을 중심으로 구성함**

이 장표는 차세대 정보계의 논리 기술 아키텍처에서 다음 두 가지를 정의한다.

1. **전사 IT Zone 체계**
2. **운영·개발·DR 환경별 구축 대상 시스템**

---

# 2. 전체 Zone Big Picture

이미지에서 확인되는 전사 IT Zone은 총 6개이다.

| No | Zone | 역할 |
|---:|---|---|
| 1 | 대내 채널 Zone | 내부 사용자가 고객의 업무 처리를 위해 접근하는 영역 |
| 2 | 대고객 채널 Zone | 고객 채널을 통해 업무 요청이 유입되는 영역 |
| 3 | 대외 채널 Zone | 대외기관과 업무 연계를 수행하는 영역 |
| 4 | 채널 통합 Zone | 대내·대외 채널 요청을 통합·중계하는 영역 |
| 5 | 서비스 제공 Zone | 업무 로직 및 데이터를 처리·저장하는 핵심 시스템 영역 |
| 6 | 대내 통합 Zone | 내부 시스템 간 인터페이스 통합을 지원하는 영역 |

# 4. Zone별 상세 표데이터

## 4.1 대내 채널 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 대내 채널 Zone |
| 정의 | 내부 사용자가 고객의 업무 처리를 위해 접근하는 영역 |
| 주요 예시 | 통합업무시스템, 정보단말 등 |
| 사용자 관점 | 내부 임직원/업무 사용자 |
| 요청 성격 | 내부 사용자 기반 업무 요청 |

### 분석

이 Zone은 외부 고객용 채널이 아니라 **내부 사용자가 고객 업무를 처리하기 위해 사용하는 업무 접점**이다.

대표적으로 다음 유형이 포함된다.

- 통합업무시스템
- 정보계 단말
- 내부 업무 UI

즉 사용자 위치는 내부이지만, 최종 업무 목적은 고객 업무 처리일 수 있다.

---

## 4.2 대고객 채널 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 대고객 채널 Zone |
| 정의 | 고객 채널을 통해 업무 요청이 유입되는 영역 |
| 주요 예시 | 인터넷뱅킹, 스마트뱅킹, 톡뱅킹 등 |
| 사용자 관점 | 외부 고객 |
| 요청 성격 | 고객 직접 요청 |

### 분석

대고객 채널 Zone은 고객이 직접 사용하는 채널 영역이다.

```text
고객
 ↓
인터넷뱅킹 / 스마트뱅킹 / 톡뱅킹
 ↓
채널 통합 Zone
 ↓
서비스 제공 Zone
```

이 Zone에서는 고객 요청이 직접 유입되므로, 이후 채널 통합 및 서비스 제공 영역으로 연결되는 진입점 역할을 한다.

---

## 4.3 대외 채널 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 대외 채널 Zone |
| 정의 | 대외기관과 업무 연계를 수행하는 영역 |
| 주요 예시 | 공공기관, 금융기관, 농협자산관리, 농정원, 농협신용보증 등 |
| 사용자/시스템 관점 | 외부 기관/외부 시스템 |
| 요청 성격 | 기관 간 업무 연계 |

### 분석

대외 채널 Zone은 개인 고객이 아니라 **외부 기관과의 업무 연계 경계**다.

원본에서 확인되는 주요 예시는 다음과 같다.

- 공공기관
- 금융기관
- 농협자산관리
- 농정원
- 농협신용보증

이 Zone은 외부기관 연계를 전사 아키텍처 안에서 별도의 채널 경계로 관리한다.

---

## 4.4 채널 통합 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 채널 통합 Zone |
| 정의 | 대내·대외 채널 요청을 통합·중계하는 영역 |
| 주요 예시 | 영업점MCA, MCI, 대외MCA 등 |
| 핵심 역할 | 채널 요청의 중계·통합 |
| 위치 | 채널 영역과 서비스 제공 Zone 사이 |

### TEXT 구조

```text
대내 채널
   │
대고객 채널
   │
대외 채널
   │
   ▼
채널 통합 Zone
├─ 영업점MCA
├─ MCI
└─ 대외MCA
   │
   ▼
서비스 제공 Zone
```

### 분석

채널 통합 Zone은 여러 채널에서 발생하는 요청을 서비스 시스템이 직접 각각 처리하지 않도록 **중간 통합 계층**을 둔다.

즉 다음 역할을 가진다.

- 채널 종류별 요청 수용
- 대내/대외 요청 통합
- 서비스 영역으로의 중계
- 채널과 서비스 간 결합도 완화

---

## 4.5 서비스 제공 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 서비스 제공 Zone |
| 정의 | 업무 로직 및 데이터를 처리·저장하는 핵심 시스템 영역 |
| 주요 예시 | 마케팅플랫폼, 데이터플랫폼, BI포탈, 데이터거버넌스, IT서비스 등 |
| 핵심 역할 | 업무처리, 데이터처리, 데이터저장 |
| 차세대 정보계 중심성 | **차세대 정보계 시스템의 중심 Zone** |

### 주요 시스템

| 시스템 영역 | 역할 |
|---|---|
| 마케팅플랫폼 | 고객/상품/캠페인/상담/실시간 마케팅 업무 |
| 데이터플랫폼 | RDW/ADW 중심 데이터 저장·처리 |
| BI포탈 | BI Portal, OLAP, Self BI 등 분석 서비스 |
| 데이터거버넌스 | 메타, 품질, 데이터 흐름 관리 |
| IT서비스 및 업무지원 | 공통 개발·운영·배포·데이터 처리 지원 |

### 분석

원본 상단 핵심 문구에서 차세대 정보계는 **“서비스 제공 Zone을 중심으로 구성”**한다고 명시한다.

따라서 NSIGHT의 실제 업무 서버와 데이터 서버는 이 Zone을 중심으로 구성되는 것이 논리 아키텍처의 기본 원칙이다.

```text
채널
 ↓
채널 통합
 ↓
┌───────────────────────────┐
│      서비스 제공 Zone     │
│                           │
│ 마케팅플랫폼              │
│ 데이터플랫폼              │
│ BI포탈                    │
│ 데이터거버넌스            │
│ IT서비스 및 업무지원       │
└───────────────────────────┘
 ↓
대내 통합 / 외부 연계
```

## 4.6 대내 통합 Zone

| 항목 | 내용 |
|---|---|
| Zone 명칭 | 대내 통합 Zone |
| 정의 | 내부 시스템 간 인터페이스 통합을 지원하는 영역 |
| 주요 예시 | API Gateway, EAI, FOS, MFT 등 |
| 핵심 역할 | 내부 시스템 간 표준 인터페이스 제공 |
| 연계 유형 | API, EAI, 파일, MFT |

### TEXT 구조

```text
서비스 제공 Zone
        │
        ▼
대내 통합 Zone
├─ API Gateway
├─ EAI
├─ FOS
└─ MFT
        │
        ▼
```

대내 통합 Zone은 애플리케이션 간 직접 연결을 최소화하고 내부 연계를 중앙화하는 구조다.

이미지의 주요 기술은 다음 4개다.

| 기술 | 용도 |
|---|---|
| API Gateway | API 기반 시스템 연계 |
| EAI | Enterprise Application Integration |
| FOS | 파일 기반 연계 |
| MFT | Managed File Transfer |

# 6. 환경별 구축 대상 시스템

원본 하단 표에서 운영·개발·DR 환경별 서비스 제공 Zone 대상 시스템이 다음과 같이 정의된다.

| 환경 | 구축 대상 시스템 (서비스 제공 Zone) | 운영 목적 |
|---|---|---|
| 운영 | 마케팅플랫폼, 데이터플랫폼, BI포탈, 데이터거버넌스, IT서비스 및 업무지원 | 고객 서비스 제공을 위한 운영 환경 |
| 개발 | 마케팅플랫폼, 데이터플랫폼, BI포탈, 데이터거버넌스, IT서비스 및 업무지원 | 신규/변경 개발 및 기능 테스트를 위한 개발 환경 |
| DR | 마케팅플랫폼, 데이터플랫폼, IT서비스 및 업무지원 | 재해복구를 위한 DR 환경 |

# 8. 운영·개발·DR 구성 차이

## 8.1 운영

운영환경은 전체 핵심 서비스 영역을 포함한다.

```text
운영
├─ 마케팅플랫폼
├─ 데이터플랫폼
├─ BI포탈
├─ 데이터거버넌스
└─ IT서비스 및 업무지원
```

운영 목적은 **고객 서비스 제공**이다.

---

## 8.2 개발

개발환경은 운영과 동일하게 주요 시스템 영역 전체를 포함한다.

```text
개발
├─ 마케팅플랫폼
├─ 데이터플랫폼
├─ BI포탈
├─ 데이터거버넌스
└─ IT서비스 및 업무지원
```

운영 목적은 **신규/변경 개발 및 기능 테스트**다.

원본 기준으로는 운영과 개발의 구축 대상 시스템 범위가 동일하다.

---

## 8.3 DR

DR환경은 운영/개발 대비 범위가 축소된다.

```text
DR
├─ 마케팅플랫폼
├─ 데이터플랫폼
└─ IT서비스 및 업무지원
```

원본 이미지에서는 다음 두 영역이 DR 구축 대상 목록에 없다.

- BI포탈
- 데이터거버넌스

### 분석

이 장표 자체만 보면 DR은 운영 전체를 1:1 복제하는 형태가 아니라 **재해복구에 필요한 핵심 업무·데이터·공통지원 중심의 선택적 DR**로 정의되어 있다.

다만 BI포탈과 데이터거버넌스가 DR에서 완전히 제외되는지, 또는 별도 복구 전략을 가지는지는 이 이미지 하나만으로 확정할 수 없다.

# 9. 환경별 시스템 매트릭스

# 10. Zone 관점 아키텍처 해석

## 10.1 Zone은 시스템 분류가 아니라 논리적 통제 경계

이 장표에서 Zone은 단순히 서버를 묶는 이름이 아니다.

각 Zone은 다음을 구분하는 논리적 경계로 볼 수 있다.

- 사용자/기관 접근 경계
- 채널 통합 경계
- 서비스 실행 경계
- 시스템 통합 경계

```text
접근 주체
  ↓
Channel Zone
  ↓
Channel Integration Zone
  ↓
Service Zone
  ↓
Internal Integration Zone
```

---

## 10.2 서비스 제공 Zone이 NSIGHT의 중심

상단 문구는 차세대 정보계 시스템이 **서비스 제공 Zone을 중심으로 구성**된다고 명시한다.

이는 이전 Big Picture에서 식별한 다음 시스템들이 한 논리 영역에 들어감을 의미한다.

```text
서비스 제공 Zone
├─ 마케팅플랫폼
├─ 데이터플랫폼
├─ BI포탈
├─ 데이터거버넌스
└─ IT서비스 및 업무지원
```

따라서 NSIGHT의 업무/데이터/공통 서비스 서버군은 이 Zone의 핵심 구성요소다.

---

## 10.3 채널과 서비스의 직접 결합을 방지

채널 영역과 서비스 영역 사이에 **채널 통합 Zone**을 둔다.

이는 구조적으로 다음 직접 연결을 지양하는 방향으로 해석할 수 있다.

```text
채널 ─X─▶ 업무 서버 직접 연결
```

대신:

```text
채널
 ↓
채널 통합
 ↓
서비스 제공
```

을 사용한다.

---

## 10.4 서비스 간 연계도 대내 통합 Zone을 사용

서비스 시스템이 다른 내부 시스템과 연계할 때는 다음 통합 기술을 사용하도록 Zone을 구분한다.

- API Gateway
- EAI
- FOS
- MFT

즉 채널 연계와 내부 시스템 연계를 **서로 다른 통합 경계**로 분리한다.

# 13. 운영 설계 관점의 시사점

아래는 이미지 정의를 기반으로 한 구조적 해석이며, 원본에 직접 적힌 설정값은 아니다.

## 13.1 운영/개발/DR 동일 Zone 원칙

원본에서는 전사 IT Zone 체계를 운영·개발·DR 전 환경에 공통 적용한다고 명시한다.

따라서 환경이 달라져도 다음은 동일해야 한다.

- Zone 명칭
- Zone 역할
- 시스템 배치 원칙
- 인터페이스 경계

차이는 주로 **구축 대상 시스템의 범위와 운영 목적**이다.

## 13.2 보안 정책도 Zone 단위로 연결 가능

Zone이 논리적 경계이므로 향후 다음 보안/네트워크 정책을 연결하기 용이하다.

- 접근통제
- 방화벽
- 통신 허용 목록
- 인증/인가
- 외부기관 연결
- 서비스 간 인터페이스 통제

단, 구체적인 방화벽 Rule이나 Network CIDR은 본 이미지에서 정의하지 않는다.

## 13.3 DR은 서비스 중요도 기반 선택 가능

DR에서 BI포탈과 데이터거버넌스가 빠져 있다는 점은 **서비스 중요도에 따른 DR 우선순위 설정** 가능성을 시사한다.

다만 실제 RTO/RPO, 복구 순서, 대체 처리 방법은 다른 DR 설계 자료에서 확인해야 한다.

# 15. 핵심 결론

1. 전사 IT Zone 체계는 **운영·개발·DR 전체 환경에 공통 적용**된다.
2. 전사 Zone은 총 **6개 Zone**으로 구성된다.
3. 차세대 정보계의 핵심 시스템은 **서비스 제공 Zone**에 배치된다.
4. 채널 요청은 **채널 통합 Zone**을 거쳐 서비스로 전달된다.
5. 내부 시스템 연계는 **대내 통합 Zone**을 통해 수행한다.
6. 운영과 개발은 5개 주요 시스템 영역을 모두 구축한다.
7. DR은 마케팅플랫폼, 데이터플랫폼, IT서비스 및 업무지원 중심으로 구성된다.
8. 원본 기준으로 BI포탈과 데이터거버넌스는 DR 구축 대상 표에 포함되지 않는다.
9. Zone 분리는 이후 물리 아키텍처, 네트워크, 보안, 서버 배치, 인터페이스 통제의 상위 논리 기준으로 사용할 수 있다.

# 16. 원본 판독 주의사항

- `농정원`, `농협신용보증` 등 대외기관 명칭은 확대 이미지 기준으로 판독하였다.
- 본 이미지에는 실제 VLAN, Subnet, 방화벽 Rule, 물리 Network Zone 등의 값은 정의되어 있지 않다.
- DR에 미포함된 BI포탈/데이터거버넌스의 최종 복구 정책은 이 이미지 하나로 확정하지 않는다.
- Zone별 실제 서버 배치와 네트워크 주소는 후속 물리 아키텍처 자료에서 별도로 확인해야 한다.
