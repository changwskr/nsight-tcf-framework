# 데이터플랫폼 논리 기술 아키텍처 통합 정의
## 이미지 기반 TEXT 아키텍처 · 전체 컴포넌트 표 · 연계 흐름 통합

> 원본 위치: `2. 논리 기술 아키텍처 > 2.4 논리 기술 아키텍처 정의`  
> 원본 페이지: `66`  
> 기준 이미지: `20(1).png`  
> 목적: 데이터플랫폼 논리 기술 아키텍처를 **텍스트 구조도로 재구성**하고, 원천계·실시간 수집·RDW·ADW·타깃시스템·대외계까지의 전체 컴포넌트와 연계방식을 하나의 표 체계로 통합한다.  
> 작성 원칙: 이미지에 표시된 명칭과 연결관계를 우선한다. 원본 장표에서 화살표 방향이 불명확한 선은 `연계`로 표현하고, 임의로 호출방향을 확정하지 않는다.

# 1. 전체 아키텍처 개요

데이터플랫폼 논리 기술 아키텍처는 다음 6개 축으로 구성된다.

1. **원천/계정계 데이터 수집**
2. **실시간 고객행동 데이터 수집**
3. **RDW 기반 실시간/운영 데이터 처리**
4. **ADW 기반 분석 데이터 처리**
5. **RDW ↔ ADW 간 ETL 연계**
6. **경영관리·리스크관리·마이데이터·대외계 타깃시스템 제공**

이미지에서 RDW 내부는 다음 컴포넌트로 구성된다.

| No | RDW 컴포넌트 | 역할 |
|---:|---|---|

| 2 | 실시간 집계/분석 | 실시간 집계 및 분석 |

| 5 | 긴급성 파일 | 긴급/파일성 데이터 처리 |
| 6 | 마케팅 플랫폼 | 마케팅 관련 데이터 영역 |
| 7 | 원천행동 로그 | 고객행동 원천 로그 |
| 8 | Feedback | 결과/피드백 데이터 |

# 7. RDW ↔ ADW 관계

```text
RDW
 │
 │ ETL
 ▼
ADW
```

| 항목 | RDW | ADW |
|---|---|---|
| 성격 | 실시간/운영 중심 | 분석/마트 중심 |
| 실시간 SoR | O | O |
| 집계/분석 | 실시간 집계/분석 | 통합/요약/집계 |
| 업무지원 | O | 간접 |
| 로그분석 | O | 분석마트로 활용 가능 |
| 데이터마트 | 마케팅/업무성 | 통합/승인/분석/보고서 |
| BI/OLAP | RDW 내부에 표현 | 분석 데이터 공급 기반 |
| Feedback | O | O |
| 주요 적재 | CDC/MFT/FOS/JDBC | ETL |
| 외부제공 | 일부 | 경영관리/리스크/마이데이터/대외계 |

# 8. 실시간 고객행동 처리 구조

```text
[인터넷뱅킹 / 스마트뱅킹]
          │
          ▼
    Wise Collector
          │
          ▼
        KAFKA
          │
          ▼
  행동 정보 처리서버
          │
      insert/JDBC
          │
          ▼
         RDW
```

이미지에서 행동정보 처리서버는 RDW에 `insert`, `JDBC` 방식으로 연결된다.

# 9. EBM 실시간 처리 구조

```text
        RDW
         ▲
         │ Polling / JDBC
         │
실시간처리서버 EBM
   ├─ 형태감지분석
   └─ Smart Offer
      (발송제어관리)
```

| 컴포넌트 | 역할 |
|---|---|
| 실시간처리서버 EBM | 실시간 이벤트 기반 처리 |
| 형태감지분석 | 고객행동/패턴 감지 |
| Smart Offer | 실시간 제안/발송제어 |
| Polling | 데이터 상태 또는 대상 조회 |
| JDBC | DB 직접 연계 |

# 14. 아키텍처 특성

## 14.1 RDW는 실시간/운영 데이터 허브

RDW에는 다음 데이터가 집중된다.

- 실시간 SoR
- 실시간 집계/분석
- 업무지원
- 로그분석
- 긴급성 파일
- 마케팅플랫폼
- 원천행동로그
- Feedback
- BI포탈
- OLAP
- 데이터품질

따라서 RDW는 단순 저장소가 아니라 **실시간 수집·업무 활용·분석 전처리·행동로그·BI 연계를 통합하는 운영 데이터 허브**로 정의할 수 있다.

---

## 14.2 ADW는 분석/마트 허브

ADW의 중심 기능은 다음과 같다.

- 통합/요약/집계
- 통합마트
- 분석/보고서마트
- 승인마트
- Feedback

즉 ADW는 **분석 목적의 통합·요약·마트 구조**를 담당한다.

---

## 14.3 실시간과 배치를 병행

데이터 수집/처리는 다음 방식이 동시에 존재한다.

```text
실시간 : CDC / Kafka / JDBC / insert / Polling
배치   : ETL / MFT / FOS
```

따라서 본 구조는 **Hybrid Data Processing Architecture**로 볼 수 있다.

---

## 14.4 내부/외부 제공 수단을 목적별로 분리

| 방식 | 주요 목적 |
|---|---|
| CDC | 변경 데이터 실시간 수집 |
| Kafka | 고객행동 이벤트 Streaming |
| JDBC | DB 직접 연계 |
| ETL | 대량 데이터 변환/적재 |
| FOS | 파일 기반 연계 |
| MFT | 관리형 파일 전송 |
| 대외 MCA | 대외 온라인 거래/연계 |

# 16. 최종 통합 정의

데이터플랫폼 논리 기술 아키텍처는 다음처럼 정의할 수 있다.

```text
원천계/채널
   ↓
CDC / MFT / FOS / ETL / Kafka
   ↓
실시간 수집·처리
   ↓
RDW
   ├─ 실시간 SoR
   ├─ 실시간 집계/분석
   ├─ 업무지원
   ├─ 로그분석
   ├─ 마케팅/행동로그
   ├─ BI/OLAP
   └─ 데이터품질
   ↓ ETL
ADW
   ├─ 통합/요약/집계
   ├─ 통합마트
   ├─ 분석/보고서마트
   ├─ 승인마트
   └─ Feedback
   ↓
경영관리 / 리스크관리 / 마이데이터 / 대외계
```

핵심 구조는 다음 4가지다.

1. **CDC 기반 계정계 실시간 수집**
2. **Kafka 기반 고객행동 Streaming**
3. **RDW 중심 실시간/운영 데이터 허브**
4. **ADW 중심 분석/마트 데이터 허브**
