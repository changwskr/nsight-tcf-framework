# 4. 공통 Default S/W

장표의 범례에서는 `Default S/W`가 공통 시스템 소프트웨어 묶음임을 나타낸다.

```text
Default S/W
 ├─ 시스템 S/W
 ├─ 서버보안
 ├─ 백업
 └─ OS백업
```

제품명은 장표에 구체적으로 기재되어 있지 않으므로 별도 시스템SW 인벤토리와 대조가 필요하다.

# 5. 아키텍처 해석

1. **환경 승격에 따라 S/W 스택은 동일 계열을 유지하되 노드 수가 증가**한다.
2. 개발에서는 Spring Boot/Kafka 등 구현기술이 구체적으로 드러나며, 운영은 서비스별 서버 단위 구성이 강조된다.
3. 운영의 단말관리/배포는 4~6노드로 확장되어 대규모 배포·운영 부하를 고려한다.
4. DR은 전체 S/W 복제형이 아니라 마케팅/미니싱글뷰/운영관리/RDW 중심의 선택적 복구 구조다.
5. 데이터 계층은 운영에서 ADW/RDW가 분리되고, 개발에서는 통합 Appliance로 축소된다.
6. 선도환경은 AS-IS CRM DB를 활용하면서 신규 WEB/WAS 및 운영도구 체계를 검증한다.
