# 1. 전체 구조

운영/DR 환경은 **의왕 센터(주 센터)**와 **안성 센터(DR 센터)**의 이중 센터 구조다.

```text
                           [대부 GSLB]
                      ┌─────────┴─────────┐
                      │                   │
            의왕 센터(주 센터)       안성 센터(DR)
                      │                   │
          ┌───────────┼───────────┐       │
          │           │           │       │
       마케팅      실적/분석   거버넌스/운영  │
          │           │           │       │
          ├──────── 데이터처리/이행 ───────┤
          │           │                   │
          └────── 저장소 / DB ─── DCI ────┘
                      │                   │
              원천 시스템           RDW Standby
                                      Data Guard
```

핵심은 **운영계는 의왕 센터에 전체 기능을 배치하고, DR은 서비스 지속에 필요한 일부 WEB/WAS/운영관리와 RDW Standby를 선택적으로 배치**한 구조라는 점이다.

# 4. 센터 간 연결

이미지에는 두 센터 사이에 다음 통신/전환 요소가 표현되어 있다.

| 구성요소 | 역할 |
|---|---|
| 대부 GSLB | 센터 수준 트래픽/서비스 전환 |
| DCI | 의왕 ↔ 안성 데이터센터 인터커넥트 |
| Data Guard | RDW DB 원격지 복제 |
| Standby | DR DB 대기계 역할 |

```text
              GSLB
        ┌──────┴──────┐
        ▼             ▼
      의왕           안성
       │              │
       └──── DCI ─────┘
              │
        Data Guard
```

# 7. 물리 아키텍처 핵심 해석

1. **주센터/DR센터 이중화** 구조이며, 센터간 네트워크는 DCI, 서비스 전환은 GSLB로 표현된다.
2. 운영계 애플리케이션은 의왕 센터에 폭넓게 배치되지만 DR은 선택적이다.
3. **RDW는 Data Guard Standby가 명시**되어 DB 수준 DR이 명확하다.
4. **ADW DR 구성은 이미지에 명시되지 않는다.** 따라서 실제 DR 범위/RPO/RTO를 별도 확인해야 한다.
5. 운영 WEB/WAS는 다중 노드, DB Appliance는 별도 전용 노드군으로 구성된다.
6. 데이터 이행 영역은 x86 ETL과 UNIX CDC중계 DB 및 임시 이행 AP를 별도 분리한다.
7. 원천시스템은 디지털금융, 코어뱅킹 원천/복제 DB, FOS로 연결된다.

# 8. 확인 필요 사항

| 항목 | 확인 필요 내용 |
|---|---|
| DR 범위 | BI포탈/Self-BI/신용실적/거버넌스 DR 미표시 사유 |
| ADW | ADW DB의 DR/복제 방식 |
| AP DR | 실시간/행동정보/고객행동 AP의 재기동 또는 대체 전략 |
| RPO/RTO | 업무별 복구 목표 |
| GSLB | 자동/수동 전환 정책 |
| DCI | 대역폭/이중화/경로 |
| ETL/CDC | DR 시 배치/CDC 재개 전략 |
| Hostname | 일부 흐릿한 Hostname은 서버 인벤토리 원본과 대조 |
