## 시스템코드 사용 정책 (1/2)

업무시스템 단위로 시스템(OS, DBMS), 미들웨어 명명 시, 인터페이스와 형상관리의 관리 기준으로 ‘시스템코드’를 사용함

### 시스템코드 정의는 다음과 같다.

- 시스템코드는 물리적(서버, 인스턴스 등)으로 구분 가능한 업무시스템 단위를 의미한다.
- 시스템코드는 단일코드로 3자리 길이를 가지며 영문 약어 명을 조합하여 유일하게 코드를 부여한다.
- 시스템코드는 반드시 하나 이상의 서비스그룹(업무) 코드와 연관되어야 한다.

※ **글로벌 시스템:** 시스템코드의 경우 기존(본점) 시스템코드와 중복되지 않게 생성하여 코드명에 “[글로벌]”의 prefix를 부여한다.

### 시스템코드 사용 부분은 아래와 같다.

#### 1) 시스템 부문 명칭

시스템에서 각 호에 해당하는 명칭 작성 시에 시스템코드를 사용하도록 권고한다.

1. 서버 Host Name 작성 시 시스템코드를 사용한다. (예: `SYSAPP01`, `SYSDBP01` 등)
2. 업무시스템 사용자 계정(APP계정, FTP계정) 작성 시 시스템코드를 사용한다. (예: `sysapp`, `sysftp` 등)
3. DBMS의 DB 오브젝트(데이터베이스명, DB SID, DB 사용자 이름) 작성 시 시스템코드를 사용한다.

※ **글로벌 시스템**

- **① Host Name:** `GROC대표코드(3)` + `시스템코드(3)` + `서버구분(2)[ap, db, sv]` + `운영구분(1)[d:개발, t:테스트, p:운영]` + `일련번호(2)`
  - 예: 동북아ROC의 코어뱅킹시스템 AP 운영 시스템 : `gnacobapp01` / 구주ROC의 정보뱅킹시스템 DB 운영 시스템 : `geunobdbp01`
- **③ DBMS(데이터베이스명, DB SID)**
  - **데이터베이스명:** `운영구분(1)[D:개발, T:테스트, P:운영]` + `GROC대표코드(3)` + `시스템코드(3)`
  - **SID:** `데이터베이스명(7)` + `일련번호(1)`
  - 예: 동남아 OLI 운영 DB 명 : `PGSAOLI` / 구주 코어뱅킹시스템 개발 DB SID : `DGEUCOB1`
  - ※ **EDB:** DB명은 소문자로 생성, DB명과 SID가 동일

## 시스템코드 사용 정책 (2/2)

업무시스템 단위로 시스템(OS, DBMS), 미들웨어 명명 시, 인터페이스와 형상관리의 관리 기준으로 ‘시스템코드’를 사용함

> 시스템코드 사용 부분은 아래와 같다. (계속)

#### 2) 미들웨어 부문 명칭

미들웨어에서 각 호에 해당하는 명칭 작성 시에 시스템코드를 사용하도록 한다.

1. 웹서버 디렉토리 구성에 시스템코드를 사용한다. (Home/Log/Document Directory 등)
2. WAS서버 컨테이너와 디렉토리 구성에 시스템코드를 사용한다. (Container Name, Home/Context Root/Log Directory 등)
3. J2EE F/W 디렉토리 구성에 시스템코드를 사용한다. (예: `/sw/neoworks/app/sys`)

※ **글로벌 시스템:** 미들웨어 부문 명칭을 사용하지 않습니다.

#### 3) 인터페이스 기준

- EAI를 통한 인터페이스 구성 시에 시스템코드를 기준으로 사용한다.
- 인터페이스 송수신 정보 등록 시 시스템코드와 서비스그룹코드를 등록한다.

※ **글로벌 시스템:** OLB를 통한 인터페이스 구성 시에 시스템코드, 서비스그룹코드를 사용한다.

#### 4) 형상관리 기준

형상관리시스템에서 시스템코드의 시스템 명칭을 기준으로 형상을 관리한다.

### 시스템 부문 명칭에서 시스템코드 미사용 예외 사항

통합 업무 서버나 일부 업무(시스템/어플리케이션 관리, 보안 등) 서버인 경우에 서버 Host Name과 FTP계정, DBMS 서버인 경우 데이터베이스명과 DB SID 명칭을 예외로 할 수 있다.

## 서비스그룹 코드 사용 정책 (1/2)

프로그램과 데이터모델 설계 시, 인터페이스와 형상관리에서 업무 구분을 위해 서비스그룹(업무) 코드를 사용함

### 서비스그룹(업무) 코드 정의는 다음과 같다.

- 어플리케이션 아키텍처 맵 상의 최하위 요소인 서비스그룹 코드는 동질적인 논리적 기능을 수행하는 서비스들의 대표 집합을 의미하며, 일명 업무코드(AA레벨2 코드)라고도 불리운다.
- 서비스그룹 코드는 단일 코드로 3자리 길이를 가지며 영문 약어명을 조합하여 유일하게 코드를 부여한다. (시스템코드와는 별개의 코드로 관리)
- 서비스그룹 코드는 반드시 하나 이상의 시스템코드와 연관되어야 한다.

### 서비스그룹(업무) 코드 사용 부분은 아래와 같다.

#### 1) 업무코드 관리

논리적인 업무 간 구분을 하기 위한 고유 업무관리 코드로 사용한다.

#### 2) 프로그램 설계

- 자바 패키지나 상용 모듈 구성 시에 어플리케이션 아키텍처 구조에 따른 서비스그룹 코드 명칭 반영한다.
- 상용처리 시스템의 전체 구조를 정의하는 논리적인 패키지로 어플리케이션 아키텍처 맵을 사용하며, 설계 단계에서 시스템과 서브시스템, 디렉터리 구조로 구체화한다. 서비스그룹은 최하위 모듈로 구성된다.
- J2EE 프레임워크를 사용한 어플리케이션에서는 어플리케이션 아키텍처 맵을 패키지 계층 구조로 사용하며, 서비스 그룹 하위에 Service/Business Task 패키지를 위치 시킨다.

## 서비스그룹 코드 사용 정책 (2/2)

프로그램과 데이터모델 설계 시, 인터페이스와 형상관리에서 업무 구분을 위해 서비스그룹(업무) 코드를 사용함

> 서비스그룹(업무) 코드 사용 부분은 아래와 같다. (계속)

#### 3) 데이터 모델 설계

- 데이터 모델 명과 테이블 생성 시 서비스그룹 코드를 사용하여 설계한다.
- 업무시스템에서 사용할 논리/물리 모델을 전형적으로 구분하기 위해 어플리케이션 아키텍처 레벨 명을 모델 명칭으로 사용한다.
  - (예: `어플리케이션코드명_서비스그룹코드명`)
- 생성되는 테이블 스키마 명칭 설계에 서비스그룹코드를 Prefix로 사용한다.

#### 4) 인터페이스 참조

- 인터페이스 구성 시 시스템코드와 함께 서비스그룹코드를 등록한다.
- 인터페이스 요건 등록 시에 시스템코드에 상응하는 서비스그룹코드를 등록하여, 업무별 인터페이스 사용현황을 파악하는데 사용한다.

#### 5) 형상관리 참조

형상관리 시에 시스템코드(명칭) 하위에 서비스그룹 코드로 업무를 구분하여 관리한다.
