# Part A — Top-down 구조 이해

## A1. 핵심 결론

두 코드는 **물리 단위(시스템코드)** 와 **논리 업무 단위(서비스그룹코드)** 를 따로 부여한 뒤, **반드시 서로 연결**한다.  
이후 Host · 계정 · DB · 미들웨어 · 인터페이스 · 형상관리 · 패키지 · 데이터모델이 같은 코드를 공유한다.

```text
업무시스템 (물리로 구분 가능: 서버·인스턴스)
        │
        │  시스템코드 (3자리, 영문 약어, 유일)
        ▼
   SYS  ──┬── Host / 계정 / DB SID
          ├── 미들웨어 경로 · WAS 컨테이너
          ├── EAI·OLB 송수신
          └── 형상관리 최상위 폴더
                │
                │  N : N 연결 (양쪽 모두 1개 이상 필수)
                ▼
서비스그룹 (동질 논리 기능의 집합 = AA레벨2 / 업무코드)
   SGC  ──┬── 자바 패키지 · 모듈
          ├── 데이터모델명 · 스키마 Prefix
          ├── 인터페이스 요건 (시스템코드와 함께)
          └── 형상관리 하위 폴더
```

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 코드 부여 순서 · 매핑표 기입 · 적용 체크 | 정책 원문 문장 → **정책 MD** |
| Host/DB/패키지/스키마 **조립 예제** | NSIGHT 12자리 Hostname 정규식 → **정의서 05** |
| 글로벌 · 예외 적용 판단 | 인터페이스 매체 상세 → **정의서 06** |

### 읽는 순서

```text
A1 → A2 계층 → A3 용어 → Part B Step 1~6 → 예제 · 실수 · 체크 → 정책 원문 재확인
```

## A2. 큰 그림 · 두 코드의 자리

```text
어플리케이션 아키텍처 맵
        │
        ├─ (상위) 어플리케이션 코드
        │         │
        │         └─ 서비스그룹코드 ★ AA레벨2, 최하위 논리 단위
        │                   │
        │                   ├─ Service
        │                   └─ Business Task
        │
물리/운영 인벤토리
        │
        └─ 시스템코드 ★ 서버·인스턴스로 구분되는 업무시스템
                  │
                  ├─ Host · OS 계정 · FTP
                  ├─ DB명 · SID · DB 사용자
                  └─ WAS Home / Context / Log
```

| 축 | 시스템코드 | 서비스그룹코드 |
|---|---|---|
| 무엇을 가리키나 | 물리적으로 나눌 수 있는 **업무시스템** | 동질 논리 기능을 묶은 **서비스 집합** |
| 길이 | 단일 3자리 영문 약어 | 단일 3자리 영문 약어 |
| 별칭 | — | 업무코드, AA레벨2 코드 |
| 관리 | 시스템코드 사전 (CMDB) | 별개 사전 (시스템코드와 분리) |
| 연결 규칙 | 서비스그룹 **1개 이상** 필수 | 시스템코드 **1개 이상** 필수 |
| 글로벌 | 본점 코드와 비중복 + 명칭 prefix `[글로벌]` | (정책상 시스템코드 쪽 규칙) |

```text
[맞음]  시스템코드 CRM  ←→  서비스그룹 CIC, CMP
[맞음]  서비스그룹 CIC  ←→  시스템코드 CRM, CHN
[금지]  시스템코드만 있고 서비스그룹 없음
[금지]  서비스그룹만 있고 시스템코드 없음
[금지]  두 사전을 하나의 코드표로 합쳐 씀
```

## A3. 용어

| 용어 | 설명 |
|---|---|
| 시스템코드 | 서버·인스턴스 등으로 구분 가능한 업무시스템 단위. 3자리 유일 |
| 서비스그룹코드 | 앱 아키텍처 맵 최하위. 업무코드(AA레벨2). 3자리 유일, 시스템코드와 별도 관리 |
| AA레벨2 | 어플리케이션 아키텍처에서 서비스그룹에 해당하는 레벨 |
| GROC대표코드 | 글로벌 거점(ROC) 3자리. Host·DB명 선두에 삽입 |
| 서버구분 | `ap` / `db` / `sv` |
| 운영구분 (Host) | `d` 개발 · `t` 테스트 · `p` 운영 (소문자) |
| 운영구분 (DB명) | `D` / `T` / `P` (대문자) |
| 미사용 예외 | 통합업무·관리·보안 서버 등. Host/FTP 또는 DB명/SID만 예외 가능 |

## A4. 사용 부문 한눈에

```text
시스템코드를 붙이는 곳
  1) 시스템     Host · APP/FTP 계정 · DB명/SID/DB사용자
  2) 미들웨어   웹 Home/Log/Document · WAS Container/Context/Log
                J2EE F/W 경로 예: /sw/neoworks/app/{시스템코드}
  3) 인터페이스 EAI 송수신에 시스템코드 (+ 서비스그룹코드)
  4) 형상관리   시스템코드의 시스템 명칭이 형상 최상위

서비스그룹코드를 붙이는 곳
  1) 업무코드   논리 업무 구분 키
  2) 프로그램   자바 패키지 · 상용 모듈 · Service/Business Task
  3) 데이터모델 모델명 = 앱코드명_서비스그룹코드명 · 스키마 Prefix
  4) 인터페이스 시스템코드와 함께 등록 → 업무별 IF 현황
  5) 형상관리   시스템코드 하위 폴더 = 서비스그룹
```

| 적용 대상 | 시스템코드 | 서비스그룹 | 글로벌 특이 |
|---|:---:|:---:|---|
| Host Name | ● | — | GROC+시스템+ap/db/sv+d/t/p+순번 |
| APP/FTP 계정 | ● | — | (본점 규칙) |
| DB명 · SID · DB사용자 | ● | — | 운영구분+GROC+시스템 / SID=DB명+순번 · EDB는 소문자·명=SID |
| 웹/WAS/J2EE 경로 | ● | — | **미들웨어 명칭 미사용** |
| EAI 송수신 | ● | ● | 글로벌은 **OLB** 경유 시 둘 다 사용 |
| 형상관리 | ● (상위) | ● (하위) | — |
| 자바 패키지 · 모듈 | — | ● | — |
| 데이터모델 · 스키마 | — | ● | — |

# Part B — 부여·적용 절차 (How-to)

## B0. 전체 Step 맵

```text
① 물리 단위 확정 → 시스템코드 부여
② 논리 업무 단위 확정 → 서비스그룹코드 부여
③ 매핑표: 시스템 ↔ 서비스그룹 (양쪽 1+)
④ 시스템 부문 적용: Host · 계정 · DB · 미들웨어
⑤ 업무 부문 적용: 패키지 · 모델 · 스키마
⑥ 인터페이스 · 형상관리 등록 → 체크리스트
```

글로벌이면 ①에서 `[글로벌]` prefix·본점 비중복을 같이 닫는다.  
예외 대상이면 ④에서 Host/FTP 또는 DB명/SID만 빼고 나머지는 적용한다.

---

## B1. 시스템코드 부여

1. 물리로 나눌 수 있는 단위인가? (서버 또는 인스턴스가 다르면 다른 코드)
2. 영문 약어 3자리, **기존 사전과 유일**
3. 연결할 서비스그룹을 최소 1개 확보 (없으면 ②를 먼저)
4. 글로벌이면: 본점 코드와 겹치지 않게 만들고 코드명에 `[글로벌]` prefix

**워크시트 — 시스템코드 사전**

| 시스템코드 | 시스템명 | 물리단위(서버/인스턴스) | 글로벌Y/N | `[글로벌]` | 연결 서비스그룹 | 담당 |
|---|---|---|---|---|---|---|
| | | | | | | |

---

## B2. 서비스그룹코드 부여

1. 앱 아키텍처 맵에서 **최하위 논리 묶음**인가? (AA레벨2)
2. 동질 논리 기능을 하는 서비스들의 대표 집합인가?
3. 영문 약어 3자리, **시스템코드 사전과 별도**, 유일
4. 연결할 시스템코드를 최소 1개 확보

**워크시트 — 서비스그룹 사전**

| 서비스그룹코드 | 업무명 (AA레벨2) | 상위 어플리케이션코드 | 연결 시스템코드 | 담당 |
|---|---|---|---|---|
| | | | | |

## B3. 매핑 (N:N)

한 시스템은 여러 업무를, 한 업무는 여러 시스템에 올라갈 수 있다. **고아 코드 금지.**

| 시스템코드 | 서비스그룹코드 | 용도 (온라인/배치/IF 등) | 비고 |
|---|---|---|---|
| | | | |

검증:

- [ ] 모든 시스템코드가 매핑 1행 이상
- [ ] 모든 서비스그룹코드가 매핑 1행 이상
- [ ] 두 코드가 같은 값으로 혼용되지 않음

## B4. 시스템 부문 명칭 조립

본점(국내) 권고 예:

| 대상 | 패턴 | 예 |
|---|---|---|
| Host | `{시스템코드}{역할}{순번}` | `SYSAPP01`, `SYSDBP01` |
| APP 계정 | `{시스템코드}app` | `sysapp` |
| FTP 계정 | `{시스템코드}ftp` | `sysftp` |
| DB명 / SID / DB사용자 | 시스템코드 포함 | (사이트 표준에 맞춤) |

글로벌 Host (11자리 조립):

```text
 GROC(3) + 시스템코드(3) + 서버구분(2) + 운영구분(1) + 일련번호(2)
  gna         cob            ap            p              01
            → gnacobapp01     동북아ROC · 코어뱅킹 · AP · 운영 · 01
  geu         nob            db            p              01
            → geunobdbp01     구주ROC · 정보뱅킹 · DB · 운영 · 01
```

글로벌 DBMS:

```text
 DB명(7) = 운영구분(1) + GROC(3) + 시스템코드(3)
 SID     = DB명(7) + 일련번호(1)

  P + GSA + OLI → PGSAOLI     동남아 OLI 운영 DB명
  D + GEU + COB + 1 → DGEUCOB1  구주 코어뱅킹 개발 SID

 EDB: DB명 소문자, DB명 == SID
```

미들웨어 (본점만, 글로벌은 미들웨어 부문 명칭 **사용하지 않음**):

| 대상 | 시스템코드를 넣는 위치 |
|---|---|
| 웹서버 | Home, Log, Document Directory |
| WAS | Container Name, Home, Context Root, Log Directory |
| J2EE F/W | 예: `/sw/neoworks/app/{시스템코드}` |

**예외 (④에서만 빼는 항목):** 통합 업무 서버, 시스템/앱 관리·보안 서버 등  
→ Host Name · FTP 계정, 또는 DBMS의 DB명 · SID 명칭.  
그 외(미들웨어·IF·형상)는 예외가 아니다.

## B5. 프로그램 · 데이터모델

```text
어플리케이션코드
    └─ 서비스그룹코드          ← 패키지 한 단
            ├─ Service
            └─ Business Task
```

| 산출물 | 규칙 | 예 |
|---|---|---|
| 자바 패키지 / 상용 모듈 | 서비스그룹코드 명칭 반영 | `...{앱}...{서비스그룹}...` |
| 아키텍처 맵 | 설계 시 시스템 → 서브시스템 → 디렉터리로 구체화. 서비스그룹 = 최하위 모듈 | |
| J2EE 앱 | 맵 = 패키지 계층. 서비스그룹 아래 Service/Business Task | |
| 데이터 모델명 | `어플리케이션코드명_서비스그룹코드명` | `CRM_CIC` |
| 테이블 스키마 | 서비스그룹코드를 **Prefix** | `{SGC}_...` |

## B6. 인터페이스 · 형상관리

**인터페이스**

1. 송수신 정보 등록 시 **시스템코드 + 서비스그룹코드** 동시 등록
2. 요건 등록 시 해당 시스템코드에 **상응하는** 서비스그룹코드를 넣는다 → 업무별 IF 현황
3. 본점: EAI 기준 시스템코드  
4. 글로벌: OLB 경유 시 시스템코드·서비스그룹코드 사용

**형상관리**

```text
형상관리시스템
  └─ {시스템코드 / 시스템 명칭}     ← 시스템 단위
        └─ {서비스그룹코드}         ← 업무 단위
              └─ 소스 · 산출물
```

## B7. 미니 예제 (가상)

전제: 국내 마케팅 분석 시스템. 시스템코드 `MPA`, 서비스그룹 `CIC`(고객접촉), `SEG`(세그먼트).

| Step | 결과 |
|---|---|
| ① | `MPA` = 분석 AP/DB 인스턴스 묶음 |
| ② | `CIC`, `SEG` 부여 (AA레벨2) |
| ③ | MPA–CIC, MPA–SEG |
| ④ Host | `MPAAPP01`, `MPADBP01` / 계정 `mpaapp` |
| ④ F/W | `/sw/neoworks/app/mpa` |
| ⑤ 모델 | `MP_CIC`, 스키마 prefix `CIC_` |
| ⑥ IF | EAI 송수신에 MPA + CIC |
| ⑥ SCM | 폴더 `MPA/CIC`, `MPA/SEG` |

글로벌 코어 AP 운영 1호기: Host `gnacobapp01` (GROC `gna` + `cob` + `ap` + `p` + `01`). 미들웨어 경로에는 시스템코드를 넣지 않는다.

## B8. 자주 하는 실수

| 실수 | 바른 적용 |
|---|---|
| 시스템코드 = 서비스그룹코드로 씀 | 사전을 분리하고 매핑으로만 연결 |
| 코드만 따고 Host/경로/IF에 안 넣음 | A4 표 전 칸을 적용 체크 |
| 글로벌 Host에 본점 패턴(`SYSAPP01`) 사용 | GROC+시스템+ap/db/sv+d/t/p+순번 |
| 글로벌인데 WAS 경로에 시스템코드 삽입 | 글로벌은 미들웨어 부문 명칭 미사용 |
| 글로벌 IF를 EAI만 등록 | OLB 구성 시 시스템+서비스그룹 |
| EDB를 대문자 DB명으로 생성 | 소문자, DB명 = SID |
| 예외 서버라며 형상·IF도 생략 | 예외는 Host/FTP 또는 DB명/SID만 |
| 서비스그룹 없는 시스템코드 배포 | 매핑 1건 이상 없으면 부여 미완료 |
| 패키지에 시스템코드를 넣음 | 패키지·스키마는 서비스그룹코드 |

---

## B9. 완료 체크리스트

**부여**

- [ ] 시스템코드 3자리 · 유일 · 물리 단위와 1:1로 설명 가능
- [ ] 서비스그룹코드 3자리 · 유일 · AA레벨2 · 시스템코드와 별도 사전
- [ ] 글로벌이면 본점 비중복 + `[글로벌]` prefix
- [ ] 매핑 N:N, 고아 코드 없음

**시스템 부문**

- [ ] Host · APP/FTP · DB명/SID/DB사용자에 시스템코드 (예외 대상은 사유 기록)
- [ ] 웹/WAS/J2EE 경로에 시스템코드 (글로벌이면 이 항 해당 없음)
- [ ] EAI(또는 글로벌 OLB) 송수신에 시스템코드+서비스그룹코드
- [ ] 형상관리 최상위 = 시스템 명칭

**업무 부문**

- [ ] 패키지/모듈에 서비스그룹코드
- [ ] J2EE면 서비스그룹 하위에 Service/Business Task
- [ ] 모델명 `앱코드_서비스그룹코드`, 스키마 Prefix = 서비스그룹
- [ ] 형상관리 하위 = 서비스그룹코드
