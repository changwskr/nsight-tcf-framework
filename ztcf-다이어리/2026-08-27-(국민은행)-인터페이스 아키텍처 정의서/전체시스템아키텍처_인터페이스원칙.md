# 전체 시스템 아키텍처 — 인터페이스 원칙

근거 문서: [`전체시스템아키텍처구조정의_TOPDOWN_강화분석.md`](전체시스템아키텍처구조정의_TOPDOWN_강화분석.md)  
교차 FACT: 같은 폴더 IA 전사 `_14`(구간 기준), `_22`(상세 원칙 1~3), `_23`(예외)

## 0. 문서 목적

본 문서는 전사 구조도(계정계–SIS–EDW–지식정보–RMS–CRM–EIS)가 고정한 **도메인 경계**를, 연계가 지켜야 할 **인터페이스 원칙**으로 내린다.

구조도는 솔루션(MCI/EAI)을 그리지 않는다. 솔루션 배치는 IA 원문 FACT로 붙인다. 구조도에서 읽힌 경계는 `ANALYSIS`, IA 장표 문장은 `FACT`로 표시한다.

충돌 시:

```text
1. 원장 확정 경계 (Host)     — 구조도 ANALYSIS, 최우선
2. IA 상세원칙 1~3           — FACT (_22)
3. 예외 (_23)                — 승인된 경우만
```

---

# 1. 한 문장 원칙

> **채널 거래는 Host에서 원장을 확정하고, 정보 소비는 SIS ODS·EDW를 통하며, 도메인 간 연계는 EAI(파일은 MFT), 채널–업무는 MCI, EDW 적재는 CDC/ETL/EAI로 목적별 분리한다. CRM/EIS/지식정보는 원장을 쓰지 않는다.**

---

# 2. 도메인 → 인터페이스 경로 (TEXT)

```text
[거래 경로] 원장 확정
Channel / Satellite  ──MCI──►  Host
대외 기관            ──EAI──►  Host / 외환전산망

[복제 경로] 운영 허브
Host / 위성원장      ──CDC/ETL/EAI──►  SIS ODS
Host 옆 ODS          ──(동기, 확인 필요)──►  SIS ODS

[분석 경로] 웨어하우스
SIS ODS              ──ETL/EAI/CDC──►  EDW (ODS Image)

[계량 경로] 리스크
원장·ODS             ──EAI/파일──►  RDM/ALM
RDM/ALM              ──EAI──────►  SIS 경영정보

[소비 경로] 조회만
EDW / SIS            ──EAI/조회──►  CRM / EIS

[행정 경로] 원장 주경로 밖
지식정보             ──EAI──────►  Host(조직·권한) / SIS(예산·평가)

금지 대각선
Channel ──X──► SIS/EDW 원장확정
CRM/EIS ──X──► Host update
SIS ODS ──X──► Host 원장 커밋 대기
내장 RMS ──X──► RDM 엔진과 동일 장애도메인 IF
```

---

# 3. 원칙 카탈로그

각 원칙은 `shall`(해야 함) / `금지` / `예외 조건`을 고정한다.

---

## IF-P01 원장 확정은 Host에서 끝낸다

근거: 구조도 Intent 1, BP-ASIS-01

```text
shall
  채널·위성의 수신·여신·신탁·외환 거래는 Host 커밋으로 완료한다.

금지
  인터넷뱅킹 / 전자금융 / IC채널이 SIS·EDW에 원장을 직접 쓴다.
  SIS ODS 적재 성공을 Host 커밋의 전제로 건다.

권고 경로
  Channel → MCI → Host → (이후) SIS ODS 복제
```

IA FACT 대응: `_22` 원칙 2 — 채널은 MCI 경유 업무 시스템.

---

## IF-P02 채널–업무는 MCI, 도메인 간·대외는 EAI

근거: IA `_14` ①②, `_22` 원칙 1·2 — **FACT**

```text
shall
  채널(단말, 자동화기기, 인터넷/스마트뱅킹) ↔ 업무시스템 = MCI
  대내 도메인(계) 간 · 대외 기관 = EAI
  파일 전송 = MFT 경유, 전송 내역은 EAI로 통합 관리

금지
  채널이 EAI만으로 원장 거래를 우회한다.
  도메인 간 DB-LINK / 공유폴더 / 임시 FTP를 상시 경로로 쓴다.
```

구조도 매핑:

| 구조도 구간 | shall IF |
|---|---|
| IB/전자금융/IC → Host | MCI |
| 대외망/외환채널 → Host·외환전산망 | EAI (대외) |
| Host → SIS | EAI 또는 CDC/ETL (IF-P04) |
| 지식정보 ↔ Host/SIS | EAI |
| RMS/ALM ↔ SIS | EAI |

---

## IF-P03 상품·Hub → 타 시스템은 Async가 기본

근거: IA `_22` 원칙 3 — **FACT**

```text
shall
  상품서비스(수신·여신·카드 등 원장 측)에서
  마케팅/CRM/경영정보/EDW로 가는 연계는 Async.

금지
  원장 커밋 스레드가 CRM·EDW·성과관리 응답을 기다린다.

예외 (IA `_23` 예외 3)
  제한적 Sync는 별도 승인. 기본값으로 되돌리지 않는다.
```

구조도 해석: Host 거래와 SIS/EDW 적재는 **같은 Runtime이 아니다**.

---

## IF-P04 운영 복제와 분석 적재를 매체별로 나눈다

근거: 구조도 SIS vs EDW 경계, IA `_14` ③ — **FACT+ANALYSIS**

```text
shall
  SIS ODS (운영 복제)
    · 소량·구조변환     → EAI
    · 대량 실시간 복제   → CDC
    · 준실시간           → EAI Deferred / 배치
  EDW (ODS Image · 성과·원가·로그)
    · EDW ↔ 단위시스템  → ETL, EAI

금지
  ODS와 EDW를 한 JDBC로 동시에 쓴다.
  EDW 적재 배치를 Host OLTP 자원에서 돌린다.
  당일 ODS를 EDW Image로 대체해 영업 조회한다.
```

```text
Host / 위성원장
      │ CDC / EAI
      ▼
   SIS ODS          ← 운영 조회 1차 소스 (BP-ASIS-02)
      │ ETL / EAI
      ▼
   EDW Image        ← 이력 · 분석
```

---

## IF-P05 위성 원장은 Host 모듈과 별도 ODS 슬롯으로 넣는다

근거: BP-ASIS-07, 구조도 카드·증권·방카

```text
shall
  신용카드 · 증권투신 · 방카 · 자산운용 데이터는
  해당 ODS 슬롯(카드 등)으로 연계한다.
  Host 수신/여신 모듈을 허위 경유하지 않는다.

금지
  카드 원장을 Host 수신 테이블에 섞어 넣은 뒤 ODS로 복제한다.
```

IF 유형: 위성 → SIS ODS 는 **데이터 IF**(CDC/ETL/EAI). 대고객 카드 거래 자체는 위성 시스템의 원장 경로.

---

## IF-P06 CRM/EIS는 소비만 한다

근거: BP-ASIS-05, 금지 4

```text
shall
  CRM(SFA·CRM분석) · EIS(임원정보·HIS)의 소스는 SIS 또는 EDW.
  원장 변경이 필요하면 Host 거래를 새로 연다.

금지
  SFA → Host UPDATE/INSERT
  EIS 화면이 ODS 적재 Job을 트리거한다.
```

IA 매핑: CRM/EIS는 마케팅 Hub·분석계에 가깝다 → 원칙 3 Async 소비.

---

## IF-P07 내장 RMS와 RDM/ALM 연계를 섞지 않는다

근거: BP-ASIS-03, Intent 4

```text
shall
  여신 심사·사후·건전성·금감원 보고  = SIS 내장 RMS 경로
  시장/신용/운영 계량 · ALM · BIS   = 하단 RMS/ALM 경로
  계량 결과는 SIS 경영정보로 EAI/파일 환류

금지
  심사 온라인 호출이 RDM 엔진 완료를 기다린다.
  두 RMS를 하나의 Interface ID로 묶는다.
```

```text
Host 여신 + 담보관리 ──► SIS 내장 RMS     (운영)
원장·포지션        ──► RDM/ALM           (계량)
RDM/ALM            ──► SIS 경영정보       (환류, Async)
```

---

## IF-P08 지식정보(행정)는 원장 주경로 밖이다

근거: BP-ASIS-06

```text
shall
  인사·감사·오피스·EDMS·자금은 EAI로 Host(조직·권한) / SIS(예산·평가)와 연결한다.
  수신·여신 거래 경로에 지식정보를 끼우지 않는다.

금지
  자점감사 시스템이 Host 원장 테이블을 직접 읽는다(상시).
  하나오피스/포털 세션으로 MCI 원장 거래를 연다.
```

---

## IF-P09 파일과 본거래를 분리한다

근거: IA `_14` ②, `_23` 예외 2 — **FACT**

```text
shall
  파일이 포함된 채널 거래:
    본거래(원장) = MCI
    파일 전송     = MFT
  Completion Signal 전에 파일 내용을 업무 반영하지 않는다.

금지
  대용량 파일을 MCI 전문 본문에 실어 Host에 넣는다.
  MFT 완료 전 EDW/ODS가 파일을 소비한다.
```

---

## IF-P10 동일 도메인 Direct는 예외로만 연다

근거: IA `_23` 예외 1 — **FACT**

```text
shall
  도메인 간은 EAI가 기본.
  동일 도메인 미들웨어 Direct는 「통합 기능이 필요할 때」만, 예외 등록 후.

금지
  Direct를 전행 기본값으로 확산한다.
```

구조도에서 SIS 내부(경영정보–ODS–내장 RMS)는 **같은 허브 내부**다. 내부 API/DB는 SIS 책임. SIS 밖(Host, EDW, CRM, 지식정보, RDM)은 EAI.

---

## IF-P11 추적 키를 경로마다 잇는다

근거: 구조도 §21 Observability — 원본에 키 없음, **ANALYSIS**

```text
shall
  Host Tx ID (또는 GUID)를 ODS 적재 · EDW Image · 로그분석까지 전달한다.
  데이터 IF는 Batch/Snapshot ID를 계약에 넣는다.
  리스크 환류는 Risk Run ID를 넣는다.

금지
  Host 거래와 EDW 행을 고객번호만으로 「같은 거래」라고 단정한다.
```

IA 표준전문·Interface ID 상세는 전사 `_42`~`_44`. 본 원칙은 **최소 추적 계약**만 고정한다.

---

## IF-P12 유형 미분류 연계를 개통하지 않는다

근거: NSIGHT 인터페이스 정의서 B1와 동일 취지. 구조도 선 종류 미확정(GAP)을 메운다.

```text
shall
  신규 IF는 아래 한 행을 고른 뒤 구현한다.
    온라인(거래) / 파일 / 데이터(복제·적재)
  한 요구에 여러 유형이면 행을 복수 등록한다.

금지
  「그냥 JDBC」 「그냥 공유폴더」로 상시화.
```

# 4. 구간 표준표

구조도 화살표 × IA 솔루션. shall은 기본 행, Direct는 예외.

| No. | 소스 | 목적 | 타깃 | shall 매체 | 유형 |
|---:|---|---|---|---|---|
| 1 | 채널(IB/단말/IC) | 원장 거래 | Host | **MCI** | 온라인 |
| 2 | 대외 기관·대외망 | 대외 거래 | Host / 외환전산망 | **대외 EAI** | 온라인 |
| 3 | Host | 운영 복제 | SIS ODS | **CDC** 또는 **EAI** | 데이터 |
| 4 | 위성(카드·증권·방카) | 운영 복제 | SIS ODS 해당 슬롯 | **CDC/ETL/EAI** | 데이터 |
| 5 | SIS ODS | Image·분석 | EDW | **ETL** · **EAI** | 데이터 |
| 6 | Host / ODS LOG | 로그 분석 | EDW 거래로그 | **ETL/EAI** | 데이터 |
| 7 | 담보·여신 | 심사·사후 | SIS 내장 RMS | **EAI** (운영) | 온라인/데이터 |
| 8 | 원장·포지션 | 계량 | RDM/ALM | **EAI/파일** | 데이터 |
| 9 | RDM/ALM | 환류 | SIS 경영정보 | **EAI Async** | 데이터 |
| 10 | EDW / SIS | 조회·캠페인 | CRM | **EAI Async** | 온라인/데이터 |
| 11 | EDW / SIS | 임원 조회 | EIS | **EAI** | 온라인 |
| 12 | 지식정보 | 행정 | Host / SIS | **EAI** | 온라인/데이터 |
| 13 | 채널 | 파일 | 파일저장 | **MFT** (+ 본거래 MCI) | 파일 |
| 14 | 도메인 간 기타 | 시스템 연계 | 타 도메인 | **대내 EAI** | 온라인 |

EDW 소량 실시간·구조 불일치는 `_14`에 따라 **EAI**. 대량 실시간 복제는 **CDC**.

# 5. 금지 한눈에

```text

[금지 B] CRM/EIS → Host 갱신
[금지 C] Host OLTP 스레드 → EDW/성과/원가 동기 대기
[금지 D] ODS ≡ EDW 단일 저장소
[금지 E] 내장 RMS IF ≡ RDM 엔진 IF
[금지 F] 지식정보 → 수신/여신 주경로
[금지 G] 파일 본문을 MCI 원장 전문에 상시 적재
[금지 H] DB-LINK / 임시 FTP / 공유폴더 상시
[금지 I] 유형 미분류 개통
```

# 7. 설계 체크리스트

신규·변경 IF 개통 전:

- [ ] 소스가 Channel / Host / 위성 / SIS / EDW / RMS / 지식정보 / CRM·EIS 중 어디인가
- [ ] 목적이 원장확정 / 운영복제 / 분석적재 / 계량 / 소비 / 행정 중 하나인가
- [ ] 표준표 행(No.1~14)을 선택했는가
- [ ] 원장 확정이 Host에서 끝나는가 (IF-P01)
- [ ] 채널이면 MCI인가 (IF-P02)
- [ ] 도메인 간이면 EAI인가 (IF-P02)
- [ ] Host→정보계면 Async인가 (IF-P03)
- [ ] ODS와 EDW 매체를 섞지 않았는가 (IF-P04)
- [ ] CRM이 Host를 쓰지 않는가 (IF-P06)
- [ ] 내장 RMS와 RDM을 한 ID로 안 묶었는가 (IF-P07)
- [ ] 파일이면 MFT + Completion Signal인가 (IF-P09)
- [ ] Tx ID / Batch ID가 계약에 있는가 (IF-P11)

하나라도 아니면 개통하지 않는다.

# 9. 확인 필요 (원칙을 더 조이지 못한 것)

| 항목 | 영향 |
|---|---|
| Host 옆 ODS ↔ SIS ODS 매체 | 표준표 3을 CDC 단독으로 못 박지 못함 |

# 10. 한 장 요약

