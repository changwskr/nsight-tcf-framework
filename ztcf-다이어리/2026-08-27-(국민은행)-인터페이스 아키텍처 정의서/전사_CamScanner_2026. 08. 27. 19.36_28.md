# 대내 채널 통합(MCI) 유형별 처리 원칙 — Local·책임자·대외기관

> 원본: `원본/CamScanner 2026. 08. 27. 19.36_28.pdf`  
> 문서: KB국민은행 · Enterprise Interface Architecture 정의서 · 원문 전사(FACT)

## 본문

**위치:** IV. 인터페이스 처리방안 / 3. 인터페이스 유형별 처리 원칙

**탭:** 상세원칙 및 지침 · 유형별 상세원칙(선택) · 전행 표준전문

Local 및 책임자 승인 거래는 MCI 자체 응답하며, 대외기관 연계 거래는 상품서비스에서 Dummy 응답 후 대외기관의 응답거래를 채널로 전송함

**범위:** Local 거래, 책임자 승인거래, 대외기관 연계 거래(Sync+BID 거래)

**소제목:** To-Be MCI 거래 유형별 처리 원칙

### 처리 원칙 설명

**1 Local 거래**
- 채널 - MCI 구간의 거래 Path
- 채널의 거래 요청을 MCI가 자체 정보를 기반으로 처리
- 예, 공통코드 조회, Log In/Off 거래 등

**2 책임자 승인 거래**
- 단말 - MCI 구간의 거래 Path
- 책임자 승인 요청 거래와 승인 거래는 MCI로 유입된 후 Push 서버에 의해 해당 담당자에게 강제전송

**3 대외기관 연계 거래**
- 채널 - MCI - 상품서비스계 - 대외기관 구간의 거래 Path
- 채널 - MCI 및 MCI - 상품서비스계 구간은 동기 거래, 상품서비스계 - EAI - 대외기관 구간은 비동기 거래
- 상품서비스계는 대외기관으로 요청전문 전송 후 Dummy 응답 전문을 채널로 전송
- MCI가 대외기관의 응답전문을 BID Adapter를 통해 수신한 후 채널로 강제 전송

## TEXT 구성도

```text
1 Local 거래
  채널(직원채널, 고객채널) ←→ I/F(MCI, 전문관리)

2 책임자 승인 거래
  일반 단말 --책임자 거래 요청--> MCI
  MCI Push 송신 --책임자 거래 요청--> 책임자 단말(Receiver)
  책임자 단말 --결과--> MCI Push 송신 --책임자 거래 결과--> 일반 단말(Receiver)

3 대외기관 연계 거래
  채널(직원채널, 고객채널, TCP Receiver)
    --Sync--> MCI/전문관리 --Sync--> 상품서비스(상품서비스, 지급결제, 여신지원, …)
    상품서비스 --Dummy 응답--> MCI --Dummy 응답--> 채널
    상품서비스 --Async--> EAI/FEP --Async--> 대외기관(금융기관, 한국은행, 금결원, …)
    대외기관 --Async--> EAI/FEP --Async--> 상품서비스
    MCI Push 송신 --> 채널 TCP Receiver
```
