# 1. L0 — 전체 시스템 Context

## 1.1 한 문장 Architecture Definition

원본 전체 그림은 다음 구조를 표현한다.

> **계정계 Host에서 발생한 거래·채널 데이터를 SIS의 ODS·경영정보·내장 RMS로 집결하고, EDW에 적재·이미지화하여 성과·원가·거래로그 분석에 쓰며, RMS/ALM·CRM·EIS가 그 결과를 소비하고, 지식정보가 Host·SIS와 행정·감사 데이터를 주고받는 전사 데이터 허브 아키텍처**

# 2. L1 — 핵심 Architecture Domain

원본에서 가장 중요한 Architecture Domain은 다음 7개다.

```text
1. Channel / Satellite Domain     (계정계 주변 채널·위성)
2. Core Banking Domain            (Host)
3. SIS Hub Domain                 (경영정보 / ODS / 내장 RMS)
4. EDW Domain                     (DW + 분석 모듈)
5. Knowledge / Admin Domain       (지식정보)
6. Risk Domain                    (RMS / ALM / 운영리스크)
7. Consumption Domain             (CRM / EIS)
```

이를 다시 그림으로 표현하면 다음과 같다.

```text
Channel / Satellite
        │
        ▼
      Host (Core)
        │
        ├──────────────────┐
        ▼                  ▼
       SIS              지식정보
        │                  │
        ├──────┐           │
        ▼      ▼           │
      EDW    RMS/ALM       │
        │      │           │
        ▼      ▼           │
      CRM / EIS ◀──────────┘
```

### ANALYSIS

SIS가 모든 정보성 데이터의 **허브**다. Host는 원천 거래를 만들고, EDW는 SIS를 거쳐 온 데이터를 장기·분석 형태로 보관하며, CRM/EIS는 EDW·SIS의 소비 계층이다.

# 3. L1-1 — Channel / Satellite Domain

## 3.1 FACT

원본 계정계 박스 **상단**에 다음이 보인다.

```text
채널 / 대외 / 상품 위성
├─ 외환
├─ 대외망
├─ 인터넷뱅킹 / 전자금융
├─ 신용카드
└─ 증권투자신탁
```

원본 계정계 박스 **하단**에 다음이 보인다.

```text
판매 / 채널 지원 위성
├─ 방카슈랑스
├─ 증권대행
├─ IC채널
└─ 자산운용
```

---

## 3.2 Channel TOP-DOWN

```text
고객 / 대외 접점
│
├─ 대고객 채널
│  ├─ 인터넷뱅킹 / 전자금융
│  └─ IC채널
│
├─ 대외 네트워크
│  ├─ 대외망
│  └─ 외환 (채널 측)
│
└─ 상품·제휴 위성
   ├─ 신용카드
   ├─ 증권투자신탁
   ├─ 방카슈랑스
   ├─ 증권대행
   └─ 자산운용
```

---

## 3.3 채널의 역할

```text
A. 대고객 거래 진입
인터넷뱅킹 / 전자금융 / IC채널 → Host

B. 대외 전문·망 연계
대외망 / 외환 → Host / 외환전산망

C. 상품 계열 독립 원장
카드 · 증권 · 방카 · 자산운용 → Host 및 SIS ODS
```

즉 채널 박스는 UI 계층이 아니라 **Host를 둘러싼 원천장**이다.

# 4. L1-2 — Core Banking Domain (Host)

## 4.1 FACT

원본 계정계 중앙 **Host** 원통에 다음 모듈이 적혀 있다.

```text
Host

├─ 여신

├─ 외환
└─ 기타
```

Host 옆에 **소형 ODS**가 별도 표시된다.

```text
┌──────────────────────────── Host ─────────────────────────────┐
│                                                               │
│ [Common]                                                      │
│ └─ 공통                                                       │
│                                                               │
```

---

## 4.3 Host의 위치

```text
Channel / Satellite
        ↓  거래
      Host
        ↓  원장 확정
   SIS ODS / 경영정보
```

Host는 **원장 확정 계층**이다. SIS·EDW는 그 결과를 복제·집계한다.

### ANALYSIS

Host 옆 ODS와 SIS 내부 ODS가 **둘 다** 그려져 있다. 계정계 로컬 운영 저장과 전사 ODS를 분리한 것으로 읽힌다. 동기 주기·동일 스키마 여부는 이미지에 없다.

# 5. L2 — SIS Hub Domain

## 5.1 FACT — SIS 내부 4층

원본 중앙 대형 원통 **SIS**는 위에서 아래로 다음 층이다.

```text
SIS
├─ <경영정보>
│  ├─ 정보공통
│  ├─ 데이터관리
│  ├─ 경비예산
│  └─ 성과 / 원가 / 계수 / 평가관리
│
├─ <ODS>
│  ├─ 고객
│  ├─ 수신
│  ├─ 여신
│  ├─ 외환
│  ├─ 카드
│  ├─ 차입
│  ├─ 자동이체
│  ├─ LOG
│  └─ 기타
│
├─ <RMS>   (SIS 내장)
│  ├─ 가계대출 / 기업여신 심사·승인
│  ├─ 사후관리
│  ├─ 기업사후관리
│  ├─ 채권사후관리
│  ├─ 자산건전성
│  ├─ 금감원
│  └─ 여신관리시스템
│
└─ 하단 위성
   ├─ 담보관리
   └─ 외환전산망
```

---

## 5.2 SIS TOP-DOWN 상세 TEXT

```text
┌────────────────────────────── SIS ──────────────────────────────┐
│                                                                 │
│ [경영정보]  관리·평가 계층                                      │
│  정보공통 · 데이터관리 · 경비예산                               │
│  성과 / 원가 / 계수 / 평가관리                                  │
│                                                                 │
│ [ODS]  운영 데이터 허브                                         │
│  고객 · 수신 · 여신 · 외환 · 카드 · 차입 · 자동이체 · LOG · 기타│
│                                                                 │
│ [내장 RMS]  여신·건전성 운영                                    │
│  심사승인 · 사후관리 · 자산건전성 · 금감원 · 여신관리           │
│                                                                 │
│ [위성]                                                          │
│  담보관리 · 외환전산망                                          │
└─────────────────────────────────────────────────────────────────┘
```

---

## 5.3 SIS의 3가지 책임

```text
A. Operational Hub
Host / 위성 → ODS (고객·수신·여신·카드 …)

B. Management Information
ODS + 지식정보(예산·인사) → 경영정보 (성과·원가·평가)

C. Credit / Supervisory Operations
여신 원장 + 담보 → 내장 RMS (심사·사후·금감원)
```

### ANALYSIS

하단 독립 박스의 RMS(RDM/ALM/내부모형)와 SIS 안의 `<RMS>`는 **이름이 같지만 층이 다르다**.

```text
SIS 내장 RMS  = 여신 심사·사후·보고 운영 시스템
하단 RMS/ALM  = 시장·신용·운영 리스크 계량 / ALM / BIS
```

둘을 한 시스템으로 합치면 안 된다.

# 6. L2 — SIS ODS 상세

## 6.1 FACT

ODS 슬롯은 Host 모듈과 **같은 업무 축**으로 맞춰져 있다.

```text
Host 모듈     SIS ODS
공통      →   (정보공통은 경영정보 층)
수신      →   수신
여신      →   여신
외환      →   외환
(위성)카드 →   카드
—         →   고객 / 차입 / 자동이체 / LOG / 기타
```

---

## 6.2 ODS TOP-DOWN 데이터 계층

```text
원천 거래 (Host / 카드 / 외환 / 자동이체)
        │
        ▼
   SIS ODS 슬롯
        │
        ├─ 고객        : 전사 고객 운영 스냅샷
        ├─ 수신·여신   : 원장 복제
        ├─ 외환·카드   : 위성 원장 복제
        ├─ 차입·자동이체 : 자금·이체 운영
        └─ LOG         : 거래·처리 로그
        │
        ▼
  경영정보 / EDW / 내장 RMS
```

### ANALYSIS

ODS는 “분석 마트”가 아니라 **운영 복제본**이다. EDW의 `ODS Image`라는 표기는 ODS 상태를 DW에 스냅샷으로 남긴다는 뜻으로 읽힌다.

# 7. L3 — EDW Domain

## 7.1 FACT

원본 우측 상단 **EDW** 원통과 하단 모듈:

```text
EDW
├─ <DW>
│  ├─ 고객

│  ├─ 잔액
│  ├─ 수익
│  ├─ 관리
│  └─ 기타 ODS Image
│
└─ 분석 모듈
   ├─ 거래로그분석
   ├─ 성과관리
   └─ 원가관리
```

---

## 7.2 EDW TOP-DOWN

```text
┌──────────────────────────── EDW ──────────────────────────────┐
│                                                               │
│ [Warehouse Core]                                              │
│ ├─ 고객 / 계좌 / 잔액 / 수익 / 관리                           │
│ └─ 기타 ODS Image                                             │
│                                                               │
│ [Analytical Apps]                                             │
│ ├─ 거래로그분석                                               │

│ └─ 원가관리                                                   │
└───────────────────────────────────────────────────────────────┘
```

---

## 7.3 SIS vs EDW 역할 경계

```text
SIS ODS
→ 최신 운영 데이터
→ 당일성 / 슬롯별 원장 복제

SIS 경영정보
→ 당기 성과·원가·평가 운영

EDW
→ 통합 이력 · ODS Image
→ 거래로그 / 성과 / 원가의 분석 저장
```

| 구분 | SIS | EDW |
|---|---|---|
| 시간성 | 운영·준실시간 | 이력·스냅샷 |
| 단위 | 업무 슬롯 ODS | 고객·계좌·잔액·수익 통합 |
| 소비 | 내장 RMS, 경영정보 | 거래로그분석, 성과/원가, CRM, EIS |

### ANALYSIS

성과관리·원가관리가 **SIS 경영정보와 EDW 하단에 모두** 있다. SIS는 운영 평가, EDW는 분석·시계열로 나누는 것이 자연스럽다. 실제 마스터가 어느 쪽인지는 이미지에 없다.

## 8.3 지식정보의 위치

### ANALYSIS

라벨 `하나오피스`, `하나세상`은 하나은행 사내 명칭이다. 본 폴더는 국민은행 IA 작업 공간이다. **장표 원천 은행은 확인 필요**로 남긴다. FACT는 그림에 적힌 이름 그대로 둔다.

```text
  ↔  Host

  ↔  EDW

```

## 11.2 Interface를 목적별로 재분류

원본은 프로토콜(MCA/EAI/CDC)을 **적지 않는다**. 목적만 재분류한다.

```text
[원장 복제]
Host / 카드 / 외환 → SIS ODS

[운영 평가]
ODS + 지식정보(인사·예산) → 경영정보

[분석 적재]
SIS ODS → EDW (ODS Image)

[리스크 환류]
RDM / ALM → SIS

[소비]
EDW → 거래로그분석 / 성과 / 원가 / CRM / EIS

[행정 연계]
지식정보 ↔ Host / SIS
```

### ANALYSIS

이 장표는 **인터페이스 솔루션 아키텍처가 아니다**. “누가 누구에게 데이터를 넘기는가”의 **데이터 연계 빅픽처**다. MCI/EAI/FEP 배치, 동기/비동기, 표준전문은 같은 폴더의 IA 전사본(`전사_CamScanner_…`)이 담당한다.

같은 폴더 `원천/시스템간 인터페이스 방안_20080303` · `원천/DW 데이터 전송 방안_20080303`과 짝으로 읽는 것이 맞다.

# 23. 강화된 Architecture Principle

## BP-ASIS-01 Host Isolation

```text
원장 확정은 Host에서 끝낸다.
SIS/EDW는 복제·집계만 한다.
```

## BP-ASIS-02 ODS as Operational Hub

```text
전사 운영 조회·후속 시스템의 1차 소스는 SIS ODS다.
```

## BP-ASIS-03 Dual RMS

```text
여신 운영 RMS ≠ 시장/신용/운영 계량 RMS
두 경계를 섞지 않는다.
```

## BP-ASIS-04 EDW as Image + Analytics

```text
EDW = ODS Image + 로그/성과/원가 분석
당일 ODS를 대체하지 않는다.
```

## BP-ASIS-05 Consume not Produce

```text
CRM / EIS는 EDW·SIS를 소비한다.
원장을 직접 쓰지 않는다.
```

## BP-ASIS-06 Admin Decoupling

```text
지식정보(인사·감사·오피스)는 원장 주경로와 분리한다.
```

## BP-ASIS-07 Satellite to ODS

```text
카드·증권·방카 등 위성 원장은 Host 모듈과 별도로 ODS 슬롯을 갖는다.
```

# 28. 최종 평가

이 장표는 단순 시스템 배치가 아니라 다음 4개 Architecture View를 동시에 담고 있다.

```text
1. Core / Satellite View     (Host와 주변 원천)
2. Data Hub View             (SIS 다층)
3. Warehouse / Analytics View (EDW)
4. Consume / Admin View      (CRM·EIS·지식정보·RMS)
```

TOP-DOWN으로 해석했을 때 전체 의도는 다음과 같다.

```text
Channel / Satellite
  ↓
Host Transaction
  ↓
SIS Operational Hub
  ↓
EDW Image / Analytics
  ↓
CRM / EIS Consumption
```

같은 폴더 문서와의 관계는 다음과 같다.

```text
본 장표 (데이터 허브 빅픽처)
  ↓
원천/DW 데이터 전송 방안_20080303
  ↓
원천/시스템간 인터페이스 방안_20080303
  ↓
CamScanner IA 정의서 (MCI/EAI/표준전문)
  ↓
전행 인터페이스 고도화 전사
```

결론적으로 본 장표는 **원장–운영허브–웨어하우스–소비**를 한 장에 고정한 전사 System Architecture Baseline이며, 인터페이스 솔루션(MCI/EAI) Baseline은 아니다.
