# 인터페이스 아키텍처 정의 접근방안

## 본문

**부제:** 기술 아키텍처 수립 Approach

Blueprint에서 정의한 아키텍처 정책, 설계 기준과 AA의 Physical View 기반의 인프라 구성기준을 기반으로 To-Be 인프라 구성방향을 수립하고 목표 용량 산정을 수행함.

**비고 박스:** 산업은행 PI 문서로 대체

### 프로세스 (좌 → 우)

| 단계 | 내용 |
|------|------|
| 아키텍처 정책 | Blueprint 내 TA 영역 설계 방향 정의. 신기술 기반 유연하고 안정적인 인프라 구축. Blueprint 내 기술영역 아키텍처 정책 정의 |
| 아키텍처 설계 기준 | 주요 영역별 TA 설계 기준 정의. 핵심 서비스 안정성, 신속성/유연성, I/F 고도화, 표준 기술 관리, 표준 인프라 구성, 프레임워크 고도화, 개발/테스트 관리, Biz. 관점 운영관리 체계, 신규 Biz./신기술 지원 |
| 아키텍처 원칙 | To-Be 기술 아키텍처 원칙 수립. 표준관리, 시스템 뷰, 시스템 구성, 도메인 구성, 인터페이스, 프로세스, 어플리케이션, 데이터, 모니터링. ¹) |
| 인프라 구성 기준 | Post 차세대 시스템 인프라 구축 구성 기준 검토. ISP 단계 목표 용량 산정을 위한 인프라 구성 방향 적용 |
| TA System View & Physical View | TA 관점 시스템 분류·명명 기준 수립(시스템, 서브시스템). 인프라 구성 방향 기반 To-Be TA Physical View 작성. H/W·S/W 구성도 수립(기술요소별, 환경별) |
| TA 원칙 보완 및 지침 수립 | 기술 아키텍처 영역별 상세 아키텍처 원칙 정의. 아키텍처 상세화 단계에서 선도구축 준비·분석·설계 수립을 진행하기 위한 TA 원칙 정의(Cross Project 또는 프로젝트별) |

### 산출물 그룹
- **Blueprint 정의서** — 앞 4단계. Post 차세대 전략 수립 단계
- **TA To-Be 아키텍처 정의서, 과제 정의서** — 뒤 2단계. 차세대 아키텍처 상세화 단계
- **기술 아키텍처 지침** — 마지막 단계와 연계

¹) 붙임 2. 참조
