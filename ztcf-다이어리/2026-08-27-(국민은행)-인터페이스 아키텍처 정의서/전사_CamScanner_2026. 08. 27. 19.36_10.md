## 본문

**부제:** 시스템 뷰 구성 기준 정의

어플리케이션 Physical view를 기반으로, 중요도별 안정성·유연성 등 TA 변화 방향을 고려하여 환경별(운영, 개발, Staging, DR) 업무 시스템 및 내부관리 시스템 서버를 구성함.

### TA 시스템 구성 기준
- 동일 플랫폼/기술요소
- 운영 안정성
- 업무 연속성

- 상이한 플랫폼(프레임워크, OS, 서버 환경) 및 기술요소(패키지 등) 기반 어플리케이션은 별도 시스템으로 구성
- 업무 연속성 및 안정성 확보를 위해 용도별(운영, 개발, Staging, DR) 서버 환경을 분리
- 서비스 가용성 및 용량 증가 수요에 대비하여 서버별 수직·수평 확장성을 고려한 노드 구성

### 어플리케이션 Physical View vs TA System View

| | 어플리케이션 Physical View | TA System View |
|--|---------------------------|----------------|
| 계층 | 도메인 → 서브 도메인 → 어플리케이션 | 계 → 시스템 → 어플리케이션 |
| 최상위 | 도메인: Logical View의 도메인과 1:1 | 계: 유사 업무 시스템 기능으로 분류한 IT 시스템 최상위 그룹. AA Physical View의 도메인과 동일 |
| 중간 | 서브 도메인: 도메인 내 어플리케이션 분석. 상이한 데이터 또는 개발언어/프레임워크이면 별도 서브 도메인. Post 차세대 신규 구축이 아닌 유지보수·대응 개발 대상은 기존 시스템 분류 체계를 따름 | 시스템: 어플리케이션 Physical View의 서브 도메인 단위로 식별. 서브 도메인 내 특정 어플리케이션이 동일 기술을 사용할 수 없으면 독립 시스템으로 식별. 서브 도메인 일반 기술군과 다르면 대표 어플리케이션명을 시스템명으로 사용. 시스템 내 어플리케이션 도식은 AP 기준으로 관리 |
| 하위 | 어플리케이션: Logical View 어플리케이션과 Physical View 어플리케이션 1:1 | 어플리케이션: 어플리케이션 아키텍처에서 정의한 실제 위치를 식별·배치하여 AA와 TA 뷰를 동기화 |
