# 대내 EAI 유형별 처리 원칙 — Full Sync·Async·Half Sync·다중전송

> 원본: `원본/CamScanner 2026. 08. 27. 19.36_38.pdf`  
> 문서: KB국민은행 · Enterprise Interface Architecture 정의서 · 원문 전사(FACT)

## 본문

Full Sync 거래는 전문 전송 후 응답 대기하며, Async Response 거래와 Half Sync 거래는 각각 송신측과 수신측이 서로 다른 프로세스에 의해 처리됨.

| # | 유형 | 상세 |
|---|------|------|
| 1 | Full Sync | 송신측: 요청전문 전송 후 응답 대기. 수신측: 요청 수신·처리 후 응답 전송. 처리 결과 확인이 필요하거나 조회성 업무 |
| 2 | Async Response | 송신측: 요청 전송 후 응답을 기다리지 않음. 별도 수신서비스가 응답 수신. 동시 다량 요청 시 송신 자원 효율(예: SAF). Timeout 건은 송신측 별도 관리 |
| 3 | Half Sync | 송신측: 요청 후 응답 대기. 수신측: 요청 수신 서비스와 응답 서비스를 분리 |
| 4 | Async 다중 전송 | 하나의 송신시스템이 다수의 수신시스템으로 전문 전송. 접속정보 등 실시간 데이터 공유. 정합성 보장이 요구되지 않는 업무 |

- 원문 페이지: 30
