# 대외 EAI 유형별 처리 원칙 — Outbound/Inbound Sync·Async

## 본문

**위치:** IV. 인터페이스 처리방안 → 3. 인터페이스 유형별 처리 원칙

Sync 거래는 요청전문 전송 후 응답전문을 대기하며, Async 거래는 응답전문을 수신하지 않거나 다른 프로세스가 수신 처리함.

| 유형 | 처리원칙 |
|------|----------|
| 1. Out-Bound Sync | 대외기관으로 요청전문 전송 후 Waiting. 기관 응답전문 수신 후 요청 서비스로 전달. 응답결과를 업무서비스에서 직접 사용하는 경우. 거래량이 많지 않은 거래는 자원 점유로 부하 가능 → 업무 요건상 필수인 경우 외 제한적 사용 |
| 2. Outbound Async-Oneway | 대외기관에 데이터 전송 후 결과를 수신하지 않거나 별도 인터페이스(Inbound Oneway)로 수신. 대량 거래 처리에 적합 |
| 3. Inbound Sync | 대외기관 요청전문을 내부시스템으로 전송하고, 내부 응답전문을 기관으로 전송 |
| 4. Inbound Async-Oneway | 대외기관 요청전문을 내부로 전송하고 결과를 수신하지 않음. 또는 대외기관 처리결과를 일방 수신 |
