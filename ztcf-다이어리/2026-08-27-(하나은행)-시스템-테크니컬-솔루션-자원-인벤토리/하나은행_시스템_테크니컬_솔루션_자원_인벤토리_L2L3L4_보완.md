# 시스템 테크니컬 솔루션 자원 인벤토리 — TRM 확장(안)

> 성격: **TRM 확장 제안** — 원문 전사(FACT)가 아님  
> 기준: 원본 Check List `OSS TRM Inventory + CSP 특성 반영`  
> 원본: [`하나은행_시스템_테크니컬_솔루션_자원_인벤토리.md`](하나은행_시스템_테크니컬_솔루션_자원_인벤토리.md)  
> 표시: 원본 헤더와 같이, **기존 TRM에 없는 항목은 노란색 신규 TRM**으로 본다  
> 사용: 확정 인벤토리와 섞어 쓰지 말 것

원본에 이미 있는 제품(JAVA, Jenkins, Harbor, K8s, Istio, ELK, WhaTap 등)은 **다시 넣지 않음**.

## TRM 작성 규칙 (원본과 동일)

| 항목 | 규칙 |
|------|------|
| 계층 | Level1 환경 → Level2 기술영역 → Level3 기술분류 → Level4 기술요소 → 제품명 |
| OSS/상용 | 은행 TRM 분류. 시중 라이선스 현황과 다를 수 있음 |
| 라이선스 | OSS만 기입 (예: Apache 2.0, MIT License) |
| 기술지원 | `상용` / `community` / `prof/community` |
| 컨테이너화 | 컨테이너 배포 가능 시 `○` |
| CSP 서비스 | 관리형 서비스의 제공 CSP |
| Cloud 사용 | `○` = private/public 모두 · `public` = 퍼블릭만 |
| 역할 중복 | 동일 제품도 역할(L3/L4)이 다르면 행을 분리 (원본 Redis·ELK·WhaTap과 동일) |
| 1행 1제품 | 제품명·공급자를 슬래시로 묶지 않음 |

컬럼: Level3 · Level4 · 제품명 · 개발/공급자 · OSS/상용 · 라이선스 · 기술지원 · 컨테이너화 · CSP 서비스 · Cloud 사용 · 비고

## 0. TRM 분류체계 (원본 + 확장)

원본 L1·L2는 유지한다. 빈 칸은 **기존 L2 아래 L3/L4 확장**을 우선하고, 기존 L2에 넣을 수 없는 영역만 **신규 L2(노란색 TRM)** 로 둔다.

```text
개발환경
├─ 프로그래밍          ← 원본 L2  · 이번: 앱/화면/단말/모바일 프레임워크 L3 확장
├─ 개발지원            ← 원본 L2  · 이번: IDE·빌드·API설계·IaC·구성관리 L3 확장
└─ 품질관리            ← 원본 L2  · 이번: 테스트도구 L4 확장 (E2E·BDD·계약)

개발관리
├─ Container Image 취약점 점검  ← 원본 (제품 추가 없음)
├─ 소스코드검사        ← 원본 L2  · 이번: SCA·DAST·시크릿 L4 확장
├─ 영향도 분석         ← 원본
└─ 어플리케이션 통합 관리 ← 원본

실행환경
├─ 웹애플리케이션서버 / 웹서버  ← 원본 (WAS/WEB 제품 추가 없음)
├─ 인터페이스          ← 원본 (Gateway/Mesh 제품 추가 없음)
├─ DBMS / Bigdata Platform ← 원본 L2 · 이번: 검색엔진 L3 확장
├─ 인프라              ← 원본 L2 · 이번: LB·DNS·CDN·CNI·스토리지·오케스트레이션 L3 확장
├─ 로깅                ← 원본 L2 · 이번: 수집기 L4 확장
├─ Backing Service     ← 원본 (MQ/Cache 제품 추가 없음)
├─ ★ 런타임            ← 신규 L2 · JVM 배포판·언어 런타임
├─ ★ 배치처리          ← 신규 L2 · 스케줄러·워크플로
├─ ★ 서버리스          ← 신규 L2 · FaaS
├─ ★ 보안              ← 신규 L2 · IAM·Secret·KMS·WAF·인증서
└─ ★ 데이터연계        ← 신규 L2 · CDC·ETL·스트리밍처리

운영환경
├─ 인프라모니터링      ← 원본 L2 · 이번: 자원 모니터링 L4 확장
├─ 성능모니터링        ← 원본 L2 · 이번: APM L4 확장
├─ Tracing             ← 원본
├─ ★ 장애관리          ← 신규 L2 · 온콜·ITSM(운영 역할)
├─ ★ 백업              ← 신규 L2
├─ ★ 재해복구          ← 신규 L2
├─ ★ 보안관제          ← 신규 L2 · SIEM·취약점·CSPM·런타임보안
└─ ★ 구성관리          ← 신규 L2 · CMDB·클라우드 자산
```

`★` = 원본에 L2가 없어 **노란색 신규 TRM 항목**.

## 20. 핵심 포인트

- 이 문서는 원본 **OSS TRM Inventory** 계층을 깨지 않는다. 기존 L2에 맞으면 L3/L4만 확장하고, 안 맞으면 노란색 **신규 L2**로 둔다.
- 이전 보완안의 `개발도구`·`빌드/패키지`·`관제·장애` 같은 임의 L2는 TRM 명칭으로 재배치했다 (개발지원, 품질관리, 모니터링, 장애관리).
- 라이선스는 제안 시점 일반값. 도입 시 원본과 같이 별도 검증 (Terraform BSL, MinIO AGPL, Elastic SSPL 등).
- 확정 TRM 반영 전 아키텍처·보안·라이선스 검토가 필요하다.
