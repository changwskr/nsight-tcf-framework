## 내용 점검 결과

표의 **골격은 정상**입니다. 개발→점검→실행→운영 흐름, OSS/상용·CSP public 구분, 역할별 중복 수록(Redis, ELK, Apigee, WhaTap)은 원본 TRM과 맞습니다. 이번 점검에서 틀린 곳만 고쳤습니다.

| 항목 | 점검 | 조치 |
|------|------|------|
| 로깅·Backing Service | 직전에 운영환경으로 옮김 | **실행환경으로 복구** (운영환경 세로칸은 모니터링부터) |
| Cloud 컬럼명 | Cloud 유형 | 헤더 원문 **Cloud 사용** |
| 기술지원 헤더 | 유료 | **상용: 상용소프트웨어** |
| TRM 강조색 | 파랑/색 | 원문 **노란색** |
| Bitbucket 비고 | 무료로 사용 가능 | 비고 열 재대조: **유료로 사용 가능** (Gitlab EE 비고는 공란) |
| NoSQL 비고의 `상동` | 편집 메모가 원문 칸에 들어감 | 본문 밖으로 이동 |

원본 그대로 두는 표기(은행 TRM 분류이지, 시중 라이선스 현황과 다를 수 있음): Gitlab Runner·Cypress·Kong·MySql을 상용, MongoDB를 AGPL+Apache 2.0, Redis를 BSD.

사진에 안 보이는 Maven/Gradle/Selenium/Pinpoint/Zabbix는 넣지 않은 상태가 맞습니다.

## 핵심 포인트

- 개발환경(언어→형상→CI/CD→레지스트리→테스트→Jira) 다음에 점검과 실행환경(WAS/WEB·API·Mesh·DB·인프라·로그·MQ)이 이어지고, 운영환경은 모니터링
- CSP 관리형은 Cloud=`public`, 자체 구축 OSS는 컨테이너화 ○ + Cloud ○
- CentOS EOS, Docker Desktop 유료화, Oracle RAC(OCI 외 제약), Java LTS/EOA, JEUS 컨테이너 비권고가 비고에 명시
- 동일 제품이 역할별로 중복 수록 (Redis NoSQL+Cache, ELK 응용로그+통합로그, Apigee Management+Gateway, WhaTap/DynaTrace 인프라+APM)
