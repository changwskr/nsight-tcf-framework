# 시스템 테크니컬 솔루션 자원 인벤토리 — L2·L3·L4 보완(안)

> 성격: **보완 제안** — 원문 전사(FACT)가 아님  
> 기준 문서: [`하나은행_시스템_테크니컬_솔루션_자원_인벤토리.md`](하나은행_시스템_테크니컬_솔루션_자원_인벤토리.md)  
> 목적: 원본 Check List에 없거나 한 줄만 있는 **개발환경 · 실행환경 · 운영환경** 계층(L2–L4)을 보강하고, 관련 **제품명 · 개발/공급자**를 채움  
> 사용: TRM 확장 검토용. 원본 확정 목록과 섞어 쓰지 말 것

원본에 이미 있는 행(JAVA, Jenkins, Harbor, K8s, Istio, ELK, WhaTap 등)은 **다시 넣지 않음**.

컬럼은 원본과 동일: Level1~4 · 제품명 · 개발/공급자 · OSS/상용 · 라이선스 · 기술지원 · 컨테이너화 · CSP · Cloud 사용 · 비고(추가 사유).

범례: Cloud `○` = private/public 모두, `public` = 퍼블릭 전용. 기술지원 `상용` / `community` / `prof/community`.

## 4. 기존 행과 붙이는 방법

원본 표에 넣을 때는 **노란색 TRM 추가 항목**으로 표시하는 것이 원본 헤더 규칙과 맞음.

권장 삽입 위치:

| 보완 L2 | 원본에서 붙일 위치 |
|---------|-------------------|
| 개발도구 · 빌드/패키지 | 개발환경 > 개발지원, CI/CD 앞 또는 Library 앞 |
| 화면/단말 프레임워크 | 개발환경 > 프로그래밍, 화면개발언어 아래 |
| IaC·구성관리 | 개발환경 > 개발지원, CI/CD 뒤 |
| 테스트 E2E·SCA·DAST | 개발환경 > 품질관리 > 테스트도구 / 개발관리 > 소스코드검사 |
| 런타임/배치 | 실행환경 > 미들웨어와 인터페이스 사이, 또는 미들웨어 L2 확장 |
| 보안 · 네트워크 · 스토리지 | 실행환경 > 인프라 옆 (인프라 L2를 쪼개도 됨) |
| 검색 · CDC/ETL | 실행환경 > 데이터 아래 |
| containerd · EKS/AKS/GKE · OpenShift | 실행환경 > 인프라 > 컨테이너 |
| 관제·백업·SIEM | 운영환경, 모니터링 다음 |

중복 주의:

- **Redis / ELK / Kafka / Nginx / Consul** 은 원본에 이미 있음. 검색용 Elasticsearch, Ingress용 Nginx, KV용 Consul은 **L4 역할만 다르게** 추가.
- **ArgoCD / Harbor / Trivy / SonarQube** 도 원본 있음. Image Updater, IaC 스캔 모드는 확장으로만.

## 5. 핵심 포인트

- 원본 Check List는 **언어·CI/CD·WAS·Mesh·DB·K8s·로그·MQ·APM** 중심이라, 은행 클라우드 TRM에 흔한 **IDE/빌드, 단말UI, IaC, IAM/Secret, LB/DNS, 오브젝트스토리지, 배치, 백업/DR, SIEM** 이 비어 있음.
- 보완 제품은 원본과 같은 OSS/상용·CSP public 패턴을 유지 (자체 구축 `○` + `community`/`prof/community`, 관리형은 `public`+`상용`).
- 라이선스는 제안 시점 일반값. 도입 시 원본과 같이 별도 검증 (Terraform BSL, MinIO AGPL, Elastic SSPL 등).
- 이 파일은 제안이며, 확정 TRM에 넣기 전에 아키텍처·보안·라이선스 검토가 필요함.
