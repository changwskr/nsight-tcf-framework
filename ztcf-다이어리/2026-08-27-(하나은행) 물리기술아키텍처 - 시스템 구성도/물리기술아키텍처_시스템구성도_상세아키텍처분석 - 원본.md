# 3. 전체 Big Picture

```text
원천 (상품처리 · BCV · 카드/증권 · 채널로그 · 레거시 · 외부)
        │
        ├─ EAI NRT ──────────────► NRT(BSA) ETCL ──► BSA
        ├─ 파일/SAM ─────────────► ADW ETCL ───────► ADW
        ├─ 전사표준 ETCL ────────► ENT ──► BDW / SEM / ACR / 단위업무
        └─ AUI ETCL ─────────────► AUI DB / 정보성 단위업무

To-Be 개발 (프로젝트ONE)
        ├─ ETL #1  ← ADW + ENT + AUI + BSA   (VM / RHEL 9 / TeraStream)
        └─ ETL #2  ← ODW / Global DW         (VM / RHEL 9 / TeraStream)

To-Be 정보계 저장
        ├─ RTW (Oracle Exa)  실시간
        ├─ ADW (Oracle Exa)  분석
        ├─ BSA (Oracle)
        ├─ HDW (Vertica)     Cold / ILM
        └─ BDP (Hive)        빅데이터

소비
        ├─ 계정/정보단말
        ├─ BI포털 · 분석도구 · 데이터 가상화
        └─ OLAP (현행 SAP BO → Target IQ/Oracle)
```

> 위 결합도는 6장표를 한 장에 겹친 **ANALYSIS**다. 원본은 장표별로 평면이 분리되어 있다.

## 4.4 흐름 해석 (ANALYSIS)

```text

AUI 경로 : BSA/ADW → AUI ETCL → AUI DB · 정보성 단위업무
```

현행은 **ETCL을 업무(NRT/ADW/전사/AUI)별로 서버 분리**하고, BSA가 NRT·전사·AUI의 공통 허브다.

## 5.3 운영 패턴 해석 (ANALYSIS)

```text
사용자 → L4 → AP1 + AP2 (Active-Active)
                │
                ├─ 공유 Storage (설치파일·매뉴얼·데이터셋)
                └─ DB1 Master (실선) / DB2 Standby (점선, 복제)
```

- AP는 **이중 Active**, DB는 **Active-Standby + 복제**.
- 비즈메타와 포탈이 동일 AP/DB 스택(DataEye Portal + Oracle)으로 그려져 있다. 논리 업무 분리는 이 장표만으로 확정할 수 없다.
- 5TB 증설 사유는 HA가 아니라 **누적 데이터셋 공유**다.

```text
                 │ ETCL AUI            │
                 │ ETCL ENT            │

```

## 8.4 분류 원칙 해석 (ANALYSIS)

장표 4가 **서버 대수**, 장표 5가 **업무 파이프**다.

```text
원천 사용구분(BCV/RTW/ADW/BSA/상품처리)
        ↓  어느 ETCL이 가져가나
ETCL Global / AUI / ENT / ADW / BSA
        ↓  개발에서 어느 VM에 올리나
ETL #2 (Global) | ETL #1 (나머지 4)
```

ENT는 현행에서 BCV·RTW·ADW·BSA를 넓게 읽고, To-Be에서는 ACR/SEM 적재로 대응한다. 장표 1의 “전사 ETCL → SEM/ACR”과 정합한다.

BSA ETCL의 To-Be 매핑에 **RTW**가 올라온다. 장표 6의 RTW(실시간 DW)와 연결되는 지점이다.

# 18. 최종 평가

이 6장표는 정보계 물리를 **세 시점**으로 고정한다.

```text
As-Is 운영 ETCL·포탈·OLAP
        ↓
프로젝트ONE 개발 ETL #1 / #2
        ↓
To-Be 정보계 데이터 계층 (RTW·ADW·BSA·HDW·BDP)
```

구조적 특징은 다음이다.

1. **현행 ETCL은 업무별 서버**이고, 개발 To-Be는 **2 VM에 논리 파이프를 유지**한다.
2. **BSA는 NRT 허브**이자 To-Be에서 **RTW와 함께** 다시 등장한다.
3. **BI포탈/비즈메타는 DataEye+JEUS+Oracle HA**, OLAP은 **별도 SAP BO + IQ/Oracle**이다.
4. **목표 데이터 구성은 Exa 실시간/분석 분리 + Vertica 이력 + Hive 빅데이터**다.
5. **이관은 sFTP가 막혀 있어** 매핑만으로는 실행 불가하고 채널 정의가 남는다.
