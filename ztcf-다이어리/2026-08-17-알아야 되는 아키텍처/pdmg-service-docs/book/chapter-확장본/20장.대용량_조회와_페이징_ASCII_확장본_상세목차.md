# 제20장. 대용량 조회와 페이징 — ASCII 확장본 상세목차

> **목차 작성 기준**
>
> 핵심 근거는 `08.대용량 페이징 처리방식.md`, `08.대용량 페이징 처리방식-1.md`, 19장의 DAO/Mapper 검증 결과다.
>
> **AS-IS 고정 사실**
>
> - 최신 핵심 재분석에서 현재 신규 `co.a` 페이징 거래는 `mgcoa5530S0`, `mgcoa8888S0`, `mgcoa9000S0` 세 개가 직접 확인된다.
> - 기본 제20장에는 `mgcoa9001S0` 추가 사례가 있지만 핵심 재분석의 직접 확인범위와 시점이 다르므로 별도 사례로 구분한다.
> - 기본 pageSize는 5530=20, 8888=20, 9000=10이며 서버 상한은 모두 100이다.
> - pageNo null/0 이하→1, pageSize null/0 이하→거래별 기본값, 100 초과→100으로 보정한다.
> - offset은 Service가 `int offset=(pageNo-1)*pageSize`로 계산하며 overflow 위험이 있다.
> - DAO COUNT는 `int`, DTO totalCount는 `long`이어서 21억 초과 건수는 중간에서 표현할 수 없다.
> - 현재 세 Mapper는 Oracle ROWNUM 이중 래핑과 별도 COUNT를 사용한다.
> - COUNT와 LIST는 공통 WHERE를 공유한다.
> - 8888은 `REQUEST_TIME DESC, GUID DESC`, 9000은 `REG_DTM DESC, TX_ID ASC`의 tie-breaker가 있다.
> - 5530은 `ORDER BY L5101` 하나이므로 L5101 고유성 확인이 필요하다.
> - 같은 Transaction에서 COUNT/LIST를 호출해도 서로 다른 시점의 결과가 될 가능성을 정책적으로 고려해야 한다.
> - 현재 Keyset/Cursor는 구현되지 않았고 Offset이 AS-IS다.
> - 8888 목록은 REQUEST/RESPONSE 전문과 예외문자열을 포함할 수 있어 pageSize 100만으로 응답바이트를 보호하지 못한다.
> - SQL Statement Timeout은 현재 없고 Online 5초 Timeout이 JDBC SQL 즉시중단을 보장하지 않는다.
