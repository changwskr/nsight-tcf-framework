# 제10장. Interceptor와 시스템 선처리 — ASCII 확장본 상세 목차

> **목차 작성 기준**
>
> 이 장은 `book.zip`의 제10장 원문과 `15.Interceptor-ServicePrevention.preHandle-1.md`, `26.시스템후처리-1.md`, `17.TCF-TcfFace-Dispatcher.md`, `55.시스템선후처리다이어그램.md`를 중심으로 확장한다.
>
> 다음 사실을 고정한다.
>
> - `ServicePreventionInterceptor.preHandle()`은 Controller 직전의 Spring MVC 시스템 선처리다.
> - 현행 preHandle의 주 책임은 Header/sys_comm 보장, GUID·Service ID·화면·IP·사용자 보완, 요청 전문 로그, Pre ImageLog다.
> - 현행 Interceptor는 정상 분기에서 모두 `true`를 반환하며 거래통제를 직접 호출하지 않는다.
> - 거래통제 코드는 STF·`MgTxControlService`·Repository에 존재하지만 현재 `TcfFacade.process()` 호출선에는 STF가 연결되지 않았다.
> - 따라서 `거래통제 코드 존재`와 `온라인 요청 실제 차단`은 다른 사실이다.
> - 현재 Repository가 지원하는 축과 시간대 통제 요구를 구분한다. 시간대 통제는 AS-IS라고 단정하지 않는다.
> - Pre/Post/Exception ImageLog는 업무 DB Transaction과 별도 Web Lifecycle에서 동작하며 업무 Commit/Rollback과 원자적이지 않다.
> - Request Thread의 Interceptor와 Worker Thread의 업무 Transaction 경계를 구분한다.
> - multipart는 Filter·Interceptor 모두 일반 JSON과 다른 경로를 타므로 인증·감사 Gap을 별도 관리한다.
> - afterCompletion은 업무 Commit Callback이 아니라 MVC 완료 Callback이다.
