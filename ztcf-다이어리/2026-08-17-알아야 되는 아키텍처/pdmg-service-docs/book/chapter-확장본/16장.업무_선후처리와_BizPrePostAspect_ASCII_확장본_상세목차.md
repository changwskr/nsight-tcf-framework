# 제16장. 업무 선후처리와 BizPrePostAspect — ASCII 확장본 상세 목차

> **목차 작성 기준**
>
> 이 장은 `book.zip`의 제16장 원문과 `21.업무선처리-BizPrePostAspect-1.md`, `25.업무후처리-BizPrePostAspect-1.md`, `22.Business-Service-1.md`, `01.트랜잭션처리 변경-1.md`, `20.Tranaactional-rdwTransactionManager-Begin-1.md`, `58.업무선후처리 다이어그램.md`를 기준으로 확장한다.
>
> **고정 사실**
> - `BizPrePostAspect`: `@Aspect`, `@Component`, `@Order(100)`, `legacy-web.enabled=true` 조건.
> - Pointcut: `execution(public * nhnis.mg.co.a.application.service..*(..))`.
> - Advice: `@Before`, `@AfterReturning`; 현재 `@AfterThrowing/@After/@Around` 없음.
> - 현재 기능은 GUID/Service ID/Method/BRC/정상 DTO 로그이며 DB DML·TX 시작·오류이력 저장 없음.
> - BRC는 `getTrtBrc/getBrc/getBRC/getL5104` Reflection 탐색.
> - `PdmgBizTxFlowAspect @Order(50)`이 바깥, BizPrePost @Order(100)이 안쪽.
> - TCF ON+Timeout ON에서는 Worker TransactionTemplate 안에서 BizPre→Service→BizPost 실행.
> - BizPost 로그는 Service 정상반환이지 최종 Commit 성공이 아님. Deadline 검사 뒤 Rollback 가능.
> - `businessDto()` sanitize는 Metadata 제거이지 개인정보 Masking이 아님.
> - 오류 `REQUIRES_NEW`, DB 후처리, Annotation Pointcut은 TO-BE/설계 예시로 구분.
