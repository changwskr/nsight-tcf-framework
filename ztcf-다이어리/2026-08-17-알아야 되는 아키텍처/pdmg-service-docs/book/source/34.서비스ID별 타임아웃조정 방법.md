# 34. 서비스ID별 타임아웃 조정 방법

> **현행화 (2026-08-25):** overrides · min-start-budget · TX Policy · JDBC cancel 관련 설정 정리.  
> 상세: [20.타임아웃.md](../../20.타임아웃.md)  
> 원본: [`34.서비스ID별 타임아웃조정 방법 - 원본.md`](./34.서비스ID별%20타임아웃조정%20방법%20-%20원본.md)

**serviceId별 `overrides`에 ms를 넣으면 됩니다.**

### `pdmg-service` `application.yml`

```yaml
nhnis:
  fw:
    timeout:
      enabled: true
      milliseconds: 5000              # 기본
      overrides:
        mgcoa5530S0: 10000            # 이 거래만 10초
        mgcoa7000S0: 15000            # 예: 15초
      pool-size: 20
      queue-capacity: 100
      min-start-budget-ms: 1000       # Worker TX 개시 최소 잔여
      sql-safety-timeout-seconds: 10  # Deadline 없을 때 MyBatis ceiling
    transaction:
      default-manager: rdwTransactionManager
      default-mode: RDW_READ_WRITE
      services:
        mgcoa5530S0:
          mode: RDW_READ_ONLY         # 최외곽 TX Policy (선택)
```

| 항목 | 설명 |
| --- | --- |
| overrides 키 | 서비스 ID (`rms_svc_c` / MDC `serviceId`와 동일) |
| overrides 값 | 제한시간(ms), `>= 1` |
| 미등록 | `milliseconds` 사용 |
| min-start-budget | remaining이 이보다 작으면 TX 없이 Timeout |
| transaction.services | 최외곽 TX readOnly 등 (Facade readOnly만으로 대체하지 말 것) |

### 기동 옵션으로만 올릴 때

```text
--nhnis.fw.timeout.overrides.mgcoa5530S0=10000
```

반영 후 **pdmg-service 재기동**.

### UI / JDBC cancel

- UI `pdmg.ui.timeout-ms`(브라우저 Abort)는 **별개**. 서버 최대 override보다 **크거나 같게**.
- JDBC cancel 검증(로컬):  
  `--nhnis.demo.mgcoa5530-jdbc-hold-ms=15000`  
  → 로그 `[JDBC-CANCEL] cancelInvoked=1` 기대 (운영 기본값 0).

### 확인

```text
504 응답 addMsgContents 의 timeoutMs=...
로그 [ONLINE-TIMEOUT] ... timeoutMs=10000 ...
```
