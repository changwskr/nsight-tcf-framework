# 빅픽처 — 차세대 정보계 도메인 개념 아키텍처 분석

## 1. 핵심 결론

이 장표는 차세대 정보계 전체를 **도메인 관점으로 분해하고, 각 도메인이 어떤 역할을 담당하며 서로 어떤 관계를 가지는지**를 보여주는 상위 개념 아키텍처다.

원본의 중심 구조는 다음 6개 영역으로 요약된다.

```text
채널
  ↕
마케팅플랫폼
  ↕
계정계 및 단위업무
  ↕
데이터플랫폼
  ↕
데이터거버넌스
  ↕
IT서비스 및 업무지원
```

또한 BI포탈은 독립된 분석 소비/활용 영역으로 배치되어 있다.

```text
마케팅플랫폼 ↔ BI포탈
데이터플랫폼 ↔ 데이터거버넌스
```

즉 이 장표는 차세대 정보계를 단순한 시스템 목록이 아니라 다음과 같은 **도메인 집합**으로 정의한다.

```text
Channel Domain
Marketing Platform Domain
BI Portal Domain
Core/Unit Business Domain
Data Platform Domain
Data Governance Domain
IT Service & Support Domain
```

그리고 우측의 `차세대 구축 방향 1~13`을 각 도메인과 연결함으로써, **전략 방향과 아키텍처 도메인을 추적 가능하게 만든 것**이 핵심이다.

# 5. 도메인 간 핵심 관계

원본의 화살표를 구조적으로 정리하면 다음과 같다.

```text
채널
 ↔
마케팅플랫폼
 ↕
계정계 및 단위업무
 ↕
데이터플랫폼
 ↔
데이터거버넌스
 ↑
IT서비스 및 업무지원
```

추가 관계:

```text
마케팅플랫폼 ↔ BI포탈
계정계 및 단위업무 ↔ BI포탈
데이터플랫폼 ↔ BI포탈
```

※ 원본은 일부 관계를 양방향 화살표로 단순 표현하므로 실제 호출방향/데이터흐름은 후속 상세설계 확인이 필요하다.

# 6. 채널 도메인 상세 분석

## 6.1 원본 FACT

```text
채널

정보계 단말
콕 뱅킹
통합업무 시스템
SMS
DM
E-mail
ATM
...
```

### 의미

채널은 고객/직원/대외 접점 역할을 한다.

```text
User / Customer
      ↓
Channel
      ↓
Application / Marketing / BI
```

### ANALYSIS

채널 도메인은 다음 역할을 가질 수 있다.

- 사용자 접점
- 업무 진입점
- 고객 Context 전달
- 메시지/알림 채널
- 서비스 소비자

```text
├─ ADW
```

### 핵심 역할


### Architecture Implication

- RDW와 ADW 역할 분리
- 실시간 vs 분석 데이터 분리
- 마트 계층 관리 필요

# 13. 차세대 구축 방향 1~13 FACT 전사

원본 우측의 `차세대 구축 방향`은 다음과 같다.

```text
1. 데이터플랫폼 구축
2. 마케팅플랫폼 구축
3. BI포탈 사용자 중심 통합 분석 환경 구축
4. 마케팅 중심의 표준 상담 프로세스 수립
5. 개인화 마케팅 컨텐츠 고도화
6. 통합 고객/상품 정보 관리 체계 수립
7. 채널 연계 체계 구축
8. 데이터 표준 정비
9. 데이터 품질 관리 체계 수립
10. 데이터 흐름 관리 체계 수립
11. 표준 프레임워크 정의 및 통합 개발 환경 구축
    (※ UI 단말 프레임워크, NH Cloud Framework)
12. 고가용성 아키텍처 구축
13. Biz Meta 중심 데이터 탐색 활용 체계 수립
```

# 42. 최종 평가

이 장표는 차세대 정보계 Big Picture를 가장 압축적으로 보여주는 핵심 자료다.

최종 구조를 다시 그리면 다음과 같다.

```text
                            ┌───────────────┐
                            │     채널      │
                            └───────┬───────┘
                                    │
                                    ▼
                    ┌────────────────────────────┐
                    │      마케팅플랫폼          │
                    │ 고객 / 상품 / 캠페인 / 상담│
                    └───────────┬────────────────┘
                                │
               ┌────────────────┼─────────────────┐
               │                │                 │
               ▼                ▼                 ▼
        ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
        │ 계정/단위업무 │ │   BI 포탈    │ │ 데이터플랫폼 │
        └──────────────┘ └──────────────┘ │ RDW / ADW   │
                                         └──────┬───────┘
                                                │
                                                ▼
                                    ┌────────────────────┐
                                    │ 데이터거버넌스      │
                                    │ Meta / DQ / Flow   │
                                    └─────────┬──────────┘
                                              │
                                              ▼
                                 ┌────────────────────────┐
                                 │ IT서비스 및 업무지원    │
                                 │ 개발/앱/데이터/인프라  │
                                 └────────────────────────┘
```

이 장표의 핵심 아키텍처적 의미는 다음과 같다.

1. **채널, 업무, 분석, 데이터, 거버넌스, 기술지원의 역할을 분리한다.**
2. **마케팅플랫폼을 고객/상품/캠페인 업무의 중심으로 둔다.**
3. **BI포탈을 분석 소비 영역으로 독립시킨다.**
4. **RDW/ADW를 포함한 데이터플랫폼을 공통 정보 기반으로 둔다.**
5. **비즈메타·데이터품질·데이터흐름을 별도 거버넌스 영역으로 둔다.**
6. **IT서비스/업무지원이 모든 상위 도메인의 공통 기반을 제공한다.**
7. **1~13 구축 방향을 각 도메인과 직접 연결해 전략→아키텍처 Traceability를 제공한다.**

따라서 이 장표는 이후 모든 상세 아키텍처 문서가 따라야 하는 **차세대 정보계 Domain Concept Architecture Baseline**으로 활용할 수 있다.

후속 문서는 다음 순서로 연결하는 것이 적절하다.

```text
Domain Concept
   ↓
Application Classification
   ↓
Logical Architecture
   ↓
Interface Architecture
   ↓
Runtime Architecture
   ↓
Data / Governance Architecture
   ↓
Technical / Physical Architecture
   ↓
Standard / Operation / Verification
```
