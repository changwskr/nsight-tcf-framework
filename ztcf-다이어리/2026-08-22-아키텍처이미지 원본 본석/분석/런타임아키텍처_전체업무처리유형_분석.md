# 런타임 아키텍처 — 전체 업무 처리 유형 분석

## 1. 핵심 결론

이 장표는 **차세대 정보계 전체 런타임 아키텍처를 “업무 처리 유형” 관점에서 분류한 통합 운영 구조도**다.

즉 단순 시스템 구성도가 아니라,

- 어떤 채널이 어떤 경로로 유입되는지,
- 어떤 시스템 간 연계가 존재하는지,
- 실시간 이벤트가 어떻게 수집되고 활용되는지,
- CDC / ETL / FOS / 배치 / 분석지원이 어느 위치에 놓이는지,
- 운영환경과 배포/개발환경이 어떻게 연결되는지

를 **1~12번 업무 처리 유형**으로 구조화한 장표다.

이 그림의 가장 중요한 메시지는 다음과 같다.

```text
채널 거래 처리
    +
시스템 간 연계 처리
    +
실시간 고객행동/오퍼링 처리
    +
데이터 동기화/ETL/분석 지원
    +
파일 연계
    +
배치 처리
= 차세대 정보계 전체 런타임 운영 모델
```

즉 이 장표는 **애플리케이션·데이터·이벤트·연계·배치·운영환경을 하나의 런타임 처리 모델로 묶어서 보여주는 종합 아키텍처 지도**라고 볼 수 있다.

## 8. 전체 런타임 흐름 시나리오

## 8.1 시나리오 A — 통합업무시스템 온라인 거래

```text
통합업무시스템
   → 영업점 MCA
   → 애플리케이션 / 마케팅플랫폼
   → API Gateway / EAI
   → 코어뱅킹 / 단위업무 / 코어DB
   → 응답
```

## 8.2 시나리오 B — 미니 싱글뷰 조회

```text

   → 영업점 MCA 또는 정보단말
   → 미니 싱글뷰 Service
   → 대내 연계 / 데이터플랫폼 조회
   → 요약 결과 반환
```

## 8.3 시나리오 C — 고객행동 수집과 오퍼링

```text
고객행태 발생
   → Wise Collector
   → Event
   → Kafka
   → 행동정보처리서버(Daemon)
   → 실시간처리서버(EBM)
   → UMS / 오퍼링 실행
```

## 17. 장표 해석 시 유의사항

이 장표는 매우 많은 요소를 한 화면에 담고 있기 때문에, 다음을 주의해야 한다.

1. **모든 화살표가 호출순서를 정확히 의미한다고 단정할 수 없다.**  
   일부는 단순 연관관계나 데이터 흐름을 나타낼 수 있다.

2. **일부 영역은 논리구조와 물리구조가 섞여 있다.**  
   예: 애플리케이션, 데이터플랫폼, 이벤트처리, 배포/운영 환경이 한 장에 함께 있다.

3. **운영·배포 하단 영역은 해상도상 일부 텍스트가 흐려 정확한 세부 판독이 어렵다.**  
   따라서 본 문서에서는 보이는 범위까지 FACT로 기록하고 나머지는 확인 필요로 구분했다.

4. **처리유형 번호는 기능 단위이기도 하고 패턴 단위이기도 하다.**  
   예: `10`은 특정 모듈이 아니라 데이터 활용 목적을 설명한다.

따라서 이 장표는 **세부 설계서라기보다 전체 런타임 처리 패턴을 분류한 상위 통합지도**로 이해하는 것이 적절하다.

## 18. 최종 평가

이 장표는 차세대 정보계 전체를 다음과 같은 관점으로 통합한다.

```text
[채널 업무 처리]
 1 정보계 단말 거래
 2 통합업무시스템 거래
 3 미니 싱글뷰

[연계 업무 처리]
 4 대내 시스템간 연계
 5 대외 시스템간 연계

[마케팅 이벤트 처리]
 6 실시간 고객 반응형 정보 수집
 7 실시간 고객 오퍼링 제공

[데이터 분석/제공 처리]
 8 CDC 실시간 데이터 동기화
 9 ETL 연계
10 데이터 분석 기반 의사결정 지원

[파일/배치 처리]
11 FOS 파일 처리 연계
12 배치 처리
```

이 분류는 매우 중요하다. 왜냐하면 차세대 정보계의 복잡성을 “시스템별”이 아니라 **“런타임 처리 유형별”**로 나누어 관리할 수 있게 해주기 때문이다.

특히 장점은 다음과 같다.

1. **온라인 거래, 이벤트, 분석, 파일, 배치를 하나의 아키텍처 프레임으로 묶었다.**
2. **데이터플랫폼과 BI/마케팅 활용을 처리유형 관점으로 연결했다.**
3. **대내/대외 연계와 채널 연계를 분리해 설계 포인트를 명확히 했다.**
4. **운영환경과 배포체계까지 포함해 실제 런타임 운영 모델로 확장했다.**

후속 상세설계 단계에서는 반드시 다음 작업이 이어져야 한다.

- 처리유형 1~12별 인터페이스 카탈로그 작성
- 유형별 표준 프로토콜 / 보안 / 오류 / 재처리 정책 정의
- 이벤트 / CDC / ETL / 파일 / 배치 운영정책 정리
- 유형별 성능 / 관측성 / SLO 정의
- DevOps / 운영도구 / 배포체계 정식 문서화

결론적으로 이 장표는 **차세대 정보계의 전체 런타임 운영모델을 “업무 처리 유형” 기준으로 구조화한 상위 아키텍처 기준선**이며, 이후 인터페이스 정의서, 운영표준서, 모니터링 설계, 장애대응 기준의 출발점으로 매우 유용하다.
