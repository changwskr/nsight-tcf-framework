## 1. 한 줄 요약

거래는 **도메인(호스트) + URL 경로(업무/WAR) + {서비스코드}** 로 1차 라우팅되고, **내부망 L4 → WEB #1/#2 → WAS #1/#2 → .war** 로 물리 처리된다. **도메인 정의(18)** 가 URL 표준, **거래 처리 경로(19~23)** 가 인프라·WAR 배치를 정의하며, PDMG/TCF에서는 **ServiceID**가 논리 거래 주소다.

## 3. 공통 거래 처리 아키텍처

### 3.1 표준 4-Tier (내부망)

모든 경로(19~23)가 동일 패턴:

```text
[Client / 정보단말 / Package UI]
        │ HTTP
        ▼
   {prefix}.prod.nacf / {path} / {서비스코드 or 패키지URL}
        │
        ▼
   ┌─────────────┐
   │  내부망 L4  │  ← Layer 4 Load Balancer
   └──────┬──────┘
          ▼
   ┌──────────────┐
   │  WEB #1 #2   │  ← 이중화 Web Tier
   └──────┬───────┘
          │ (교차 연결 M:N)
          ▼
   ┌──────────────┐
   │  WAS #1 #2   │  ← 이중화 Application Tier
   │  *.war       │
   └──────────────┘
```

### 3.2 전체 거래 처리 경로 TEXT 표 (19번)

| 구분 | Client | URL (운영 예) | L4 | WEB | WAS / WAR |
|---|---|---|---|---|---|
| **미니싱글뷰** | 통합업무 시스템 | `ms.prod.nacf/ms/{코드}` | MS L4 | MS WEB×2 | MS WAS×2 · `/ms.war` |
| **마케팅** | 정보 단말 | `mp.prod.nacf/ic|pc|bc/...` | MP L4 | MP WEB×2 | MP WAS×2 · 12 WAR |
| **신용실적** | BI포탈 정보단말 | `cr.prod.nacf/cr/{코드}` | CR L4 | 신용실적 WEB×2 | 신용실적 WAS×2 · `/ws.war`, `/cr.war` |
| **BI포탈** | Package UI | `pt.prod.nacf/{패키지URL}` | PT L4 | BI포탈 WEB×2 | BI포탈 WAS×2 |
| **OLAP** | Package UI | `oa.prod.nacf/{패키지URL}` | OA L4 | OLAP WEB×2 | OLAP WAS×2 |
| **Self-BI** | Package UI | `sb.prod.nacf/{패키지URL}` | SB L4 | Self-BI WEB×2 | Self-BI WAS×2 |

### 3.3 ASCII Big Picture (19번 통합)

```text
┌─── Client Layer ───────────────────────────────────────────────────────────┐
│  MS(통합업무)     MP(정보단말)      CR(BI정보단말)                          │
│  Package UI ── BI포탈(pt) / OLAP(oa) / Self-BI(sb)                         │
└───────┬──────────────┬─────────────────┬───────────────────────────────────┘
        │              │                 │
        ▼              ▼                 ▼
   ms.prod.nacf   mp.prod.nacf     cr.prod.nacf     pt / oa / sb.prod.nacf
        │              │                 │                 │
        ▼              ▼                 ▼                 ▼
   [내부망 L4]    [내부망 L4]      [내부망 L4]       [내부망 L4 ×3]
        │              │                 │                 │
        ▼              ▼                 ▼                 ▼
   WEB×2 → WAS×2   WEB×2 → WAS×2   WEB×2 → WAS×2    WEB×2 → WAS×2 (각)
   /ms.war         12×.war         /ws /cr.war      솔루션 WAR
```

## 4. 업무별 상세 경로

### 4.1 미니싱글뷰 (20번)

| 항목 | 내용 |
|---|---|
| Client | 미니싱글뷰 (통합업무 시스템) |
| URL | `http://ms.prod.nacf/ms/{서비스코드}` |
| 인프라 | 내부망 L4 → 미니싱글뷰 WEB #1/#2 → WAS #1/#2 |
| 배포 | **`/ms.war`** (양 WAS 동일) |
| HA | WEB↔WAS 교차 연결 (M:N) |

```text
Client → ms.prod.nacf/ms/{서비스코드}
      → L4 → WEB#1|#2 → WAS#1|#2 → ms.war
```

### 4.2 마케팅플랫폼 (21번)

| 항목 | 내용 |
|---|---|
| Client | 마케팅플랫폼 (정보 단말) |
| URL | `http://mp.prod.nacf/{업무}/{서비스코드}` (12 path) |
| 인프라 | 내부망 L4 → 마케팅플랫폼 WEB #1/#2 → WAS #1/#2 |
| WAS | 12 WAR 동시 배치 (ws, ic, pc, bc, sa, pd, cm, eb, ss, cs, ct, mg) |

**Path-based routing**: URI 2번째 segment(`/ic/`, `/cm/` …) → **해당 WAR**로 라우팅.

### 4.3 BI포탈 · 신용실적 (22번)

| 항목 | 내용 |
|---|---|
| Client | BI포탈 (정보 단말) |
| URL | `http://cr.prod.nacf/cr/{서비스코드}` |
| 인프라 | L4 → **신용실적** WEB×2 → WAS×2 |
| WAR | **`/ws.war`** (SSO 인증) + **`/cr.war`** (신용실적) |

**해석**: `/cr/` path ↔ `/cr.war` 1:1. SSO(`/ws.war`)는 동일 WAS 컨테이너 내 인증 모듈.

### 4.4 업무 솔루션 — BI포탈 / OLAP / Self-BI (23번)

| 솔루션 | Client | URL | 인프라 |
|---|---|---|---|
| BI포탈 | BI포탈 Package UI | `pt.prod.nacf/{패키지URL}` | BI포탈 WEB/WAS ×2 |
| OLAP | OLAP Package UI | `oa.prod.nacf/{패키지URL}` | OLAP WEB/WAS ×2 |
| Self-BI | Self-BI Package UI | `sb.prod.nacf/{패키지URL}` | Self-BI WEB/WAS ×2 |

**해석**: Package UI 기반 — `{서비스코드}` 대신 **`{패키지 URL}`** 로 라우팅. 3개 솔루션 **독립 L4·WEB·WAS** 스택.

## 5. URL → 논리 업무 → ServiceID 연결

```text
[물리 라우팅]                    [논리 업무]              [PDMG/TCF]
────────────────────────────────────────────────────────────────────
Host: mp.prod.nacf        →   Application Group: MP
Path: /ic/                →   업무구분: IC (통합고객)
Path: /ic/{서비스코드}     →   ServiceID: mpic????S0
                                      │
                                      ▼
                              TcfFacade / Dispatcher
                                      │
                                      ▼
                              Handler → Facade → Service → DAO
```

| URL 요소 | 아키텍처 매핑 | 예 |
|---|---|---|
| Host prefix | 어플리케이션 그룹·배포 도메인 | `mp`, `ms`, `cr` |
| Path segment 1 | WAR context / 업무구분 | `/ic/` → ic.war |
| `{서비스코드}` | **ServiceID** (논리 거래) | `mpica0001S0` |
| `{패키지URL}` | Package UI 솔루션 경로 | pt/oa/sb |

## 6. 라우팅 · 제어 원칙

| No | 원칙 | 설명 |
|---:|---|---|
| **R1** | **도메인 = 1차 분기** | Host(`ms`/`mp`/`cr`/`pt`/`oa`/`sb`)가 L4·WEB·WAS 스택 결정 |
| **R2** | **Path = 2차 분기** | MP: `/ic/`→ic.war · CR: `/cr/`→cr.war |
| **R3** | **서비스코드 = 3차 분기** | WAS 내부 Controller Method / ServiceID |
| **R4** | **경계 = Controller** | 타 도메인 연계는 HTTP·API·TCF (→ 호출구조 ④⑤) |
| **R5** | **이중화 표준** | L4 + WEB×2 + WAS×2 + 교차 연결 |
| **R6** | **내부망 격리** | L4 이하 전 구간 **내부망** |

### 6.1 Client 유형별 진입

|---|---|---|

## 7. End-to-End Flow ID

| Flow ID | 흐름 |
|---|---|
| F01 | MS: Client → `ms/.../ms/{코드}` → L4 → WEB → WAS → ms.war |
| F02 | MP: 단말 → `mp/.../ic/{코드}` → L4 → WEB → WAS → ic.war |
| F03 | CR: BI단말 → `cr/.../cr/{코드}` → L4 → WEB → WAS → cr.war (+ ws SSO) |

## 8. PDMG/TCF 연관 시사점

| 영역 | 시사점 |
|---|---|
| **ServiceID** | URL `{서비스코드}` = TCF Registry Key · Evidence · Timeout |
| **도메인 경계** | `mp`↔`cr` = 호출구조 **⑤ 타 그룹 C→C** (HTTP/API) |
| **WAR = 업무구분** | 패키지 `nhnis.mp.ic.*` ↔ `/ic.war` ↔ `mp.prod.nacf/ic/` |
| **ExecutionDeadline** | L4~WAS 구간은 infra · **WAS 진입 후** TCF bind |
| **Phase 5** | CruzAPIM·타 도메인 호출 시 Deadline 전파 후보 |

```text
[PDMG TCF ON — MS/MP/CR 온라인]

Browser/단말
  → {prefix}.prod.nacf/{path}/{serviceId}
  → L4 → WEB → WAS → *.war
  → OnlineTransactionController (POST)
  → TcfFacade(serviceId) → Handler → Facade → Service → DAO
```
