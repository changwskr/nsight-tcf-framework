# 빅픽처 — 최상위 아키텍처 구성 · 전체 시스템 구조 분석

## 1. 분석 개요

첨부 장표의 **최상위 아키텍처 구성**을 기준으로, 차세대 정보계의 **채널 → 어플리케이션 서비스 → 마케팅 이벤트 처리 → 데이터플랫폼 → 유관·대외 연계** 를 한 화면에서 읽는 **전체 시스템 아키텍처 구조**를 분석한다.

장표는 좌측 **채널·채널통합**, 중앙 **어플리케이션 서비스(마케팅·BI)·마케팅 이벤트 처리**, 우측 **데이터플랫폼(RDW/ADW/거버넌스/BI 데이터)·유관시스템·대외**, 횡단 **EAI · IF 백본 · ETL(FOS/MFT)** 로 구성된다.

기존 [`빅픽처_전체시스템아키텍처구조정의_상세분석.md`](./빅픽처_전체시스템아키텍처구조정의_상세분석.md)가 동일 계열 Big Picture를 장문 전사한 상세본이라면, 본 문서는 첨부 **최상위 구성** 이미지를 기준으로 **영역·백본·연계 매체**를 압축한 구조 분석이다.

> 이 문서는 이미지에서 판독한 논리 구조를 분석한 것이다. 박스 내부 모듈 전수명, EAI/MCA 제품명, Kafka 토픽, RDW/ADW 물리 경계, IaaS 배포 단위는 레이어드·인터페이스·런타임 문서와 대조해야 한다.

## 2. 핵심 결론

- **정보계 Big Picture의 골격**: 채널(좌) · 앱 서비스+이벤트(중) · 데이터플랫폼+유관/대외(우).
- **앱 중심축 2개**: **마케팅플랫폼**과 **BI포탈**(신용실적·OLAP 포함), 공통으로 **Web(IaaS) + Application FWK(IaaS)**.
- **이벤트 축 분리**: Web/Mobile·고객행태 → Wise Collector → **Kafka** → 행동정보처리 · **EBM 실시간처리** → UMS → DMZ(SMS/PUSH/MAIL).
- **데이터플랫폼 이원화**: **RDW**(실시간·로그·피드백)와 **ADW**(분석·마트), 종단 **IF 백본**.
- **거버넌스 횡단**: 비즈메타·데이터품질·데이터흐름이 데이터플랫폼 안에 위치한다.
- **연계 백본 다중화**: 온라인·계정 **MCA**, 유관 **EAI**, 데이터 **IF 백본**, 파일 **ETL/FOS/MFT**, 대외 **대외 MCA**.
- **BI는 앱·데이터 이중 표현**: 앱 서비스의 BI포탈과 데이터 측 BI/신용실적·OLAP가 **JDBC 등**으로 맞닿는다.
- **구축 강조 영역(해석)**: 마케팅·이벤트 · 데이터플랫폼 · BI · 거버넌스가 차세대 핵심 구축 축이다.

## 3. 장표 영역 전사

### 3.1 채널 · 채널통합

| 구성요소 | 역할(해석) | 주요 연계 |
|---|---|---|
| 계정 단말 | 계정계 UI·거래 | MCA |
| 정보 단말 · Package UI | 정보계 UI · Single View | JSON 서비스 |
| Web UI · Mobile UI | 디지털 채널 | HTTP · Wise Collector Proxy |
| 고객행태 | 행동·이벤트 원천 | Collector / Kafka 계열 |
| DMZ (SMS/PUSH/MAIL) | 대고객 메시지 출구 | UMS · 이벤트 정보 |

### 3.2 어플리케이션 서비스

| 플랫폼 | 구성(장표) | 인프라 |
|---|---|---|
| 마케팅플랫폼 | 통합고객관리 · 통합상품관리 · 상담판매지원 등 | Web(IaaS) · App FWK(IaaS) |
| BI포탈 | BI포탈 · **신용실적** · OLAP | Web(IaaS) · App FWK(IaaS) |
| 단말관리 · 단말배포 | 단말 운영·배포 | (앱 서비스 인근) |

### 3.3 마케팅 이벤트 처리

| 구성요소 | 역할(해석) |
|---|---|
| Wise Collector (수집) | Web/Mobile·행태 수집 |
| KAFKA | 고객행동 스트리밍 버스 |
| 행동정보처리서버 | 행동 데이터 처리·적재 |
| 실시간처리 서버 / EBM | 이벤트 기반 마케팅(IaaS) |
| UMS | 통합 메시징 → PUSH 등 |

### 3.4 데이터플랫폼

| 영역 | 역할(해석) |
|---|---|
| IF 백본 | 데이터계 종단 연계 고속도로 |
| RDW | 실시간 SoR · 로그 · 피드백 · 마케팅 정보 |
| ADW | 분석 SoR · 집계 · 통합/부서 마트 |
| BI포탈(데이터) | OLAP · 신용실적 · Self BI 등 |
| 데이터거버넌스 | 비즈메타 · 품질 · 흐름관리 |
| Big Data | 수집/적재 · 메시지·분석 모델링 |
| 데이터 분류/저장 | 상위 저장·분류 계층 |

### 3.5 유관 · 대외 · 횡단 연계

| 매체/영역 | 대상 | 역할(해석) |
|---|---|---|
| EAI | 계정 코어 · 경영 · 리스크 · BCP 등 | 유관시스템 온라인/배치성 연계 |
| MCA | 계정·채널 | 채널·계정 통합 |
| 대외 MCA | 계열사 · 외부기관(KT, Nice, KCB 등) | 대외 연계 |
| ETL · FOS · MFT | 데이터플랫폼 ↔ 외부/계열 | 파일·객체 이동 |
| JDBC / Agent | 이벤트·앱 ↔ RDW/ADW | DB·에이전트 적재 |

## 4. 전체 TEXT 아키텍처 그림

```text
[채널]                    [어플리케이션 서비스]              [데이터플랫폼]
 계정단말 ──MCA──┐         ┌─ 마케팅플랫폼 (Web/FWK IaaS) ─┐     ┌─ RDW (실시간/로그/피드백)
 정보단말/Package│ JSON    │  통합고객·상품·상담판매 …      │     ├─ ADW (분석/마트)
   UI ───────────┼────────▶│                                │ JDBC├─ BI(OLAP·신용실적·Self)
 Web/Mobile ─────┤         ├─ BI포탈 (신용실적·OLAP)        │◀────┤─ 데이터거버넌스
 고객행태 ───────┘         └─ 단말관리·단말배포             │     ├─ Big Data
                           │                                │     └─ IF 백본 (종단)
                           ▼                                │
                    [마케팅 이벤트 처리]                     │
                     Wise Collector → KAFKA                  │
                     → 행동정보처리 → EBM 실시간(IaaS)      │
                     → UMS → DMZ(SMS/PUSH/MAIL)             │
                                                            │
[유관시스템] ◀── EAI ──▶ 앱/데이터                         │
[대외 MCA] ── 계열사·외부기관                               │
[ETL/FOS/MFT] ─────────────────────────── 데이터플랫폼 ─────┘
```

## 5. 영역 간 연계 매핑

| # | 출발 | 매체 | 도착 | 설계 의미 |
|---|---|---|---|---|
| 1 | 계정 단말 | MCA | 채널통합·계정 경로 | 계정 거래 표준 채널 |
| 2 | 정보 단말 / Package | JSON | 정보계 앱 서비스 | 정보계 UI·싱글뷰 |
| 3 | Web/Mobile | HTTP · Collector | Wise Collector / Kafka | 디지털·행태 수집 |
| 4 | 마케팅·BI 앱 | App FWK | 업무 로직 | IaaS 표준 프레임워크 |
| 5 | BI 앱 | JDBC 등 | BI/신용실적·OLAP 데이터 | 분석·실적 조회 |
| 6 | Kafka/행동처리 | JDBC·Agent | RDW | 준실시간 적재 |
| 7 | RDW/ADW | IF 백본 | 마트·거버넌스·BI | 데이터계 내부 고속도로 |
| 8 | 앱 서비스 | EAI | 유관(코어·경영·리스크…) | 기간계·관리계 연계 |
| 9 | EBM/UMS | 이벤트 | DMZ 메시징 | 실시간 고객 접촉 |
| 10 | 데이터플랫폼 | ETL/FOS/MFT | 계열·대외 | 파일·객체 대량 이동 |
| 11 | 대외 MCA | MCA | 계열사·외부기관 | 대외 표준 창구 |

### 5.1 매핑에서 읽히는 설계 의도

1. **채널 유형별로 연계 매체를 나눈다**(MCA vs JSON vs Collector).
2. **온라인 앱(마케팅·BI)** 과 **이벤트 파이프(Kafka·EBM)** 를 분리한다.
3. **데이터는 RDW/ADW 이원화** 후 IF 백본으로 묶는다.
4. **유관은 EAI, 대외는 대외 MCA, 파일은 ETL/FOS/MFT** 로 백본을 전문화한다.
5. BI·신용실적은 **앱 화면과 데이터 저장**을 한 Big Picture에서 동시에 보여 정합을 강조한다.

## 6. 주요 End-to-End 흐름

### 6.1 정보계 온라인 (단말 → 마케팅/BI)

```text
정보 단말 / Package UI
  → JSON
  → 어플리케이션 서비스 (마케팅 or BI, App FWK)
  → (필요 시) EAI → 유관 / JDBC → 데이터플랫폼
  → 응답
```

### 6.2 계정 채널

```text
계정 단말 → MCA → 채널통합/계정 경로 → (유관·코어)
```

### 6.3 마케팅 이벤트 · 메시지

```text
Web/Mobile/고객행태
  → Wise Collector → Kafka
  → 행동정보처리 / EBM 실시간
  → UMS → DMZ → SMS/PUSH/MAIL
  → (병행) RDW 적재
```

### 6.4 분석 · 거버넌스

```text
RDW/ADW/Big Data
  → IF 백본
  → 마트 · BI(OLAP·신용실적) · 거버넌스(메타·품질·흐름)
  → BI포탈 앱 조회
```

### 6.5 파일 · 대외

```text
데이터플랫폼 ↔ ETL/FOS/MFT ↔ 계열·외부
대외 MCA ↔ 계열사·외부기관
```

## 7. 전체 구조 설계 원칙

1. **채널·앱·이벤트·데이터·유관/대외**를 계층·영역으로 분리한다.
2. **마케팅과 BI**를 정보계 앱의 양대 축으로 두고 App FWK·IaaS로 표준화한다.
3. **실시간 행동(Kafka/EBM)** 과 **정형 분석(ADW)** 부하를 런타임 분리한다.
4. **연계 매체는 전용 백본**(MCA / EAI / IF / ETL / 대외 MCA)으로만 통과시킨다.
5. **거버넌스는 데이터플랫폼 내부 횡단**으로 메타·품질·흐름을 통제한다.
6. BI·신용실적은 **앱 I/F 문서·데이터용량·레이어드**와 용어를 일치시킨다.
7. 통합개발·형상배포 표준의 **IaaS 컨테이너 착지**가 본 도의 Web/FWK/EBM IaaS와 맞닿는다.

## 8. 영역별 특성 요약

| 영역 | 장점 | 위험 | 통제 |
|---|---|---|---|
| 채널 다원화 | 접점 커버 | 매체 혼선 | MCA/JSON/Collector 계약 |
| 마케팅·BI 앱 | 업무·분석 분리 | 이중 구현 | App FWK·공통 라이브러리 |
| Kafka/EBM | 실시간 마케팅 | 유실·지연 | 재처리·관측·UMS SLA |
| RDW/ADW | 실시간 vs 분석 | 기준일 불일치 | IF 백본·마감 게이트 |
| 거버넌스 | 메타·품질 | Batch 지연 | SLA·비즈메타 정합 |
| EAI/대외 MCA | 유관·대외 표준 | 단일 장애 | HA·쿼터·감사 |
| ETL/FOS/MFT | 대량 이동 | 경로 오용 | 매체별 계약 |

## 10. 점검 체크리스트

- [ ] 채널별 진입 매체(MCA/JSON/Collector) 계약이 있는가?
- [ ] 마케팅·BI App FWK·IaaS 배포 단위가 형상배포 표준과 맞는가?
- [ ] Kafka→EBM→UMS→DMZ 경로의 SLA·실패 보정이 있는가?
- [ ] RDW/ADW/IF 백본 소유·마감·모니터링이 정의되어 있는가?
- [ ] 거버넌스(메타·품질·흐름)와 비즈메타 IF 문서가 정합하는가?
- [ ] EAI·대외 MCA·ETL/FOS/MFT 각각의 카탈로그가 있는가?
- [ ] 신용실적·BI 시스템간 연계 분석과 본 도 위치가 일치하는가?
- [ ] 상세 Big Picture 문서·시스템 그룹·레이어드와 교차 검증했는가?

## 11. 종합 평가

최상위 아키텍처 구성은 차세대 정보계를 **채널 · (마케팅+BI) 앱 · 마케팅 이벤트 · 데이터플랫폼(RDW/ADW/거버넌스) · 유관/대외**로 펼친 전체 시스템 구조다. 횡단으로는 **MCA · EAI · IF 백본 · ETL/FOS/MFT · Kafka** 가 매체별 고속도로 역할을 한다.

운영·설계 품질은 **영역 경계 준수, 백본 우회 금지, RDW/ADW·거버넌스 정합, 이벤트 메시지 SLA**에 좌우된다. 상세 Big Picture·레이어드·인터페이스·런타임·용량·형상배포 문서와 함께 읽어야 전체 아키텍처가 닫힌다.
