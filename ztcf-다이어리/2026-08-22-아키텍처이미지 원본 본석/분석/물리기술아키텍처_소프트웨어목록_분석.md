# 물리기술아키텍처 — 소프트웨어 목록 분석

> 원본 범위: `3. 물리 기술 아키텍처 > 3.4 소프트웨어 목록`  
> 원본 설명: 정보계 차세대 시스템 운영환경 구성을 위한 S/W 목록(17종) 및 버전  
> 분석 원칙: 장표의 제품명·버전을 그대로 기록하고, 빈 버전은 미확정으로 관리한다. 제품의 최신성이나 지원기간은 장표만으로 단정하지 않는다.

---

## 1. 핵심 결론

차세대 정보계의 소프트웨어 표준은 IaaS 기반의 `Red Hat 9.4 + JDK 21 + Apache + Tomcat + NH F/W`를 중심으로 하고, 데이터·분석·개발 도구를 업무별로 추가하는 구조다.

- IaaS OS는 Red Hat 9.4, 물리 서버는 AIX 7.X, Appliance는 Oracle Linux를 사용한다.
- Java 실행환경은 JDK 21이다.
- WEB/WAS 표준은 Apache와 Tomcat, 애플리케이션 프레임워크는 NH F/W다.
- Appliance DBMS는 Oracle 21Ai로 표기되어 있다.
- 데이터거버넌스는 DQ Miner, Meta Miner, Data Hawk로 구성된다.
- CDC는 물리 서버의 Oracle GoldenGate, 마케팅 스트림은 Kafka 4.X를 사용한다.
- ETL은 개발 IaaS와 운영 물리 서버에 DataStage를 배치한다.
- DevOps는 GitLab·GitLab Runner, 보고서는 RD, SQL 품질은 OpenPOP, 이행은 SQL Canvas를 사용한다.

```text
업무 솔루션
  ├─ WebTopSuite / BI Matrix / Kafka
  ├─ DQ Miner / Meta Miner / Data Hawk
  ├─ DataStage / GoldenGate
  └─ GitLab / Runner / RD / OpenPOP / SQL Canvas
           ↓
Apache / Tomcat / NH F/W / JDK 21
           ↓
Red Hat 9.4 / AIX 7.X / Oracle Linux
           ↓
Oracle 21Ai Appliance
```

## 4. 계층별 소프트웨어 구조

### 4.1 기반 운영체제

```text
IaaS 서버      → Red Hat 9.4
물리 서버      → AIX 7.X
Appliance 서버 → Oracle Linux (버전 미기재)
```

- Red Hat은 장표에서 `Redhat`으로 표기되어 있다.
- AIX는 ETL·CDC 등 물리 서버 계층과 연관된다.
- Oracle Linux는 DB Appliance의 기반 OS다.
- O/S는 장표 비고상 `구성점검 제외` 대상이다.

### 4.2 Java·WEB·WAS·프레임워크

```text
NH F/W
   ↓
Tomcat
   ↓
Apache
   ↓
JDK 21
   ↓
Red Hat 9.4
```

실제 실행 순서는 Apache → Tomcat → NH F/W 애플리케이션이지만, 설치 스택 관점에서는 OS·JDK·WAS·프레임워크의 의존성을 함께 관리해야 한다.

| 구성요소 | 역할 | 핵심 확인사항 |
|---|---|---|
| JDK 21 | Java 실행환경 | LTS 정책, JVM 옵션, GC, 암호화 provider |
| Apache | WEB 서버 | 버전, MPM, TLS, module, 보안패치 |
| Tomcat | WAS/Servlet Container | 버전, connector, session, thread pool |
| NH F/W | 공통 애플리케이션 프레임워크 | 호환 JDK·Tomcat, 배포 단위, 공통 라이브러리 |

### 4.3 데이터베이스·CDC·ETL

```text
Oracle GoldenGate
        ↓ CDC
Oracle DB 21Ai / RDW·ADW Appliance
        ↑ ETL
DataStage
```

- Oracle DB는 Appliance 서버에 위치한다.
- GoldenGate는 물리 서버의 CDC 기능으로 표시된다.
- DataStage는 개발 IaaS와 운영 물리 서버로 환경별 배치가 다르다.
- 제품명 표기는 장표의 `Oracle Golden Gate`, `Datastage`를 유지했으며 공식 표기와의 정합성은 자산대장에서 확인해야 한다.

### 4.4 데이터거버넌스

```text
DQ Miner   → 데이터 품질 진단·규칙
Meta Miner → 비즈니스 메타데이터
Data Hawk  → 데이터 흐름·계보
```

세 제품은 품질·메타·흐름을 각각 담당하는 거버넌스 도구군이다. 공통 메타모델과 권한, 수집주기, RDW·ADW 접속계정을 통합 관리해야 한다.

### 4.5 분석·채널·마케팅

```text
WebTopSuite → 단말 UI
BI Matrix   → BI 포탈 / Self-BI
Kafka 4.X   → 마케팅 행동 이벤트 스트림
RD          → 보고서 출력
```

Kafka의 `4.X`는 광범위한 버전 범위이므로 정확한 major/minor/patch와 KRaft 구성, client 호환성을 확정해야 한다.

### 4.6 DevOps·품질·이행

```text
GitLab
  ↓ pipeline
GitLab Runner
  ↓ build/deploy
애플리케이션

OpenPOP    → SQL 품질
SQL Canvas → 데이터 이행
```

- GitLab과 Runner는 소스관리·배포 자동화 공급망을 구성한다.
- OpenPOP와 SQL Canvas는 개발·이행 단계의 품질 및 변환 통제 도구다.

## 7. “17종”과 실제 제품 수 차이

장표 본문은 `S/W 목록(17종)`이라고 설명하지만 표에는 19개 기능 구분 행과 21개 중복 제거 제품명이 보인다.

```text
표의 기능 구분 행 : 19개
식별 제품명       : 21개
본문 선언         : 17종
```

가능한 원인:

1. O/S와 JAVA를 17종 집계에서 제외
2. Apache·Tomcat·NH F/W를 하나의 공통 플랫폼으로 집계
3. 개발/운영 DataStage를 하나의 제품으로 집계
4. 문서 개정 과정에서 본문 종수 미갱신

정확한 기준은 라이선스 목록 또는 소프트웨어 자산관리(SAM) 기준으로 재확정해야 한다.

## 11. 최종 평가

소프트웨어 목록은 차세대 정보계의 기본 기술 스택과 주요 업무 솔루션을 한눈에 보여주지만, 운영 자산관리 기준으로는 버전과 제조사 정보가 부족하다. 특히 Apache·Tomcat·NH F/W·GoldenGate·DataStage·GitLab 등 핵심 구성요소의 정확한 버전이 빠져 있어 호환성·취약점·라이선스 분석에 제약이 있다.

따라서 본 목록을 기준선으로 사용하되, **정확한 제품 버전·Patch, 설치 Hostname, 라이선스, EOL/EOS, 구성점검 정책**을 보완한 소프트웨어 자산대장으로 확장해야 한다.
