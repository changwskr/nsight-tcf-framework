# 물리기술아키텍처 — 시스템용량 분석

## 1. 분석 개요

첨부 장표 4종(**BI포탈 Capacity · 마케팅플랫폼 Capacity · BI포탈 운영 Capacity · 마케팅플랫폼 운영 Capacity**)을 기준으로, BI포탈·마케팅플랫폼의 **단일 구성(CPU/Memory/Disk) × 대수(인스턴스)** 로 산정한 **개발·운영 환경 시스템 용량**을 분석한다.

장표 공통 구조는 `구분 · 용도 · 단일 구성 · 대수(또는 인스턴스#) · 환경 합계 · 비고` 이다. 앱/게이트웨이 계열은 **CPU=0** 표기가 반복되고, 마케팅 **운영** 장표만 **IMDG(Gemfire)** 에 CPU·대용량 메모리를 명시한다.

레이어드·하드웨어구성·소프트웨어구성 문서와 맞물려, 본 문서는 **용량 산정표 전사를 중심으로 한 물리 용량 Baseline** 이다.

> 이 문서는 이미지에서 판독한 수치를 분석한 것이다. CPU=0의 의미(미기재·공유풀·별도 산정), 인스턴스=대수=VM/컨테이너 여부, 합계 행의 산술 검증 불일치는 원본 장표·인벤토리와 재대조가 필요하다.

## 2. 핵심 결론

- **대상 이원화**: 용량 장표는 **BI포탈**과 **마케팅플랫폼**을 분리해 산정한다.
- **환경 이원화**: 각 플랫폼에 **개발 Capacity**와 **운영 Capacity**가 있다.
- **산식**: `환경 합계 ≈ 단일 구성 × 대수(인스턴스#)` (장표 표기 기준).
- **CPU는 앱 표에서 사실상 미기재**: 대부분 행 CPU=0. **IMDG(Gemfire)만 CPU 명시**.
- **공통 인프라**: 양 플랫폼 모두 **Service Registry(디스커버리)** · **Spring Cloud Gateway(라우팅)** 를 두고, 비고에 **컨테이너·HA(인스턴스 2)** 를 명시한다.
- **BI 고부하**: **웹정형보고서(CP)** · **엑셀 업/다운로드(EX)** 가 단일 Mem **8GB**. 운영에서 CP는 **인스턴스 5**로 Mem **40GB**.
- **마케팅 운영 스케일업**: 개발 대비 업무 WAS 단일 Mem이 **2→4GB**로 상향되고, 대수·WEB 대수가 늘어 **허브 합계 Mem 92GB**.
- **마케팅 IMDG가 용량 지배**: Gemfire server VM **4대 × 64GB** → Mem **256GB**. 허브(92GB)보다 훨씬 크다. Plan: **nh-extra-medium**.
- **관리성 단일 노드**: Master Solution(MS)·xAdmin(UM)은 개발에서 **대수 1**. 운영 BI/마케팅 허브 표에서도 MS는 **1**.

## 9. 용량 설계에서 읽히는 원칙

1. **단일 구성 × 인스턴스**로 환경 용량을 산정하고, 합계 행을 조달·할당 Baseline으로 쓴다.
2. **MSA 공통부**(Discovery·Gateway)는 플랫폼마다 두고 **컨테이너 HA 2**로 고정한다.
3. **리포트·엑셀·IMDG**처럼 메모리 민감 구간에 용량을 몰아 준다.
4. **개발은 운영보다 작지만 HA 대수(대체로 2)는 유지**해 다중 인스턴스 검증이 가능하게 한다.
5. **관리 솔루션(MS, 개발 UM)** 은 단일 인스턴스로 용량을 절약한다.
6. **IMDG는 VM · Gateway/Registry는 컨테이너**로 인프라 형태를 나눈다.
7. 앱 표의 **CPU=0**은 “무제한”이 아니라 **본 장표 범위 밖 산정**으로 취급하고, IMDG·호스트 인벤토리와 별도 대조한다.

## 12. 종합 평가

네 장표의 시스템용량은 **BI포탈·마케팅플랫폼 × 개발·운영** 격자에서 **단일 사양×인스턴스**로 산정된 물리 Baseline이다. BI는 **웹정형보고서·엑셀**이, 마케팅 운영은 **IMDG(Gemfire)** 가 용량을 지배하며, 양측 모두 **Spring Cloud Registry/Gateway 컨테이너 HA**를 공유 패턴으로 둔다.

운영 품질은 **고메모리 구간의 격리, CPU 미기재 보완, 개발·운영 카탈로그 정합, 허브+IMDG 합산 보고**에 좌우된다. 하드웨어/소프트웨어 구성도·서버 인벤토리와 함께 읽어야 물리 아키텍처가 닫힌다.
