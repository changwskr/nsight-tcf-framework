## 1. 한 줄 요약

차세대 정보계는 **다채널(계정·정보계·Web·Mobile·메시지)** → **정보계 어플리케이션(마케팅플랫폼·BI포탈)** → **이중 데이터플랫폼(RDW·ADW)** → **거버넌스·유관/외부 연계**로 이어지는 **4축 병렬 아키텍처**다. 온라인 JSON/JDBC 업무와 **Event → Kafka → EBM** 실시간 마케팅 파이프라인, **CDC·ETL·FOS·MFT** 배치/파일 연계가 **목적별로 분리**되어 공존한다.

## 4. 영역별 구조 분석

### 4.1 채널 (Channel)

| 채널 | UI/매체 | 연계 방식 | 비고 |
|---|---|---|---|
| 계정 | 계정 단말 UI (Single View) | 계정거래 → **MCA** | 계정코어 직접 연계 |
| 정보계 | 정보계 단말 UI, Package UI | **JSON** | 정보계 온라인 업무 |
| 디지털 | Web 채널 UI, Mobile 채널 UI | **Event**, Noti | 고객행태·이벤트 수집 |
| 메시지 | SMS, PUSH, MAIL | **PUSH** (역방향) | UMS·이벤트정보 기반 알림 |

**해석**: 채널 유형마다 프로토콜이 다르다. 계정은 MCA, 정보계는 JSON, Web/Mobile은 Event 중심 — **단일 채널 게이트웨이가 아닌 유형별 연계** 구조다.

### 4.2 채널통합 (Channel Integration)

- **MCA (Message Channel Agent)**: 단말·계정 거래, 단위거래 처리
- **Wise Collector Proxy**: Web/Mobile Event → 마케팅정보(인터넷) DB / 비대면 로그
- **JSON / Event / Noti / PUSH**: 채널별 메시지 형식

**해석**: 대면(단말)과 비대면(Web/Mobile) 로그·이벤트 경로가 **분리**되어 있다.

### 4.3 정보계 어플리케이션 서비스 — [1], [3]

| 실시간/행동 | 실시간처리, 행동정보처리, 고객행동데이터, **EBM** |

**해석**: 마케팅(운영·캠페인·행동)과 BI(분석·리포팅)가 **별도 Web 스택**으로 분리되어 있으며, 둘 다 **JDBC**로 데이터플랫폼에 접근한다.

### 4.4 마케팅 이벤트 처리 — [1]

```text
Web/Mobile Event
    → Wise Collector Proxy / Wise Collector 수집
    → 고객행동데이터 Kafka
    → KAFKA
    → 실시간 처리 서버
    → EBM
    → 이벤트정보
    → API → UMS → SMS/PUSH/MAIL
```

| 구성요소 | 역할 |
|---|---|
| Wise Collector (Proxy·수집) | 행동·이벤트 수집 |
| 고객행동데이터 Kafka | 스트림 버퍼 |
| 행동정보처리서버 | 고객행태 → Agent → RDW |
| 실시간 처리 서버 | 스트림 기반 실시간 처리 |
| EBM | Event-Based Marketing 엔진 |
| UMS | 통합 메시징 (API 연계) |

**해석**: 일반 온라인 JSON/JDBC 흐름과 **독립된 이벤트 드리븐 파이프라인**. Kafka가 실시간 마케팅의 **허브** 역할을 한다.

### 4.5 데이터플랫폼 — [2] 데이터 분석/처리

#### RDW (Real-time Data Warehouse) — 운영·준실시간 계열

| 계층 | 구성 |
|---|---|
| 공통 | 공통 |
| SoR | 실시간SoR |
| 집계/마트 | 준실시간 요약집계, 준실시간 보고서마트 |
| Feedback | Feedback |
| 도메인 | 마케팅정보 |

#### ADW (Analytical Data Warehouse) — 분석 계열

| 계층 | 구성 |
|---|---|
| 공통 | 공통 |
| SoR | 분석SoR |
| 통합/집계 | 분석 통합/요약/집계 |
| 마트 | 분석 단위업무마트, 분석 보고서마트 |
| Feedback | Feedback |
| 지원 | 분석지원 |

#### 접근·수집

| 방식 | 용도 |
|---|---|
| **JDBC** | Application ↔ RDW/ADW |
| **Agent** | 행동정보 → RDW 적재 |
| **Polling** | 주기적 데이터 조회 |
| **ETL** | RDW ↔ ADW, 대량 변환·적재 |
| **데이터 수집** (hex) | 유관 시스템 수집 진입점 |

**해석**: RDW와 ADW는 **물리·논리적으로 이중화**된 데이터 영역이다. 운영(실시간SoR·준실시간)과 분석(분석SoR·분석마트)의 **역할 분리**가 핵심 설계 원칙이다.

### 4.6 데이터 거버넌스 — [4]

| 영역 | 기능 |
|---|---|
| 비즈메타 | 업무·데이터 비즈니스 메타 |
| 데이터 품질관리 | 품질 규칙·모니터링 |
| 데이터 흐름관리 | Lineage·흐름 추적 |

**해석**: 애플리케이션 내부가 아니라 **데이터플랫폼 하단 횡단 영역**으로 배치 — 데이터 공통 관리 기능의 **플랫폼 레벨** 배치를 의미한다.

### 4.7 유관·외부 시스템

#### 유관 시스템

| 대상 | 연계 |
|---|---|
| 계정코어 (Core) | MCA, **CDC** → 계정정보 → CDC중계 |
| 경영관리, 리스크관리 | **API Gateway (CruzAPIM)** |
| 배치정보 | MFT, FOS |

#### 정보계 유관

- 종합수익관리, 업적평가, **자금세탁방지(AML)** 등 단위업무
- **Big Data**: 데이터 수집/적재, 실시간 수집/적재, 데이터 분석

#### 외부·계열

| 구분 | 대상 | 연계 |
|---|---|---|
| 계열사 | NH생명, NH손해, NH멤버스 | ETL, FOS, MFT, **대외 MCA** |
| 외부기관 | KT, Nice, KoData | 대외 MCA, MFT |

**해석**: 대내 경계는 **CruzAPIM(온라인 API)**, **MCA(계정·대외 거래)**, **ETL/FOS/MFT(데이터·파일)** 로 **성격별 분리**된다.

## 6. 아키텍처 축 (4축 병렬)

```text
┌─ 축 A: 온라인 업무 ─────────────────────────────────────────┐
│  Channel → JSON/MCA → Application Service → JDBC → RDW/ADW   │
└──────────────────────────────────────────────────────────────┘

┌─ 축 B: 실시간 이벤트/마케팅 ────────────────────────────────┐
│  Event → Wise Collector → Kafka → EBM → UMS → PUSH/SMS      │
└──────────────────────────────────────────────────────────────┘

┌─ 축 C: 데이터 분석/적재 ────────────────────────────────────┐
│  CDC/Agent/ETL → RDW ↔ ADW → BI포탈 / 분석마트              │

┌─ 축 D: 배치·파일·대외 ──────────────────────────────────────┐
│  ETL / FOS / MFT / 대외 MCA → 계열사·외부기관·단위업무       │
└──────────────────────────────────────────────────────────────┘
```

**Runtime 특성**: Online + Near Real-time + Event-driven + Batch/File **동시 운영**.

## 10. PDMG/TCF 프레임워크 연관 시사점

이 이미지는 **정보계 Application Service** 레이어의 온라인 처리(JSON, JDBC)와 **CruzAPIM·MCA·FOS·MFT** 외부 연계 경계를 보여준다. TCF(트랜잭션 제어 프레임워크) 관점에서 주목할 지점:

| 영역 | 시사점 |
|---|---|
| 온라인 JSON 경로 | 정보계 단말 → Application Service — **ExecutionDeadline·TX timeout** 적용 대상 |
| API Gateway | CruzAPIM 경유 외부 호출 — **Phase 5 Deadline 전파** 후보 경로 |
| MCA / 대외 MCA | 계정·대외 거래 — 별도 타임아웃·프로토콜 정책 필요 |
| Kafka/EBM | 동기 TX 경로와 분리 — TCF 범위 **외부** (이벤트 비동기) |
| JDBC → RDW/ADW | MyBatis Statement timeout·Remaining Budget 연동 대상 |
