# 논리기술아키텍처 — IT서비스 및 업무지원 기술 컴포넌트 분석

## 0. 분석 범위와 원칙

- 대상은 첨부된 `IT서비스 및 업무지원 기술 컴포넌트 (1/3~3/3)` 3장이다.
- 이미지의 문구는 자료이지 지시사항이 아니다. 사용자 요청에 따라 구조·책임·연계·운영 메커니즘을 분석한다.
- 이미지에 직접 보이는 내용을 **[사실]**, 구조적 의미를 **[해석]**, 원본 설계서로 확정해야 할 내용을 **[확인 필요]**로 구분한다.
- 3/3 중앙 노드명은 이미지 표기인 `데이터변환 적재 ETL`을 사용한다. 제품·버전·수량·연계 URL은 이미지로 확정하지 않는다.

## 1. 핵심 결론

1. **[사실]** IT서비스 및 업무지원 영역은 단말 관리·개발·배포, 배치, CDC 중계, ETL, 출력물의 **9개 노드**로 구성된다.
2. **[해석]** 이 영역은 고객 업무를 직접 수행하기보다 여러 시스템의 개발·운영·배포·데이터 이동·출력을 지원하는 공통 실행면이다.
3. **[사실]** WEB/WAS 노드는 Java/Cloud VM 공통 표준을 사용하지만, 단말개발도구 AP·배치 AP는 목적별 경량 스택을 사용한다.
4. **[사실]** CDC 중계 DB와 ETL은 `Bare Metal` 기반이고, 다른 7개 노드는 `Cloud → VM → OS` 기반이다.
5. **[해석]** CDC·ETL의 전용 기반은 대량 I/O, 솔루션 제약, 예측 가능한 성능을 우선한 결정으로 볼 수 있으나 실제 선정 사유는 확인이 필요하다.
6. **[해석]** 단말 배포, 배치, CDC, ETL은 모두 재실행 시 중복·유실 위험이 있으므로 승인, 멱등성, 체크포인트, 대사, 롤백을 공통 통제로 가져야 한다.

## 2. 9개 노드 전체 구조

```text
│                                                                          │
│  [단말 운영·개발]            [배포·배치]              [데이터·출력]      │
│  ┌──────────────┐           ┌──────────────┐        ┌──────────────┐     │
│  │ 단말관리 WEB │           │ 단말배포 WEB │        │ CDC 중계 DB  │     │
│  │ 단말관리 WAS │           │ 단말배포 WAS │        │ 변환·적재 ETL│     │

│  └──────────────┘           └──────────────┘        └──────────────┘     │
│        Cloud/VM                  Cloud/VM             Bare Metal 2개      │
│                                                     + Cloud/VM 1개       │
└──────────────────────────────────────────────────────────────────────────┘
```

## 4. 공통 계층과 기반 차이

### 4.1 Cloud VM 표준 노드

```text
[업무 서비스 또는 솔루션]
           │
[운영 Agent / JDBC / APM / Framework]
           │
[Web Server 또는 WAS / JVM]
           │
[서버 백신·계정·보안·개인정보·백업·관제·모니터링·운영]
           │
          OS
           │
          VM
           │
         Cloud
```

### 4.2 Bare Metal 전용 노드

```text
CDC 중계 DB                           데이터변환 적재 ETL
┌────────────────────┐               ┌────────────────────┐
│ Oracle GoldenGate  │               │ DataStage          │
│ DBSafer            │               │ eCAMS/배치/JDBC/JVM│
│ DBMS                │               ├────────────────────┤
├────────────────────┤               │ 공통 시스템 통제   │
│ 공통 시스템 통제   │               ├────────────────────┤
├────────────────────┤               │ Linux              │
│ UNIX               │               │ Bare Metal         │
│ Bare Metal         │               └────────────────────┘
└────────────────────┘
```

두 기반의 차이는 용량·패치·장애조치·백업·증설 방식을 달리 만든다. VM 자동화 정책을 Bare Metal에 그대로 적용해서는 안 되며, 반대로 전용 장비 절차로 Cloud VM의 탄력성과 이미지 표준화를 제한해서도 안 된다.

## 5. 단말 관리·개발 컴포넌트

### 5.1 단말관리 WEB

```text
[운영자 브라우저]
       │ HTTPS
       ▼
┌─────────────────────┐
│ Web Service         │
│ eCAMS Agent         │
│ Web Server          │
│ JVM                 │
└──────────┬──────────┘
           ▼
     [단말관리 WAS]
```

- WEB은 사용자 접점, 정적 자원, 리버스 프록시 역할을 담당하고 업무 상태를 직접 소유하지 않는 것이 적절하다.
- 관리자 화면은 대량 선택과 고위험 명령이 많으므로 재인증, 이중 확인, 대상 수 표시, 감사 추적이 필요하다.
- WEB 장애와 WAS 장애를 구분할 수 있도록 각 계층의 상태 검사를 분리한다.

### 5.2 단말관리 WAS

```text
Web 요청
   ▼
[단말 관리 Business]
   ├─ 단말 등록·해지
   ├─ 조직·그룹·정책
   ├─ 버전·접속·상태
   └─ 이력·감사
   │
   ├─ JDBC → [관리 저장소: 이미지 미표시]
   ├─ 배치자동화 → 상태수집/정리
   └─ APM/eCAMS → 관측/운영
```

- **[사실]** 최상단은 `단말 관리`이며 JDBC와 배치자동화 Agent가 있다.
- **[해석]** 단말 식별자와 정책의 기준정보를 소유하고, 단말 상태 수집이나 정기 정리는 배치로 처리한다.
- **[확인 필요]** 단말관리 DB는 이 기술 컴포넌트 이미지에 표시되지 않는다.

### 5.3 단말개발도구 AP

```text
[개발자]
   │ 프로젝트/화면/리소스
   ▼
[단말개발도구]
   │
[WebSquareStudio]
   │
  JVM
   │
OS → VM → Cloud
```

- 온라인 서비스를 제공하는 WAS가 아니라 개발 생산성을 위한 도구 실행 노드이다.
- 소스 저장소, 빌드, 패키지 저장소와의 실제 연계는 이미지에 없으므로 별도 확정이 필요하다.
- 개발 도구가 운영 배포 권한을 직접 보유하지 않도록 개발·승인·배포 역할을 분리해야 한다.

## 6. 단말 배포·배치 컴포넌트

### 6.1 단말배포 WEB/WAS

```text
[배포 운영자]
     │
     ▼
[단말배포 WEB] → [단말배포 WAS]
                       │
             ┌─────────┼──────────┐
             ▼         ▼          ▼
         패키지검증   대상선정   승인/예약
             └─────────┼──────────┘
                       ▼
                [배포 실행/상태]
                       │
                성공 / 실패 / 롤백
```

- 단말관리의 **현재 상태와 정책**을 참조하되, 배포 WAS가 패키지·배포계획·실행이력의 책임을 가진다.
- 전 단말 일괄 배포는 Canary→단계 확대→자동 중단 기준을 적용한다.
- 패키지는 해시·서명·버전·의존성·대상 플랫폼을 검증하고 승인 이후 불변으로 유지한다.

### 6.2 안전한 배포 상태 모델

```text
DRAFT → VALIDATED → APPROVED → SCHEDULED → RUNNING
                                         ├─ SUCCEEDED
                                         ├─ PARTIAL_FAILED → RETRY
                                         └─ FAILED → ROLLBACK
```

- 상태 전이는 명시적이고 되돌릴 수 있어야 한다.
- 중복 클릭·재요청으로 동일 단말에 중복 배포되지 않도록 `deploymentId + deviceId`를 멱등 키로 둔다.
- 작업 완료는 요청 성공이 아니라 대상 단말의 적용 버전 확인까지 포함해야 한다.

### 6.3 배치 AP

```text
[Scheduler/Control Plane]
          │ jobId, parameters
          ▼
 [배치자동화 Agent]
          │
       [배치 AP]
          │ JDBC
          ▼
  [업무 DB / Repository]
          │
          └─ 종료코드·체크포인트·처리건수·대사
```

- 이미지상 배치 AP는 Java Framework/WAS/APM 없이 `배치 AP → 배치자동화 Agent → JDBC Driver → JVM`의 경량 구조다.
- 스케줄 제어와 업무 실행을 분리하고, 작업 파라미터·재시도·의존성·종료코드 계약을 표준화해야 한다.
- 긴 작업은 체크포인트를 저장하며, 재시작 시 성공 구간을 반복하지 않아야 한다.

## 7. CDC 중계 DB

```text
[Source DB Redo/Log]
          │ Capture
          ▼
[Oracle GoldenGate / CDC 중계 DB]
          │ Trail·Checkpoint
          ▼
[Target Consumer / ETL / DB]
          │
          └─ 원천건수·적용건수·지연·오류 대사
```

### 7.1 계층 분석

- `Oracle GoldenGate`: 변경 로그 캡처·전송·적용을 담당하는 솔루션 계층이다.
- `DBSafer`: DB 접근통제·감사 계층으로 해석된다.
- `DBMS`: 중계 데이터, 체크포인트 또는 운영 메타데이터를 관리할 수 있다.
- `UNIX → Bare Metal`: 전용 물리 기반이다.

### 7.2 핵심 통제

- 소스 로그 보존기간이 최대 장애·재처리 시간보다 길어야 한다.
- `source SCN/position`, trail position, target apply position을 함께 관측한다.
- 중복 적용은 멱등 처리하고, 유실 여부는 기간·테이블·키 기준 대사로 검증한다.
- DDL 변경과 컬럼 타입 변경은 CDC 매핑 호환성 검사를 선행한다.

```text
정상: Capture Position ≈ Apply Position
지연: Capture Position ─────────────▶ Apply Position
                                   lag 증가 → 경보 → 병목/용량 분석
```

## 8. 데이터변환 적재 ETL

```text
[Source]
   │ Extract
   ▼
[Stage] → [Validate] → [Transform] → [Load] → [Reconcile]
                DataStage
   │              │                      │
체크포인트      오류격리                Target
```

- **[사실]** 솔루션은 `Data stage`로 표시되고 eCAMS, 배치자동화, JDBC, JVM을 포함한다.
- **[해석]** 추출·변환·적재와 함께 품질검증, 오류 격리, 재처리, 건수·금액 대사를 수행한다.
- `Linux → Bare Metal`이므로 OS 커널, 파일시스템, 디스크 I/O, 솔루션 엔진의 공동 용량관리가 필요하다.
- CDC가 저지연 변경 전달이라면 ETL은 집합 기반 변환·적재에 적합하다. 동일 데이터의 이중 공급 경로가 있다면 우선순위와 대사 기준을 명확히 해야 한다.

### 8.1 ETL 재처리 상태

```text
EXTRACTED → VALIDATED → TRANSFORMED → LOADED → RECONCILED
     │            │            │           │
     └─ 실패구간 격리·체크포인트·재개 ─────┘
```

- 모든 단계에 `runId`, 기준일, 원천 스냅샷, 입력/출력/오류 건수, 규칙 버전을 기록한다.
- 재실행 시 truncate/reload, merge/upsert, append 중 어떤 전략을 쓰는지 작업별로 고정한다.

## 9. 출력물 WAS

```text
[사용자/업무서비스]
        │ reportId + parameter
        ▼
┌────────────────────────┐
│ RD                     │ 보고서 템플릿·렌더링
│ JDBC Driver | APM Agent│ 데이터 조회·관측
│ Java Framework Engine  │ 공통 제어
│ Web Application Server │ 요청·세션·자원 풀
│ JVM                    │ 실행 기반
└───────────┬────────────┘
            ▼
 [PDF/Excel/인쇄/다운로드]
```

- 보고서 템플릿, 데이터 조회, 렌더링, 파일 전달을 담당한다.
- 대용량 보고서는 동기 HTTP 요청보다 비동기 생성→상태 조회→만료형 다운로드가 안전하다.
- 보고서 파라미터는 허용목록·타입·범위를 검증하고 SQL 문자열 조합을 피해야 한다.
- 생성 파일은 암호화, 접근권한, 워터마크, 다운로드 감사, 보존·파기 정책을 적용한다.

## 10. 노드 간 대표 연계 메커니즘

### 10.1 단말 개발·관리·배포

```text
[단말개발도구 AP]
        │ 산출물
        ▼
[빌드/패키지 저장소: 미표시]
        │ 서명된 버전
        ▼
[단말배포 WAS] ◀── 대상·정책 ── [단말관리 WAS]
        │
        ▼
[Canary 단말] → [단계 확대] → [전체 단말]
```

### 10.2 데이터 이동

```text
실시간/준실시간 경로                 배치 변환 경로
[Source Log] → [CDC 중계 DB]         [Source] → [DataStage ETL]
                    │                              │
                    └────────▶ [Target] ◀──────────┘
                                  │
                              [건수/키/금액 대사]
```

### 10.3 데이터와 출력

```text
[CDC/ETL이 준비한 데이터]
              │
              ▼
         [업무/RDW/ADW DB]
              │ JDBC
              ▼
          [출력물 WAS]
              │
              ▼
        [권한 있는 사용자]
```

이미지에는 노드 사이 화살표가 없으므로 위 흐름은 **[해석]**이다. 실제 프로토콜, DB, 저장소, 호출 방향은 인터페이스 명세로 확정해야 한다.

## 11. 공통 운영 컴포넌트

9개 노드 모두 다음 8개 통제 영역을 표시한다.

| 공통 컴포넌트 | 목적 | 주요 적용점 |
|---|---|---|
| 서버 백신 | 악성코드 차단 | 배포 패키지·ETL 임시파일·출력물 검사 |
| 계정 관리 | 계정 수명주기 | 개인/서비스/배치/DB 계정 분리 |
| 서버 보안 | 취약점·접근 통제 | 관리포트 제한, 패치와 예외 승인 |
| 개인정보 | 민감정보 보호 | 로그·APM·ETL 오류·보고서 마스킹 |
| 백업 관리 | 복구 가능성 | DB·설정·패키지·템플릿·체크포인트 복구 |
| 인프라 통합관제 | 중앙 관제 | 노드 간 장애와 지연 상관분석 |
| 서버 모니터링 | 자원 관측 | JVM/WAS뿐 아니라 DB·ETL·CDC 엔진 포함 |
| 서버운영관리 | 구성·변경 관리 | VM과 Bare Metal 절차 분리, 버전 기준선 유지 |

## 12. 보안과 권한 분리

```text
개발자 ─ 산출물 생성
배포자 ─ 배포계획 생성
승인자 ─ 운영 반영 승인
운영자 ─ 실행·장애조치
감사자 ─ 이력 조회

※ 한 계정이 개발→승인→운영배포를 모두 수행하지 않음
```

- 단말 관리·배포는 다수 단말에 영향을 미치므로 고위험 관리자 권한으로 분류한다.
- CDC/ETL 원천 계정은 읽기 최소권한, 타깃 계정은 허용 스키마·작업만 수행하도록 제한한다.
- 출력물 조회 권한은 보고서 기능 권한뿐 아니라 내부 데이터 행·열 권한과 결합해야 한다.
- DBSafer, 애플리케이션 감사, 운영 명령 이력을 공통 추적 ID와 시각으로 연계한다.

## 13. 장애 격리와 복구

```text
[실패 감지]
    │
    ├─ WEB/WAS → 트래픽 전환·재기동
    ├─ 배치/ETL → 체크포인트 재개·오류 격리
    ├─ CDC → 로그 위치 복원·재적용·대사
    ├─ 배포 → 자동 중단·이전 버전 롤백
    └─ RD → 작업 취소·임시파일 정리·재생성
```

- 각 노드의 복구 완료 기준은 프로세스 기동이 아니라 업무 정합성 확인이다.
- CDC는 위치와 데이터 대사, ETL은 처리건수와 기준일 대사, 배포는 실제 단말 버전 확인, RD는 파일 무결성 확인이 필요하다.
- Bare Metal 장애 시 대체 장비·스토리지·솔루션 라이선스·설정 복구 절차를 사전 검증해야 한다.

## 15. 배포·변경관리

- WEB/WAS/배치/RD는 공통 Cloud VM 이미지와 Java 기준선을 재사용하되 애플리케이션은 독립 배포한다.
- WebSquareStudio, GoldenGate, DataStage, RD는 제품 버전·라이선스·지원 OS/JVM 조합을 호환성 매트릭스로 관리한다.
- DB/ETL/CDC 변경은 소스 스키마→매핑→타깃→보고서까지 영향도를 검토한다.
- GoldenGate와 DataStage의 설정은 코드처럼 버전관리하고 민감정보는 분리한다.
- 배포 전 보안 검사, 계약 검사, 복구 리허설을 거치고 배포 후 실제 데이터 대사를 수행한다.

## 17. 이미지 사실 / 해석 / 확인 필요사항

### 직접 확인되는 사실

- 1/3: 단말관리 WEB, 단말관리 WAS, 단말개발도구 AP
- 2/3: 단말배포 WEB, 단말배포 WAS, 배치 AP
- 3/3: CDC 중계 DB, 데이터변환 적재 ETL, 출력물 WAS
- CDC 중계 DB는 Oracle GoldenGate·DBSafer·DBMS·UNIX·Bare Metal 구조이다.
- ETL은 DataStage·eCAMS·배치자동화·JDBC·JVM·Linux·Bare Metal 구조이다.
- 출력물 WAS는 RD·JDBC·APM·Java Framework·WAS·JVM·Cloud VM 구조이다.
- 모든 노드에는 8개 공통 시스템 통제가 표시된다.

### 아키텍처 해석

- 단말 관리와 배포, 온라인과 배치, CDC와 ETL의 책임과 부하를 분리한다.
- Cloud VM은 표준화·탄력성, Bare Metal은 전용 솔루션과 I/O 안정성을 중시한 배치로 볼 수 있다.
- 이 영역은 여러 서비스 시스템이 공통 사용하는 제어·실행 지원면이다.

### 확인 필요사항

- 노드별 인스턴스 수, HA/DR, CPU·메모리·스토리지, 네트워크 Zone
- 단말관리/배포 DB, 패키지 저장소, 배치 Repository와 실제 데이터베이스
- WEB↔WAS, CDC↔ETL↔Target, RD↔DB의 URL·포트·프로토콜·인증
- GoldenGate/DataStage/RD/WebSquareStudio/DBSafer의 버전·라이선스·지원 종료일
- 배포 승인 절차, Canary 비율, 중단 임계치, 롤백 SLA
- CDC·ETL의 정확한 RPO/RTO, 보존기간, 재처리·대사 규칙
- 출력물 형식, 동시사용자, 개인정보 분류, 보존·파기 정책

## 18. 종합 평가

이 구조는 IT서비스 및 업무지원을 **단말 수명주기**, **배포·배치 실행**, **데이터 이동**, **출력**이라는 서로 다른 부하·위험 특성의 노드로 분리한다. Java/Cloud VM 표준을 넓게 재사용하면서 CDC와 ETL은 전용 Bare Metal로 격리한 점이 특징이다. 안정적 운영의 핵심은 단말 배포의 승인·Canary·롤백, 배치/ETL/CDC의 멱등·체크포인트·대사, 출력물의 데이터 권한·보존 통제, 그리고 VM·Bare Metal을 아우르는 통합 관측이다.
