## 1. 한 줄 요약

**정보단말 UI F/W(xFrame)** 은 **xDataSet** 으로 **NHINS Controller**(` /ins/{ServiceId}`)에 요청하고, Controller는 **xDataSet↔Map↔ServiceContext** 브릿지로 **동일 Service(Biz)** 를 호출한다. **NB Spring Controller**(` /nb/{ServiceId}`)는 **JSON↔DTO** 경로로 **같은 Service**에 합류하며, Service 내부에서 **Map→DTO Mapping**·**표준전문(CtoC/EAI)**·**MIDAS** 연계가 수행된다.

## 3. 3-Tier TEXT 표그림

### 3.1 계층 · 구성요소

| Tier | 블록 | 구성 | 역할 |
|---|---|---|---|
| **PT** | **UI F/W (xFrame)** | **xDataSet** | 단말 화면·그리드 데이터셋 |
| **PT** | **WEB** | HTTP 클라이언트 | xFrame → WAS 전송 |
| **BT** | **NHINS Controller** | `/ins/{ServiceId}` | xDataSet ↔ Map · ServiceContext |
| **BT** | **NB Spring Controller** | `/nb/{ServiceId}` | JSON ↔ DTO · 표준전문 |
| **Service** | **Service (Biz Logic)** | Map/DTO 처리 · MIDAS · 표준전문 | 업무 로직 · 연계 |

### 3.2 xDataSet 구조 (장표 JSON 예)

```json
{
  "XDATASETS": {
    "header": {
      "version": "VERSION.1",
      "scrennno": "..."
    },
    "datasets": [
      {
        "id": "...",
        "row_info_arr": [ ... ],
        "column_info_arr": [ ... ],
        "column_name_arr": [ ... ]
      }
    ]
  }
}
```

> **해석**: 단말은 **버전·화면번호(header)** + **다중 dataset(그리드/폼)** 으로 입·출력을 표현한다. Charset **UTF-8** ([캐릭터셋](./캐릭터셋_정의_분석.md)).

### 3.3 Controller 2경로 비교

| 항목 | **NHINS Controller** (단말/xFrame) | **NB Spring Controller** (JSON) |
|---|---|---|
| **URL** | `http://{host}/ins/{ServiceId}` | `http://{host}/nb/{ServiceId}` |
| **Wire 포맷** | **xDataSet** | **JSON** (표준전문) |
| **입력 변환** | xDataSet → **Map** | JSON → **DTO** (UnMarshal) |
| **Context** | Map → **ServiceContext** 저장 | DTO + hdr (ServiceContext) |
| **Service 호출** | Input DTO = **Dummy** (Map이 실데이터) | Input DTO = **실데이터** |
| **출력 변환** | Map → **xDataSet** | DTO → **JSON** (UnMarshal) |
| **선·후** | 시스템 선(거래제어) · 후(Exception) | 동일 |
| **PDMG 대응** | **Gap** (xDataSet 미지원) | `OnlineTransactionController`에 **근접** |

### 3.4 NHINS 경로 10단계 (장표)

| Step | 처리 | 계층 | 상세 |
|---:|---|---|---|
| **①** | xDataSet 전달 | PT→BT | xFrame → Nhins Controller |
| **②** | 서비스 ID 인식 | BT | URL `/ins/{ServiceId}` 패턴 |
| **③** | 입력전문 변환 | BT | **xDataSet → Map** |
| **④** | Context 저장 | BT | 변환 Map → **ServiceContext** |
| **⑤** | 서비스 호출 | BT→Svc | Input DTO는 **Dummy** · Map이 실입력 |
| **⑥** | Map 조회 | Svc | ServiceContext에서 **Map 가져오기** |
| **⑦** | DTO Mapping | Svc | Map **컬럼별** → DTO 필드 생성 |
| **⑧** | Map Return | Svc→BT | 처리 결과 **Map** 반환 |
| **⑨** | 출력 변환 | BT | **Map → xDataSet** |
| **⑩** | 응답 Return | BT→PT | xDataSet → xFrame |

**Service 내부 부가 처리** (장표):

| 처리 | 조건 |
|---|---|
| **표준전문 생성** | CtoC 통신 · **EAI 연계** 필요 시 |
| **MIDAS 연계** | MIDAS Library 호출 |

## 4. 아키텍처 설계 포인트

### 4.1 Map 브릿지 패턴 (NHINS)

단말 xDataSet은 **컬럼·행 배열** 구조이므로, Controller가 **Map** 으로 정규화해 **ServiceContext**에 적재한다. Service 호출 시 Spring 시그니처는 **Dummy DTO**로 통과하고, **실데이터는 Map**에서 ⑥⑦ 단계로 DTO에 매핑한다.

**의도**: xFrame UI 모델과 Java DTO 모델을 **ServiceContext Map**으로 느슨하게 결합.

### 4.2 이중 Controller · 단일 Service

| 원칙 | 내용 |
|---|---|
| **진입 분리** | 단말(xDataSet) vs JSON(**표준전문**) — **Controller 2종** |
| **업무 통합** | **Service(Biz)** 는 **단일** — Map/DTO 양쪽 수용 |
| **FWK 공통** | 시스템 선(거래제어)·후(Exception) — **FWK LIB** 공유 ([온라인_프레임워크_구성](./온라인_프레임워크_구성_분석.md) C08) |

### 4.3 표준전문 · GUID · Charset 연계

| 표준 | 본 장표 적용 |
|---|---|
| [전문_표준화](./전문_표준화_분석.md) | NB 경로 = json/http 표준전문 · NHINS = xDataSet(**단말 전용**) |
| [GUID_관리](./GUID_관리_체계_분석.md) | 채널(단말) 최초 GUID — WebTopSuit/xFrame |
| [캐릭터셋](./캐릭터셋_정의_분석.md) | 채널·xFrame **UTF-8** |

## 5. PDMG/TCF · Runtime 매핑

> 이 절은 장표의 목표/참조 구조를 현재 저장소 소스와 대조한 결과다. 따라서 `/ins`, `/nb`, xDataSet, MIDAS는 **장표에서 확인된 요소**이며, 아래 표에서 `—`로 표시한 항목은 현재 PDMG 구현에서 확인되지 않은 Gap이다.

| 장표 | PDMG/TCF (AS-IS) | Gap |
|---|---|---|
| **NB Spring Controller** | `OnlineTransactionController` · `POST /{serviceId}` · JSON `hdr_nhnis`+`dto` | URL prefix `/nb` vs PDMG flat path |
| **NHINS Controller** | — | **xDataSet · /ins · Map 브릿지 미구현** |
| **ServiceContext Map** | `ServiceContext` · `ServiceContextHolder` · `hdr_nhnis` | Map 저장 vs Header+DTO 분리 |
| **③④ xDataSet→Map** | — | xFrame 전용 변환기 |
| **⑤ Dummy DTO** | `RequestBodyArgumentResolver` — **실 dto** 전달 | 호출 계약 **상이** |
| **⑥⑦ Map→DTO** | Handler가 **dto** 직접 수신 | Map column mapping **없음** |
| **시스템 선·후** | `DefaultFilter` · Interceptor · stf/etf | 동일 개념 |
| **MIDAS** | — | NH Cloud Library |
| **표준전문 CtoC/EAI** | CruzAPIM Adapter | Service outbound |

### 5.1 소스 검증 근거

| 확인 사항 | 현재 구현 근거 | 판정 |
|---|---|---|
| HTTP 진입점 | `OnlineTransactionController.java:51-115` — `/online`, `/{businessCode}/online`, `/{serviceId}`를 받고 JSON의 `dto`를 `TcfFacade`로 전달 | **확인** |
| Service ID 결정 | `OnlineTransactionController.java:121-154` — `ServiceContext Header → 요청 JSON → path` 순으로 결정 | **확인** |
| 요청 Context 생성 | `DefaultFilter.java:98-225` — JSON을 파싱해 `hdr_nhnis`와 GUID를 추출하고 `ServiceContext` 생성 | **확인** |
| Context 데이터 구조 | `ServiceContext.java:13-27` — Header, HTTP 요청/응답, `userContext`, 요청/응답 원문 보유 | **확인** |
| JSON → DTO | `RequestBodyArgumentResolver.java:62-73` — JSON의 `dto` 노드를 대상 DTO 타입으로 역직렬화 | **확인** |
| 공통 선·후처리 | `TcfFacade.java:76-120` — `stf.preProcess → Dispatcher → etf.postProcess` 실행 | **확인** |
| 업무 분기 | `mgcoa5530Handler.java:29-40` — `serviceId`에 따라 업무 Facade 호출 | **확인** |
| DTO → JSON 응답 | `ResponseBodyArgumentResolver.java:124-167` — `hdr_nhnis`와 업무 결과 `dto`를 응답 JSON으로 조립 | **확인** |
| `/ins/{serviceId}`·xDataSet 변환 | 현재 Java/설정 소스 검색 결과 대응 Controller·변환기 없음 | **미구현 Gap** |
| `/nb/{serviceId}` prefix | 현재 Controller는 `/nb` prefix 없이 `/online` 또는 `/{serviceId}` 사용 | **계약 차이** |

> 위 `파일:라인`은 분석 시점(2026-08-22)의 저장소 기준이다. 장표에 나타난 제품 구조와 현재 PDMG 구현을 혼동하지 않기 위한 검증 좌표이며, 소스 변경 시 다시 확인해야 한다.

```text
[PDMG Baseline — NB 경로에 해당]

pdmg-ui (JSON)
  → DefaultFilter → ServiceContext (hdr_nhnis)
  → OnlineTransactionController  ← NB Spring Controller 개념
  → TcfFacade → Handler → Facade → Service (*DTOin 실데이터)
  → JSON 응답

[NHINS/xFrame — 장표 TO-BE / Gap]

xFrame (xDataSet)
  → NhinsController /ins/{serviceId}
  → xDataSet→Map→ServiceContext
  → Service (Dummy DTO + Map from Context)
  → Map→xDataSet → xFrame
```
