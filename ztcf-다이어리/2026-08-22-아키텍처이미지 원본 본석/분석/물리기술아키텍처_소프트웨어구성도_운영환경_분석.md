# 물리기술아키텍처 — 소프트웨어 구성도 — 운영환경 분석

> 원본 범위: `3. 물리 기술 아키텍처 > 3.2 소프트웨어 구성도`  
> 원본 페이지/이미지: 74쪽, `85737/29.png`  
> 분석 원칙: 장표에 보이는 노드·소프트웨어·OS를 우선 기록한다. `@`가 붙은 명칭은 원문을 유지하며 제품명·버전을 임의 확정하지 않는다.

## 1. 핵심 결론

운영환경 소프트웨어는 업무 애플리케이션 위에 WEB/WAS·배치·ETL·CDC·DB 접근통제·관제 도구를 계층화하고, 대다수 업무 서버를 `Linux (RHEL9)`로 표준화한 구조다.

- 마케팅·BI·신용실적·Self-BI·거버넌스·단말 노드는 업무별 WEB/WAS 또는 AP 스택을 사용한다.
- 배치는 `Spring Batch + Petra Cipher + DBMS Client(Oracle) + Control-M` 조합이다.
- ETL은 `Data Stage + DBMS Client + Control-M` 조합이다.
- CDC중계 DB는 `OGG + DB Safer + DBMS`이며 UNIX 기반이다.
- ADW/RDW Appliance는 `DB Safer + DBMS`, RDW에는 OGG가 추가된다.
- 이행용 변환·이행·SQL품질·추출 노드는 `[임시]`로 별도 구성된다.
- 모든 노드의 `Default S/W`는 시스템 S/W, 서버보안, 백업, OS백업 책임을 포괄하지만 실제 제품은 장표에서 확정되지 않는다.

```text
업무 Application
 ├─ WEB/WAS/AP
 ├─ 전용 Solution/Engine
 ├─ Scheduler·DB Client·Agent
 ├─ Default S/W
 └─ OS: Linux(RHEL9) / Linux / UNIX
            │
            ▼
 DB/Appliance: OGG · DB Safer · DBMS
```

## 2. 근거 수준

| 수준 | 내용 |
|---|---|
| 확인 사실 | 운영 소프트웨어 구성도에 32개 노드 유형이 표시됨 |
| 확인 사실 | 노드별 수량, 업무 S/W, Default S/W, OS가 표시됨 |
| 확인 사실 | Linux(RHEL9), Linux, UNIX가 노드 유형에 따라 구분됨 |
| 확인 사실 | 배치, ETL, OGG, DB Safer, Control-M 등 전용 S/W가 표시됨 |
| 확인 사실 | 임시 데이터이행 노드 4종이 표시됨 |
| 설계 해석 | Default S/W는 범례상 시스템 S/W·서버보안·백업·OS백업의 공통 운영 에이전트 묶음 |
| 설계 해석 | WEB/WAS 다중 노드와 DB Appliance는 업무 확장·가용성 경계 |
| 미확정 | Default S/W에 포함되는 정확한 제품·버전·설정 |
| 미확정 | `@` 접미 명칭의 정확한 솔루션명과 제조사 |
| 미확정 | WEB/WAS 제품과 JVM 버전, Linux/UNIX 세부 배포판 |
| 미확정 | `Data Stage`가 IBM DataStage를 뜻하는지 여부와 버전 |

## 3. 전체 소프트웨어 지형

```text
┌─ 마케팅 ───────────────────────────────────────────┐
│ 마케팅/미니싱글뷰 WEB·WAS + 실시간·행동정보 AP     │
├─ 분석 ─────────────────────────────────────────────┤
│ BI포탈·신용실적·Self-BI WEB·WAS·AP                 │
├─ 거버넌스/단말 ────────────────────────────────────┤
│ DQMiner·흐름관리·WebTop·EdgeSquare                 │
├─ 운영지원 ─────────────────────────────────────────┤
│ Spring Batch·Control-M·Petra Cipher·Report Design  │
├─ 데이터 처리/이행 ─────────────────────────────────┤
│ Data Stage·OGG·Open POP·DBMS Client                │
├─ 데이터베이스 ─────────────────────────────────────┤
│ ADW/RDW Appliance·DB Safer·DBMS                    │
└─ 공통 기반 ────────────────────────────────────────┘
  Default S/W + Linux(RHEL9)/Linux/UNIX
```

### 3.1 전체 소프트웨어 세로형 구성도

아래 구성도는 각 노드에서 소프트웨어가 **업무 기능 → 실행 소프트웨어 → 연계·운영 도구 → 공통 소프트웨어 → OS** 순서로 적재되는 구조를 세로로 표현한다.

```text
┌──────────────────────────────────────┐
│             업무 애플리케이션        │
│ 마케팅 / BI / 신용실적 / Self-BI     │
│ 비즈메타 / 데이터품질 / 데이터흐름   │
├──────────────────────────────────────┤
│             실행 소프트웨어          │
│ WEB / WAS / AP / Spring Batch        │
│ Report Design / Data Stage / DBMS    │
├──────────────────────────────────────┤
│             연계·제어 도구           │
│ DBMS Client / OGG / Control-M        │
│ WebTop / EdgeSquare / DB Safer       │
├──────────────────────────────────────┤
│              Default S/W             │
│ 시스템 S/W / 서버보안 / 백업 / OS백업│
├──────────────────────────────────────┤
│                    OS                │
│       Linux(RHEL9) / Linux / UNIX    │
└──────────────────────────────────────┘
```

| 행동정보처리 AP | #1,#2 | 데이터관리@Master, 행동정보데이터@, WEB, WAS, Default S/W | Linux(RHEL9) |
| 고객행동데이터 AP | #1~#3 | 실시간 감지엔진, 행동정보엔진, Default S/W | Linux(RHEL9) |

```text

        ┌──────────────────┼─────────────────┐
        ▼                  ▼                 ▼
[실시간처리@] [데이터관리@Master/행동정보데이터@] [감지·행동 엔진]
```

AP에 WEB/WAS가 함께 표시된 경우 독립 제품 계층인지 내장 런타임인지 상세 설치설계로 확인해야 한다.

|---|---:|---|---|
| BI포탈 WEB | #1,#2 | BI포탈, WEB, Default S/W | Linux(RHEL9) |
| BI포탈 WAS | #1,#2 | BI포탈, BI, WAS, Default S/W | Linux(RHEL9) |
| 신용실적 WEB | #1,#2 | 신용실적, WEB, Default S/W | Linux(RHEL9) |
| 신용실적 WAS | #1,#2 | 신용실적, WAS, Default S/W | Linux(RHEL9) |
| Self-BI WEB | #1,#2 | Self-BI, WEB, Default S/W | Linux(RHEL9) |
| Self-BI WAS | #1,#2 | Self-BI, WAS, Default S/W | Linux(RHEL9) |

```text
[BI포탈 WEB] ─ [BI포탈/BI/WAS] ─┐

[Self-BI WEB] ─ [Self-BI WAS] ───┤
```

Self-BI AP는 단일 노드로 표시되므로 제품 자체 HA, 재기동, 작업 상태 복구를 확인해야 한다.

|---|---:|---|---|
| 비즈메타/데이터품질 WAS | #1,#2 | DQMiner, 비즈메타, WAS, Default S/W | Linux(RHEL9) |
| 데이터흐름관리 WAS | #1 | 흐름관리, WAS, Default S/W | Linux(RHEL9) |

```text
[DQMiner] + [비즈메타] + [WAS]
          │ 메타·품질 연계
          ▼
     [흐름관리] + [WAS]
          │
```

이미지 해상도와 기존 전사본에는 `DOMiner`/`DQMiner` 표기 차이가 존재한다. 데이터품질 솔루션의 정확한 제품명은 설치 인벤토리에서 확인해야 한다.

## 8. 배치와 마스터솔루션

### 배치 AP

```text
[Control-M]
     │ Schedule
     ▼
[Spring Batch] ─ [Petra Cipher]
     │
[DBMS Client(Oracle)] → DB
     │
[Default S/W] → Linux(RHEL9)
```

| 구성 | 역할 |
|---|---|
| Spring Batch | Job/Step 기반 배치 실행 |
| Control-M | 일정·의존관계·실행 제어 |
| Petra Cipher | 암호화/보안 계열로 해석, 정확한 적용 범위 미확정 |
| DBMS Client(Oracle) | DB 접속 클라이언트 |

### 마스터솔루션

```text
[프레임워크]
    ↓
[WEB] + [WAS]
    ↓
[Default S/W] + Linux(RHEL9)
```

마스터솔루션 #1은 테크시스템부 영역으로 점선 분리되어 제어면 성격을 가진다.

```text
                    │
              [DBMS Client]
             Source → Transform → Target
```

스케줄러는 실행을 제어하고 ETL 도구는 데이터 변환을 수행하므로 책임을 혼동하면 안 된다.

---

## 10. CDC와 DB Appliance

| 노드 | 번호 | 주요 S/W | OS |
|---|---:|---|---|
| CDC중계 DB | #1,#2 | OGG, DB Safer, DBMS, Default S/W | UNIX |
| ADW Appliance | #1~#6 | DB Safer, DBMS, Default S/W | Linux |
| RDW Appliance | #1,#2 | OGG, DB Safer, DBMS, Default S/W | Linux |

```text
[Source DB]
    │ OGG Capture/Trail
    ▼
[CDC중계 DB: OGG + DB Safer + DBMS / UNIX]
    │ OGG
    ▼
[RDW: OGG + DB Safer + DBMS / Linux]
    │ ETL
    ▼
[ADW: DB Safer + DBMS / Linux]
```

OGG가 CDC중계 DB와 RDW에 모두 설치되지만 Capture·Pump·Replicat의 실제 배치는 장표에서 확정할 수 없다. DB Safer는 DB 접근통제로 해석하되 제품 정책과 우회 차단 범위는 확인해야 한다.

---

## 11. 임시 데이터이행 스택

| 노드 | 번호 | 주요 S/W | OS |
|---|---:|---|---|
| [임시] 데이터이행(변환) AP | #1~#6 | 데이터 변환, DBMS Client, Default S/W | Linux(RHEL9) |
| [임시] 데이터이행 AP | #01 | 데이터이행@, DBMS Client, Default S/W | Linux(RHEL9) |
| [임시] SQL품질 AP | #01 | Open POP, DBMS Client, WAS, Default S/W | Linux(RHEL9) |
| [임시] 데이터이행 추출 DB | #01 | 데이터추출@, DBMS Client, Default S/W | UNIX |

```text
[추출 DB: 데이터추출@]
          │
[변환 AP ×6: 데이터 변환]
          │
[SQL품질 AP: Open POP + WAS]
          │
[이행 AP: 데이터이행@] → 목표 DB
```

임시 서버는 이행 완료 후 존치·축소·폐기 결정을 하고, 계정·데이터·로그·백업을 함께 정리해야 한다.

## 12. UNO Dashboard와 관측

```text
[각 노드 Metric/Log/Event]
            │
            ▼
     [UNO Dashboard #1]
            │
      운영자 조회/경보
```

UNO Dashboard는 단일 노드이며 업무 처리면과 분리된 관측면이다. Dashboard 장애가 업무 장애로 오인되지 않도록 원천 모니터링 데이터와 알림 경로를 별도로 유지해야 한다.

## 13. Default S/W 해석

장표 범례는 Default S/W의 범주를 다음과 같이 제시한다.

```text
Default S/W
 ├─ 시스템 S/W
 ├─ 서버보안@
 ├─ 백업@
 └─ OS백업@
```

| 통제영역 | 최소 관리항목 |
|---|---|
| 시스템 S/W | 패키지·에이전트·시간동기화·로그 |
| 서버보안 | 백신/EDR, 접근통제, 무결성, 취약점 |
| 백업 | 파일·DB·설정 백업, 보존, 복구시험 |
| OS백업 | 이미지/Bare Metal 복구, 설정 복원 |

`@` 접미는 장표 표기이며 특정 제품 또는 법적 인증을 뜻한다고 단정하지 않는다.

## 14. 표준 소프트웨어 계층

```text
L1 업무       : BI포탈, Self-BI, 비즈메타, EBM, 흐름관리...
L2 실행       : WEB, WAS, Spring Batch, Data Stage, Report Design
L3 연계       : DBMS Client, OGG, Control-M
L4 보안/관제  : DB Safer, Petra Cipher, Default S/W, UNO
L5 데이터     : DBMS
L6 OS         : Linux(RHEL9), Linux, UNIX
```

### 의존성 원칙

```text
업무 S/W → 표준 Runtime → 공통 Agent → OS
       ↘ DB/API/File Client ↘ 외부 시스템

상위 계층은 하위 표준에 의존하되
공통 Agent가 업무 로직을 소유하지 않는다.
```

---

## 15. 패치·버전·형상관리

```text
제품목록(SBOM) → 취약점 식별 → 영향분석 → 개발/검증
 → Change 승인 → Rolling/계획 배포 → Smoke Test → 증적
```

- 노드별 업무 S/W, 런타임, Agent, OS의 버전을 CMDB에 연결한다.
- 2노드 이상은 한 노드씩 패치하고 서비스 상태를 확인한다.
- UNIX와 Linux의 패치 절차·지원 종료일을 분리 관리한다.
- 임시 이행 서버도 운영 데이터에 접근하므로 동일한 보안 기준을 적용한다.

---

## 16. 보안·계정·비밀정보

```text
사용자/서비스 → 인증 → 서버/DB 접근통제 → 업무 S/W
                       │
                  DB Safer/감사
                       │
                 비밀정보 Vault
```

- OS, WAS, DB, Control-M, OGG, ETL 계정을 목적별로 분리한다.
- DBMS Client 설정 파일에 평문 비밀번호를 두지 않는다.
- 배치 암호화 키와 애플리케이션 비밀정보를 Artifact에서 분리한다.
- 임시 이행 계정은 종료일과 자동 폐기 정책을 가진다.

---

## 17. 가용성과 복구

```text
다중 노드 업무: LB 우회 → 노드 복구 → 재편입
단일 노드 업무: 감지 → 재기동/재배포 → 상태 복구
DB/CDC: 복제·백업 → 일관성 확인 → 서비스 재개
Batch/ETL: Checkpoint → 멱등 재실행 → 결과 대사
```

소프트웨어 HA는 서버 수만으로 보장되지 않는다. 세션, 파일, Queue, Job Repository, OGG Trail, ETL Checkpoint가 복구 가능해야 한다.

## 20. 최종 평가

운영 소프트웨어 구성은 Linux(RHEL9)를 중심으로 업무 WEB/WAS/AP를 표준화하면서, 배치·ETL·CDC·DB·단말에 각 전용 솔루션을 조합한 계층형 구조다. 특히 Control-M, OGG, DB Safer, Default S/W는 여러 업무를 가로지르는 운영 제어면이므로 장애·패치의 영향도가 크다.

완성도는 제품 설치 여부가 아니라 버전 표준, 계정·비밀 분리, Rolling Patch, 작업 Checkpoint, 복제 Lag, 백업 Restore, 임시 서버 폐기를 일관되게 운영하는 데 달려 있다. 장표의 불명확한 제품명과 `@` 표기는 설치 인벤토리와 라이선스 자료로 확정해야 한다.
