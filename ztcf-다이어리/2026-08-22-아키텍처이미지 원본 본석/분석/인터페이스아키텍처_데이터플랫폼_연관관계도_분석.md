# 인터페이스 아키텍처 — 데이터플랫폼 연관관계도 분석

## 1. 핵심 결론

이 장표는 **데이터플랫폼을 RDW(RD)와 ADW(AD) 두 축으로 분리하고, 각 축 내부의 업무/데이터 영역을 모듈 단위로 구조화한 연관관계도**다.

즉 이 그림의 핵심은 외부 시스템 간 연결선보다, **데이터플랫폼 내부의 책임 분리와 저장·가공·활용 영역의 계층적 구분**에 있다.

가장 중요한 구조적 메시지는 다음과 같다.

| 구분 | 핵심 의미 | 아키텍처 판단 |
|---|---|---|
| RDW | 실시간·준실시간 활용 중심 데이터플랫폼 | **운영 활용/근실시간 대응 영역** |
| ADW | 분석·통합·마트·지원 중심 데이터플랫폼 | **분석/심화 활용 영역** |
| 공통 CO | RDW/ADW 공통 기능 | **플랫폼 공통 서비스/기반 영역** |
| 피드백 FA | RDW/ADW 모두에 존재 | **양방향 데이터 피드백 또는 결과 환류 구조** |
| ZD / RM / UM / DA | 집계/보고서/업무마트/분석지원 세분화 | **활용 목적별 데이터 구조 분리** |

즉 이 장표는 데이터플랫폼을 다음처럼 정의한다.

```text
데이터플랫폼
 ├─ RDW (실시간/준실시간 활용 중심)
 │   ├─ 공통 CO
 │   ├─ 실시간 SoR SR
 │   ├─ 준실시간 요약집계 ZD
 │   ├─ 준실시간 보고서 마트 RM
 │   └─ 피드백 FA
 │
 └─ ADW (분석/심화 활용 중심)
     ├─ 공통 CO
     ├─ 분석 SoR SR
     ├─ 분석통합요약집계 ZD
     ├─ 분석단위업무마트 UM
     ├─ 분석보고서마트 RM
     ├─ 피드백 FA
     └─ 분석지원 DA
```

이 구조는 **“운영 활용 중심 RDW”와 “분석 활용 중심 ADW”를 명확히 분리하면서도, 공통·피드백 기능을 통해 상호 연계 가능한 데이터플랫폼 구조”**를 나타낸다.

## 2. 장표 구성요소 전사

## 2.1 상단 메타 정보

- 좌측 상단 제목: **데이터플랫폼**
- 중앙 메인 제목: **데이터플랫폼 인터페이스 구성도**
- 우측 상단 말풍선: **업무팀 분석단위 구체화**
- 우측 상단 메모: **확인 필요**
- 우측 상단 버튼성 표기: **닫기**

### 해석

- `업무팀 분석단위 구체화`는 ADW의 분석단위업무마트(UM) 등 세부 분석영역이 **아직 더 구체화될 수 있음**을 시사한다.
- `확인 필요` 표시는 이 장표의 일부 세부 항목이 **최종 확정 전 검토 또는 상세화가 필요함**을 의미한다.

---

## 2.2 중앙 데이터플랫폼 영역

장표 중앙에는 하나의 큰 외곽 박스 안에 상단 RDW, 하단 ADW 두 영역이 배치되어 있다.

### 상단 영역

- **데이터 플랫폼 RDW RD**

RDW 우측 세부 구성요소:

- 공통 **CO**
- 실시간SoR **SR**
- 준실시간요약집계 **ZD**
- 준실시간보고서마트 **RM**
- 피드백 **FA**

### 하단 영역

- **데이터 플랫폼 ADW AD**

ADW 우측 세부 구성요소:

- 공통 **CO**
- 분석SoR **SR**
- 분석통합요약집계 **ZD**
- 분석단위업무마트 **UM**
- 분석보고서마트 **RM**
- 피드백 **FA**
- 분석지원 **DA**

### RDW 세부 해석

| 모듈 | 의미 해석 |
|---|---|
| 공통 CO | RDW 공통 기능/기반 |
| 실시간SoR SR | 실시간 Source of Record 영역 |

- RDW는 **운영 활용 및 준실시간 데이터 활용 중심 구조**다.
- `실시간SoR`가 존재하므로 단순 집계창고가 아니라 **기준 데이터 보유 영역**의 성격을 가진다.
- `준실시간요약집계`, `준실시간보고서마트`가 분리되어 있으므로 **집계와 활용 구조를 분리**하고 있다.
- `피드백 FA`는 마케팅/BI/분석 결과 또는 운영결과를 다시 반영하는 피드백 지점일 가능성이 높다.

- ADW는 **분석/경영판단/주제별 활용 중심 구조**다.
- RDW보다 더 세분화된 모듈 구성을 가지며, 특히 `UM`, `DA`가 추가되어 있다.
- `분석단위업무마트 UM`은 업무팀별/주제별 세분화 가능성을 내포한다.
- `분석지원 DA`는 데이터 분석 지원, 모델 지원, 분석활동 지원용 영역일 가능성이 높다.

## 4.4 RDW와 ADW 비교 텍스트 그림

```text
┌───────────────────────────────── RDW vs ADW 비교 ─────────────────────────────────┐
│                                                                                   │
│   RDW (RD)                                                ADW (AD)                │
│   ─────────                                                ─────────                │
│   공통 CO                                                  공통 CO                 │
│   실시간SoR SR                                             분석SoR SR              │
│   준실시간요약집계 ZD                                      분석통합요약집계 ZD     │
│   준실시간보고서마트 RM                                    분석단위업무마트 UM     │
│   피드백 FA                                                분석보고서마트 RM       │
│                                                            피드백 FA               │
│                                                            분석지원 DA             │
│                                                                                   │
│   초점: 실시간/준실시간 활용                               초점: 분석/심화 활용    │
│   성격: 운영지원/근실시간                                  성격: 분석지원/보고/마트│
│                                                                                   │
└───────────────────────────────────────────────────────────────────────────────────┘
```

### 비교 해석

- RDW는 **실시간성/준실시간성**에 무게가 있다.
- ADW는 **분석/업무마트/보고서/지원기능**에 무게가 있다.
- 두 구조 모두 `공통 CO`와 `피드백 FA`를 갖고 있어 **공통기능과 환류구조를 공유**한다.
- RDW에는 `UM`, `DA`가 없고 ADW에만 있어, **ADW가 더 분석지향적**이다.

## 4.5 상위 개념 흐름 텍스트 그림

```text
                데이터플랫폼
                     │
         ┌───────────┴───────────┐
         │                       │
         ▼                       ▼
      RDW(RD)                 ADW(AD)
         │                       │
         │                       │
   실시간SoR 중심             분석SoR 중심
   준실시간 요약집계          분석통합요약집계
   준실시간 보고서 마트       분석단위업무마트
   피드백                     분석보고서마트
                              피드백
                              분석지원
```

이 장표는 구체적 입·출력 시스템을 보여주지 않지만, 구조상 다음처럼 해석할 수 있다.

```text
원천 데이터 / 운영 데이터
        ↓
      RDW
        ↓
(필요 시 요약·피드백·근실시간 활용)
        ↓
      ADW
        ↓
분석 / 업무마트 / 보고 / 분석지원
```

> 주의: 위 흐름은 장표의 구조적 해석이며, 원본 그림에 RDW→ADW 화살표가 직접 보이는 것은 아니다. 따라서 이는 **ANALYSIS** 수준으로 다뤄야 한다.

## 5. 인터페이스 관점 상세 분석

## 5.1 이 장표에서의 “인터페이스” 의미

일반적인 인터페이스 구성도는 외부 시스템 간 연결선을 강조하지만, 이 장표는 다르다.

이 그림에서 인터페이스는 다음 두 층위로 이해하는 것이 적절하다.

1. **플랫폼 수준 인터페이스**  
   - RDW와 ADW라는 두 플랫폼 축의 구분

2. **내부 데이터 영역 인터페이스**  
   - CO, SR, ZD, RM, UM, FA, DA 등 내부 모듈 간 책임 분리

즉 이 장표는 **“외부 연계 흐름도”보다 “데이터플랫폼 내부 논리 인터페이스 구조도”**에 가깝다.

---

## 5.2 RDW 인터페이스 관점

RDW는 다음처럼 해석할 수 있다.

| 인터페이스 레벨 | 해석 |
|---|---|
| 실시간 SoR SR | 실시간 기준 데이터 인터페이스 |
| 준실시간요약집계 ZD | 집계 가공 인터페이스 |
| 준실시간보고서마트 RM | 리포팅 제공 인터페이스 |
| 피드백 FA | 결과 환류 인터페이스 |
| 공통 CO | 공통 운영/관리 인터페이스 |

즉 RDW 내부에서 이미 **기준데이터, 집계데이터, 보고데이터, 피드백데이터가 구분**되어 있다.

---

## 5.3 ADW 인터페이스 관점

ADW는 RDW보다 더 확장된 구조를 가진다.

| 인터페이스 레벨 | 해석 |
|---|---|
| 분석 SoR SR | 분석 기준 데이터 인터페이스 |
| 분석통합요약집계 ZD | 통합분석용 집계 인터페이스 |
| 분석단위업무마트 UM | 주제/업무단위 데이터마트 인터페이스 |
| 분석보고서마트 RM | 분석·경영 리포트 제공 인터페이스 |
| 피드백 FA | 분석결과 환류 인터페이스 |
| 분석지원 DA | 분석활동 지원 인터페이스 |
| 공통 CO | 공통 운영/관리 인터페이스 |

ADW는 단순 저장창고가 아니라 **분석 서비스를 제공하는 플랫폼**으로 보는 것이 맞다.

---

## 5.4 공통(CO)과 피드백(FA)의 공통성

장표에서 특히 중요한 점은 RDW와 ADW에 모두 다음 두 모듈이 있다는 점이다.

- 공통 CO
- 피드백 FA

### 구조적 의미

```text
RDW ── 공통 CO / 피드백 FA
ADW ── 공통 CO / 피드백 FA
```

이는 다음을 의미할 수 있다.

1. 플랫폼마다 독립 공통기능을 가진다.
2. 피드백 메커니즘이 RDW/ADW 양쪽 모두 필요하다.
3. 데이터플랫폼이 단순 적재형이 아니라 **결과 환류를 내장한 구조**다.

---

## 5.5 업무팀 분석단위 구체화의 의미

우측 상단의 `업무팀 분석단위 구체화`는 매우 중요한 메모다.

이는 특히 ADW의 아래 항목과 연관성이 높다.

- 분석단위업무마트 UM
- 분석보고서마트 RM
- 분석지원 DA

### 해석

- 업무팀별 분석요구가 더 구체화되면 ADW 내부 마트 구조가 세분화될 수 있다.
- 현재 장표는 **상위 수준의 구조만 확정**하고, 세부 분석단위는 추후 정의할 가능성이 높다.
- 따라서 이 장표는 **완성형 상세모델이 아니라 상위 구조 정의서**에 가깝다.

## 11. 성능 및 용량 관점

장표를 성능 관점에서 해석하면 다음과 같다.

### RDW

- 실시간SoR은 **저지연 적재/조회** 요구 가능성이 높다.

- 준실시간보고서마트는 **조회응답과 적시성**이 중요하다.

- 분석지원은 **분석 생산성 지원 성능**이 중요하다.

즉 이 장표는 성능적으로도 다음을 시사한다.

```text
RDW = 빠르고 자주 갱신되는 활용 데이터
ADW = 무겁고 다양하게 소비되는 분석 데이터
```

## 15. 장표 해석 시 유의사항

이 장표는 외부 시스템과의 인터페이스보다는 **데이터플랫폼 내부 논리영역 분해도**에 가깝다.

특히 다음은 추가 상세설계 확인이 필요하다.

- RDW와 ADW 사이 직접 데이터 이동 관계
- FA(피드백)의 실제 입력/출력 대상
- CO(공통)에 포함되는 기능 범위
- ADW 업무단위업무마트 UM의 세부 분류체계
- 분석지원 DA의 실제 역할(도구 지원인지, 데이터 지원인지)
- RM이 어떤 보고서/사용자 그룹을 대상으로 하는지

또한 `업무팀 분석단위 구체화`, `확인 필요` 표기가 있기 때문에, 현재 장표는 **상위 기준선 또는 논리 설계 초안**으로 해석하는 것이 적절하다.

## 16. 최종 평가

이 장표는 데이터플랫폼을 다음 두 축으로 구조화한다.

```text
RDW = 실시간/준실시간 활용 데이터 플랫폼
ADW = 분석/업무마트/보고/지원 데이터 플랫폼
```

그리고 각 축 내부를 다시 `SoR → 집계 → 마트 → 피드백` 중심으로 분해함으로써, 데이터플랫폼이 단순 저장소가 아니라 **활용 목적에 따라 구조화된 서비스형 데이터 플랫폼**이라는 점을 보여준다.

가장 중요한 아키텍처 포인트는 다음과 같다.

1. **RDW와 ADW를 명확히 분리했다.**  
2. **실시간 활용과 분석 활용의 목적 차이를 구조에 반영했다.**  
3. **공통 CO와 피드백 FA를 양쪽에 두어 환류형 구조를 암시했다.**  
4. **ADW는 분석마트·보고서마트·분석지원까지 포함하는 확장형 구조다.**  
5. **업무팀 분석단위는 후속 상세설계에서 구체화되어야 한다.**

따라서 후속 설계 단계에서는 반드시 다음이 필요하다.

- RDW/ADW 역할정의서 작성
- SoR / ZD / RM / UM / DA / FA 용어 정의
- 업무팀별 분석단위 마트 설계 기준 수립
- 피드백 데이터 흐름 정의
- 데이터 계보/정합성/재처리/권한통제 기준 수립

결론적으로 이 장표는 **데이터플랫폼의 내부 구조와 활용 목적 분리 원칙을 설명하는 상위 연관관계도**로 매우 유용하며, 이후 RDW/ADW 상세 설계, 데이터 계보 설계, 분석 마트 설계의 기준점이 된다.
