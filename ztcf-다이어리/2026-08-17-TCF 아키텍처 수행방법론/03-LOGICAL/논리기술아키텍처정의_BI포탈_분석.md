# 논리 기술 아키텍처 정의 — BI포탈 분석

## 0. 분석 범위와 판독 원칙

- 대상은 첨부된 `BI 포탈 논리 기술 아키텍처` 장표이다.
- 이미지 문구는 분석 자료이며 지시사항으로 취급하지 않는다.
- 이미지에서 직접 확인되는 내용은 **[사실]**, 구조적 의미는 **[해석]**, 별도 원본과 설계서로 확정할 내용은 **[확인 필요]**로 구분한다.
- 선의 화살표와 소유관계가 명확하지 않으면 호출 방향을 임의 확정하지 않고 `연계`로 표현한다.
- 장표 제목의 `BI 포탈` 표기를 기본으로 사용하며, 근거 파일명의 `BI포털`은 동일 영역을 지칭한다.

## 1. 핵심 결론

1. **[사실]** BI포탈은 신용실적, Data Eye 포탈·대시보드, Self-BI, OLAP의 네 실행영역을 하나의 채널 경험으로 제공한다.
2. **[해석]** 단일 포털 UI를 제공하지만 내부 런타임과 분석 방식은 분리하여 기능·부하·장애 범위를 격리한다.
3. **[사실]** 신용실적은 NH Cloud Framework, Self-BI는 BI-Matrix, OLAP은 MSTR로 표현된다.
4. **[사실]** RDW와 ADW가 데이터 기반이며 RDW→ADW는 ETL로 연결된다. 배치 AP·ETL·Control-M이 데이터 준비를 지원한다.
5. **[해석]** RDW는 운영·신용실적·포탈 조회에, ADW는 분석·Self-BI·OLAP·경영정보에 가까운 역할을 수행한다. 실제 쿼리 소스는 기능별 확정이 필요하다.
6. **[사실]** IT 메타·비즈메타·데이터 품질, 대내 Cruz APIM/EAI/FOS/MFT, 대외 FOS/대외 MCA/MFT가 연계 영역으로 표시된다.
7. **[해석]** 가장 중요한 횡단 통제는 SSO/권한, 데이터셋 인증, 쿼리 자원 격리, 개인정보 마스킹, 보고서 반출 통제, 계보·품질·신선도 표시다.

## 4. 채널·접근·인증

```text
[사용자]
   │
[인증 관리]
   │ session/token/role
   ▼
[정보계 단말 / 패키지 단말]
   │ HTTP(S)
   ▼
[L4] → [WEB] → [BI포탈 각 Application]
```

- L4는 가용성과 부하분산, WEB은 접속 종단·정적 콘텐츠·역방향 프록시를 담당한다.
- BI 서비스는 여러 솔루션으로 분리되므로 포털 SSO 토큰을 각 솔루션 권한 모델로 안전하게 매핑해야 한다.
- 세션 고정, 토큰 재사용, 관리자 기능 접근, 보고서 URL 직접 접근을 통제해야 한다.
- **[확인 필요]** 이미지에는 인증 제품, 토큰 형식, TLS 종단, WAF/API Gateway가 표시되지 않는다.

### 4.1 통합 권한 모델

```text
사용자 ─ 조직/직무/등급
   │
   ├─ 기능 권한: 포탈·대시보드·Self-BI·OLAP
   ├─ 데이터 권한: 주제·행·열·민감도
   ├─ 작업 권한: 조회·작성·공유·승인·반출
   └─ 관리자 권한: 계정·권한·연계·시스템 설정
```

기능 권한만으로 데이터 접근을 허용하지 않고, 데이터 권한과 반출 권한을 별도로 평가해야 한다.

## 5. 신용실적 애플리케이션

### 5.1 기능 구성

| # | 기능 | 책임 분석 |
|---:|---|---|
| 1 | 수신 실적 | 수신 관련 실적 조회·집계 |
| 2 | 여신 실적 | 여신 관련 실적 조회·집계 |
| 3 | 계좌 실적 | 계좌 단위 실적 조회 |
| 4 | 사무량 관리 | 업무량·처리량 관리 |
| 5 | 종합 메리트 | 종합 성과·메리트 지표 |
| 6 | 기타 실적 | 기타 실적 범주 |
| 7 | BIMS | 별도 실적/정보 기능; 약어 확정 필요 |
| 8 | 실적 공동 | 공동 실적 관련 기능; 상세 정의 필요 |

```text
┌──────────── 신용실적 Application ────────────┐
│ 수신·여신·계좌 실적 / 사무량 / 종합메리트   │
│ 기타실적 / BIMS / 실적공동                   │
├──────────────────────────────────────────────┤
│ Application Framework (NH Cloud Framework)   │
├──────────────────────────────────────────────┤
│ WAS                                          │
└─────────────────┬────────────────────────────┘
                  │ JDBC/연계
                  ▼
              RDW / ADW
```

### 5.2 실적 데이터 원칙

- 지표명, 산식, 기준일, 조직 귀속, 원천, 버전, 확정 상태를 메타데이터로 관리한다.
- 잠정 실적과 확정 실적을 구분하고 결산 이후 재산출·소급 변경 절차를 둔다.
- 동일 지표가 신용실적, 대시보드, OLAP에서 다르게 계산되지 않도록 인증 지표를 재사용한다.
- 조직 변경 시 과거 실적의 귀속 기준과 현행 조직 조회 기준을 명시한다.

## 6. BI포탈 애플리케이션(Data Eye)

| # | 기능 | 역할 |
|---:|---|---|
| 1 | 계정/권한 관리 | 사용자·조직·역할·데이터 권한 관리 |
| 2 | 결재 관리 | 데이터·보고서·공유·반출 승인 |
| 3 | 통합 검색 | 데이터셋·보고서·용어·콘텐츠 검색 |
| 4 | 데이터 활용 지원 | 분석 데이터 탐색·활용 지원 |
| 5 | 커뮤니케이션 | 공지·문의·협업 기능 |
| 6 | 보고서 관리 | 보고서 등록·분류·버전·배포 |
| 7 | 관련 시스템 연계 | 내부·외부 시스템 연결 |
| 8 | 관리자 기능 | 환경·운영·감사·정책 관리 |

```text
                      [Data Eye BI포탈]
       ┌───────────────┼────────────────┐
       ▼               ▼                ▼
 [탐색·검색]       [관리·결재]      [활용·연계]
 데이터셋/보고서    권한/승인/감사    Self-BI/OLAP/대시보드
       │               │                │
       └───────────────┼────────────────┘
                       ▼
                [공통 Portal WAS]
```

### 6.1 통합 검색

- 검색 대상의 기술 메타, 비즈니스 용어, 소유자, 품질, 신선도, 인증 상태를 함께 색인한다.
- 권한 없는 객체는 검색 결과·자동완성·건수에서도 노출하지 않는다.
- 검색 결과는 원본 데이터가 아니라 메타데이터를 기본으로 하며 샘플 조회는 별도 권한을 요구한다.

### 6.2 결재·보고서 관리

```text
DRAFT → REVIEW → APPROVED → PUBLISHED → DEPRECATED → RETIRED
   │        │         │           │             │
 작성자   검토자    승인자      배포버전       대체/폐기
```

보고서와 데이터셋은 승인 당시의 SQL/모델/필터/권한/데이터 기준시점을 고정해 재현 가능해야 한다.

## 7. 대시보드 애플리케이션

```text
[대시보드 Application]
       ├─ 경영 Dashboard
       └─ 거버넌스 Dashboard
                 │
                WAS
                 │
             RDW / ADW
```

- 경영 대시보드는 경영 KPI, 추세, 목표 대비 실적을 제공하는 영역으로 해석된다.
- 거버넌스 대시보드는 데이터 품질, 표준, 메타, 활용, 이슈 상태를 제공하는 영역으로 해석된다.
- KPI 타일마다 정의·산식·기준시점·갱신주기·소유자를 표시해야 한다.
- 캐시는 응답을 개선하지만 데이터 신선도를 숨기지 않도록 `dataAsOf`를 노출한다.

## 8. Self-BI 애플리케이션(BI-Matrix)

```text
[사용자]
   │ 자연어 질의 / 비정형 분석
   ▼
[Self-BI Application (BI-Matrix)]
   │ semantic model / governed dataset
   ▼
[Query Generation & Guardrail]
   │
   ▼
 RDW / ADW
```

### 8.1 자연어 질의 통제

- 질문을 임의 SQL로 바로 변환하지 않고 승인된 의미 계층·데이터셋·지표에 매핑한다.
- 생성 SQL은 허용 스키마, SELECT-only, 행 수, 실행시간, 비용 한도를 검증한다.
- 사용자 질문, 해석된 지표·필터, 생성 SQL, 데이터 기준시점, 결과를 감사 가능하게 기록한다.
- 모호한 용어는 추정 실행보다 후보 정의와 확인 질문을 제공한다.

### 8.2 비정형 보고서

- 사용자 제작 보고서는 개인→조직 공유→인증 보고서의 승격 수명주기를 갖는다.
- 데이터셋 버전 변경 시 영향도와 재검증이 필요하다.
- 외부 파일 결합은 악성파일, 개인정보, 데이터 유출과 품질 위험을 통제한다.

## 9. OLAP 애플리케이션(MSTR)

```text
[OLAP Application (MSTR)]
        ├─ 정형 보고서
        └─ 비정형 보고서
               │
          semantic/cube
               │
              WAS
               │
            RDW / ADW
```

- 정형 보고서는 고정된 산식·레이아웃·배포주기, 비정형 보고서는 사용자 탐색을 중심으로 한다.
- 큐브/캐시 갱신시각과 원천 ADW 적재 완료시각을 연결해야 한다.
- Drill-down 시 상위 집계와 상세 합계가 일치하도록 집계 가능성(additivity)과 차원 계층을 검증한다.
- 대규모 Export는 온라인 Query Pool과 분리하고 행 수·파일 크기·만료를 제한한다.

## 10. 네 실행영역 비교

| 관점 | 신용실적 | Data Eye/대시보드 | Self-BI | OLAP |
|---|---|---|---|---|
| 주목적 | 실적 업무 | 포털·검색·관리·KPI | 자유 탐색·자연어 | 다차원 분석·보고서 |
| 기술 | NH Cloud Framework | Data Eye/WAS | BI-Matrix/WAS | MSTR/WAS |
| 사용자 | 실적 업무 담당자 | 전사 BI 사용자·관리자 | 분석 사용자 | 정형/고급 분석 사용자 |
| 데이터 | 실적·업무 데이터 | 메타·보고서·KPI | 인증 데이터셋 | 큐브·마트 |
| 주요 위험 | 산식·확정상태 | 권한·검색노출·승인 | 폭주 SQL·잘못된 해석 | 큐브 신선도·Export |
| 격리 기준 | 업무 트랜잭션 Pool | 포털 Pool | Ad-hoc Query Pool | OLAP/Batch Pool |

```text
단일 사용자 경험
      │
      ├─ 신용실적: 업무형
      ├─ Data Eye: 포털·관리형
      ├─ Self-BI: 탐색형
      └─ OLAP: 다차원·보고서형
              │
        공통 SSO·권한·메타·품질·감사
```

## 11. RDW·ADW 데이터 경로

```text
                 [배치 AP] ─ JDBC ─┐
                                    ▼
[원천/마케팅정보] ─ CDC/ETL ───▶ [RDW] ─ ETL ─▶ [ADW]
                                    ▲              │
                 [ETL] ─ JDBC ─────┘              ├─ 경영정보 JDBC
                                                   ├─ Self-BI/OLAP
                                                   └─ 대내·대외 제공
```

### 11.1 데이터 소스 원칙

- RDW는 최신·운영성·실적 조회, ADW는 통합·이력·집계·마트 분석에 우선 사용한다.
- 기능별 소스가 불명확하면 같은 지표가 RDW와 ADW에서 다르게 보일 수 있으므로 지표별 Authority를 지정한다.
- RDW→ADW 적재 완료 전에는 해당 기준일의 ADW 보고서를 `미완료/잠정`으로 표시한다.
- Query는 읽기 전용 계정과 Resource Group을 사용하고 업무 DB를 직접 수정하지 않는다.

### 11.2 데이터셋 계약

```text
DatasetContract {
  datasetId, owner, purpose, schemaVersion,
  businessKeys, measures, dimensions,
  classification, rowPolicy, columnPolicy,
  dataAsOf, refreshSla, qualityStatus,
  lineage, retention, approvedUses
}
```

## 12. 배치·ETL·Control-M

```text
[Control-M]
    │ schedule / dependency / calendar
    ├────────▶ [배치 AP] ─ JDBC ─▶ RDW/ADW
    └────────▶ [ETL] ───── ETL/JDBC ─▶ RDW/ADW
                                    │
                       완료·건수·금액·품질 대사
```

- 스케줄 제어와 업무 로직을 분리하고 `jobId/runId/businessDate`를 표준 식별자로 사용한다.
- ADW 마트와 큐브·대시보드 Refresh는 선행 ETL·품질 검증 완료 후 실행한다.
- 부분 성공은 완료로 보지 않고 실패 구간을 격리한 뒤 체크포인트부터 재개한다.

```text
EXTRACT → VALIDATE → TRANSFORM → LOAD → RECONCILE → PUBLISH
              │           │        │          │
              └──── 실패 격리·선택 재실행 ────┘
```

## 13. 마케팅정보·계정계·BCV·경영정보

```text
[계정계] ◀── CDC 중계 ── [마케팅 정보]
[BCV]    ◀── MFT/ETL ─── [마케팅 정보/ADW]
[경영정보] ◀── JDBC ───── [ADW]
```

장표의 선 방향이 모두 명확한 것은 아니므로 위 그림은 연계 관계를 나타낸다. 데이터 Producer/Consumer, Authority, 기준시점은 인터페이스 명세로 확정해야 한다.

## 14. 데이터거버넌스 연계

```text
[IT 메타] ──────┐
[비즈메타] ─────┼─ FOS/연계 ─▶ [BI포탈 Catalog/Search]
[데이터 품질] ──┘                    │
                                    ├─ 정의·소유자·계보
                                    ├─ 품질·신선도·인증
                                    └─ 활용·영향도
```

- IT 메타는 물리 객체·시스템·인터페이스, 비즈메타는 용어·지표·소유자, 품질은 규칙·측정·이슈를 제공한다.
- 메타 연계 실패 시 마지막 성공 스냅샷을 표시하되 최신성 경고를 노출한다.
- 인증 데이터셋과 인증 보고서는 승인된 정의·품질·계보를 충족해야 한다.

```text
                    ┌──────── 대내 시스템 ────────┐
```

| MFT | 관리형 대량 파일 | 송수신 확인·재전송·감사 |
| 대외 MCA | 외부기관 전문 | 레이아웃·문자셋·타임아웃·대사 |

- Data Eye, BI-Matrix, MSTR, NH Cloud Framework의 지원 OS/JVM/브라우저/DB 조합을 호환성 매트릭스로 관리한다.

## 17. 쿼리·성능·자원 격리

```text
Data Platform Workload
 ├─ Portal/Search Pool      짧은 조회·메타 검색
 ├─ Credit Performance Pool 실적 업무
 ├─ Dashboard Pool          반복 KPI·Cache
 ├─ Self-BI Pool            Ad-hoc·자연어 SQL
 ├─ OLAP Pool               Cube·복합 집계
 ├─ Export Pool             대량 파일 생성
 └─ ETL/Batch Pool          적재·Refresh
```

- Pool별 동시성, Query Timeout, Scan량, 메모리, 우선순위를 설정한다.
- 폭주 Query는 자동 취소하고 사용자에게 비용·대체 데이터셋·필터 가이드를 제공한다.
- 대시보드 캐시와 OLAP 큐브는 원천 적재 완료 이벤트에 따라 Refresh하고 기준시점을 표시한다.
- Self-BI의 자유도를 유지하되 업무 온라인 및 확정 배치를 침해하지 않게 한다.

## 18. 보안·개인정보·반출

```text
[사용자]
   │ SSO + 역할
   ▼
[기능 권한]
   │
[데이터셋 권한: row/column/purpose]
   │
[Query/Report]
   │
   ├─ 화면 표시: 마스킹
   ├─ 공유: 승인·수신자 제한
   └─ 반출: 결재·암호화·워터마크·만료·감사
```

- 개인정보·신용정보는 화면, Query 결과, Cache, 임시파일, Export, 로그에서 일관되게 통제한다.
- 관리자라도 업무 데이터 원문 접근은 별도 권한과 사유가 필요하다.
- 자연어 질문과 생성 SQL에도 민감정보가 포함될 수 있으므로 마스킹·보존정책을 적용한다.
- 보고서 링크는 추측 불가능하고 짧은 만료시간을 가지며 재공유를 제한한다.

## 19. 장애·복구

```text
[장애]
   ├─ L4/WEB/WAS → 정상 노드 전환·무상태 복구
   ├─ SSO/권한 → Fail Closed·긴급접근 감사
   ├─ RDW/ADW → 읽기 제한·신선도 표시·복구 후 대사
   ├─ ETL/Batch → checkpoint·선택 재개·대사
   ├─ Self-BI/OLAP → Query 취소·Pool 보호
   ├─ 메타/품질 → 마지막 스냅샷+최신성 경고
```

복구 완료는 프로세스 재기동이 아니라 권한, 데이터 기준시점, 마트·큐브·대시보드 결과의 정합성 확인으로 판단한다.

## 22. 이미지 사실 / 해석 / 확인 필요사항

### 이미지에서 직접 확인되는 사실

- 인증 관리, 정보계 단말, 패키지 단말, HTTP, L4, WEB가 표시된다.
- 신용실적 Application과 8개 기능, NH Cloud Framework, WAS가 표시된다.
- BI포탈 Application(Data Eye)과 8개 기능, 경영·거버넌스 대시보드가 표시된다.
- Self-BI Application(BI-Matrix)의 자연어 질의·비정형 보고서가 표시된다.
- OLAP Application(MSTR)의 정형·비정형 보고서가 표시된다.
- 공통 기반으로 VM과 IaaS가 표시된다.
- 배치 AP, ETL, JDBC, Control-M, RDW, ADW와 RDW→ADW ETL이 표시된다.
- 마케팅정보, CDC 중계, 계정계, BCV, 경영정보가 표시된다.
- IT 메타, 비즈메타, 데이터 품질, 대내·대외 시스템이 표시된다.
- GitLab, Git Runner, eCAMS, Nexus, FWK Manager가 표시된다.

### 아키텍처 해석

- BI포탈은 통합 진입점을 제공하되 네 분석 런타임을 책임·부하별로 분리한다.
- RDW는 운영·최신 조회, ADW는 통합·분석·마트 조회에 우선한다.
- Data Eye는 검색·권한·승인·보고서와 다른 BI 도구를 연결하는 포털 제어면이다.
- 메타·품질 연계는 신뢰 가능한 데이터셋과 보고서를 식별하는 기반이다.

### 반드시 확인할 사항

- 각 선의 실제 방향, 프로토콜, 포트, 인증, 동기/비동기 여부
- 네 애플리케이션의 실제 RDW/ADW 데이터 소스와 쿼리 계정
- 신용실적 BIMS·실적 공동의 정확한 업무 정의
- Data Eye, BI-Matrix, MSTR의 제품 버전·라이선스·HA·지원 환경
- 자연어 질의의 모델, 의미 계층, SQL Guardrail, 학습 데이터 정책
- KPI·지표·보고서의 Authority, 기준시점, 잠정/확정·변경 절차
- 배치·ETL 의존성, 체크포인트, 재처리·대사, Refresh 순서
- IT메타·비즈메타·품질 연계 스키마와 최신성 SLA
- 개인정보·신용정보 등급, 반출 승인, 파일 보존·파기
- 노드 수량, 네트워크 Zone, 방화벽, 용량, RTO/RPO, DR 구성

## 23. 종합 평가

이 장표는 BI포탈을 단일 보고서 시스템이 아니라 **신용실적 업무, Data Eye 포털·대시보드, Self-BI 자연어 탐색, MSTR OLAP**을 하나의 접근·권한 체계로 묶는 복합 분석 플랫폼으로 정의한다. 장점은 사용자 경험 통합과 실행 런타임 분리다. 핵심 위험은 서로 다른 도구의 권한 불일치, 같은 KPI의 산식 불일치, Self-BI/OLAP의 자원 폭주, ADW 신선도, 대량 반출이다. 인증 데이터셋·공통 의미계층·행/열 권한·Query Pool·dataAsOf·계보·품질·반출 감사를 횡단 통제로 적용해야 한다.
