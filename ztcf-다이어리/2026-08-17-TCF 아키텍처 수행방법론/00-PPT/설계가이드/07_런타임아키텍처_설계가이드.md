# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 **업무가 어떤 런타임으로 흐르는가**를 고정한다. IF 매체·Hostname·Control-M Job 내부를 쓰기 전에, 아래를 먼저 잡는다.

```text
유형 # (1~12)는 무엇인가?
주/보조로 나눌 복수 흐름인가?
시퀀스 · IF · SLO · 재처리를 어디에 쓸까?
개통 전 Evidence는 무엇인가?
```

```text
요구 / 채널 / 연계 / 이벤트 / 데이터 / 파일 / 배치
        │
        ▼
런타임 유형 # (대유형 6 · 소유형 12)
        │
        ▼
시퀀스 · IF(06) · ServiceId(08) · SLO · Gate
```

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 유형 #을 **어떤 순서로** 고르고 카드를 채울지 | shall 문장 자체 → **정의서 07 Part B** |
| 시퀀스·Owner·SLO·재처리 **기입 방법** | IF 표준표 전문 → 06 |
| 초보자 실수·미니 예제 · Gate 워크시트 | 8단계·GUID 본문 → 08 · Control-M 상세 → 09 |

### 읽는 순서

```text
A1 → A2 큰 그림 → Part B Step 1~7 → 예제·실수 → 정의서 Part B로 규범 확인
```

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① 판별 트리로 유형 # (주/보조)
② 유형 총괄표에서 IF·SLO 감각 확인
③ 유형 카드 — E2E 골격(#1/#11/#12)·Timeout·시퀀스
④ 설계서 must 항목 채우기 (FOS↔MFT · Control-M↔BatchStatus)
⑤ IF(06)·ServiceId·GUID(08) 연결
⑥ Gate — 정상/지연/장애
⑦ 7장 완료 표 · 후속 위임
```

규범·금지 원문: [`정의서 07 Part B`](../정의서/07_런타임아키텍처_정의서.md) · E2E·Timeout → **§B4**.

## B1. Step 1 — 판별 트리로 유형 고르기

```text
사람이 화면에서 기다리는 동기 거래인가?
  ├─ 정보단말 UI ──────────────▶ #1
  ├─ 통합업무(MCA 경유) ───────▶ #2
  └─ 미니 싱글뷰 ──────────────▶ #3

시스템이 API/전문으로 붙는가?
  ├─ 대내(APIM 등) ────────────▶ #4
  └─ 대외·타기관 ──────────────▶ #5

고객 행동·오퍼·메시지인가?
  ├─ 수집(Collector/Kafka) ────▶ #6
  └─ 오퍼링(EBM/UMS/PUSH) ───▶ #7

데이터 이동·분석인가?
  ├─ CDC 실시간 ───────────────▶ #8
  ├─ ETL 배치 적재 ────────────▶ #9
  └─ BI/OLAP/리포트 조회 ─────▶ #10
```

## B3. Step 3 — 유형 카드 · E2E 골격 워크시트

채널·연계·이벤트·데이터·파일·배치별로 시퀀스 ASCII를 먼저 그린다. 상세 shall은 **정의서 §B4**.

| # | 시퀀스 감각 (설계서에 복사·확장) |
|---:|---|
| 1 | 단말 → `/ins/{ServiceId}` → Service → DB/연계 · GUID |
| 2 | 통합업무 → MCA → 정보계 AP → 응답(MCA 변환) |
| 3 | 채널 → MCA → 미니싱글뷰 Service → 응답 |
| 4 | AP ──Cruz APIM──▶ 대내 (논리 API만) |
| 5 | 정보계 ──APIM/대외──▶ 기관 · 인증서·대사 **별도** |
| 6 | Collector → Kafka → 행동정보 · **이벤트 서버 분리** |
| 7 | EBM → UMS → SMS/PUSH/MAIL · #6과 **시퀀스 분리** |
| 8 | 코어 → CDC → Downstream → RDW · 체크포인트 |
| 9 | BCV/RDW → ETL → DW/ADW · 창↔피크 분리 · 대사 |
| 10 | BI/OLAP → JDBC → ADW/마트 |
| 11 | ↔ FOS · 완료신호 후 소비 · FOS≠MFT 직접 |
| 12 | Control-M → Shell → Job · BatchStatus 매핑 |

위험 감각 기입 예: #2 MCA 장애=대면 중단 · #5 Gateway만으로 갈음 금지 · #12 앱 cron만 운영 금지.

### B3.1 E2E 골격 — #1 / #11 / #12 (복사·기입)

규범 ASCII: 정의서 §B4.1.1 · §B4.5.1 · §B4.5.2.

**#1 정보계 단말** — 설계서에 첨부 ☐

```text
사용자 → 웹전용브라우저/Package UI
      → JSON/HTTP (+GUID)
      → 정보계 App (/ins/{ServiceId} · 08 8단계)
      → (필요) RDW/ADW · 대내 API
      → Sync Response → 단말
```

| 항목 | 기입 |
|---|---|
| ServiceId / 진입 | |
| 보조 연계 (있으면) | |
| P95 목표·측정 구간 | |

**#11 FOS 파일** — 첨부 ☐

```text
App/Batch/DP → Staging → FOS
  ├─ 대내 송수신
  └─ 대외 → MFT → 기관 (역: 대외→MFT→FOS→정보계)
  → (완료신호 후) ETL/Batch → RDW/ADW
```

| FOS 책임 | MFT 책임 | App→MFT 직접 호출 금지 ☐ |
|---|---|---|
| 계약·라우팅·상태·완료신호 | 전송·전송보안 | |

FOS=전달 · ETL=내용 처리 · Batch=#12 — 한 시퀀스에 뭉개지 않음.

**#12 배치** — 첨부 ☐

```text
Control-M → Batch AP/Agent → NH Cloud Batch FW
  → JDBC/ETL/FOS·API → BatchStatus/ExitStatus → OS exit → Control-M
```

## B8. 미니 예제

```text

  │
  ├─ 주 #7 (오퍼) · 보조 #6 (수집) — 시퀀스 분리
```
