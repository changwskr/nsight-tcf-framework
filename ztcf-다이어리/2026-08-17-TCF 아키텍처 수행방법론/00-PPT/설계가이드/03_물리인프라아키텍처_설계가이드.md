# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 **어느 논리가 어느 물리·센터인가**를 고정한다. Hostname 코드표·DB RAC·Drill을 쓰기 전에, 아래를 먼저 잡는다.

```text
02 논리 노드는 무엇인가?
의왕인가 안성인가 · 환경은?
Hostname·대수·SW·용량 근거는?
운영↔DR 대응표가 있는가?
```

```text
Logical Node (02)
        │
        ▼
Center · Env · Hostname · HW/SW · Capacity
        │
        ▼
Inventory (DNS / CMDB / IaaS / 모니터 / 백업 일치)
```

목적 한 줄: **논리 없는 물리 신설 금지 · 환경별 구성도 분리 · 운영↔DR·용량 근거.**

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 논리→물리 매핑표 **기입 순서** | shall 문장 자체 → **정의서 03 Part B** |
| 센터·순번·DR 대응 · SW·용량 워크시트 | Hostname 12자리 코드표 → 05 |
| 초보자 실수·미니 예제 | DB RAC/OGG → 04 · Zone 논리 → 02 · Drill → 11 |

### 읽는 순서

```text
A1 → A2 큰 그림 → Part B Step 1~7 → 예제·실수 → 정의서 Part B로 규범 확인
```

## A2. 큰 그림 · 최상위 박스

```text
논리: 마케팅 WEB
  운영  의왕  sb….wb01 / wb02
  DR   안성  sb….wb51 / wb52   ← 순번 51~99 (05)
```

```text
Physical Infrastructure
│
├─ Center: 의왕(01~49) · 안성(51~99)
├─ Mapping: Logical → Env → Center → Hostname → HW/SW
├─ Diagrams: 운영·DR·개발·선도·검증 (분리)
├─ Ops↔DR: 대응표 + L4/GSLB
└─ Evidence: SW 목록 · 용량 MD · Inventory
```

| 축 | 이 장에서 할 일 | 상세 위임 |
|---|---|---|
| 센터 | 의왕/안성 · 순번 대역 | 정의서 B3 · 05 |
| 매핑 | must 필드 완비 | 정의서 B4 |
| DR/HA | 대응표 · AA 전제 | 11 · HA-DR.md |
| SW·용량 | 동기화 · 인용 | 04-PHYSICAL 용량 MD |

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① 논리→물리 매핑표 (must 필드)
② 환경별 HW/SW 구성도 분리
③ 운영↔DR 대응표 · 순번 대역
④ SW 범주 인벤토리 · 종·버전 동기화
⑤ Capacity Baseline 인용 · 용량 근거
⑥ 인벤토리 · DNS/CMDB 일치
⑦ HA 연결 전제 · 3장 완료 표
```

규범·금지 원문: [`정의서 03 Part B`](../정의서/03_물리인프라아키텍처_정의서.md) · 용량·SW → **§B7**.  
DB RAC/OGG 세부는 [`04_데이터베이스아키텍처_설계가이드.md`](./04_데이터베이스아키텍처_설계가이드.md).

## B1. Step 1 — 논리→물리 매핑표

**규칙**: 02에 없는 논리로 서버 신설 금지(예외 ADR).

| 논리 노드 | 환경 | 센터 | Hostname | 대수 | OS/Type | 시스템 그룹 | SW |
|---|---|---|---|---:|---|---|---|
| 마케팅 WEB | 운영 | 의왕 | (05로 부여) | 2 | Linux/IaaS | WEB | … |

must 필드 점검(정의서 B4.1):

| 항목 | 검증 질문 |
|---|---|
| 논리 노드명 | 02와 **동일 명칭**인가? |
| 환경 | 구성도와 일치하는가? |
| 센터 | 순번 대역과 정합하는가? |
| Hostname | 05 12자리 · 중복 없는가? |
| 대수·Type | 용량 근거가 있는가? |
| SW 종·버전 | 목록과 일치하는가? |

매핑 감각:

- 논리 1 → 물리 N (Scale-out) OK · **역할·그룹·환경**을 행마다 반복  
- 한 Host 복수 역할 → 대표 논리 + CMDB 부가  
- 선도 = 동일 Zone·논리 · 축소 대수만 · **사유 문서화**

## B2. Step 2 — 환경별 구성도 분리

```text
┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│ 운영   │ │  DR    │ │ 개발   │ │ 선도   │ │ 검증   │
│ HW/SW  │ │ HW/SW  │ │ HW/SW  │ │ HW/SW  │ │ HW/SW  │
└────────┘ └────────┘ └────────┘ └────────┘ └────────┘
     ※ 한 장에 섞지 않음 · 복사 시 Hostname·순번·센터 재검증
```

참고: `물리기술아키텍처_하드웨어구성도_*` · `소프트웨어구성도_*`.

---

## B3. Step 3 — 운영↔DR 대응표

| 센터 | 역할 | 순번 |
|---|---|---|
| 의왕(주) | 운영·개발·선도·검증 기본 | **01~49** |
| 안성(DR) | 재해복구 인스턴스 | **51~99** |

| 역할 | 운영 Host | DR Host | Traffic/전환 |
|---|---|---|---|
| 마케팅 WEB #1 | …01 | …51 | L4/GSLB 등 |

기입 규칙:

1. 법인·앱코드·플랫폼·환경`o`·용도 동일, **순번만 DR 대역**(05).  
2. `01↔51` 1:1이 정책이면 할당표에 명시, 아니면 ADR.  
3. **물리 Host만 있고 앱·배치·DNS 전환 절차가 없으면** DR 미완성(11 연계).  
4. DR Host를 01~49에, 개발/검증에 51~99를 두지 않는다.

## B4. Step 4 — SW 범주 인벤토리 · 종·버전 동기화

규범: **정의서 §B7 · §B7.2**.

```text
SW 구성도  ←동기화→  SW 목록(종·버전)  ←동기화→  Inventory (SSOT)
```

- 구성도에만 / 목록에만 = **유령 SW** (금지)  
- 버전 변경: 영향분석 → 변경관리 → 구성도·목록·인벤토리 **동시 갱신**  
- 미기재 버전 = **OPEN** · 개통 전 확정  
- 참고: `물리기술아키텍처_소프트웨어목록_분석.md`

## B5. Step 5 — Capacity Baseline · 용량 근거

대수·Mem·CPU·Scale-out은 [`물리기술아키텍처_시스템용량_분석.md`](../../04-PHYSICAL/물리기술아키텍처_시스템용량_분석.md) **및 Inventory를 인용**.  
규범: **정의서 §B7 · §B7.1**.

산식: `환경 합계 ≈ 단일 구성 × 대수`. 앱 표 CPU=0 → 무제한이 아니라 **본 장표 범위 밖**.

### B5.1 Capacity Baseline 기입 (§B7.1)

설계서에 Baseline을 **인용·대조**한다(수치 원문=정의서/용량 MD).

| 플랫폼 | 환경 | 대수 | Mem 합계 | Disk 합계 | 본 프로젝트 인용 ☐ |
|---|---|---:|---:|---:|---|
| BI포탈 | 개발 | 28 | 90 GB | 56 GB | |
| BI포탈 | 운영 | 28 | 102 GB | 56 GB | |
| 마케팅 | 개발 | 26 | 48 GB | 48 GB | |
| 마케팅 | 운영(허브+GW) | 31 | 92 GB | 62 GB | |
| 마케팅 | 운영(IMDG) | 7 | 280 GB | 80 GB | |
| 마케팅 | 운영(**합산**) | 38 | 372 GB | 142 GB | 허브+IMDG 항상 합산 |

Registry·Gateway = 플랫폼별 **컨테이너 HA×2**. IMDG = **VM**.

| 할 일 | 비고 |
|---|---|
| BI·마케팅 **개발/운영 분리 산정** 존중 | |
| Gateway/Registry HA 대수(예: 2) 반영 | 구성도·용량 |
| 감(感) 산정·임의 감축 금지 | 정의서 §B7 |

| 논리 노드 | 대수 | Mem/CPU | 용량 MD 절 | 인용 ☐ |

## B8. 미니 예제

```text
개발 마케팅 WEB
  │
  ├─ 논리: 마케팅 WEB (02에 존재)
  ├─ 환경 t · 센터 의왕 · 용도 wb · 순번 01
  ├─ DR 행: N/A (개발)
  ├─ SW: 개발 허용 버전 (목록 동기화)
  ├─ 용량: 개발 산정표 인용
  └─ Inventory 행 등록 · DNS 일치

운영 마케팅 WEB (DR 포함)
  │
  ├─ 의왕 …wb01/wb02 ↔ 안성 …wb51/wb52
  ├─ L4/GSLB · 전환 절차 링크(11)
  └─ 구성도(운영)·구성도(DR) 분리
```

## B9. 자주 하는 실수

| 실수 | 올바른 태도 |
|---|---|
| Host만 있고 그룹·환경 없음 | 논리 라벨·매핑 must |
| 02에 없는 논리로 신설 | ADR 없이 금지 |
| DR 대응표 없음 | 01↔51 대응 + 전환 |
| 구성도 ≠ 목록 버전 | 동기화 |
| 감으로 Scale-out | 용량 MD 인용 |
| 환경 한 장에 혼재 | 운영/DR/개발 분리 |
| 개발에 DR 순번 | 51~99는 DR만 |
| 정의서 안 보고 가이드만 | 규범은 정의서 Part B |
