# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 **Hostname·랙 이전**에, 논리 노드가 Zone·시스템·레이어에 어디에 앉는지를 고정한다.

```text
어느 환경(운영/DR/개발/선도)?
어느 논리 시스템(MP·DP·BI·DG·IM)?
어느 Zone(6)에 두는가?
어느 레이어(Client→Service→I/F→Data)?
```

```text
Vision · Big Picture (01)
        │
        ▼
Logical (본 장)
  6 Zone · 논리 시스템 · 레이어드 · 환경 5/3
        │
        ▼
Physical(03) · IF(06) · Mechanism(08) · Runtime(07)
```

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 환경·Zone·레이어드 **기입 순서** | shall 원문 → **정의서 02 Part B** |
| Zone 배치표·축소 사유 **워크시트** | Hostname·센터·BOM → 03·05 |
| 초보 실수·미니 예제 | IF 매체 표준표 → 06 · 8단계/GUID → 08 |

### 읽는 순서

```text
A1 → A2 Zone 큰 그림 → Part B Step 1~7 → 예제·실수 → 정의서 Part B로 규범 확인
```

상세 도식·FACT/ANALYSIS: 정의서 02 Part A · `03-LOGICAL/*`.

---

## A2. 큰 그림 · 6 Zone

```text
[대내 채널] [대고객 채널] [대외 채널]
        \         |         /
         [ 채널 통합 Zone ]     ← MCA / MCI / 대외MCA
                  |
         [ 서비스 제공 Zone ]   ← MP / DP / BI / DG / IM
                  |
         [ 대내 통합 Zone ]     ← APIM / EAI / FOS / MFT
```

표준 요청 경로:

```text
채널(3종) → 채널 통합 → 서비스 제공 →(필요시)→ 대내 통합
```

| 축 | 이 장에서 할 일 | 상세 위임 |
|---|---|---|
| Zone | 6 Zone 배치·허용/금지 연결 표시 | 정의서 B3~B4 |
| 환경 | 운영·개발 5 / DR·선도 3 분리 | 정의서 B5 |
| 레이어드 | Client→Service→I/F→Data | 정의서 B6 · IF 매체는 06 |

---

## A3. 용어 (설계 시 암기)

| 용어 | 설명 |
|---|---|
| Zone | 유입·중계·처리·내부연계 **책임** 경계 (subnet≠Zone) |
| 서비스 제공 Zone | MP·DP·BI·DG·IM 핵심 |
| 채널 통합 | MCA · MCI · 대외 MCA |
| 대내 통합 | APIM · EAI · FOS · MFT |
| 논리 시스템 | 서비스 제공 Zone 내 상시 구축 단위 |
| 레이어드 | Client → Service → I/F → Data (→배포) |
| 선도(Pilot) | 동일 Zone · **축소 구축 범위** |

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① 환경 행 분리 (운영/DR/개발/선도 혼재 금지)
② 대구분 → 논리 시스템 (MP·DP·BI·DG·IM)
③ 6 Zone 배치표
④ 기술 컴포넌트 체크
⑤ 레이어드 ASCII(MP/DP/BI/DG) · Fast/Deep · 카탈로그 · 소유 Data
⑥ DR/선도 축소 사유·복구
⑦ 금지·완료 표 · 후속 위임
```

규범·금지 원문: [`정의서 02 Part B`](../정의서/02_논리기술아키텍처_정의서.md) · 레이어드·카탈로그 shall → **정의서 §B6**.

---

## B1. Step 1 — 환경 행 분리

| 환경 | 상시 수 | 할 일 |
|---|---:|---|
| 운영 | 5 | 마케팅·DP·BI·DG·IT지원 |
| 개발 | 5 | 운영과 동일 · 데이터·계정·대외 **격리** |
| DR | 3 | 마케팅·DP·IT지원 (BI·DG 즉시기동 제외 많음) |
| 선도 | 3 | 마케팅·DP·IT지원 (ADW 등 축소 가능) |

```text
한 장에 운영+DR 섞지 말 것
  → 환경별 절·표·도면으로 분리
이행용 임시 → 상시 수에 미포함
```

**확인 질문**: “이 도면만 보고 지금이 운영인지 DR인지 말할 수 있는가?”

---

## B2. Step 2 — 대구분 → 논리 시스템

| 대구분 | 논리 시스템 |
|---|---|
| **MP** | 마케팅플랫폼 |
| **RD**+**AD** | **데이터플랫폼** (코드 분리, 시스템 하나) |
| **BI** | BI포탈 |
| **DG** | 데이터거버넌스 |
| **IM** | IT서비스·업무지원 |

```text
App Group ≠ System Group (1:1 아님)
Hostname 없이 역할만 식별
```

워크시트:

| 대구분 | 논리 시스템 | 이번 설계 포함(Y/N) | 비고 |
|---|---|---|---|
| MP | 마케팅 | | |
| RD+AD | 데이터플랫폼 | | |
| BI | BI포탈 | | |
| DG | 거버넌스 | | |
| IM | IT지원 | | |

## B3. Step 3 — 6 Zone 배치표

| # | Zone | 대표 구성 |
|---:|---|---|
| 1~3 | 대내·대고객·대외 채널 | 유입 |
| 4 | 채널 통합 | MCA / MCI / 대외MCA |
| 5 | 서비스 제공 | MP·DP·BI·DG·IM |
| 6 | 대내 통합 | APIM / EAI / FOS / MFT |

설계서에 복사:

| 논리 노드 | Zone | 연계 대상 Zone | 비고 |
|---|---|---|---|
| 예: 마케팅 WEB | 서비스 제공 | 채널 통합 | |
| 예: APIM 호출 | 대내 통합 | 서비스 제공 | |

채널·통합 Zone 박스는 PPT처럼 **연계 대상 표시**인 경우가 많다.  
허용·금지 연결 요약은 정의서 B4 — 여기서는 “직접 원장·타 DAO” 경로가 도면에 없는지 확인.

## B4. Step 4 — 기술 컴포넌트 체크

근거: `논리기술아키텍처_기술컴포넌트정의_*`

| 논리 시스템 | 점검 예 |
|---|---|
| 마케팅 | WEB · 미니싱글뷰 · 행동/실시간 AP · 마케팅 DB |
| 데이터플랫폼 | Collector · ETL · Scheduler · RDW/ADW 역할 |
| BI | Portal · OLAP · Self-BI · BI DB |
| DG | 메타·품질 WAS · 거버넌스 DB (원장 대체 아님) |
| IT지원 | 배치 · CDC 중계 · ETL · 단말관리 |

이벤트(Kafka/EBM)는 **온라인 WAS와 경로 분리** 표시.

## B5. Step 5 — 레이어드 ASCII · Fast/Deep · 카탈로그 · 소유 Data

규범 원문·ASCII 골격: **정의서 §B6 · §B6.1~B6.4** (본 Step는 기입·첨부 절차).

### B5.1 공통 골격 + 플랫폼 ASCII 첨부

```text
Client Access → Service → I/F → Data → (형상·배포)
```

설계서에 **해당 플랫폼 ASCII를 복사·첨부**하고, 프로젝트 델타만 표시한다(계층 우회 금지).

| 플랫폼 | 첨부 ☐ | 설계서 위치/링크 | 델타 한 줄 |
|---|---|---|---|
| **MP** (마케팅) | | | |
| **DP** (데이터플랫폼) | | | Client=운영제어 |
| **BI** | | | |
| **DG** | | | WAS≠처리 대체 |

ASCII 원문은 정의서 §B6.1. 선도는 해당 플랫폼 MD에서 축소분을 명시.

### B5.2 Fast / Deep Path 점검 (DP)

규범: 정의서 §B6.2. 설계서 체크:

| 점검 | ☐ | 기입 |
|---|---|---|
| Fast Path: 원천→OGG/CDC→RDW (준실시간) | | Owner·SLA·Writer |
| Deep Path: BCV/ETL→ADW (분석) | | Owner·SLA·Writer |
| RDW→ADW ETL Dataset 계약 분리 | | |
| 동일 Target에 OGG+ETL **이중 Writer 없음** | | |
| 원천·외부의 RDW/ADW 직결 JDBC 없음 | | |
| 계층 호출: WEB≠업무로직 · DB=DAO만 · 외부=I/F만 | | |

### B5.3 노드 기술 카탈로그 must 필드

규범 표: 정의서 §B6.3. 논리 노드마다 설계서/인벤토리에 복사:

| 분류 | 필수 항목 (기입) |
|---|---|
| 식별 | nodeId · systemId · environment · owner · criticality |
| 실행 | solution · artifactVersion · technologyStack · JVM/DBMS version |
| 기반 | OS image/version · VM flavor 또는 Appliance · Cloud zone |
| 보안 | account source · vaccine/security · 개인정보 등급 · 예외 |
| 운영 | monitoring profile · backup policy · runbook · patch group |
| 복구 | HA · backup target · RPO · RTO · restore evidence |
| 연결 | endpoint · port · upstream/downstream · dependency |

**DP Baseline 컴포넌트** 등록 ☐ (정의서 §B6.3 표): OGG/CDC · ETL · DBSafer · FOS/MFT · Control-M/Scheduler/Job Shell · Exadata RDW/ADW.

### B5.4 소유 Data

| 플랫폼 | 설계서 헤더에 적을 것 |
|---|---|
| 마케팅·BI·DG·선도 | 레이어드 MD **내 기능 박스** + ASCII 첨부 |
| 데이터플랫폼 | RDW(준실시간) vs ADW(분석) **역할 분리** |

소유 원칙 (절차 확인 — 규범은 정의서 §B6.4):

1. 타 시스템 DAO/DB 직접 접근 없음  
2. RDW/ADW 역할 혼재 없음  
3. BI·마케팅의 DW는 **계약된 조회·연계**만  
4. DG는 원장·마트 **대체 처리자 아님**

## B6. Step 6 — DR / 선도 축소 사유

| 항목 | 기입 |
|---|---|
| 빠지는 시스템 | 예: BI, DG |
| 사유 | RTO · 용량 · 고객서비스 우선순위 (**“PPT에 없어서” 불가**) |
| 데이터 우선 | DR: **RDW 우선** 등 |
| 백업·후순위 복구 | 11·HA-DR과 문장 연결 |

```text
운영 5를 그대로 복사 ≠ DR 설계
축소 = 복구·선행 검증 우선의 의도적 범위
```

## B8. 미니 예제

```text
개발 환경 · 마케팅 캠페인+오퍼
  │
  ├─ 환경: 개발 (5시스템) — 운영과 분리 도면
  ├─ 시스템: MP (+ 필요 시 DP)
  ├─ Zone: 서비스제공 WEB + 채널통합 MCA 표시
  ├─ 컴포넌트: WEB · (이벤트 경로는 WAS와 분리 표시)
  ├─ 레이어: Client → Service → I/F → Data(마케팅 DB)
  └─ 아직 안 함: Hostname(03) · IF 매체 No.(06)
```
