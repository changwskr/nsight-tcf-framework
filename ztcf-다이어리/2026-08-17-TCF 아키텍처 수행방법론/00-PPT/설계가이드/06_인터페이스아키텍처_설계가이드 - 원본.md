# 06. 인터페이스 아키텍처 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)
> **PPT 장**: 6장 · 슬라이드 90~100
> **방법론 폴더**: `03-LOGICAL (인터페이스*)`
> **작성일**: 2026-08-26

---

## 1. 목적

온라인·파일·데이터 연계의 표준 매체와 Context를 설계하여, 시스템 간 자원 경합을 줄이고 플랫폼 독립성을 유지한다.

## 2. 적용 범위

- **포함**: 정보계 IF 원칙, 온라인/파일/데이터 표준표, 상위 Context·플랫폼별 연관도
- **제외**: 거래 시퀀스 상세(7장), 전문/GUID 필드(8장), Upload/RD 구현(9장)
- **원칙 키워드**: 도메인 특성 고려 · 서비스 플랫폼 독립

## 3. 설계 원칙

1. **자원 분리**: 온라인 AP / 배치 AP 자원을 분리하고, ETL·이벤트(Kafka)·CDC 중계를 독립 공간으로 둔다.
2. **표준 매체 강제**: 경로 유형에 맞는 인터페이스 시스템만 사용한다(임의 P2P 지양).
3. **양방향 대칭**: 정보계↔대내/대외는 동일 표준(APIM/FOS/GSE 등)을 양방향에 적용한다.
4. **플랫폼 Context**: 마케팅·데이터·BI·거버넌스 연관도를 상위 Context와 정합시킨다.
5. **솔루션 UI 예외 명시**: 패키지 UI 등 예외 경로는 표에 명시하고 남용하지 않는다.

## 4. 설계 기준 (결정 규칙)

- **온라인**: 대면=영업점 MCA, 비대면=MCI, 정보계 단말·패키지 UI=직접(경유 없음), 대내·대외=API G/W(CruzAPIM), 타법인=GSE.
- **파일**: 정보계↔단말/패키지/대내/대외는 FOS(대외는 대외MCA 경유 FOS).
- **데이터**: 코어→DW = CDC(실시간) 또는 BCV+ETL, RDW→ADW·타시스템 = ETL.
- 신규 연계는 구분(온라인/파일/데이터)·소스·IF시스템·타겟·설명을 표준표 행으로 추가한다.

## 5. 구성·경계

```text
온라인 : MCA / MCI / (직접) / CruzAPIM / GSE
파일   : FOS (±대외MCA)
데이터 : CDC · ETL
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 표준표에 없는 매체 도입 시 ADR·표준 개정 | 임시 FTP/직접 JDBC를 상시 경로로 사용 |
| CDC·ETL·이벤트 서버 역할을 분리 설계 | 온라인 WAS에 대량 ETL을 혼재 |
| 플랫폼 연관도를 IF 표준과 함께 갱신 | 코드만 추가하고 Context 미갱신 |

## 7. 설계 체크리스트

- [ ] 온라인/파일/데이터 표준표가 최신인가?
- [ ] 신규 연계가 표준 매체만 사용하는가?
- [ ] CDC/ETL/이벤트/온라인 자원 분리가 지켜지는가?
- [ ] 마케팅·데이터·BI·비즈메타 연관 분석과 모순 없는가?
- [ ] 패키지 UI·직접 경로 예외가 문서화되었는가?
