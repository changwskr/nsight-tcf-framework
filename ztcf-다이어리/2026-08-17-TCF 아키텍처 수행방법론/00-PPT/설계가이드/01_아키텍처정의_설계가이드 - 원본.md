# 01. 아키텍처 정의 — 설계가이드

> **기준**: [`NSIGHT_아키텍처_정의서_통합본_20260825_분석.md`](../NSIGHT_아키텍처_정의서_통합본_20260825_분석.md)

> **방법론 폴더**: `01-VISION · 02-BIG-PICTURE`
> **작성일**: 2026-08-26

---

## 1. 목적

차세대 정보계의 Technical · Application · Data 아키텍처 범위를 확정하고, 개편 방향·도메인·분류체계·시스템 그룹·주제영역·최상위 구조를 설계 기준으로 고정한다. 인프라·개발·유관 담당자가 동일 언어로 시스템을 식별할 수 있게 한다.

## 2. 적용 범위

- **포함**: 문서 목적, 개편 4대 방향, 개념 아키텍처, 앱 도메인/분류체계, 시스템 그룹, 데이터 주제영역, 전체 시스템·대상 서버 식별
- **제외**: 환경별 논리 노드 상세(2장), 물리 Inventory(3~5장), IF 매체(6장), 런타임 시퀀스(7장)
- **독자**: AA/SA, PM, 인프라·개발 리더

## 3. 설계 원칙

1. **고객 중심**: 채널 연계·CX·UI/UX를 설계 의사결정의 우선순위로 둔다.
2. **데이터 기반**: 실시간 수집·즉시 제공·현업 활용이 가능하도록 플랫폼 경계를 잡는다.
3. **통합 정보**: 고객·상품·채널 통합 조회가 가능하도록 도메인·주제영역을 정렬한다.
4. **유연·안정**: 표준 구조·확장 플랫폼·안정 운영을 동시에 만족하는 분류·그룹 체계를 채택한다.
5. **환경 독립 정의**: 비전·분류·그룹은 운영/DR/개발/선도에 공통으로 적용하고, 환경차는 2~5장에서만 분기한다.

## 4. 설계 기준 (결정 규칙)

- 어플리케이션 **대구분(그룹) → 업무구분(앱) → 세부기능** 3단 분류를 모든 설계서·패키지·거래코드의 상위 키로 사용한다.
- 마케팅플랫폼(MP), 데이터플랫폼/RDW(RD), BI포탈(BI), 데이터거버넌스, IT서비스·업무지원을 **시스템 그룹**으로 식별한다.
- 데이터 주제영역은 데이터플랫폼 RDW(공통·실시간 SoR·준실시간 요약집계 등)를 축으로 정의하고, 상세 가이드는 영역별 문서로 위임한다.
- 대상 서버는 논리 서버군 식별까지 1장에서 끝내고, Hostname·스펙은 3~5장 표준을 따른다.
- Technical/Application/Data 정의 범위는 본 통합본을 적용한다. Data 상세는 주제영역 문서를 참조한다.

## 5. 구성·경계

```text
차세대 정보계
├─ Technical  : 운용환경별 논리·물리, 센터, 백업·가용성
├─ Application: 구성·분류·동작원리·표준화
└─ Data       : 주제영역 (상세는 영역별 가이드)

시스템 그룹 (대표)
├─ 마케팅플랫폼 (MP)
├─ 데이터플랫폼 / RDW (RD)
├─ BI포탈 (BI)
├─ 데이터거버넌스
└─ IT서비스 및 업무지원
```

## 6. Do / Don't

| Do | Don't |
|---|---|
| 분류체계 코드(한글/영문/코드)를 설계·구현 산출물에 동일하게 기입 | 임의 약어·별칭으로 그룹/앱을 재명명 |
| 개편 4대 방향에 비추어 신규 요구의 수용 여부를 기록 | 방향과 무관한 국소 최적화만으로 경계 변경 |
| 주제영역과 시스템 그룹 매핑을 명시 | 주제영역 없이 테이블·배치만 선행 설계 |

## 7. 설계 체크리스트

- [ ] 개편 4대 방향이 요구사항/에픽에 반영되어 있는가?
- [ ] 앱 그룹·업무·기능 코드가 `02-BIG-PICTURE` 분류체계와 일치하는가?
- [ ] 시스템 그룹별 대상 서버군이 식별되었는가?
- [ ] 데이터 주제영역 정의와 RDW 축이 문서화되었는가?
- [ ] 전체 시스템 구조(채널·단말·플랫폼·활용)가 최상위도에 표현되었는가?
