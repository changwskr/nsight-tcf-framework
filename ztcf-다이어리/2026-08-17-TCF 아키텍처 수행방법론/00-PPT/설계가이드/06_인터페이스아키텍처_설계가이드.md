# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 채널·대내·대외·DB 경로마다 **어느 IF 중계를 쓸지**를 표로 고정한다. 임의 P2P(직접 JDBC·임시 FTP)를 상시 경로로 두지 않는다.

```text
온라인인가? 파일인가? 데이터(DB↔DB)인가?
  → 표준표에서 한 행 선택
  → 계약 기입 · Context 갱신 · 런타임 # 연결
```

```text
Zone·논리 (02) · Data 소유 (04)
        │
        ▼
IF 매체 표준 (본 장)
  온라인 · 파일 · 데이터
        │
        ▼
런타임 유형(07) · 전문·GUID(08)
```

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 유형 판별·표준표 행 선택·계약 템플릿 | shall 원문 → **정의서 06 Part B** |
| Context 갱신·런타임 # 매핑 | Zone 배치 자체 → 02 · Hostname → 03·05 |
| 초보 실수·미니 예제 | 8단계·GUID 상세 → 08 · 시퀀스 1~12 → 07 |

### 읽는 순서

```text
A1 → A2 판별·큰 그림 → Part B Step 1~8 → 예제·실수 → 정의서 Part B
```

표준표 전문·경로별 shall: 정의서 06 Part B · `인터페이스아키텍처_*표준정의_분석.md`.

## A2. 큰 그림 · 3유형

```text
신규 연계
   │
   ├─ 화면·API·요청/응답 ──▶ 【온라인】 MCA/MCI/APIM/GSE/Direct
   ├─ 파일 송수신 ──────────▶ 【파일】   FOS · FOS+대외MCA
   └─ DB↔DB 동기·적재 ─────▶ 【데이터】 CDC · ETL
```

| 축 | 이 장에서 할 일 | 상세 위임 |
|---|---|---|
| 온라인 | 표준표 No.1~9 행 선택 | 정의서 B4 |
| 파일 | FOS 일원화 · 계약 10항목 | 정의서 B5 |
| 데이터 | CDC vs ETL · 지연 SLA | 정의서 B6 · 04 |

구축 원칙 4줄(암기): 온/배 자원 분리 · ETL 독립 · 이벤트 분리 · CDC 중계.

## A3. 용어 (설계 시 암기)

| 용어 | 설명 |
|---|---|
| 온라인 / 파일 / 데이터 IF | 요청응답 · 파일 · DB↔DB |
| IF 시스템 | MCA, MCI, Cruz APIM, GSE, FOS, CDC, ETL |
| Direct | 중계 없음 — **예외·책임 가중** |
| Interface ID | 연계 계약 키 |
| Completion Signal | 파일 완료 전 소비 금지 |
| 논리 API | Gateway 등록 단위 (물리 URL 아님) |

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① 판별 트리로 유형(온/파일/데이터) 확정
② 구축 원칙 4줄 위배 점검
③ 온라인 표준표 행 선택
④ 파일 표준표 · 계약 · 파일명/Layout/상태모델
⑤ 데이터 표준표 · CDC/ETL
⑥ 연계 1행 템플릿 기입
⑦ Context·연관도 must · MP/BI 매핑 · 런타임 #
⑧ 완료 체크 · 08 정합
```

규범·금지 원문: [`정의서 06 Part B`](../정의서/06_인터페이스아키텍처_정의서.md) · 파일·연관도 → **§B5 · §B7**.

## B1. Step 1 — 유형 판별

```text
한 요구에 여러 유형?
  → 표준표 행을 복수로 쪼갠다 (시퀀스·계약 섞지 않음)
예: 파일 업로드 + DW 적재
  → 파일 1행 + 데이터(ETL) 1행 + 런타임 11·9(또는 12)
```

| 질문 | 유형 |
|---|---|
| 화면·API·요청/응답? | 온라인 |
| 파일 송수신? | 파일 |
| DB↔DB 변경·적재? | 데이터 |

---

## B2. Step 2 — 구축 원칙 4줄 점검

| # | 원칙 | 설계 질문 |
|---:|---|---|
| 1 | 온라인 AP / 배치 AP 분리 | 실시간 WAS에 대량 배치 넣는가? |
| 2 | ETL 서버 독립 | 대량 가공이 전용 공간인가? |
| 3 | 이벤트 서버 분리 | Kafka·오퍼링이 고속 경로인가? |
| 4 | CDC 중계 | 원천 DB 부하를 Downstream으로 분산했는가? |

위배 시 경로·Owner 재설계 — 규범은 정의서 B3.

---

## B3. Step 3 — 온라인 표준표 행 선택

요약(전문·경로 shall → 정의서 B4):

| No. | IF | 전형 |
|---:|---|---|
| 1 | 영업점 MCA | 대면 |
| 2 | MCI | 비대면 |
| 3 | Direct | 정보계 단말 |
| 4 | Direct | Package UI **예외** |
| 5·6 | Cruz APIM | 정보계↔대내 |
| 7·8 | API G/W | 정보계↔대외 |
| 9 | GSE | 타 법인 |

절차 체크:

- [ ] 표준표 No. ___ 선택 (없으면 ADR)  
- [ ] Direct면 앱 측 인증·검증·Rate Limit·감사 목록  
- [ ] APIM이면 **논리 API명·버전** (물리 URL 없음)  
- [ ] 대외면 인증서·재전송·대사·타임아웃 Owner  
- [ ] 전문 형식은 08과 맞춤  

```text
대면 ── MCA ──▶ 정보계
비대면 ── MCI ──▶ 정보계
정보계 ↔ 대내 ── Cruz APIM
타법인 ── GSE ──▶ 정보계
```

## B5. Step 5 — 데이터 표준표 · CDC/ETL

| No. | IF | 성격 |
|---:|---|---|
| 1 | CDC | 코어 → 정보계 DW (실시간) |
| 2 | ETL | 코어 BCV → DW (배치·보정) |
| 3 | ETL | RDW → ADW |
| 4·5 | ETL | DW ↔ 타 DB |

| 질문 | CDC | ETL |
|---|---|---|
| 방금 커밋 변경? | ○ | |
| 초기·대량·일마감? | | ○ |
| 모델링·마트 중심? | | ○ (특히 RDW→ADW) |

CDC 기입 순서: 캡처 대상 → DDL 대응 → 커밋 순서 → 중계 → I/U/D → 체크포인트 → 지연 SLA(측정 구간 ADR).  
ETL: 추출 시점 · BCV→ETL 선후 · Full/Incremental · CDC와 겹칠 때 우선순위.

명칭 `정보계 DW`/`DW`/`RDW`는 등록부에서 **논리명·스키마·소유** 매핑(04).
