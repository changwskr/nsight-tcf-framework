# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 SELF-BI·OLAP·EBM·Package UI 등 **업무 솔루션**을 플랫폼·IF·런타임·보안 경계 안에 둔다.  
“솔루션이라 아키텍처 제외”는 설계 출발점에서 버린다.

```text
Package · SELF-BI · EBM · 포탈 …
        │
        ▼
소속 · IF · 런타임 · 보안 헤더 고정
        │
        ▼
06 / 07 / 08 / 09 와 구멍 없이 연결
```

```text
업무 솔루션 아키텍처 (10장)
        │
        ├─ 소속 (BI / MP / RD·AD / DG / IM)
        ├─ IF · 매체 · Direct 예외
        ├─ 런타임 주/보조 # (1~12)
        └─ 데이터 소유 · SSO · 표준전문
```

### PPT Gap (절차용)

PPT 10장 본문이 약하면 설계서에 Gap 문구를 넣고 Baseline 4종을 인용한다.  
복사용 문구·규범: **정의서 10 §B1**.

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 필수 헤더 **기입 순서** | shall 문장 자체 → **정의서 10 Part B** |
| 소속·IF·런타임 **매핑 방법** | Hostname·스펙 → 03·05 |
| 초보자 실수·미니 예제 | IF 표준표·시퀀스 전문 → 06·07 · 8단계 → 08 |

### 읽는 순서

```text
A1 → A2 큰 그림 → A3 용어 → Part B Step 1~7 → 예제·실수 → 정의서 Part B로 규범 확인
```

## A2. 큰 그림 · 최상위 박스

```text
        [채널/포탈/Package UI]
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
      IF(06)  Runtime  표준·SSO
      Direct?   (07)    (08·09)
      FOS?
```

| 축 | 이 장에서 할 일 | 상세 위임 |
|---|---|---|
| 소속 | BI/MP/RD·AD/DG/IM **확정** | 01·02 · 레이어드 MD |
| IF | 표준표 No. · Direct 예외 여부 | 06 |
| 런타임 | 주/보조 # 1~12 | 07 |
| 보안·전문 | SSO · 표준전문 예외 | 08·09 |

```text
Business Solution
├─ BI ── OLAP · Self-BI · 신용실적 · 포탈
├─ MP ── 캠페인 · 오퍼 · 접점 · EBM
├─ RD/AD ── 마트 · 적재 · CDC/ETL 산출
├─ DG ── 메타 · 품질 · 흐름 · 비즈메타
└─ IM ── IT 공통 · 지원 도구
```

상세 도식·FACT: 정의서 10 Part A · `03-LOGICAL` 레이어드.

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① PPT Gap · Baseline 선언
② 솔루션명 · UI 유형
③ 소속 (BI/MP/RD·AD/DG/IM) · 레이어드 MD
④ IF 유형·매체·표준표 No. · Direct 예외
⑤ 런타임 주/보조 # · RD/단말 진입 규범
⑥ 데이터 소유 · SSO · 표준전문 예외
⑦ 미니기준(신용실적/RD/단말) · 완료 표
```

규범·금지 원문: [`정의서 10 Part B`](../정의서/10_업무솔루션아키텍처_정의서.md) · 미니기준 → **§B5 · §B7**.

## B1. Step 1 — PPT Gap · Baseline

| 질문 | 기입 |
|---|---|
| PPT 10장 본문 충분한가? | Y → Gap 미사용 / N → Gap 문구 |
| Baseline | 정의서 + LOGICAL + RUNTIME #N + MECHANISM |

```text
PPT 약함
   │
   ├─ Gap 문구 붙여넣기 (정의서 B1)
   ├─ 런타임 유형 #N 명시
   └─ “PPT만으로 예외” 금지
```

**확인 질문**: “이 설계서가 PPT 목차만으로 예외를 정당화하지 않는가?”

## B7. Step 7 — 미니기준 패키지 Step (신용실적 / RD / 단말)

해당 솔루션이면 아래를 **필수**로 채운다. 규범 원문: **정의서 §B7.1~B7.3**.

### B7.1 신용실적 Package Direct

| 점검 | ☐ | 기입 |
|---|---|---|
| 소속 **BI** · 런타임 **#10**(적재면 보조 **#9**) | | |
| Direct 예외 = 06 예외 행 + 연계 맵 + Gap | | |
| 보고서(BI포탈) ≠ 대시보드(DG) 매체 혼동 없음 | | |
| ADW/RDW = 허용 계약만 · DAO 공유 없음 | | |
| 신용실적 IF MD 재사용(재발명 금지) | | |

연계 맵 감각(정의서 §B7.1 ASCII 첨부 ☐):

```text
신용실적 ─보고서─▶ BI포탈
         ─대시보드─▶ DG
         ─▶ 비즈메타 / ADW / RDW (계약)
```

### B7.2 RD Map→String · `/rd/{serviceId}`

| 점검 | ☐ | 기입 |
|---|---|---|
| 진입 = `/rd/{serviceId}` (NhRDController) | | |
| 입력 Map · 출력 String | | |
| `/ins/` JSON DTO와 진입·응답 **분리** | | |
| 헤더: IF=RD · 표준표 No.(또는 예외) · 런타임 # | | |

### B7.3 정보단말 패키지·화면 명명

| 점검 | ☐ | 기입 |
|---|---|---|
| 트리 링크: `_wpack_` / `webTop/cm` / `screen/{대구분}/…` | | |
| `_wpack_` **직접 수정 금지** | | |
| 화면명=`[대구분][업무][분류][일련][유형].xml` · 경로 접두부 일치 | | |
| 예: `BI/CR/A/bicra0000M0.xml` · `MP/CO/A/mpcoa0000M0.xml` | | |

## B10. 자주 하는 실수

| 실수 | 올바른 태도 |
|---|---|
| “솔루션=아키텍처 제외” | 헤더부터 포함 |
| Direct를 일반 API에 확대 | 06 예외 행만 |
| 신용실적 IF 재발명 | 기존 MD·§B7.1 재사용 |
| RD를 `/ins/`로 혼용 | `/rd/` Map→String |
| `_wpack_` 직접 수정 | screen XML 원본 |
| 전부 #10 | 행동별 # 분리 |
| SSO 우회 상시화 | 시한·승인·감사 |
| Gap 없이 PPT만으로 예외 | Gap 문구 + Baseline |
| 정의서 안 보고 가이드만 | 규범은 정의서 Part B |
