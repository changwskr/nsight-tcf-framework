# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 **설계의 출발점**이다. 서버·SQL·IF 매체를 쓰기 전에, 아래를 고정한다.

```text
무엇을 T / A / D로 부를까?
누가 이 문서를 쓰는가?
어느 방향(4대)·품질(NFR)로 갈까?
업무를 어떤 코드(MP~IM)에 올릴까?
```

```text
Vision (방향·NFR)
        │
        ▼
Big Picture (분류·그룹·전체구조)
        │
        ├─ Application : MP / RD / AD / BI / DG / IM
        ├─ Technical   : 어디에 · 어떤 역할로
        └─ Data        : RDW / ADW · 주제영역
```

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| 1장 산출물을 **어떤 순서로** 채울지 | shall 문장 자체 → **정의서 01 Part B** |
| 헤더·표·태그 **기입 방법** | Zone·Hostname·IF 매체 → 02~06 |
| 초보자 실수·미니 예제 | 런타임 시퀀스·8단계 → 07~08 |

### 읽는 순서

```text
A1 → A2 큰 그림 → Part B Step 1~7(코드표·그룹·주제영역6 포함) → 예제·실수 → 정의서 Part B로 규범 확인
```

## A2. 큰 그림 · 최상위 박스

```text
[채널] ──▶ [마케팅·BI] ──▶ [RDW/ADW·거버넌스]
                ↕
           이벤트(Kafka/EBM/UMS)
                │
         [EAI/APIM/FOS/대외]
```

| 축 | 이 장에서 할 일 | 상세 위임 |
|---|---|---|
| Technical | “논리·물리·센터를 **나중에** 채운다”고 경계만 | 02~05·11 |
| Application | 분류·방향·표준화 **위치** 표시 | 06~10 |
| Data | 주제영역·RDW/ADW **위치** | 04·DG |

상세 도식·FACT/ANALYSIS: 정의서 01 Part A · `VISION_개요_*`.

# Part B — 설계 절차 (How-to)

## B0. 전체 Step 맵

```text
① 목적·독자·3축
② 개편 4대 방향 태그
③ NFR 5축 · SLA 초안 · Timeout
④ 대구분 MP~IM · 업무구분 코드표(B5.1) · 기능
⑤ 시스템 그룹↔서버 역할 매핑(B5.2)
⑥ 주제영역 6개 트리(B5.3) · 빅픽처 위치
⑦ 1장 완료 표 · 후속 위임
```

규범·코드표·금지 원문(전체표 복붙 금지): [`정의서 01 Part B`](../정의서/01_아키텍처정의_정의서.md) **§B5.1~B5.3**.

## B1. Step 1 — 목적·독자·3축

| 항목 | 질문 | 기입 예 |
|---|---|---|
| 목적 | 이해 / 설계적용 / 운영합의? | 설계적용 |
| 독자 | 인프라·개발·유관? | 개발 PL + SA |
| 축 | T / A / D 중 이번 산출물 | A 주 + T(논리 위치) |

**확인 질문**: “이 문서만으로 우리 일이 MP인지 BI인지 말할 수 있는가?”

---

## B2. Step 2 — 개편 4대 방향 태그

| # | 방향 | 설계 질문 |
|---:|---|---|
| 1 | 고객 중심 서비스 | 채널·CX·UI 개선? |
| 2 | 데이터 기반 의사결정 | 실시간/준실시간 활용? |
| 3 | 통합 정보 활용 | 고객·상품·채널 통합조회? |
| 4 | 유연·안정 운영 | 표준·확장·장애격리? |

```text
요구/에픽
   │
   ├─ 방향 번호(1~4, 복수 OK) 기입
   ├─ 안 걸리면 → 범위 재검토 또는 ADR
   └─ 방향만 있고 NFR/SLA 없으면 → 미완료
```

참고 비전 한 줄: *데이터 기반 실시간 의사결정 + 고객 중심 채널 + 비즈니스 민첩성*.

## B3. Step 3 — NFR · SLA · Timeout

근거: [`NFR.md`](../../01-VISION/NFR.md) · [`SLA.md`](../../01-VISION/SLA.md)

| NFR | 설계에서 할 일 |
|---|---|
| Performance | FAST/DEEP · 온/배 · RDW/ADW · Kafka vs ETL **분리** 표시 |
| Availability | 기능별 분리 · AP Active-Active · 현실적 DB DR |
| Scalability | 서비스=VM Scale-Out · 데이터 병렬 · 도메인 독립 |
| Security | SSO/JWT · 마스킹 · 전송암호 · 감사 |
| Observability | GUID · APM · 거래로그 · Evidence |

| 구분 | SLA 초안 예 |
|---|---|
| 일반 온라인/마케팅 | ~3초 (측정 구간 명시) |
| FAST 이벤트·오퍼링 | ~1초 |
| 일배치 | 오전 6시 이전 |
| CDC | 수치 충돌 가능 → **측정 구간 ADR** |

```text
Timeout (깨지지 않게)
DB Query  <  Transaction  <  Integration  <  Client/Channel
```

| NFR | Runtime에서 증명 |
|---|---|
| Perf | 응답·지연 |
| Avail | 장애 시나리오 |
| Scale | 부하 증가 |
| Sec | 보안시험 |
| Obs | E2E Trace |

워크시트(설계서에 복사):

| NFR | 적용(Y/N) | 지표(초안) | 측정 구간 |
|---|---|---|---|
| Perf | | | |
| Avail | | | |
| Scale | | | |
| Sec | | | |
| Obs | | | |

## B4. Step 4 — 대구분 · 업무구분 코드표(B5.1) · 기능

근거: `빅픽처_어플리케이션분류체계구성정의_*` · **규범 코드표 = 정의서 01 §B5.1** (전체표는 정의서·CMDB SSOT).

| 코드 | 이름 |
|---|---|
| **MP** | 마케팅플랫폼 |
| **RD** | 데이터플랫폼 RDW |
| **AD** | 데이터플랫폼 ADW |
| **BI** | BI포탈 |
| **DG** | 데이터거버넌스 |
| **IM** | IT서비스·업무지원 |

```text
대구분(2) + 업무구분(2) + 기능(1)  → 예: MP + IC + A = MPICA
유일성: 업무구분만으로 식별 불가 → 대구분+업무구분 (RD-SR ≠ AD-SR)
```

할 일:

1. **정의서 §B5.1**에서 대구분별 업무구분 코드 찾기 (없으면 CMDB·분류 개정 — **임의 약어 금지**)  
2. 헤더: `대구분= / 업무구분= / 기능=`  
3. 패키지·ServiceId(08)와 **같은 언어** 유지  
4. RD/AD를 “DP/DW” 한 단어로 합치지 않기  

워크시트(설계서에 복사 · 코드 원문은 정의서 B5.1 참조):

| 대구분 | 업무구분(2) | 한글명(정의서) | 기능(1) | CMDB 등록 | 헤더 한 줄 |
|---|---|---|---|---|---|
| MP/RD/AD/BI/DG/IM | | | | ☐ | `대구분= / 업무구분= / 기능=` |

**확인**: “이 업무구분만 보고 RD인지 AD인지 헷갈리지 않는가?” → 대구분 병기.

## B5. Step 5 — 시스템 그룹 ↔ 서버 역할 매핑(B5.2)

| 개념 | 의미 |
|---|---|
| App Group | MP/RD/… |
| System Group | WEB/WAS/AP/DB/ETL/CDC/Batch 등 **배치 역할** |
| 논리 Base Name | `sbmpco` · `sbrdco` · `sbadco` · `sbbi*` 등 (Hostname 전) |

```text
App Group  ≠  System Group (1:1 아님)
예: RD+AD → 논리상 하나의 데이터플랫폼 시스템 그룹 가능
```

할 일: **정의서 §B5.2** 예시표에서 App Group → System/서버 역할 → 논리 Base Name → 업무구분 예를 고른 뒤 아래를 채운다. Hostname·인스턴스 번호는 [`05`](./05_시스템표준정의_설계가이드.md).

워크시트:

| App Group | System/서버 역할 | 논리 Base(예: sbmpco) | 업무구분 예 | Hostname 위임(05) |
|---|---|---|---|---|
| | WEB/WAS/AP/DB/… | | | ☐ |

## B6. Step 6 — 주제영역 6개 트리(B5.3) · 빅픽처 위치

규범 트리·업무구분 묶음: **정의서 01 §B5.3** (전체 복붙 금지 · 위치만 기입).

```text
차세대 정보계 데이터 주제영역
├─ 데이터플랫폼 RDW
├─ 데이터플랫폼 ADW
├─ BI포탈
├─ 마케팅플랫폼
├─ 데이터 거버넌스
└─ IT서비스 및 업무지원
```

| 질문 | 답 작성 |
|---|---|
| 주제영역 6 중 어디? | 위 트리 중 **하나** (복수면 경계 문장) |
| RDW vs ADW? | 실시간·로그·피드백 vs 분석·마트 |
| 채널만 / 이벤트까지 / DW까지? | **문장으로** 경계 |
| 빅픽처 박스 위치? | 그림에 표시 |
| 주제영역 ≠ EDW SA? | 플랫폼·업무·관리 영역(데이터 관리 관점)임을 인지 |

워크시트:

| 주제영역(6 중) | RDW/ADW/해당없음 | 업무구분 묶음(정의서 B5.3) | 빅픽처 박스 문장 |
|---|---|---|---|
| | | | |

## B8. 미니 예제

