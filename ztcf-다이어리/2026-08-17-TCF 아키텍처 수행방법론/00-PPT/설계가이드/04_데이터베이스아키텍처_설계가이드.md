# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 **어느 DW·어느 유입·어느 접근인가**를 고정한다. “DW 하나”로 뭉개기 전에, 아래를 먼저 잡는다.

```text
RDW인가 ADW인가?
CDC인가 ETL인가 · Downstream인가?
누가 어떤 계정으로 접근하는가?
OLTP 피크와 배치 창은 분리되는가?
```

```text
계정계 Source
        │
        ├─ CDC/OGG ──▶ Downstream ──▶ RDW (준실시간 SoR)
        └─ ETL(BCV) ────────────────▶ RDW
                                        │
                                        └─ ETL ──▶ ADW (분석 SoR)
```

목적 한 줄: **RDW ≠ ADW · CDC ≠ ETL · 계정계 직결 금지 · 접근표 · Integrity First DR.**

### 이 가이드가 답하는 것 / 답하지 않는 것

| 답하는 것 (절차) | 답하지 않는 것 |
|---|---|
| RDW/ADW·CDC/ETL·접근표 **기입 순서** | shall 문장 자체 → **정의서 04 Part B** |
| Downstream·OLTP/배치·HA 연결 워크시트 | Hostname 조립 → 05 · IF 전체표 → 06 |
| 초보자 실수·미니 예제 | Zone 전문 → 02 · Drill 수치 → 11 · DDL 전문 |

### 읽는 순서

```text
A1 → A2 큰 그림 → Part B Step 1~8 → 예제·실수 → 정의서 Part B로 규범 확인
```

```text
          ┌────────────── RDW ──────────────┐

          └───────────────┬─────────────────┘
```


## B1. Step 1 — RDW vs ADW

| 질문 | RDW | ADW |
|---|---|---|
| 실시간·준실시간·피드백? | ○ | |
| 분석·집계·부서 마트? | | ○ |
| 마케팅 운영성 조회? | ○ (계약 범위) | 필요 시 ETL 후 |
| BI·DG·IT지원 분석 영역? | | ○(구성도 확인) |

워크시트:

| 항목 | 기입 |
|---|---|
| 소속 (RDW/ADW/기타) | |
| 논리명 · 물리 서비스 | |
| 스키마 · 소유 시스템 | |
| 부적합 부하 회피 한 줄 | |

“DW” 단일 명칭으로 역할을 뭉개지 않는다. RDW/ADW는 **부하·책임 분리**(단순 Active 이중 복제가 아님).

## B2. Step 2 — RAC·이중화 전제

| Baseline | 내용 |
|---|---|
| 형태 | RDW·ADW 각 **Exadata RAC** · 1식 이중화 · Active–Active |
| 노드 수 | 구성도·인벤토리로 확정 |
| 금지 | **단일 노드 가정**으로 용량·가용 설계 |

근거: [`데이터베이스아키텍처_DB이중화구성도_분석.md`](../../04-PHYSICAL/데이터베이스아키텍처_DB이중화구성도_분석.md).

## B3. Step 3 — CDC vs ETL (06과 동일 표)

| 소스 | IF | 타깃 | 성격 | 설계에서 확정할 것 |
|---|---|---|---|---|
| 코어뱅킹 DB | **CDC** | RDW | 변경분 실시간 | 지연 SLA·측정 구간 |
| 코어 BCV | **ETL** | DW/RDW | 배치·대량·보정 | 배치 창·정합성 |
| RDW | **ETL** | ADW | 분석 모델 적재 | 소유·스키마 |
| DW(정보계) | **ETL** | 타 DB | 정보계→외부 | 계약·마스킹 |
| 타 DB | **ETL** | DW | 외부→정보계 | 원천 책임·품질 |

**금지 감각**: CDC에 대량 배치 / ETL로 실시간 가장 / Owner·SLA 미분리.

## B4. Step 4 — Downstream · OGG E2E · CDC must

계정계 부하 최소화 → **Downstream 포함**.  
근거: [`데이터베이스아키텍처_OGG구성도_분석.md`](../../04-PHYSICAL/데이터베이스아키텍처_OGG구성도_분석.md) · **정의서 §B5.1·B5.1a**.

### B4-a. OGG E2E 골격 기입 (정의서 B5.1a)

> Source에 Extract를 두지 않음 · Downstream Mining → Pump → RDW Replicat.

| 단계 | 위치 | 프로세스 | 본 설계 기입(Host/Service) | ☐ |
|---:|---|---|---|---|
| ① | 계정계 Source | Redo · LNSn/RFS | | |
| ② | Downstream | **Extract**(Standby Redo Mining→Local Trail) | | |
| ③ | Downstream | **Pump**(→ RDW ACFS Remote Trail) | | |
| ④ | RDW Target | **Replicat** | | |

확인:

- [ ] Source에 OGG Extract **재배치 없음**  
- [ ] 중계 DB #1·#2 + 공유 Trail Failover 전제  
- [ ] 지연 SLA = Source+Extract+Pump+Replicat **합** · 측정 구간 ADR  

### B4-b. CDC must (정의서 B5.2)

| 항목 | 기입 |
|---|---|
| 캡처 대상(테이블·스키마) | |
| DDL 대응 절차 | |
| 커밋 순서 보장 | |
| Trail/큐 · 보존 | |
| I/U/D 적용 규칙 | |
| 체크포인트·재시작 | |
| 지연 SLA · 측정 구간 **ADR** | |

계정계 원천에 정보계 배치·대량 조회 **직결 금지**.

## B5. Step 5 — 서버별 접근 매트릭스 (정의서 B6)

규범 전체 호출×RDW1~2×ADW1~6 표: **정의서 §B6** (P=Primary · S=Secondary · -=없음 · 실구현=**RAC Service**).  
가이드는 **해당 호출자 행만** 채운다.

근거: [`데이터베이스아키텍처_서버별데이터베이스접근방안_분석.md`](../../04-PHYSICAL/데이터베이스아키텍처_서버별데이터베이스접근방안_분석.md).

워크시트(정의서 B6에서 호출 서버를 고른 뒤 복사):

| 호출 서버/앱 | RDW1 | RDW2 | ADW1 | ADW2 | ADW3 | ADW4 | ADW5 | ADW6 | 방식 | 계정·권한 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|---|---|
| (예: 마케팅 #1) | P/S | S/P | - | - | - | - | - | - | JDBC | |
| | | | | | | | | | | |

규칙:

1. 호출 → 대상 → 방식 → 계정·권한을 **표로 고정**  
2. BI·마케팅 RDW/ADW는 **허용 계약** 범위  
3. 타 업무 소유 테이블 DAO/직접 SQL **금지**(08)  
4. 접근표에 없는 경로 → 개통·배포 금지  
5. `#1`→홀수 Node P, `#2`→짝수 Node P **교차** Baseline

## B9. 미니 예제

```text
신용실적 마트
  │
  ├─ 소속: ADW · 스키마/소유 명시
  ├─ 유입: RDW → ETL → ADW (#9)
  ├─ OGG(계정계→RDW): Downstream Extract/Pump · RDW Replicat (Source Extract 없음)
  ├─ 조회: BI/신용실적 WAS → JDBC → ADW 그룹 B(#3–#4)
  ├─ 창: 야간 적재 ↔ 오전 조회 피크 분리
  ├─ RAC: ADW Exadata · 단일 노드 가정 금지
  └─ 접근: 정의서 B6 행 기입 · 마케팅 WAS의 ADW 직결 검토→거부/ADR
```
