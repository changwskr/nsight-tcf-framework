## 1. 목적

단말·온라인·배치 프레임워크와 Upload/Download·RD·Inbound·SSO·예외·거래로그 등 **구성 요소의 책임과 진입점**을 정의한다.  
프레임워크가 제공하는 기능을 업무 코드에 **재구현하지 않는다**.

---

## 2. 온라인 진입점

| 경로 | URL | Wire | 변환 |
|---|---|---|---|
| 단말(xFrame) | `/ins/{ServiceId}` | xDataSet | → Map → ServiceContext |
| JSON | `/nb/{ServiceId}` | JSON | → DTO |

### 규범

1. **동일 ServiceId = 동일 Biz Service**로 합류한다.  
2. 임의 서블릿·비표준 URL 난립을 금지한다.  
3. ServiceId ↔ Controller 1:1 (08).  
4. 단말 경로 10단계(인식·변환·Context·Service·역변환)를 준수한다.

---

## 3. Framework vs 업무 책임

| Framework | 업무 개발 |
|---|---|
| ServiceId 라우팅 · 8단계 골격 · 시스템 선·후 · TX 경계 · 공통 예외·로그 훅 | 도메인 규칙 · DTO · 업무 선·후 검증 · 화면 메시지 |

## 5. 배치 프레임워크 (런타임 #12)

| 계층 | 책임 | 도구 |
|---|---|---|
| 오케스트레이션 | 등록·일정·선후행·기동·모니터링 | Control-M 등 |
| 실행 | Job/Step · commit · 재시작 | Spring Batch/표준 배치 FW |
| 상태 | JobInstance·checkpoint | JobRepository |
| 데이터 | 업무 원장 | 원장 DB (상태 DB와 분리) |

### 금지

- 온라인 WAS에서 장기 Batch  
- 프로그램 내부 Scheduler만으로 운영 배치  
- 재실행 시 중복 적재  
- 초대형 단일 TX  
- 업무일자 System Date 하드코딩  

Control-M 성공 조건과 BatchStatus/ExitStatus를 **매핑**한다.
