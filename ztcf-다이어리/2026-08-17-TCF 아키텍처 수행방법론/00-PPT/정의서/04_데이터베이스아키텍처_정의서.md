# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 정보계 DW(RDW/ADW)의 **역할 분리·이중화·유입 경로·Downstream·서버별 접근·OLTP/배치 공존·HA/DR** 기준을 정의하여, “DW 하나”로 뭉개진 설계를 금지한다.

```text
계정계 Source
        │
        ├─ CDC/OGG ──▶ Downstream ──▶ RDW (준실시간 SoR)
        └─ ETL(BCV) ────────────────▶ RDW
                                        │
                                        └─ ETL ──▶ ADW (분석 SoR)
```

목적(한 줄):

```text
RDW ≠ ADW
CDC ≠ ETL
계정계 직결 금지 · 접근표 · Integrity First DR
```

| 축 | 장표의 정의 초점 | 핵심 대상 |
|---|---|---|
| 역할 분리 | RDW / ADW | 데이터·개발·BI |
| 유입 | CDC · ETL · Downstream | IF·물리 |
| 공존·HA | OLTP/배치 · RAC · DR | DBA·운영 |

### 이 문서가 답하는 것과 답하지 않는 것

| 답하는 것 (개요 수준) | 답하지 않는 것 (후속·인접) |
|---|---|
| RDW/ADW 정의·소속 판정 | Hostname 조립 (05) |
| RAC Baseline · Downstream | IF 온라인/파일 전체표 (06) |
| CDC/ETL 전체표 · CDC must | Zone·레이어드 전문 (02) |
| 서버별 접근표 · OLTP/배치 | Drill·RTO 수치 전문 (11) |
| HA/DR Integrity First 연결 | 스키마 DDL 전문 |

한 문장: **“어느 DW·어느 유입·어느 접근인가”를 고정**하고, **매체표·명명·Drill은 인접 정의서에 위임**한다.

# Part B — 적용 규범

> 설계·구현·검토 시 **Part B를 우선**한다. Part A와 표현이 다르면 Part B의 shall/must/금지를 따른다.

## B1. 준수 의무

1. 신규 저장·조회·적재는 **RDW 또는 ADW(또는 승인된 소유 DB)** 중 소속을 must 명시한다.  
2. CDC와 ETL 책임·SLA를 혼동하지 않는다.  
3. 계정계 원천에 정보계 배치·조회를 **과다 직결**하지 않는다(중계·BCV·CDC 경로).  
4. 타 업무 소유 테이블에 DAO/직접 SQL을 금지한다(공개 API·표준 IF).

## B2. 용어 (규범용)

| 용어 | 정의 |
|---|---|
| RDW | Real-time Data Warehouse. 준실시간 SoR, 로그·피드백·마케팅·운영성 조회 |
| ADW | Analytic DW. 분석 SoR, 집계·마트·대량 조회 |
| RAC | Active-Active DB 다중 노드 |
| Exadata | RDW/ADW 어플라이언스 Baseline |
| CDC | 변경 로그 실시간(준실시간) 캡처 |
| OGG | GoldenGate 계열 복제 |
| Downstream | 계정계 부하 분산을 위한 중계 구성 |
| BCV | 복사본/스냅샷 원천(ETL용) |
| 정보계 DW | 장표 표기. 설계서에서는 논리명·물리·스키마·소유로 **분해 필수** |

## B3. RDW / ADW

| 구분 | 정의 | 적합한 부하 | 부적합 |
|---|---|---|---|
| **RDW** | 준실시간 SoR · 로그 · 피드백 · 마케팅 정보 | 온라인·이벤트 근접 조회 | 대량 분석이 상시 점유 |
| **ADW** | 분석 SoR · 집계 · 마트 | BI·부서 마트·대량 조회 | “실시간처럼” 가장한 경로 |

### shall

1. RDW와 ADW는 **단순 Active 이중 복제가 아니라 부하·책임 분리**로 정의한다.  
2. “DW” 단일 명칭으로 역할을 뭉개지 않는다.  
3. BI·DG·IT지원의 분석 영역은 구성도에서 **ADW(또는 지정 스키마)** 소속을 확인한다.  
4. 장표의 `정보계 DW` / `DW` / `RDW`는 설계서에 **논리명 · 물리 서비스 · 스키마 · 소유 시스템**으로 매핑한다.

## B4. 이중화 (RAC)

1. RDW·ADW는 각각 **Exadata RAC 이중화**를 Baseline으로 한다.  
2. 장표 Baseline: 각 **1식 이중화**, RAC(Active–Active) 노드 구성은 구성도·인벤토리로 확정한다.  
3. **단일 노드 가정**으로 용량·가용성을 설계하지 않는다.  
4. DR·복제 전략은 Integrity First를 따르며, 이론적 DB Active-Active 운영 복잡성을 그대로 채택하지 않는다(11·HA-DR).

## B5. 데이터 유입 (CDC / ETL)

06 데이터 IF와 **동일 표**를 규범으로 한다.

| 소스 | IF | 타깃 | 성격 | shall |
|---|---|---|---|---|
| 코어뱅킹 DB | **CDC(실시간)** | 정보계 DW(RDW) | 변경분 실시간 | 지연 SLA·측정 구간 |
| 코어뱅킹 DB BCV | **ETL** | 정보계 DW | 배치·대량·보정 | 배치 창·정합성 |
| RDW | **ETL** | ADW | 분석 모델 적재 | 소유·스키마 명시 |
| DW(정보계) | **ETL** | 타 시스템 DB | 정보계→외부 | 계약·마스킹 |
| 타 시스템 DB | **ETL** | DW | 외부→정보계 | 원천 책임·품질 |

### B5.1 Downstream (must)

1. 계정계 부하 최소화를 위해 **Downstream(중계)** 구성을 원칙으로 한다.  
2. OGG/CDC 구성도를 준수한다: `데이터베이스아키텍처_OGG구성도_분석.md`.  
3. 계정계 원천에 정보계 배치·대량 조회를 **직결**하지 않는다.

### B5.1a OGG E2E 골격 (shall)

> Source에 Extract를 두지 않고 Downstream Mining → Pump → RDW Replicat.

| 단계 | 위치 | 프로세스 | 역할 |
|---:|---|---|---|
| ① | 계정계 Source | Redo · LNSn/RFS | Online/Archived Redo를 중계 DB Standby Redo로 전송 |
| ② | Downstream 중계 | **Extract** | Standby Redo Mining → Local Trail 생성 |
| ③ | Downstream 중계 | **Pump** | Trail을 RDW ACFS Remote Trail로 전송 |
| ④ | RDW Target | **Replicat** | Trail 적용 → RDW DB 반영 |

- 중계 DB #1·#2 + 공유 Trail은 Extract·Pump Failover 기반.  
- Source에 OGG Extract를 **재배치하지 않음**(Mining 부하의 Downstream 이전).  
- 지연 SLA = Source 전송 + Extract + Pump + Replicat 합 · 측정 구간 ADR.

### B5.2 CDC 설계 must 항목

| 항목 | 내용 |
|---|---|
| 캡처 대상 | 테이블·스키마 목록 |
| DDL 대응 | 추가·변경·폐기 절차 |
| 커밋 순서 | 순서 보장 여부 |
| Trail/큐 | 경로·용량·보존 |
| I/U/D 적용 | 적용 규칙 |
| 체크포인트 | 재시작·복구 |
| 지연 SLA | 측정 구간 **ADR** |

### B5.3 유입 금지

- CDC 파이프에 **대량 배치** 책임 혼재  
- ETL로 “실시간처럼” 가장  
- 표준표에 없는 임시 JDBC/파일 직결 상시화  
- CDC와 ETL SLA·Owner 미분리  
- Source DB에 Extract 직배치로 Downstream 원칙 파기

## B7. OLTP와 대용량 배치 공존

> 근거: `데이터베이스아키텍처_OLTP및대용량배치수행방안_분석.md`

1. 온라인 피크와 배치 윈도우를 **겹치지 않게** 정의한다.  
2. 자원(서버·서비스·큐·스키마/리소스 그룹)을 **분리**한다.  
3. 실패 시 **재처리·정합성 Owner**를 명시한다.  
4. 온라인 경로에 대량 ETL 잡을 혼재시키지 않는다.

### B7.1 ADW Node 그룹

| 그룹 | Node | 역할 | 주요 호출자 |
|---|---|---|---|
| **A** | ADW #1–#2 | **대용량 배치 / OLAP** (Undo·Temp 추가) | ETL·배치 AP·OLAP |
| **B** | ADW #3–#4 | **일반 배치 / BI** | BI포탈·신용실적·Self-BI·일반 ETL |
| **C** | ADW #5–#6 | **Online / 거버넌스** | 데이터흐름관리·비즈메타·데이터품질 |

그룹 내 2노드는 정상 시 분산, 장애 시 **상호 Failover**. RAC Service를 업무 단위로 구성한다.

### B7.2 RDW Node 역할

| Node | 역할 |
|---|---|
| **RDW #1** | 마케팅 Online 중심(AP #1 affinity) |
| **RDW #2** | 마케팅 Online(AP #2) + **OGG Replicat** + **대용량 ETL** |

- OGG·대용량 ETL이 #2에 집중되므로 Online 경합·N-1 부하를 검증한다.  
- affinity는 connection 고정이 아니라 **RAC Service**로 구현.

## B8. HA / DR

[`HA-DR.md`](../../04-PHYSICAL/HA-DR.md): **AP Active-Active + 현실적 DB DR · Integrity First**.

1. 장애 시나리오에 **RDW · ADW · CDC Relay**를 포함한다(11 정의서).  
2. RTO/RPO·정합성 전략 없이 “RAC이므로 고가용”만 쓰지 않는다.  
3. DR Host(03·05)와 DB 복제/전환 절차가 **대응**되어야 한다.
