# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 단말·온라인·배치 프레임워크와 Upload/Download·RD·Inbound·SSO·예외·거래로그의 **책임·진입점**을 정의한다.  
FW가 제공하는 기능을 업무 코드에 **재구현하지 않는다**.

```text
Client / Channel
        │
        ▼
진입점 (/ins · /nb) ──▶ Framework
        │                    │
        │                    ├─ 라우팅 · 8단계 · TX · 로그
        │                    └─ 메커니즘 부품
        ▼
   Biz Service (동일 ServiceId 합류)
```

목적(한 줄):

```text
표준 진입점 · FW 책임 · 메커니즘 재사용 · 배치 계층 분리
        │
        ▼
업무는 도메인만 · 운영 배치는 Control-M
```

| 영역 | 장표의 정의 초점 | 핵심 대상 |
|---|---|---|
| 온라인 진입 | `/ins` · `/nb` · ServiceId | 단말·개발 |
| FW vs 업무 | 제공 범위 · 재구현 금지 | 프레임워크·앱 |
| 메커니즘 | Upload/RD/Inbound/SSO/예외/로그 | 공통 부품 |
| 배치 | 오케스트레이션·실행·상태·원장 | Control-M·Batch FW |

### 이 문서가 답하는 것과 답하지 않는 것

| 답하는 것 (개요 수준) | 답하지 않는 것 (후속·인접) |
|---|---|
| `/ins`·`/nb` 진입·합류 규칙 | 8단계 본문 (08) |
| FW vs 업무 책임 경계 | IF 표준표 전문 (06) |
| 메커니즘 사용/미사용/예외 | 런타임 #1~#11 시퀀스 (07) |
| 배치 4계층 · Control-M shall | Hostname·용량 (03·05) |
| 형상배포·상용 FW 경계 | RTO Drill (11) |

한 문장: **“어디서 들어가고 무엇이 FW 책임인가”를 고정**하고, **표준 전문·런타임 시퀀스는 인접 정의서에 위임**한다.

### 읽는 순서 권장

```text
A1 핵심 → A3 장표 재현 → A4 계층 트리
        │
        ├─ 진입점이면 A5
        ├─ FW/업무면 A6
        ├─ 메커니즘이면 A7
        ├─ 배치면 A8~A9
        └─ 적용은 Part B
```

# Part B — 적용 규범

> 설계·구현·검토 시 **Part B를 우선**한다. Part A와 표현이 다르면 Part B의 shall/must/금지를 따른다.

## B1. 준수 의무

1. 온라인 신규 Service는 **`/ins` 또는 `/nb` + ServiceId**로만 진입한다.  
2. FW가 제공하는 라우팅·TX·로깅·메커니즘을 업무에서 **재구현하지 않는다**.  
3. 배치 운영은 **Control-M 중앙 통제**를 전제로 한다(07 #12와 정합).  
4. 본 정의서와 충돌하는 설계는 **ADR/Gap 승인 전** 적용하지 않는다.

## B2. 용어 (규범용)

| 용어 | 정의 |
|---|---|
| ServiceId | 온라인 서비스 식별자. Controller 1:1 · 단말/JSON 합류 키 |
| ServiceContext | 단말(`/ins`) 경로의 표준 Context |
| JobRepository | 배치 실행 상태 저장소. 원장 DB와 분리 |
| 메커니즘 | Upload/RD/Inbound/SSO/Exception/거래로그 등 FW 공통 부품 |
| 오케스트레이션 | Control-M 등 일정·선후행·모니터링 계층 |

## B3. 온라인 진입점

| 경로 | URL | Wire | 입력 변환 | Context |
|---|---|---|---|---|
| 단말(xFrame) | `/ins/{ServiceId}` | xDataSet | → Map | ServiceContext |
| JSON | `/nb/{ServiceId}` | JSON | → DTO | DTO+hdr |

### shall

1. **동일 ServiceId = 동일 Biz Service** 합류.  
2. ServiceId ↔ Controller **1:1**(08).  
3. 임의 서블릿·비표준 URL 금지.  
4. 단말 경로: ServiceId 인식 → xDataSet↔Map → Context → Service → 역변환 → 응답.  
5. Charset UTF-8 등 캐릭터셋 정의(08)와 정합.  
6. xDataSet: `header(version·화면번호) + datasets[]` 준수.

## B4. Framework vs 업무

| Framework (shall 제공) | 업무 개발 (shall) |
|---|---|
| ServiceId 라우팅 · 8단계 골격 · 시스템 선·후 · TX 경계 · 공통 예외·로그 훅 | 도메인 규칙 · DTO · 업무 선·후 · 화면 메시지 |

FW 로깅·TX·라우팅을 업무에서 재구현 **금지**.

### B5.1 SSO 계약 (shall)

| 계약 필드 | 역할 |
|---|---|
| `nonce` | 서버 세션에 보관한 일회성 난수. 요청 body만으로 검증 **금지** |
| `ticket` | SSO 발급 증표. 복호화·서명/무결성 검증 후 내부 userId를 **권위값**으로 사용 |
| `ssoId` | 요청 측 식별자. ticket 내부 ID와 **일치 검증용**. 단독 신뢰 **금지** |

1. 검증 성공 시에만 업무 세션(`userId`/`loginYN` 등)을 생성한다.  
2. nonce는 검증 후 **즉시 소비**(재전송·동시 성공 차단).  
3. **금지**: SSO 우회 로그인 상시화 · 브라우저 `ssoId`만으로 세션 복사 · ticket 미검증 신뢰 · URL query로 ticket 평문 전달.

### B5.2 Upload / Download 시퀀스 (shall)

**Upload** (`/upload/{serviceId}` · Multipart → `Map(List, Body)`):

```text
xFrame → NhFileController → 선처리 → Multipart→Map
  → Service: File[] PUT(Object Storage/FOS) + Body·메타 DB
  → 후처리 → 성공/실패 응답
```

**Download** (`/download/{serviceId}`):

```text
xFrame → NhFileController → 선처리 → Service(fileId→objectKey)
  → Object Storage GET(InputStream) → HTTP OutputStream 복사 → 후처리·감사
```

1. 바이너리=FOS/Object Storage · 메타=DB. 업무별 로컬 FS/FTP 클라이언트 **금지**.  
2. **완료 전 소비 금지**: Upload `COMPLETED`(또는 동등 완료신호) 전 업무 원장 반영·후속 거래 기동 금지. Download는 **전송 완료 후** 성공 감사.  
3. 외부 계약은 `fileId`(불투명). 원본 파일명을 저장소 경로로 직접 사용 **금지**.  
4. GUID·serviceId·fileId/objectKey로 거래·파일 **상관**.

### B5.3 예외 계약 — `NhBaseException` (요약)

Service는 예외를 `NhBaseException`으로 정규화해 throw → Controller/경계에서 **rollback 선행** → 공통 ErrorProcess → 표준 오류전문 + xFrame 메시지.

| 구분 | 필드(요약) | 노출 |
|---|---|---|
| 외부 계약 | `stdErrCode` · `errMsgType`(RUNTIME/COMMON/BIZ/AUTH/SERVICE) · 메시지 args | 클라이언트·IF |
| 사용자 메시지 | `stdErrMsgContents` · `addMsgContents` | UI(허용 범위) |
| 내부 진단 | `obskindCode`(장애종류) · `errServiceName`/`errClassName` · `errMethodName` · `errFileName` · `pgmLineNo` · cause | 로그·관제(운영 UI 과다 노출 금지) |

오류전문·UI·진단정보를 **한 객체에서 수집하되 표현 단계에서 분리**. 예외 삼키기·업무별 오류 DTO 난립 **금지**.

### B5.4 거래로그 must 컬럼 · GUID

이중 관측: **Console/App Metric** + **업무 DB 거래로그**. DB는 요청 시 INSERT → 정상/오류 후처리에서 **동일 GUID 행 UPDATE**(lifecycle).

| must 컬럼(공통) | 설명 |
|---|---|
| GUID / 글로벌ID | E2E correlation (08과 정합) |
| 서비스ID | ServiceId |
| 요청·응답 일시 · 소요시간 | 성능·미완료 탐지 |
| 사용자 · 단말IP(해당 시) | 감사 |
| 결과구분 · 에러코드/내용 | SUCCESS/FAILED/TIMEOUT |
| 요청·응답 전문(또는 ref) | 재현·마스킹 정책 적용 |

Console과 DB의 GUID·서비스·시간·결과는 **동일 논리 이벤트**에서 파생. GUID 없는 분산 로그만 남기는 것 **금지**.

## B6. 배치 프레임워크 (런타임 #12)

근거(08-22): `메커니즘-아키텍처 구성-배치_처리_프레임워크_구조_및_컴포넌트_분석.md`

### B6.1 계층 분리 (must)

| 계층 | 책임 | 도구 |
|---|---|---|
| 오케스트레이션 | 등록·일정·선후행·기동·모니터링 | **Control-M** 등 |
| 실행 | Job/Step · commit · 재시작 | Spring Batch/표준 배치 FW |
| 상태 | JobInstance·checkpoint | **JobRepository** |
| 데이터 | 업무 원장 | 원장 DB (**상태 DB와 분리**) |

### B6.2 기동 체인 (shall)

```text
Control-M Agent → Shell(환경·인자·exit code) → JobLauncher
  → Job → Step(Chunk: Reader→Processor→Writer | Tasklet)
  → JobRepository(checkpoint/status) ↔ 원장 DB(업무 I/O)
```

1. Shell은 bootstrap·파라미터 검증·ExitStatus→OS exit code 변환에 **한정**. Shell에서 업무 DB 갱신 **금지**.  
2. Control-M 성공 조건 ↔ BatchStatus/ExitStatus **매핑**. Agent timeout ≠ Job 실패로 단정하지 말고 JobRepository를 확인한다.

### B6.3 배치 shall

1. 작업을 자동화 관리에 **등록**.  
2. 선후행·달력·수시 승인을 Control-M에 둔다.  
3. JobParameters로 JobInstance를 식별(업무일자·회차 등). 완료 instance 동일 파라미터 **중복 신규 실행 금지**.  
4. **재시작 shall**: 실패 Step은 JobRepository checkpoint(마지막 commit 이후)부터 재개 · Writer **멱등**(업무키) · BATCH_*를 운영자가 직접 COMPLETED로 UPDATE **금지**(표준 restart/abandon만).  
5. 대량 반복은 Chunk Step · 단발성 작업은 Tasklet.

### B6.4 배치 금지

| 금지 | 이유 |
|---|---|
| 온라인 WAS에서 장기 Batch | 자원 경합·타임아웃 |
| 앱 내부 Scheduler만으로 운영 | 휴일·선후행·승인 부족 |
| 재실행 중복 적재 | 정합성 |
| 초대형 단일 TX | 락·롤백 |
| 업무일자 System Date 하드코딩 | 재처리·마감 오류 |
| JobRepository와 원장 DB 혼용 | 재시작·감사 붕괴 |

## B7. 형상배포 · 상용 FW

1. 개발/운영 빌드 표준·통합개발환경(GitLab·Runner·NEXUS 등)에 **없는 산출물의 운영 투입 금지**.  
2. 자체 FW와 상용/솔루션 위임 경계를 표로 관리하고 **중복 구현을 제거**한다.

- `/ins`·`/nb` 외 임의 진입 URL 상시화
