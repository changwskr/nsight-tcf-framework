## 1. 목적과 적용 범위

### 1.1 목적

차세대 정보계 아키텍처의 **공통 이해 체계와 적용 기준선**을 제공하여, 인프라·개발·유관 담당자가 Technical / Application / Data를 동일 언어로 식별·적용하도록 한다.

### 1.2 포함 / 제외

| 포함 | 제외 |
|---|---|
| 3축 정의·개편 방향·NFR·SLA 기준선 | 서버 Hostname·스펙 |
| 대구분 MP~IM · 3단 분류 | Zone 상세·레이어드 (02 정의서) |
| 시스템 그룹·주제영역 위치 | IF 매체·런타임 시퀀스 |

### 1.3 준수 의무

1. 신규 요구·기능은 본 정의서의 **대구분·방향·NFR**에 매핑한 뒤 상세 설계한다.  
2. 분류 코드 임의 약어·별칭 사용을 금지한다.  
3. 충돌 시 ADR/Gap 승인 전 적용하지 않는다.

## 2. 아키텍처 3축 정의

| 축 | 정의 초점 | 핵심 대상 |
|---|---|---|
| **Technical** | 운용환경별 논리·물리 구성, SW, 센터, 백업·가용성 | 인프라·기술 플랫폼 |
| **Application** | 구성·분류·동작 원리·표준화 | 업무 애플리케이션·개발 |
| **Data** | 데이터 주제영역 | 데이터 구조·분류 (상세는 영역별 가이드) |

상세 구현·운영 Runbook은 영역별 가이드·후속 정의서에 위임한다.

---

## 3. 개편 4대 방향

모든 아키텍처·요구 판단은 다음 방향에 **기여 여부를 명시**한다.

| # | 방향 | 정의 |
|---:|---|---|
| 1 | 고객 중심 서비스 강화 | 채널 연계·CX·UI/UX 개선 |
| 2 | 데이터 기반 의사결정 강화 | 실시간 수집·즉시 제공·현업 활용 |
| 3 | 통합 정보 활용 기반 | 고객·상품·채널 통합 조회 |
| 4 | 유연·안정 운영체계 | 표준 구조·확장 플랫폼·안정 운영 |

어느 방향에도 해당하지 않으면 범위 재검토 또는 ADR로 기록한다.

## 4. NFR 5축 정의

| NFR | 목표(요지) | 설계 전략(요지) |
|---|---|---|
| **Performance** | 온라인·이벤트 성능 보호, 대량이 온라인 침해 금지 | FAST/DEEP·온/배·RDW/ADW·Kafka vs ETL 분리 |
| **Availability** | 이중화·장애 영향 최소화·현실적 DR | 기능별 분리·Fault Isolation·AP Active-Active·Integrity First DB DR |
| **Scalability** | 부하·서비스 증가 대응 | 서비스 VM Scale-Out·데이터 병렬 확장·도메인 독립 |
| **Security** | 인증·권한·개인정보·전송 보호 | SSO/JWT·마스킹·암호화·감사·FW 공통 |
| **Observability** | 평시 측정·E2E 추적 | GUID·APM·거래로그·Runtime Evidence |

### 4.1 SLA 기준선 (프로젝트에서 수치 확정)

| 구분 | 전략 Baseline 예 |
|---|---|
| 일반 온라인/마케팅 | 약 3초 |
| FAST 이벤트·오퍼링 | 약 1초 |
| 일배치 | 오전 6시 이전 완료 |
| CDC 등 | 문서 간 충돌 시 **측정 구간을 ADR로 확정** |

### 4.2 Timeout 계층

`DB Query < Transaction < 외부 Integration < Client/Channel` 순을 깨지 않는다.

## 5. 어플리케이션 분류 체계

### 5.1 3단 구조

```text
대구분(Application Group, 2) → 업무구분(Application, 2) → 기능(Function, 1)
```

기능 코드는 분석·설계 시 반영한다. 코드 사전(CMDB)을 Single Source로 한다.

### 5.2 대구분 코드 (고정)

| 코드 | 명칭 |
|---|---|
| **MP** | 마케팅플랫폼 |
| **RD** | 데이터플랫폼 RDW |
| **AD** | 데이터플랫폼 ADW |
| **BI** | BI포탈 |
| **DG** | 데이터거버넌스 |
| **IM** | IT서비스 및 업무지원 |

데이터플랫폼은 논리상 하나여도 분류 코드는 **RD와 AD로 분리**한다.

### 5.3 시스템 그룹

App Group을 WEB/WAS/AP/DB/ETL/CDC/Batch 등 **배치 역할**에 매핑한 단위다. App Group ≠ System Group 1:1일 수 있다(예: RD+AD → 데이터플랫폼 시스템 그룹).

---

## 6. 데이터 주제영역 · 최상위 구조

1. 데이터는 주제영역 정의에 따라 분류하며, RDW(실시간·로그·피드백 등)와 ADW(분석·마트) 축을 혼동하지 않는다.  
2. 신규 기능은 Big Picture 최상위 구조상 **채널 / 앱 서비스 / 이벤트 / 데이터플랫폼 / 유관·대외** 중 위치를 명시한다.
