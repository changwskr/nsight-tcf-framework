## 1. 목적

온라인 거래의 **패키지 계층·8단계 골격·표준전문·GUID·캐릭터셋·호출 규칙**을 전 업무에 동일 적용한다.

---

## 2. 패키지·계층

```text
대구분 → 업무구분 → 기능 → Controller / Service / DAO / resource
```

분류 코드(01)와 패키지 경로를 동일 언어로 유지한다. ServiceId와 Controller 메서드는 **1:1**.

---

## 3. 거래 처리 8단계

| Step | 이름 | 필수 | 담당 |
|---:|---|---|---|
| 1 | 시스템 선처리 | 필수 | Framework |
| 2 | 공통 선처리 | 선택 | 애플리케이션 |
| 3 | 업무 선처리 | 선택 | 서비스 |
| 4 | Controller 본처리 | 필수 | 개발 |
| 5 | Biz Service | 필수* | 개발 (*0개 호출 가능하나 통상 존재) |
| 6 | 업무 후처리 | 선택 | 서비스 |
| 7 | 공통 후처리 | 선택 | 애플리케이션 |
| 8 | 시스템 후처리 | 필수 | Framework (Commit/Rollback·로그·해제) |

- Controller → Service는 **DTO**. Service → DAO → SQL → DB.  
- 본처리 직후 응답을 완료로 보지 않는다. **8단계까지** 완료해야 한다.  
- Controller에서 SQL/DAO 직접 호출 금지.  
- 공통 선처리에 ServiceId별 조건문 폭주 금지.

---

## 4. 표준전문

1. 채널~채널통합~업무 AP~대내통합~연계는 **표준전문**을 적용한다.  
2. **패키지 UI → BI** 는 예외(개별 처리). 설계서에 명시.  
3. FLAT와 JSON/HTTP는 동일 표준의 **구간별 표현**이다. MCA 등은 변환 책임을 진다.  
4. Direct(정보단말)라도 인증·GUID·오류전문·거래로그 규칙은 동일 적용.

---

## 5. GUID

| 규칙 | 내용 |
|---|---|
| R1 | 표준전문 내 GUID를 노드 간 식별자로 사용 (Package UI 제외 가능) |
| R2 | **채널**이 최초 거래 시작 시 GUID 설정 |
| R3 | 로그는 **원거래글로벌ID**로 E2E 조회 |
| R4 | 노드 경유 시 **진행번호 +1** 후 전달 |

왕복 모델 진행번호 1~7. 진행번호 자동 +1의 구현 주체(어댑터 vs AP)는 프로젝트에서 확정·스키마와 대조한다(Gap 가능).

---

## 6. 캐릭터셋

화면·연계·DB 구간별 캐릭터셋을 정의·준수한다. 파일 IF Layout과 정합한다.

## 7. 업무 간 호출

1. 계층 방향: Controller → Service → DAO만.  
2. 타 기능: Service 계약. 타 앱: 공개 API. 타 그룹/외부: 06 표준 IF.  
3. 타 업무 DAO/테이블 직접 접근 **금지**.  
4. 원격 호출을 로컬 TX로 묶지 않음 → 멱등·타임아웃·보상.
