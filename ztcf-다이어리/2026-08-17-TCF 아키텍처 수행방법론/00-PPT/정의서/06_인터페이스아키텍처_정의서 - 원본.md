## 1. 목적

온라인·파일·데이터 연계의 **표준 매체와 원칙**을 고정하여 자원 경합을 줄이고 플랫폼 독립성을 유지한다.  
표준표에 없는 매체는 **ADR·표준 개정 없이 상시 경로로 쓰지 않는다**.

### 구축 원칙 (must)

1. 온라인 AP / 배치 AP **자원 분리**  
2. ETL 서버 **독립**  
3. 이벤트(Kafka) 서버 **분리**  
4. CDC **중계**로 원천 부하 분산  

---

## 2. 연계 유형 분류

신규 연계는 다음 중 하나로 분류한다. 복수면 **행을 분리**한다.

| 유형 | 정의 |
|---|---|
| 온라인 | 화면·API·요청/응답 |
| 파일 | 파일 송수신 |
| 데이터 | DB↔DB 동기화·적재 |

---

## 3. 온라인 인터페이스 표준

| No. | 소스 | IF 시스템 | 타깃 | 설명 |
|---:|---|---|---|---|
| 1 | 통합업무시스템 | 영업점 MCA | 정보계 | 대면 표준 |
| 2 | 비대면 채널 | MCI | 정보계 | 비대면 표준 |
| 3 | 정보계 단말 | 없음(Direct) | 정보계 | 중계 없음 — 앱이 인증·검증 직접 |
| 4 | 패키지 UI | 없음(Direct) | 정보계 솔루션 | 예외 — 남용 금지 |
| 5 | 정보계 | API G/W(Cruz APIM) | 대내 | 양방향 표준 |
| 6 | 대내 | API G/W(Cruz APIM) | 정보계 | 양방향 표준 |
| 7 | 정보계 | API G/W | 대외 | 대외 전문 |
| 8 | 대외 | API G/W | 정보계 | 대외→정보계 |
| 9 | 타 법인 | GSE | 정보계 | 법인 간 표준 |

### 온라인 규범

- APIM 경유 시 **논리 API**만 호출한다. 물리 URL 하드코딩 금지.  
- Direct는 인증·인가·검증·Rate Limit·감사·오류를 앱이 **직접** 제공한다.  
- 대외는 Gateway 외에 DMZ·인증서·암호화·대사·타임아웃을 별도 정의한다.

### 파일 계약 must
