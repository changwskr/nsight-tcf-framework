# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 SELF-BI·OLAP·EBM·Package UI 등 **업무 솔루션**을 플랫폼·IF·런타임·보안 경계 안에 두는 Baseline Entry Point다.  
IF·런타임·SSO 구멍이 생기지 않도록 한다.

```text
업무 솔루션 아키텍처 (10장)
        │
        ├─ 소속 (BI / MP / RD·AD / DG / IM)
        ├─ IF · 매체 · Direct 예외
        ├─ 런타임 주/보조 # (1~12)
        └─ 데이터 소유 · SSO · 표준전문
```

목적(한 줄):

```text
Package · SELF-BI · EBM · 포탈 …
        │
        ▼
소속 · IF · 런타임 · 보안 헤더 고정
        │
        ▼
06 / 07 / 08 / 09 와 구멍 없이 연결
```

| 솔루션 성격 | 장표의 정의 초점 | 핵심 대상 |
|---|---|---|
| BI·OLAP·신용실적 | 소속 BI · Package Direct 예외 | BI 포탈 / 현업 분석 |
| 캠페인·EBM | 소속 MP · FAST 런타임 | 마케팅 / 오퍼 |
| 마트·적재 | 소속 RD/AD | 데이터 플랫폼 |
| 메타·비즈메타 | 소속 DG | 거버넌스 |
| IT 지원 도구 | 소속 IM | IT 공통 |

### 이 문서가 답하는 것과 답하지 않는 것

| 답하는 것 | 답하지 않는 것 (후속) |
|---|---|
| 필수 헤더 · 소속 매핑 | Hostname·스펙 (03·05) |
| PPT Gap Baseline 선언 | IF 표준표 전문 (06) |
| IF/런타임·SSO 규칙 요약 | 런타임 시퀀스 전문 (07) |
| 금지·체크리스트 | 메커니즘 8단계 전문 (08) |

한 문장: **“솔루션을 어디에 소속시키고 어떤 IF/런타임으로 묶을지”를 고정**하고, **매체표·시퀀스 상세는 06·07에 위임**한다.

### PPT Gap (Baseline 선언)

PPT 10장 본문이 미비하거나 목차만일 경우 Baseline:

```text
PPT 10장 약함
        │
        ├─ ① 본 정의서 (헤더·규범)
        ├─ ② 03-LOGICAL 레이어드/IF
        ├─ ③ 06-RUNTIME 유형 1~12
        └─ ④ 05-MECHANISM (SSO·표준전문 예외)
```

복사용 Gap 문구 (FACT 템플릿):

> PPT 10장 본문 미비. 본 설계는 03-LOGICAL 레이어드/IF + 06-RUNTIME 유형 #N + 05-MECHANISM(SSO/예외) 을 Baseline으로 함.

추후 PPT 보강 시 본 헤더·체크리스트를 장표 목차로 사용한다.

### 읽는 순서 권장

```text
A1 핵심·Gap → A3 장표 구조 → A4 소속 트리
        │
        ├─ 헤더가 궁금하면 A5
        ├─ IF/런타임 위치가 궁금하면 A6
        └─ 도입 리뷰는 Part B
```

# Part B — 적용 규범

> 설계·도입·변경 리뷰 시 **Part B를 우선**한다. Part A와 표현이 다르면 Part B의 shall/must/금지를 따른다.

## B1. 준수 의무 · PPT Gap

1. 솔루션 도입·변경 설계서는 **§B3 필수 헤더**를 빠짐없이 기입한다.  
2. Package Direct·표준전문 예외는 06·08의 **예외 행**만 허용한다.  
3. 기존 신용실적·비즈메타 IF MD를 재사용하고 **동일 연계를 재발명하지 않는다**.  
4. PPT 10장 본문 미비 시 아래 Baseline을 쓴다.

Baseline:

1. 본 정의서  
2. `03-LOGICAL` 레이어드/IF 분석 MD  
3. `06-RUNTIME` 유형 1~12  
4. `05-MECHANISM`(SSO·표준전문 예외)

복사용 Gap 문구:

> PPT 10장 본문 미비. 본 설계는 03-LOGICAL 레이어드/IF + 06-RUNTIME 유형 #N + 05-MECHANISM(SSO/예외) 을 Baseline으로 함.

## B2. 용어 (규범용)

| 용어 | 정의 |
|---|---|
| Package UI | 상용 화면(예: MSTR). 표준전문 **예외** 가능 |
| SELF-BI / OLAP | 현업·다차원 분석 |
| 신용실적 | BI 특수 연계(전용 IF MD) |
| EBM | 이벤트 기반 마케팅 실시간 |
| 비즈메타 | DG 메타·연관 |
| Direct | IF 시스템 미경유 — **예외·책임 가중** |

## B3. 필수 헤더 (must)

솔루션 도입·변경 설계서는 다음을 **반드시** 기입한다. 공란·“추후”만 있으면 리뷰 미통과.  
(헤더 필드 집합은 고정 — 08-22 보강은 §B5·§B7 예시로 채운다.)

| 항목 | 내용 | 참조 |
|---|---|---|
| 솔루션명 | 공식명 | — |
| 소속 시스템 그룹 | BI / MP / RD·AD / DG / IM | 01·02 |
| UI 유형 | 패키지 UI / 포탈 / 단말 / 없음 | — |
| IF 유형·매체·표준표 No. | 온라인/파일/데이터 + 행 번호 | 06 |
| 런타임 주/보조 # | 1~12 | 07 |
| 데이터 소유 | RDW / ADW / 마케팅 / 메타 … | 02·04 |
| 인증 | SSO 사용 여부 | 09 |
| 표준전문·Direct 예외 | 있음/없음 + 사유 | 06·08 |
| 레이어드 근거 MD | 경로·문서명 | 03-LOGICAL |
| PPT Gap 문구 | 사용 여부 | §B1 |

텍스트 템플릿:

```text
솔루션명:
소속 시스템 그룹: BI | MP | RD/AD | DG | IM
UI 유형: 패키지 UI | 포탈 | 단말 | 없음
IF 유형·매체·표준표 No.:
런타임 주/보조 #: (1~12)
데이터 소유: RDW | ADW | 마케팅 | 메타 …
인증: SSO 사용 □ / 미사용 □ (09)
표준전문·Direct 예외: 있음□ 사유:
레이어드 MD 링크:
PPT Gap 문구: 사용□
```

PPT 10장 약함 시 §B1 Gap 문구를 **헤더에 체크**하고, Baseline(본 정의서·03-LOGICAL·06-RUNTIME·05-MECHANISM)을 설계서 본문에 명시한다.

## B4. 소속 매핑 (shall)

| 성격 | 소속 | 레이어드 근거(예) |
|---|---|---|
| OLAP·Self-BI·신용실적·포탈 | **BI** | `…레이어드…BI포탈_*` |
| 캠페인·오퍼·접점·EBM | **MP** | 마케팅플랫폼 레이어드 |
| 마트·적재·CDC/ETL 산출 | **RD/AD** | 데이터플랫폼 레이어드 |
| 메타·품질·흐름·비즈메타 | **DG** | 거버넌스 + 비즈메타 IF |
| IT 공통·지원 도구 | **IM** | IT지원 레이어드 |

소속이 불명확하면 01 대구분·02 논리 시스템에 재매핑한 뒤 진행한다. “솔루션 전용 Zone”을 임의 신설하지 않는다.

## B5. IF · 런타임 규범

### B5.1 IF

1. **Package Direct**는 06 온라인 표준의 **예외 행**만 허용. 일반 API·채널 경로에 확대 금지.  
2. 파일 연계는 **FOS**(06). 공유폴더·임시 FTP 상시화 금지.  
3. 신용실적: `인터페이스아키텍처_BI포탈_신용실적_시스템간연계분석.md` 재사용.  
4. 비즈메타: `인터페이스아키텍처_데이터거버넌스_비즈메타_시스템간연관관계_구조분석.md` 재사용.  
5. 표준표에 없는 매체는 ADR/표준개정 전 상시 경로로 쓰지 않는다.  
6. RD(레포트) 데이터 조회는 **`/rd/{serviceId}`** 전용 진입 · **Map→String** 계약(§B7.2). 일반 `/ins/` JSON DTO 경로와 혼용 금지.  
7. 정보단말 Package UI는 `_wpack_/webTop/...` 패키지·화면 명명(§B7.3 · 08)을 따른다.

### B5.2 런타임 매핑 (주 번호)

| 행동 | 런타임 # (shall) |
|---|---|
| 포탈/패키지 조회 | **#10** (또는 채널 **#2·#3**) |
| 오퍼·PUSH | **#6~#7** |
| CDC/ETL 준비 | **#8~#9** |
| 파일 | **#11** |
| 야간 집계·배치 | **#12** |

시퀀스 상세는 07 유형 카드·RUNTIME 상세분석 MD. EBM 오퍼는 **#7**이 주이고, 수집 **#6**과 분리한다. “전부 #10”으로 뭉개지 않는다.

### B5.3 08·09와의 관계

| 항목 | 처리 (must) |
|---|---|
| 표준전문 | Package면 **예외 명시** |
| GUID | 예외 여부 명시 · 가능하면 추적키 유지 |
| 진입 | 포탈/패키지 URL · SSO · (RD면 `/rd/{serviceId}`) |
| 레포트 | RD 메커니즘 사용 여부 · Map/String 계약 |
| 단말 패키지 | `_wpack_` 직접 수정 금지 · screen XML 원본 기준 |

## B6. 데이터 · 보안

1. 테이블/마트 **소유 시스템**과 솔루션의 읽기/피드백을 구분한다.  
2. 마스킹·역할·SSO는 NFR Security·09와 정합한다.  
3. 거버넌스 솔루션은 업무 데이터 **직접 처리자**가 아니다(02).  
4. ADW/RDW 직접 접근은 04 접근표·허용 계약 범위로 제한한다.  
5. SSO 우회를 상시화하지 않는다(예외는 시한·승인·감사).

### B7.1 신용실적 Package Direct — 연계 맵 (shall 재사용)

근거: `인터페이스아키텍처_BI포탈_신용실적_시스템간연계분석.md`

```text
              ┌─ 보고서 ──▶ BI포탈 (메뉴·프레임 소비)
웹정형보고서 ─┤
(신용실적)    └─ 대시보드 ▶ 데이터거버넌스
              │
              ├─ BI포탈/비즈메타 (메타·권한·용어)
              ├─ ADW (분석·집계)
              └─ RDW (정형·원장성)
```

- 동일 모듈을 포탈=**보고서**, DG=**대시보드**로 이원화 소비한다. 매체를 재발명하지 않는다.  
- Package Direct·표준전문 예외는 06 예외 행 + 본 맵 + Gap 문구로만 허용.  
- 헤더: 소속 **BI** · 런타임 **#10**(적재면 보조 **#9**) · Direct 예외 ○.

### B7.2 RD Map→String 계약 · 전용 진입 (shall)

근거: `레포팅_RD_연계_아키텍처_분석.md` · `메커니즘_레포팅_RD_연계_*`

```text
xFrame ─Map─▶ /rd/{serviceId} (NhRDController)
                 │ 선처리
                 ▼
              Service/DAO ─Query─▶ DB
                 │
                 ▼ String (후처리)
xFrame ◀─────────────────────────┘
```

- 입력 **Map**(조회조건) · 출력 **String**(RD 소비). JSON DTO 일반 거래(`/ins/`)와 **진입·응답 계약 분리**.  
- 헤더에 IF=RD 전용 · 표준표 No.(또는 예외) · 런타임 # 기입.

### B7.3 정보단말 패키지 트리 · 화면 명명 (shall)

근거: `메커니즘-아키텍처표준화_정보단말패키지구성_분석.md`

```text
webapp/
├── _wpack_/          ← 빌드 JS (직접 수정 금지)
├── cm/               ← 전사 기본 공통
├── websquare/        ← 엔진
└── webTop/
    ├── cm/           ← 정보단말 공통
    ├── layout/
    └── screen/{대구분}/{업무}/{분류}/{화면ID}.xml
         예: BI/CR/A/bicra0000M0.xml · MP/CO/A/mpcoa0000M0.xml
```

- 명명 감각: `[대구분][업무][분류][일련][유형].xml` — 경로 접두부와 파일명 일치.  
- 공통 승격: screen → webTop/cm → cm (역의존 금지).  
- 솔루션 도입 시 UI 유형=단말/패키지이면 본 트리를 헤더·설계서에 링크한다.
