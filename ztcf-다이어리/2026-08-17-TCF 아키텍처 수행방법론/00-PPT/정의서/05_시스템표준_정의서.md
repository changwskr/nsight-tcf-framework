# Part A — Top-down 구조 이해

## A1. 핵심 결론

이 장은 차세대 정보계의 **서버 식별·경로·계정·포트 Baseline**을 정의한다.  
임의 명명·비공식 계정/포트로 인한 운영·보안·DR 불일치를 금지한다.

```text
시스템 표준 (5장)
        │
        ├─ Hostname (고정 12자리)
        ├─ 파일시스템 (표준 FS · 3분류 · 예외표)
        ├─ 사용자 계정 (환경·역할 분리)
        └─ 서버 포트 (현황표 · 충돌 검사)
```

목적(한 줄):

```text
법인·앱·플랫폼·환경·용도·순번
        │
        ▼
유일·검증 가능한 Host 식별
        │
        ▼
FS · 계정 · 포트와 동일 인벤토리
        │
        ▼
배포 · 개통 · DR · 모니터 정합
```

| 표준 영역 | 장표의 정의 초점 | 핵심 대상 |
|---|---|---|
| Hostname | 12자리 코드 조립·검증·예시 | 인프라 / CMDB / DNS |
| FS | Linux 표준 · AP/DB 3분류 · 예외 | OS · 스토리지 |
| 계정 | 환경·역할 분리 · 비밀관리 | 보안 · 운영 |
| 포트 | 현황표 등록 · FW/LB 일치 | 네트워크 · 개통 |

### 이 문서가 답하는 것과 답하지 않는 것

| 답하는 것 | 답하지 않는 것 (후속) |
|---|---|
| Hostname 12자리 코드표·정규식 | Zone·레이어드 (02) |
| DR=순번 51~99 · 환경 `o` 유지 | 논리→물리 매핑표 전문 (03) |
| FS·계정·포트 shall | DB 스키마·RAC (04) |
| 03·인벤토리 교차검증 원칙 | IF 매체 (06) · Drill (11) |

한 문장: **“서버를 무엇으로 부를지·어디에 무엇을 둘지”를 고정**하고, **용량·구성도·장애 Drill은 03·11에 위임**한다.

### 읽는 순서 권장

```text
A1 핵심 결론 → A3 12자리 골격 → A4~A5 코드 축
        │
        ├─ FS·계정·포트 위치가 궁금하면 A6
        ├─ 03 교차·검증이 궁금하면 A7
        └─ 등록·개통 적용은 Part B
```

# Part B — 적용 규범

> 설계·등록·배포·개통 시 **Part B를 우선**한다. Part A와 표현이 다르면 Part B의 shall/must/금지를 따른다.

## B1. 준수 의무

1. 신규·변경 Host는 본 정의서 규칙으로만 등록한다.  
2. 임의 이름(`Mkt-Web-01` 등)·비공식 계정·미등록 포트를 금지한다.  
3. 03 물리 목록·인벤토리와 **불일치하면 배포·개통하지 않는다**.  
4. 표에 없는 법인·용도·플랫폼 코드는 **표준 개정·ADR 전** Hostname에 넣지 않는다.

## B2. 용어 (규범용)

| 용어 | 정의 |
|---|---|
| Hostname | 영문 소문자+숫자 **고정 12자리**, 구분자 없음 |
| 애플리케이션 코드 | 대구분(2)+업무구분(2). CMDB 사전 필수 |
| 용도 코드 | WEB/WAS/AP/DB 등 논리 역할 2자리 |
| 순번 대역 | 의왕 01~49 · 안성(DR) 51~99. **00·50 금지** |

## B3. 서버 호스트 명명 (고정 12자리)

근거: [`../../04-PHYSICAL/물리기술아키텍처_시스템표준_서버호스트명명규칙_분석.md`](../../04-PHYSICAL/물리기술아키텍처_시스템표준_서버호스트명명규칙_분석.md)

```text
hostname = 법인(2) + 대구분(2) + 업무구분(2) + 서버(1) + 환경(1) + 용도(2) + 순번(2)
         = 12자리, 영문 소문자+숫자, 구분자 없음
예: sb | mp | co | l | o | wb | 01  →  sbmpcolowb01
```

| 위치 | 길이 | 의미 | 예 |
|---:|---:|---|---|
| 1~2 | 2 | 법인 | `sb` |
| 3~6 | 4 | 대구분+업무구분 | `mpco` |
| 7 | 1 | 서버/플랫폼 | `l` |
| 8 | 1 | 환경 | `o` |
| 9~10 | 2 | 용도 | `wb` |
| 11~12 | 2 | 순번 | `01` |

### B3.1 법인 코드 (2) — 전체표

| 코드 | 법인 |
|---|---|
| `sb` | 상호금융 |
| `nh` | 중앙회(상호금융 제외) |
| `nb` | 은행 |
| `fg` | 금융지주 |
| `ag` | 경제지주 |

법인 코드는 자산 소유·운영 책임의 최상위 분류다. 표에 없는 법인 코드를 임의 신설하지 않는다(표준 개정 필요).

### B3.2 애플리케이션 코드 (4) = 대구분(2)+업무구분(2)

1. 의미는 **중앙 애플리케이션 코드 사전(CMDB)** 을 따른다.  
2. 장표 예시(`mpco`, `rdco`)만으로 세부 확정하지 않는다.  
3. 필수 관리 속성: 코드·공식명·소유/운영 조직·상태(예약/사용/폐기)·중복 금지.  
4. CMDB에 없는 4자리로 Hostname을 만들지 않는다.

### B3.3 서버/플랫폼 코드 (1) — 전체표

| 코드 | 의미 | 분석 |
|---|---|---|
| `i` | Unix–IBM | IBM UNIX 계열 |
| `h` | Unix–HP | HP UNIX 계열 |
| `o` | Unix–Oracle | Oracle UNIX 계열 |
| `l` | Linux | Linux 서버 계열 |
| `w` | Windows | Windows 서버 계열 |
| `x` | Exadata | Oracle Exadata 어플라이언스 |

플랫폼 코드와 실제 OS/장비가 **불일치하면 등록 거부**.

### B3.4 환경 코드 (1) — 전체표

| 코드 | 의미 |
|---|---|
| `o` | 운영 |
| `v` | 검증 |
| `t` | 개발 |

**DR은 환경 문자를 바꾸지 않는다**(통상 `o` 유지). DR 구분은 **순번 51~99**로만 한다. 환경 코드 `d` 등을 임의 도입하지 않는다.

### B3.5 용도 코드 (2) — 전체표 (다중 행)

| 코드 | 용도 | 일반적 배치 계층 |
|---|---|---|
| `ap` | AP 서버 | 애플리케이션/처리 서버 |
| `db` | DB 서버 | 데이터베이스 서버 |
| `wb` | WEB 서버 | 웹 서버 |
| `ws` | WAS 서버 | 웹 애플리케이션 서버 |
| `bk` | 백업 서버 | 백업 처리·저장 관리 |
| `bt` | 배치 서버 | 배치 실행 서버 |
| `tl` | ETL 서버 | 데이터 추출·변환·적재 서버 |

1. 용도 코드는 **논리 역할**을 표시한다.  
2. 한 서버가 복수 역할을 수행하면 **대표 용도**를 Hostname에 쓰고, 부가 역할은 CMDB 속성으로 관리한다.  
3. 표에 없는 용도 코드(`mq`, `kf` 등)를 임의 할당하지 않는다(표준 개정·ADR).  
4. 용도와 설치 SW 역할이 불일치하면 등록 거부.

### B3.6 순번 (2) — 전체표

| 대역 | 의미 | 센터 |
|---|---|---|
| `01`~`49` | 주센터 인스턴스 | 의왕 |
| `51`~`99` | DR 인스턴스 | 안성 |
| `00` · `50` | **할당 금지** | — |

1. `51~99`는 DR센터 자산에만 할당한다.  
2. 개발(`t`)·검증(`v`) Host에 DR 순번 사용을 **금지**한다.  
3. DR Host는 환경 `o`를 사용해야 한다(장표 Baseline).  
4. 운영↔DR 1:1(`01↔51` 등) 의무 여부는 03 할당 정책·ADR로 고정한다.

### B3.7 예시 역분해

| Host | 해석 |
|---|---|
| `sbmpcolowb01` | 상호금융·마케팅·Linux·운영·WEB·의왕#01 |
| `sbmpcolowb51` | 동일 역할 **DR** #51 |
| `sbmpcoltwb01` | 개발(`t`) WEB |
| `sbrdcoxodb01` | RDW · Exadata · 운영 DB |
| `sbrdcoxodb51` | RDW 운영 DB의 안성 DR |
| `sbrdcoxtdb01` | RDW · Exadata · 개발 DB |

### B3.8 등록 전 검증 (must)

1. 길이 정확히 **12** · 소문자·숫자만 · 구분자 없음  
2. 법인·플랫폼·환경·용도 코드표 일치  
3. 애플리케이션 4자리 **CMDB 사전 대조**  
4. 순번 ∈ 01~49 또는 51~99 · **00/50 아님**  
5. DR이면 센터=안성 · 환경=`o` · 순번≥51  
6. 인벤토리·DNS·CMDB·IaaS·모니터·백업에서 **유일**  
7. 플랫폼·용도 ↔ 실제 OS/SW 역할 일치  

형식 1차 검사(앱코드는 사전 대조 필수):

```regex
^(sb|nh|nb|fg|ag)[a-z]{4}[iholwx][ovt](ap|db|wb|ws|bk|bt|tl)(0[1-9]|[1-4][0-9]|5[1-9]|[6-9][0-9])$
```

## B4. 파일시스템

### B4.1 OS 표준 마운트 (논리 표준 목록)

> 장표의 `vg_os` 표기는 **논리적 분류**다. 실제 LV·디바이스·FS 유형은 설치 표준에서 확정한다. (**ANALYSIS**)

| Mount | 역할 | shall |
|---|---|---|
| `/` | root | 필수 |
| `/boot` | 부트 | 필수 (실제 장치는 설치 표준) |
| `/etc` | 설정 | 보통 `/`와 동일 FS |
| `/dev` | 장치 | 가상 FS · 백업/용량 대상 아님 |
| `/root` | 관리자 홈 | root 전용 |
| `/usr` | OS 프로그램 | 패키지 관리자 원칙 |
| `/home` | 일반 사용자 홈 | **업무 서비스 계정 홈으로 쓰지 않음** |
| `/tmp` | 임시 | 용량·권한 통제 |
| `/var` | 로그·가변 | 필수 분리 권장 |
| `/var/crash` | 덤프 | 장애 덤프 |
| `/userdir` | **업무 계정 홈** | 업무 계정은 여기 |
| `/<SW명>` | WEB/WAS/보안/관제 등 | 솔루션 설치 영역 |

### B4.2 AP / DB 업무 경로 (3분류)

| 영역 | 경로 | shall / 금지 |
|---|---|---|
| AP 프로그램 | `/pgm` | 배포·실행 바이너리. HA 시 `/pgm_<hostname>` 등 **접미 규칙**을 표준표에 등록 |
| AP 로그 | `/aplog` | 앱 로그 전용. OS `/var`와 혼재 금지 |
| 업무 홈 | `/userdir` | 업무 계정 홈 (B5와 정합) |
| Oracle Home | `/nhod` | Oracle 소프트웨어 Home. **DB 데이터 파일 경로로 사용 금지** |
| 분리/백업 등 | `/sepa` · `/seba` · `/SMS` · `/SMT/perfmon` · `/usr/local/TOS` | 장표·분석에 정의된 용도만. 임의 전용 금지 |

```text
OS(/ · /var · /userdir · /<SW>)
   │
   ├─ AP:  /pgm  · /aplog  · /userdir
   └─ DB:  /nhod (Home)  ≠  데이터 파일 영역
```

### B4.3 적용 규칙

1. Linux OS **표준 FS**를 기본으로 한다.  
2. AP/DB는 **B4.2 경로**를 따른다.  
3. 예외는 **예외표**(사유·승인자·만료) 없이 허용하지 않는다.  
4. 표준 경로 밖의 중요 데이터 배치를 금지한다.  
5. `/home`에 업무 서비스 계정을 두지 않는다(`/userdir` 사용).

### B6.2 미기재(OPEN) — 개통 전 확정 필수

장표에 **포트 미기재**인 항목은 현황표에 행을 채우기 전 상시 개통을 금지한다.

| 구분 | 이름 | 상태 |
|---|---|---|
| 단말UI | WebTopSuite | OPEN |
| 데이터품질 | DQ Miner | OPEN |
| 비즈메타 | Meta Miner | OPEN |
| 데이터흐름 | Data Hawk | OPEN |
| CDC | Oracle GoldenGate | OPEN |
| BI | Data Eye · BI MATRIX | OPEN |
| 마케팅 | Kafka | OPEN |
| ETL | DataStage | OPEN |
| 배포 | GitLab Runner | OPEN |
| SQL품질 | OpenPOP | OPEN |
| 이행 | SQL Canvas | OPEN |

### B6.3 적용 규칙

1. 포트는 **B6.1·현황표에 등록된 값만** 사용한다.  
2. 신규·OPEN 항목은 현황표에 행 추가 · **충돌 검사** · FW/LB 반영 후 할당한다.  
3. 임시 포트의 상시화를 금지한다.  
4. FW·로드밸런서 규칙과 포트표가 불일치하면 개통하지 않는다.  
5. Tomcat `8080`·Oracle Listener는 **승인된 구간**에서만 접근한다.

## B7. 교차 검증 (03 · 인벤토리)

| 검사 | 기준 |
|---|---|
| Hostname | 본 정의서 §B3 |
| FS | 표준/예외표 |
| 계정·포트 | 표준표 = 인벤토리 |
| 물리 목록 | 03 매핑·SW 버전과 일치 |

물리 목록(03)·인벤토리와 Hostname·계정·포트·FS가 **불일치하면 배포·개통하지 않는다**.

## B8. 금지

- 12자리 외·대문자·구분자·임의 별칭 Hostname  
- DR을 환경 문자만으로 구분(`d` 등) · 개발에 51~99 할당  
- `00`/`50` 순번 · 표 밖 용도·법인 코드  
- CMDB 미등록 앱코드  
- 비공식 계정·공용 비밀번호·미등록 포트  
- FS 예외표 없는 경로 일탈 · `/nhod`에 DB 데이터 저장 · `/home`에 업무 서비스 계정  
- B6.2 OPEN(미기재) 포트를 수치 확정 없이 상시 개통
