# NSIGHT 서버 최종 상세 인벤토리

> 농협 상호금융 NSIGHT 정보계 Physical Architecture 서버 Baseline

## 1. 문서 목적

본 문서는 지금까지 제공된 서버 목록 및 용량산정 화면을 기준으로 서버별 **CPU, Memory, Disk, tpmC, 역할, DR, 도입/상태**를 하나의 기준정보로 통합한 최종 정리본이다.

본 인벤토리는 `서버 1대 = 1행`을 원칙으로 하며, Physical Architecture와 향후 Runtime/Capacity 정보를 연결하기 위한 기준 자료로 사용한다.

## 2. 관리 원칙

- CPU는 원 산정값과 최종 조정값을 분리하여 관리한다.
- Memory는 GB 단위로 관리한다.
- Disk는 OS Disk와 추가 Disk를 분리한다.
- tpmC는 서버 벤치마크/용량산정 지표이며 실제 업무 TPS와 동일한 값으로 해석하지 않는다.
- `-`는 원본 화면상 미기재 또는 해당 항목 비적용을 의미한다.
- Appliance의 대용량 Disk 값은 원본 자료의 병합/공통 자원값을 서버별 행에 반복 표기한 값이다.

## 6. 아키텍처 해석 시 주의사항

### 6.1 tpmC와 TPS 분리

`tpmC`는 서버의 기준 성능/용량산정 지표이고, `TPS`는 실제 애플리케이션 업무 처리량이다. 따라서 tpmC 값을 그대로 TPS로 사용하지 않는다.

### 6.2 CPU 산정값과 조정값

일부 서버는 산정 CPU와 최종 수정 CPU가 다르다. 예를 들어 마케팅플랫폼 WAS는 35 Core 산정 후 32 Core로 조정되어 있으므로, 인프라 발주/할당 기준과 용량산정 근거를 함께 보존해야 한다.

### 6.3 Disk

OS Disk와 추가 Disk를 분리 관리한다. 향후 파일시스템 설계 단계에서는 추가 Disk를 `/app`, `/log`, `/data`, `/backup` 등의 Mount Point 및 LVM 구조로 다시 분해한다.

### 6.4 다음 연결 정보

이 인벤토리 이후의 Architecture Baseline은 다음 관계로 확장한다.

```text
System / Application
        ↓
Server / Hostname
        ↓
CPU / Memory / Disk / tpmC
        ↓
Apache / Tomcat / JVM
        ↓
Tomcat Thread / JVM Heap
        ↓
HikariCP / DB Session
        ↓
RDW / ADW
        ↓
TPS / p95 / 장애 잔여 처리량
```
