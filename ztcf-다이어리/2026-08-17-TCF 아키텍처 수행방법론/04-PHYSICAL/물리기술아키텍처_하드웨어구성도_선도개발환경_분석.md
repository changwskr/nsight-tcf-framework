# 물리기술아키텍처 — 하드웨어 구성도 — 선도개발환경 분석

> 원본 범위: `3. 물리 기술 아키텍처 > 3.1 하드웨어 구성도`  
> 원본 페이지/이미지: 73쪽, `85737/27.png`·`28.png`  
> 명칭 주의: 장표 제목은 `선도 환경`이며, 본 문서는 사용자의 요청에 따라 이를 선도개발환경으로 분석한다.  
> 분석 원칙: 이미지의 서버 역할·번호·배치를 사실로 기록하고, 미표시 기능은 “없음”이 아니라 범위 확인 대상으로 관리한다.

---

## 1. 핵심 결론

선도개발환경은 **의왕 센터(주 센터)**에 마케팅 핵심 WEB/WAS, 단말 개발·배포 지원체계, 정보계 스토리지와 `CRM DB #1`만 배치한 경량 선행 검증환경이다.

- 마케팅플랫폼 WEB #1, WAS #1의 단일 노드 구성이다.
- 미니싱글뷰 WEB/WAS는 마케팅플랫폼 WEB/WAS 서버에 통합된다.
- 단말관리·단말배포·단말개발도구와 소스관리·마스터솔루션·라이브러리를 포함한다.
- 데이터 계층은 신규 ADW/RDW Appliance가 아니라 CRM DB #1 중심이다.
- 디지털금융, 코어뱅킹 원천DB·복제DB, FOS가 원천시스템으로 표시된다.
- 실시간/행동 AP, BI, 데이터거버넌스, ETL, 배치, DR 등은 장표에 표시되지 않는다.

```text
                    의왕 센터(주 센터)
┌──────────────────────────────────────────────────────┐
│ 1) 마케팅                                           │
│    마케팅플랫폼 WEB #1 ─ WAS #1                     │
│    ※ 미니싱글뷰 WEB/WAS 통합                        │
├──────────────────────────────────────────────────────┤
│ 2) 운영관리                                         │
│    단말관리·배포 WEB/WAS · 개발도구 · 소스관리      │
│    마스터솔루션 · 라이브러리                        │
├──────────────────────────────────────────────────────┤
│ 3) 저장소/DB: 정보계 스토리지 + CRM DB #1           │
├──────────────────────────────────────────────────────┤
│ 원천: 디지털금융 / 코어뱅킹 원천DB·복제DB / FOS     │
└──────────────────────────────────────────────────────┘
```

## 2. 증적과 근거 수준

| 수준 | 내용 |
|---|---|
| 확인 사실 | 의왕 센터 단일 배치와 IaaS 영역이 표시됨 |
| 확인 사실 | 마케팅, 운영관리, 저장소/DB 3개 영역이 표시됨 |
| 확인 사실 | 각 서버가 #1 단일 노드로 표시됨 |
| 확인 사실 | 미니싱글뷰 통합 주석이 표시됨 |
| 확인 사실 | 정보계 스토리지, CRM DB #1, 4개 원천시스템이 표시됨 |
| 확인 사실 | 27·28 이미지는 서버 역할·번호·배치가 동일한 중복 촬영본 |
| 설계 해석 | 전체 기능 구현보다 플랫폼·단말 개발/배포 경로의 조기 검증에 초점을 둔 환경 |
| 설계 해석 | CRM DB는 기존 데이터 구조와 신규 애플리케이션의 호환성 검증 지점으로 해석 가능 |
| 미확정 | CRM DB의 정확한 DBMS, 버전, Hostname, 데이터 범위 |
| 미확정 | 미니싱글뷰의 Process/JVM/Instance 분리 수준 |
| 미확정 | `라이브러리`가 물리 서버인지 Repository 논리 서비스인지 여부 |
| 미확정 | 원천시스템과 실제 통신 여부 및 테스트 데이터 마스킹 방식 |

## 3. 물리 계층 구조

```text
[개발자/선도 사용자]
        │
        ▼
[마케팅 WEB #1] ─ [마케팅 WAS #1]
        │                  │
        └─ 미니싱글뷰 ─────┘
                           │
[단말 개발·배포 도구군] ──┼─ [CRM DB #1]
                           │
                   [정보계 스토리지]
                           │
                  [원천 DB / FOS]
```

장표의 범례에는 AP, DB, WEB, WAS, ETL, 베어메탈, IaaS가 있으나 실제 선도환경 박스에는 WEB, WAS, AP, DB와 IaaS가 중심이다.

## 4. 마케팅 영역

| 역할 | 번호 | Hostname 판독 |
|---|---:|---|
| 마케팅플랫폼 WEB | #1 | `sbmpcoltwb01` |
| 마케팅플랫폼 WAS | #1 | `sbmpcoltws01` |

```text
[마케팅플랫폼 WEB #1]
   ├─ 마케팅 WEB 기능
   └─ 미니싱글뷰 WEB 기능
              │
              ▼
[마케팅플랫폼 WAS #1]
   ├─ 마케팅 WAS 기능
   └─ 미니싱글뷰 WAS 기능
```

### 통합 배치의 영향

```text
장점: 서버 수↓ / 배포경로 단순 / 조기 검증 빠름
위험: 장애영향 공유 / 자원경합 / 로그혼재 / 배포결합
통제: Process·Port·Config·Log·Artifact·계정 분리
```

장표가 확인하는 것은 **서버 통합**이다. 동일 JVM 또는 동일 애플리케이션 인스턴스라는 의미까지 확정할 수 없다.

## 5. 운영관리 영역

| 역할 | 번호 | Hostname/비고 |
|---|---:|---|
| 단말관리 WEB | #1 | `sbimxmtlwb01` |
| 단말관리 WAS | #1 | `sbimxmtlws01` |
| 단말배포 WEB | #1 | `sbimxdltwb01` |
| 단말배포 WAS | #1 | `sbimxdltws01` |
| 단말개발도구 AP | #1 | `sbimxmtap01` |
| 소스관리 AP | #1 | `sbimsmltap01` |
| 마스터솔루션 | #1 | `sbimfwltap01`, 테크시스템부 표기 |
| 라이브러리 | #1 | 테크시스템부, Hostname 판독 불가 |

```text
[단말개발도구 AP]
       │ 산출물
       ▼
[소스관리 AP] ─ [마스터솔루션] ─ [라이브러리]
       │                                │
       ▼                                ▼
[단말배포 WEB] ─ [단말배포 WAS] ───▶ [선도 단말]
       ▲
[단말관리 WEB] ─ [단말관리 WAS]
```

### 책임 분리

```text
단말관리: 단말 등록·상태·정책
단말개발: 화면/모듈 작성·빌드
소스관리: 버전·브랜치·변경이력
라이브러리: 의존성·공통모듈 저장
마스터솔루션: 프레임워크/기준구성 통제
단말배포: 승인 산출물 전달
```

도구가 같은 환경에 있어도 개발자, 승인자, 배포자 권한은 분리해야 한다.

## 6. 저장소와 CRM DB

| 구성 | 번호 | 해석 |
|---|---:|---|
| 정보계 스토리지 | 미표시 | 개발 산출물·데이터 저장 기반 |
| CRM DB | #1 | 선도용 단일 DB, 상세 Hostname 확인 필요 |

```text
선도: [CRM DB #1]
         │
         ├─ 기존 데이터 모델 호환성
         ├─ 마케팅 CRUD/조회 검증
         └─ 신규 DB 이행 전 기준 비교

개발: [ADW/RDW DB Appliance #1,#2]
운영: [ADW #1~#6] + [RDW #1,#2]
```

CRM DB를 `AS-IS 개발 DB`로 보는 설명은 관련 구성내역 문서에서 확인되지만, 첨부 장표 자체에는 `AS-IS`가 직접 표시되지 않는다. 따라서 본 문서에서는 보강 근거로만 사용한다.

## 7. 원천시스템 연계

```text
[디지털금융] ─────────────┐
[코어뱅킹 원천DB] ────────┼─ 추출/조회/파일 연계 ─ [CRM DB/마케팅]
[코어뱅킹 복제DB] ────────┤
[FOS] ────────────────────┘
```

| 원천 | 선도환경 통제 |
|---|---|
| 디지털금융 | API/전문 Stub 또는 승인 연계 |
| 코어뱅킹 원천DB | 직접 접근 최소화·Read Only |
| 코어뱅킹 복제DB | 테스트 조회 우선, 최신성 표시 |
| FOS | 파일명·Manifest·체크섬·완료표시 |

이미지의 배치는 연계 대상 존재를 나타내지만 실제 연결선·프로토콜·접속 방향은 명확하지 않다.

## 8. 선도환경의 포함·미포함 범위

```text
포함
 ├─ 마케팅/미니싱글뷰 WEB·WAS
 ├─ 단말 관리·개발·배포
 ├─ 소스·라이브러리·마스터 구성
 ├─ CRM DB
 └─ 원천 연계 대상

장표 미표시
 ├─ 실시간/행동정보/고객행동 AP
 ├─ BI포탈/신용실적/Self-BI
 ├─ 데이터거버넌스/RD/배치/ETL
 ├─ ADW/RDW Appliance
 └─ DR/GSLB/DCI/Data Guard
```

미표시 항목을 선도 검증 완료로 간주해서는 안 된다. 해당 기능은 본 개발환경, 통합시험 또는 별도 PoC에서 검증해야 한다.

## 9. 개발환경과의 차이

| 항목 | 선도개발환경 | 개발환경 |
|---|---|---|
| 목적 | 핵심 경로 조기 검증 | 전체 기능 통합개발 |
| 마케팅 WEB/WAS | 각 1 | 각 1 |
| 미니싱글뷰 | 마케팅 서버 통합 | 동일 |
| 마케팅 AP | 미표시 | 3종 AP 포함 |
| BI·거버넌스 | 미표시 | 포함 |
| 단말 도구 | 핵심 도구 포함 | 핵심+ETL·배치·RD·관측 확대 |
| DB | CRM DB #1 | ADW/RDW 통합 Appliance #1,#2 |
| 데이터 이행 | 미표시 | SQL품질/이행 임시 AP |

```text
선도 환경 성공
   │ 구조·계약·도구체계 검증
   ▼
본 개발환경 확대
   │ AP·BI·거버넌스·ADW/RDW·이행 검증
   ▼
통합/성능/운영 전환 검증
```

## 10. 선도 개발 흐름

```text
요구사항 → 단말개발도구 → Source Commit → Build
 → Library/Artifact 등록 → 선도 WEB/WAS 배포
 → CRM DB 연계 → 기능시험 → 결함/학습 반영
```

### 배포 흐름

```text
Commit → Review → Build → Unit Test → Artifact Hash
 → 승인 → 단말/WEB/WAS 배포 → Smoke Test → 결과 기록
```

### DB 변경 흐름

```text
DB Script → 정적검사 → CRM DB 적용 → Rollback 검증
 → 본 개발 ADW/RDW용 변환/보완 → 재검증
```

선도 DB와 목표 DB 구조가 다를 수 있으므로 CRM DB에서 성공한 SQL이 ADW/RDW에서 그대로 성공한다고 가정하면 안 된다.

---

## 11. 승격 게이트

```text
Gate 1 기능: 핵심 사용자 시나리오 통과
Gate 2 계약: API/전문/파일/DB Schema 확정
Gate 3 공급망: Source→Build→Artifact→Deploy 추적
Gate 4 보안: 권한·비밀정보·마스킹·감사 검증
Gate 5 이식성: CRM DB 종속성과 환경 종속 제거
Gate 6 복구: 재배포·Rollback·데이터 복구 검증
            ↓
       본 개발환경 승격
```

선도환경의 목적은 운영 완성도를 증명하는 것이 아니라 불확실성이 큰 기술·업무 가정을 빠르게 검증하고 본 개발환경의 표준으로 환류하는 것이다.

---

## 12. 보안과 데이터 보호

```text
원천 데이터 → 승인 → 최소 추출 → 마스킹/가명화
          → 선도환경 적재 → 접근감사 → 만료 → 안전 폐기
```

- 운영 원천DB 직접 접속은 최소화하고 복제DB·Stub·샘플 데이터를 우선한다.
- CRM DB 계정은 애플리케이션, 개발자, 배포, 조회 계정으로 분리한다.
- 단말 배포물은 서명과 Hash로 변조 여부를 검증한다.
- 소스관리·라이브러리·마스터솔루션의 관리자 권한을 분리한다.
- 비밀정보는 소스와 배포물에 포함하지 않는다.

## 13. 단일 노드 복구 전략

```text
노드 장애 → 관측 경보 → 프로세스/VM 재기동
        → 실패 시 이미지·IaC로 재생성
        → Artifact 재배포 → 설정 복원 → Smoke Test
```

선도환경은 HA보다 재생성 가능성이 중요하다. 다음을 코드/저장소로 관리해야 한다.

```text
Source + Build Definition + Artifact + Configuration
+ DB Migration + Seed Data + Access Policy + Test Script
= 재현 가능한 선도환경
```

## 14. 관측과 종료 기준

| 영역 | 지표/증적 |
|---|---|
| WEB/WAS | 오류율, 응답시간, JVM, Connection Pool |

| 원천 연계 | 호출/파일 건수, 지연, 오류, 대사 |
| 보안 | 권한 변경, 비밀정보 탐지, 데이터 반입·폐기 |

```text
선도 종료
 = 가설 검증 완료
 + 미해결 Gap/위험 등록
 + 산출물·표준 본 개발환경 이관
 + 선도 데이터/계정/임시자원 정리
```

## 16. 주요 위험

```text
단일 노드        → 장애 시 전체 선도 중단
서버 통합        → 마케팅/미니싱글뷰 장애영향 공유

```

## 18. 최종 평가

선도개발환경은 마케팅과 미니싱글뷰의 통합 WEB/WAS, 단말 개발·관리·배포 공급망, CRM DB 연계를 빠르게 검증하는 최소 물리 환경이다. 전체 개발환경보다 훨씬 좁은 범위이므로 빠른 가설검증에는 적합하지만 성능·HA·ADW/RDW·BI·거버넌스·배치·DR의 완성도를 증명하지는 않는다.

성공 기준은 단순 기능 시연이 아니라 검증된 인터페이스와 배포 산출물을 본 개발환경으로 재현 가능하게 이관하는 것이다. 특히 CRM DB와 목표 ADW/RDW 사이의 차이, 통합 서버의 장애영향, 원천 데이터 보호를 명시적으로 관리해야 한다.
