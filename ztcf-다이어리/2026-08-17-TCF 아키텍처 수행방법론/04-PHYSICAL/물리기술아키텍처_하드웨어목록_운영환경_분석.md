# 물리기술아키텍처 — 하드웨어 목록 — 운영환경 분석

> 원본 범위: `3. 물리 기술 아키텍처 > 3.3 하드웨어 목록`  
> 원본 장표: 운영환경 (1/3)~(3/3), 78~80쪽  
> 공통 조건: 운영, 의왕센터. 대부분 `x86 / Linux / IaaS`, 일부 `IBM / UNIX / 단독`, DB는 `Oracle / Linux / Appliance`로 구성됨.  
> 주의: 장표에서 여러 행에 걸쳐 병합된 CPU·MEM·Disk 값은 개별 서버가 아닌 장비·랙 단위 합계일 수 있으므로 `공유/합계`로 표시한다.

---

## 1. 핵심 결론

운영 하드웨어는 애플리케이션을 IaaS 기반 x86 Linux로 표준화하고, ETL·CDC는 단독 서버, RDW·ADW는 Oracle Appliance로 분리한 계층형 구성이다.

- 마케팅플랫폼은 실시간·행동 데이터 처리를 위해 AP 노드와 대용량 추가 Disk를 사용한다.
- BI/Self-BI는 WEB/WAS/AP 역할별로 자원을 차등 배분하며 Self-BI AP가 특히 큰 메모리를 사용한다.
- 단말관리·배포는 다수의 수평 노드로 구성되어 채널 및 배포 부하를 분산한다.
- ETL은 64 Core·512 GB 메모리 노드 2대, CDC 중계 DB는 UNIX 단독 노드 2대다.
- RDW는 Quarter Rack, ADW는 Full Rack으로 표기된 대용량 Oracle Appliance다.
- 데이터 이행 장비는 `[임시]`로 분리되어 있으며 사업 종료 후 폐기·회수 계획이 필요하다.

```text
운영 하드웨어 계층
  ├─ IaaS: WEB / WAS / AP
  ├─ 단독: ETL / CDC 중계 DB
  ├─ Appliance: RDW / ADW
  └─ 임시장비: 변환 / 이행 / SQL품질 / 추출 DB
```

## 2. 표기 및 판독 기준

| 항목 | 기준 |
|---|---|
| CPU | vCPU 또는 Core로 표기된 장표 값을 그대로 기록 |
| MEM | GB 단위 |
| OS Disk | GB 단위, `-`는 장표 미기재 |
| 추가 Disk | GB 단위, `1,024` 등 천 단위 구분 유지 |
| Hostname | 장표 문자 판독 기준이며 구축 CMDB와 대조 필요 |
| Appliance | 병합된 자원 수치는 Rack/장비 전체 합계 가능성 표시 |
| 미기재 | `-`로 기록하며 0 또는 미할당을 의미한다고 단정하지 않음 |

| IaaS·UNIX·Appliance 혼재 | 운영 절차·도구 분산 | 플랫폼별 패치·백업·관제 Runbook |
| 대용량 로컬/추가 Disk | 장애 시 복구시간 증가 | 스토리지 유형, RAID, 백업 RTO 확인 |
| 단일 데이터흐름 WAS | 장애·성능 병목 | 재기동·복구와 수평 확장 검토 |
| 임시장비 장기 존치 | 보안·비용·데이터 잔존 | 종료일·소유자·폐기 증적 관리 |
| Self-BI 비고 불명확 | 제품·라이선스 누락 | AUD·TRINITY 의미와 라이선스 확인 |

## 14. 최종 평가

운영환경 하드웨어는 업무 서버의 IaaS 표준화와 데이터 처리 계층의 전용 장비화를 결합한 구조다. WEB/WAS는 다중 노드로 가용성과 처리량을 확보하고, 고객행동·Self-BI·ETL·데이터흐름처럼 자원 집약적인 기능에는 메모리 또는 Disk를 집중 배분했다.

가장 중요한 관리 과제는 **77개 자산의 CMDB 정합성, Appliance 병합 사양의 정확한 해석, 미기재 자원 보완, 이기종 플랫폼 운영 표준화, 임시 이행 장비 폐기 관리**다.
