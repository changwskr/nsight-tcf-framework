## 3. 거래 처리 구조 TEXT 표그림

원본 이미지의 **상→하 처리 순서**와 **좌(흐름도)·우(상세)** 배치를 TEXT 표·ASCII로 변환한 것이다.

### 3.1 8단계 처리 요약

| Step | 처리 단계 | 범위 (Scope) | 필수/선택 | 담당 | 핵심 역할 |
|---:|---|---|---|---|---|
| **①** | 시스템 선 처리 | 어플리케이션 그룹 | **필수** | NH Cloud Framework | 시스템 자원 할당, 거래 통제, 입력 로그 처리 |
| **②** | 공통 선 처리 | 어플리케이션 | 선택 (필요 시) | 공통 업무 담당자 | 공통 영역 로직 구현 |
| **③** | 업무 선 처리 | 서비스ID (Controller 내 Method) | 선택 (필요 시) | 개별 업무 담당자 | 공통 로직 구현 |
| **④** | 업무 본 처리 | Controller | **필수** | Controller | 서비스ID↔Method 1:1, 거래 메인 흐름 제어, Biz 0~n 호출 |
| **⑤** | Biz 로직 | Service | **필수** | Service Class | 업무 로직 구현, DTO·DAO 사용, DB 접근 |
| **⑥** | 업무 후 처리 | 서비스ID (Controller 내 Method) | 선택 (필요 시) | 개별 업무 담당자 | 업무 후 필수 처리 요건 검증 |
| **⑦** | 공통 후 처리 | 어플리케이션 | 선택 (필요 시) | 공통 업무 담당자 | 업무 후 필수 처리 요건 검증 |
| **⑧** | 시스템 후 처리 | 어플리케이션 그룹 | **필수** | NH Cloud Framework | Commit/Rollback, 출력 조립, 출력 로그, 자원 해제 |

## 4. 단계별 구조 분석

### 4.1 ① 시스템 선 처리 · ⑧ 시스템 후 처리

| 항목 | 선 처리 (①) | 후 처리 (⑧) |
|---|---|---|
| 담당 | NH Cloud Framework | NH Cloud Framework |
| 범위 | 어플리케이션 그룹 | 어플리케이션 그룹 |
| 역할 | 자원 할당, 거래 통제, 입력 로그 | Commit/Rollback, 출력 조립, 출력 로그, 자원 해제 |

**해석**: 애플리케이션 코드가 아닌 **프레임워크 횡단 관심사** 영역. 거래 생명주기의 **시작·종료 경계**를 정의한다.

### 4.2 ②③⑥⑦ 선택적 선·후 처리

| Step | 범위 | 구현 주체 | 트리거 |
|---|---|---|---|
| ② 공통 선 | 어플리케이션 | 공통 업무 담당자 | 필요 시 |
| ③ 업무 선 | 서비스ID | 개별 업무 담당자 | 필요 시 |
| ⑥ 업무 후 | 서비스ID | 개별 업무 담당자 | 업무 후 검증 |
| ⑦ 공통 후 | 어플리케이션 | 공통 업무 담당자 | 업무 후 검증 |

**해석**: 점선 박스 = **Extension Point**. 모든 거래에 필수가 아니며, 공통·개별 업무 요건에 따라 선택 구현한다.

### 4.3 ④ 업무 본 처리 (Controller)

| 항목 | 내용 |
|---|---|
| 관계 | **서비스ID : Controller Method = 1 : 1** |
| 책임 | 업무 거래 처리, 거래 메인 처리 흐름 제어 |
| 하위 호출 | Biz Logic Service **0~n개** (DTO 경유) |

**해석**: Controller는 **오케스트레이터**. 단일 Service만 호출할 수도 있고, 복합 거래는 여러 Service를 순차·조합 호출한다.

### 4.4 ⑤ Biz 로직 (Service) · DB

| 항목 | 내용 |
|---|---|
| 구현체 | Service Class |
| 데이터 | DTO (입·출력) |
| 영속 | DAO / SQL → Database |

**해석**: 실제 **업무 규칙·DB CRUD**는 Service·DAO에 집중. Controller는 흐름만, Service는 로직만 담당하는 **관심사 분리**.

|---|---|
| Processing Pipeline | 8단계 선·본·후 처리 파이프라인 |
| Framework Boundary | ①⑧ = NH Cloud Framework / ②~⑦ = Application |
| Optional Hooks | ②③⑥⑦ = 점선 · 필요 시 구현 |

| Layer Flow | Controller → DTO → Service → DAO/SQL → DB |
| Transaction | ⑧에서 Commit/Rollback 확정 |
| Orchestration | Controller가 0~n Service 호출 |

## 6. PDMG/TCF 프레임워크 매핑

장표 8단계와 PDMG TCF 구현의 **대응 관계**다. (AS-IS: `pdmg-fw` 기준)

| Step | 장표 | PDMG/TCF 대응 | 비고 |
|---:|---|---|---|
| ① | 시스템 선 처리 | Filter, ServicePreventionInterceptor, `stf.preProcess()` | `TcfFacade` 진입 전·직후 |
| ② | 공통 선 처리 | Application 공통 Pre-hook (선택) | 프로젝트별 구현 |
| ③ | 업무 선 처리 | Handler/업무 Pre-hook (선택) | 서비스ID 단위 |
| ④ | 업무 본 처리 | `OnlineTransactionController` → `TcfFacade.process()` → `TransactionDispatcher` | 서비스ID 1:1 |
| ⑤ | Biz 로직 | `TransactionHandler` → Business Facade → Service → DAO | DTO 전달 |
| ⑥ | 업무 후 처리 | 업무 Post-hook (선택) | 필수 처리 요건 검증 |
| ⑦ | 공통 후 처리 | Application 공통 Post-hook (선택) | |
| ⑧ | 시스템 후 처리 | `etf.postProcess()`, ResponseBodyAdvice, TX Commit/Rollback | ExecutionDeadline·Evidence 종료 |

```text
[PDMG TCF ON 실행선 — 장표 대응]

HTTP 요청
  → Filter / Interceptor          ← ① 시스템 선 (일부)
  → OnlineTransactionController
  → TcfFacade.process(serviceId)
       → ExecutionDeadline bind
       → stf.preProcess()          ← ① 거래 통제
       → OnlineTimeoutExecutor
            → TransactionDispatcher → Handler
                 → Facade → Service → DAO   ← ④⑤
       → etf.postProcess()         ← ⑧ 후처리·deadline
  → 거래 응답
```

> **Gap**: ②③⑥⑦(공통·업무 선후처리)는 장표상 Extension Point이나, TCF Core에 **표준 Bean/API로 고정되어 있지 않음** — 업무 Handler·Facade에서 선택 구현.
