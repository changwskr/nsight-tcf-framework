## 1. 한 줄 요약

온라인 프레임워크는 **`nhnis.{대구분}.{업무구분}.{세부업무구분}`** 패키지 경로가 **업무 분류와 4계층(controller · service · dao · dto) 책임**을 동시에 표현하는 **Layered Architecture 표준**이다. Java 소스(`src/main/java`)와 **ORM Mapper XML(`resource`)** 이 동일 업무코드 계층으로 대응하며, **서비스ID**가 Controller Method · Service Class · DAO Class · DTO 파일명의 공통 식별자다.

## 3. 온라인 프레임워크 TEXT 표그림

원본 이미지의 **좌→우 분류 계층**과 **상→하 4계층 구현**을 TEXT 표·ASCII로 변환한 것이다.

### 3.1 분류 계층 (좌→우)

| 계층 | 컬럼명 | 예시 (mp/co/a) | 역할 |
|---:|---|---|---|
| 0 | **Top** | `nhnis` | 루트 패키지·조직 식별 |
| 1 | **어플리케이션 그룹 (대구분)** | `mp` | 애플리케이션 그룹 코드 |
| 2 | **어플리케이션 (업무구분)** | `co` | 업무 도메인 구분 |
| 3 | **기능 (세부 업무구분)** | `a`, `b`, `......` | 세부 기능 단위 (반복 가능) |
| 4 | **업무 구현** | controller / service / dao / dto | 4계층 구현 패키지 |

### 3.2 4계층 · Resource 대응 표

| 계층 | Java 패키지 | 예시 파일 | 서비스ID 대응 | 역할 (이미지 설명) |
|---|---|---|---|---|
| **Controller** | `package nhnis.mp.co.a.controller` | `mpcoaController.java` | **Controller Class Method** | 본 처리 거래 처리 흐름 제어 · Service Method 호출 |
| **Service** | `package nhnis.mp.co.a.service` | `mpcoa0001Service.java` | **Service Class** | Biz Logic 구현체 · DTO·DAO 객체로 로직 처리 |
| **DAO** | `package nhnis.mp.co.a.dao` | `mpcoa0001DAO.java` | **DAO Class** | DB Access (C/R/U/D) · SQL ID → OR Mapper |
| **DTO** | `package nhnis.mp.co.a.dto` | `mpcoa0001SDTOIn.java`<br>`mpcoa0001SDTOOut.java`<br>`mpcoa0001SDTOio.java` | 서비스별 In/Out/IO | 서비스 입력·출력 데이터 구현체 |
| **Resource** | `resource` → `mp` → `co` → `a` | `mpcoa0001-ORA.xml`<br>`mpcoa0002-ORA.xml` | SQL ID (DAO 연동) | OR Mapper XML (Oracle) |

### 3.3 좌→우 · 상→하 배치 표

| 구역 | 분류 (Top→기능) | Java 업무 구현 | Resource (Mapper) | 계층 설명 (우측) |
|---|---|---|---|---|
| 예시 a | `nhnis` → `mp` → `co` → **`a`** | **controller** → mpcoaController.java | - | 서비스ID = Controller Class Method<br>거래 처리 흐름 제어 |
| | | **service** → mpcoa0001Service.java | - | 서비스ID = Service Class<br>Biz Logic 구현 |
| | | **dao** → mpcoa0001DAO.java | **mpcoa0001-ORA.xml** | 서비스ID = DAO Class<br>DB C/R/U/D · SQL ID → OR Mapper |
| | | **dto** → SDTOIn / SDTOOut / SDTOio | **mpcoa0002-ORA.xml** | 입력·출력·입출력 동일 데이터셋 |
| 확장 b | `nhnis` → `mp` → `co` → **`b`** | (동일 4계층 패턴 반복) | (동일 Mapper 패턴) | 세부 업무 `b`에 동일 구조 적용 |
| 확장 … | `......` | (반복) | (반복) | 기능 단위마다 패키지·파일 세트 복제 |
| 수평 확장 | `co` 하위 다른 업무 | `mp`/`co`/`x`/… | `resource/mp/co/x/` | 업무구분별 동일 패턴 |

## 4. 계층별 구조 분석

### 4.1 Controller Layer

| 항목 | 내용 |
|---|---|
| 패키지 | `nhnis.mp.co.a.controller` |
| 예시 | `mpcoaController.java` |
| 서비스ID | **Controller Class Method** (= 메서드 단위 서비스ID) |
| 책임 | 본 처리(메인) 거래 처리 흐름 제어 |
| 하위 호출 | Service Method 호출 |

**해석**: Controller 클래스명에는 S/C/U/D 구분자를 넣지 않고, **메서드·매핑 단위**로 서비스ID(조회/등록/수정 등)를 표현한다. (프로젝트 명명규칙과 일치)

### 4.2 Service Layer

| 항목 | 내용 |
|---|---|
| 패키지 | `nhnis.mp.co.a.service` |
| 예시 | `mpcoa0001Service.java` |
| 서비스ID | **Service Class** (= 클래스 단위, 식별번호 4자리까지) |
| 책임 | 업무 처리를 위한 Biz Logic 구현체 |
| 의존 | DTO·DAO 객체 사용 |

**해석**: Service는 **트랜잭션·업무 규칙**의 중심. TCF Facade/Service 경계와 직접 연관된다.

### 4.3 DAO Layer

| 항목 | 내용 |
|---|---|
| 패키지 | `nhnis.mp.co.a.dao` |
| 예시 | `mpcoa0001DAO.java` |
| 서비스ID | **DAO Class** |
| 책임 | DB Access (Create/Read/Update/Delete) |
| 연계 | SQL ID 호출 → OR Mapper → DB Data Access |

**해석**: DAO는 **MyBatis SQL ID**와 1:1 대응. Statement timeout·Remaining Budget 적용 대상.

### 4.4 DTO Layer

| 항목 | 내용 |
|---|---|
| 패키지 | `nhnis.mp.co.a.dto` |
| 예시 In | `mpcoa0001SDTOIn.java` |
| 예시 Out | `mpcoa0001SDTOOut.java` |
| 예시 IO | `mpcoa0001SDTOio.java` |
| 책임 | 서비스 입력·출력 값 처리 데이터 구현체 |
| 변형 | 입력/출력 분리 또는 입출력 동일 데이터셋 |

**해석**: DTO 파일명에 **서비스ID 전체**(S/C/U/D 구분자 포함)가 들어간다. Controller/Service/DAO와 달리 **기능 구분자가 파일명에 포함**된다.

### 4.5 Resource (ORM Mapper)

| 항목 | 내용 |
|---|---|
| 경로 | `resource` → `mp` → `co` → `a` |
| 예시 | `mpcoa0001-ORA.xml`, `mpcoa0002-ORA.xml` |
| DB 구분 | `-ORA` = Oracle |
| 대응 | DAO Class · SQL ID와 동일 식별번호 |

**해석**: Java 패키지 계층과 **동일 업무코드 경로**를 resource에도 반영 — 코드·SQL·업무분류 **3자 대응** 구조.

## 5. 서비스ID · 파일명 규칙 정리

이미지와 프로젝트 명명규칙(`NAMING_CONVENTION.md`)을 대조한 표다.

| 대상 | 명명 패턴 | 예시 | 서비스ID 포함 |
|---|---|---|---|
| Controller | `{mp}{co}{a}{0000}Controller.java` | `mpcoa0000Controller.java` | Method 단위 (S0/C0/…) |
| Service | `{mp}{co}{a}{0001}Service.java` | `mpcoa0001Service.java` | 식별번호까지 |
| DAO | `{mp}{co}{a}{0001}DAO.java` | `mpcoa0001DAO.java` | 식별번호까지 |
| DTO In | `{서비스ID}DTOin.java` | `mpcoa0001S0DTOin.java` | **전체** |
| DTO Out | `{서비스ID}DTOout.java` | `mpcoa0001S0DTOout.java` | **전체** |
| Mapper | `{mp}{co}{a}{0001}-ORA.xml` | `mpcoa0001-ORA.xml` | 식별번호까지 |

> **주의**: 이미지에는 `SDTOIn`/`SDTOOut`/`SDTOio` 표기가 보이나, 현행 PDMP 명명규칙은 `DTOin`/`DTOout`/`DTOio`를 사용한다. 원본 장표와 구현 규칙의 **표기 차이**는 Inventory 검증 대상이다.

### 5.1 서비스ID 구조 (참고)

```text
[대구분 2자][업무구분 2자][세부업무 1자][식별번호 4자][구분자 1자][순번 1자]
예: mpcoa0000S0  →  mp + co + a + 0000 + S + 0
```

## 6. 아키텍처 관점 핵심 정리

| 관점 | 확인되는 구조 |
|---|---|
| Package Architecture | `nhnis.{group}.{app}.{function}.{layer}` |
| Layer Architecture | Controller → Service → DAO (+ DTO 횡단) |
| Code–SQL Alignment | Java DAO ↔ `{id}-ORA.xml` 동일 식별번호 |
| Business Taxonomy | 패키지 경로 = 업무 분류 (mp/co/a) |
| Scalability | 기능(`a`,`b`,…)·업무(`co`,…) 수평 복제 |
| Service Identity | 서비스ID = Controller Method / Service / DAO / DTO 공통 키 |

## 7. PDMG/TCF 프레임워크 연관 시사점

| 영역 | 시사점 |
|---|---|
| **Controller** | TCF Facade 진입점 · ExecutionDeadline bind 시작 후보 |
| **Service** | `@Transactional` · Biz Logic · Remaining Budget 소비 |
| **DAO / OR Mapper** | MyBatis Statement timeout · SQL ID = Evidence 추적 키 |
| **DTO** | 온라인 JSON 직렬화·입출력 계약 |
| **서비스ID** | 거래 추적·Evidence Registry·Runtime Monitor 공통 식별자 |
| **resource 경로** | `rdw/mp/co/a/` — DB 스키마·Mapper 배치 표준 |

## 8. 판독 제한·검증 필요 항목

| 항목 | 상태 |
|---|---|
| `mpcoaController.java` vs `mpcoa0000Controller.java` | 이미지는 식별번호 생략 표기 — 명명규칙과 대조 필요 |
| DTO 접미사 `SDTOIn` vs `DTOin` | 장표·구현 표기 차이 |
| `resource` vs `src/main/resources/rdw/` | 이미지는 `resource` 단순 표기 — 실제 배포 경로는 프로젝트 표준 확인 |
| 기능 `b`, `......` 세부 명칭 | 이미지에 코드만 표기 |
| co 외 업무구분(ic, ms, sa 등) | 이미지는 co 예시만 — 수평 확장은 `......`로 암시 |
