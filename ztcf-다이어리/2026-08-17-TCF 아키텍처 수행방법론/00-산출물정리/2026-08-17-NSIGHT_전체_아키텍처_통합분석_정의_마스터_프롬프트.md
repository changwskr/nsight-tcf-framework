# 2. 절대 준수 원칙

## 2.1 확인된 것과 제안을 섞지 않는다

모든 핵심 판단에는 반드시 아래 상태 중 하나를 부여한다.

| 상태 | 의미 |
|---|---|
| `[FACT]` | 문서·이미지·소스·설정·런타임 증적에서 직접 확인 |
| `[CONFIRMED]` | 복수 근거가 일치하고 현재 기준으로 사용할 수 있음 |
| `[DECISION]` | 프로젝트에서 명시적으로 선택·승인한 아키텍처 기준 |
| `[AS-IS]` | 현재 구현 또는 현재 운영 구조 |
| `[TO-BE]` | 목표 아키텍처로 확정된 구조 |
| `[PROPOSAL]` | 아직 승인되지 않은 아키텍트 제안 |
| `[GAP]` | AS-IS와 TO-BE 또는 문서·소스·설정 간 불일치 |
| `[RISK]` | 장애·보안·성능·운영·일정 위험 |
| `[OPEN]` | 의사결정 또는 추가 자료가 필요한 항목 |
| `[UNKNOWN]` | 현재 Evidence만으로 확인 불가 |
| `[DEPRECATED]` | 과거 기준이며 현재 기준에서 폐기 |

다음 행위를 금지한다.

```text
PROPOSAL을 FACT처럼 표현
과거 문서를 CURRENT처럼 표현
AS-IS를 TO-BE로 자동 승격
소스에 존재한다는 이유만으로 표준이라고 판단
확인되지 않은 값 임의 생성
UNKNOWN을 추측으로 메움
```

## 2.2 Source Baseline을 혼합하지 않는다

다음 System Scope는 반드시 분리한다.

```text
A. NSIGHT 전체 목표 Architecture
B. NSIGHT TCF Framework
C. PDMG AS-IS / Reference
D. PDMK AS-IS
E. PDMP AS-IS
F. 업무 서비스 모듈군
G. Infrastructure / Middleware
H. Data Platform / Migration
I. AI / Harness / Ontology / Model
J. 과거 문서 / 책 / Diary / Build Help / Generated 자료
```

특히 **PDMG Source 분석 기준**은 프로젝트에서 지정한 다음 모듈을 기본 Source Baseline으로 사용한다.

```text
pdmg-ui
pdmg-jwt
pdmg-fw
pdmg-service
pdmg-om
```

단, 특정 ZIP/Branch에 어떤 모듈이 실제로 존재하지 않으면:

```text
[EXPECTED BASELINE]에는 존재
[CURRENT SOURCE SNAPSHOT]에는 없음
→ GAP 또는 UNKNOWN
```

으로 표현하고 존재한다고 가정하지 마라.

NSIGHT TCF의 구조를 PDMG AS-IS에 덮어쓰지 말고, PDMG AS-IS를 NSIGHT 전체 TO-BE로 자동 승격하지 마라.

충돌 시 기본 우선순위는 다음과 같다.

# 5. STEP 1 — Architecture Vision

NSIGHT의 전략적 배경과 비전을 먼저 정의한다.

프로젝트 자료에서 확인되는 방향을 근거로 다음 질문에 답한다.

```text
왜 기존 정보계를 다시 설계하는가?
정보계는 저장소인가, 경영 플랫폼인가?
배치 중심에서 무엇으로 전환하는가?
실시간·배치·분석은 어떤 역할을 가지는가?
데이터 기반 판단과 고객 반응을 어떻게 지원하는가?
향후 10년을 견디기 위한 아키텍처 특성은 무엇인가?
```

최소 5대 NFR을 정의한다.

| NFR | 핵심 검토 |
|---|---|
| Performance | TPS, p95, Thread, DB, GC, Timeout |
| Availability | HA, 장애격리, Fail-Over/Back, DR |
| Scalability | Scale-Out, VM/JVM/Application 확장 |
| Security | SSO, JWT, 권한, 개인정보, Key |
| Observability | GUID, ServiceId, Log, Metric, Trace, OM |

숫자 기준은 문서 버전 간 충돌 여부를 먼저 확인한다.


# 35. Known Architecture Anchors — 검증 출발점

다음은 프로젝트에서 반복적으로 논의된 **검증 출발점**이다. 최종 확정값으로 무조건 사용하지 말고 Source/Evidence와 재대조한다.

## 35.1 Strategy

```text
정보계 = 단순 저장소가 아니라 데이터가 흐르고 반응하고 판단을 지원하는 플랫폼
Vision → Big Picture → Logical → Physical → Mechanism → Runtime
5대 NFR = Performance / Availability / Scalability / Security / Observability
```

## 35.2 Application / TCF

```text
ServiceId 중심
Controller → TCF → STF → Timeout/Transaction → Dispatcher
→ Handler → Facade → Service → Rule/DAO → Mapper → DB → ETF
```

## 35.3 WEB/WAS

```text
WEB = Apache
WAS = Tomcat
WAS Server/VM ≠ Tomcat JVM ≠ Application/WAR
구성도상의 Container = Tomcat JVM Instance로 정의한 자료 존재
Apache 1 Instance에서 Multi Listen Port 구성 가능
```

## 35.4 Security

```text
SSO + JWT
Private Key = Token Issuer
Public Key/JWKS = Validator
Gateway 우회 시 업무 Application 자체 검증 필요
```

## 35.5 Data

```text
RDW / ADW 역할 분리
실시간과 배치 병행
CDC/Kafka/ETL/Batch
Migration = Source → Stage → Transform/Validate → Target → Reconciliation
```

## 35.6 Performance

```text
전체 사용자/세션/동시요청/TPS를 분리
p95 목표가 존재
TPMC와 TPS는 동일 개념이 아님
Tomcat Thread와 Hikari Pool을 독립 산정하지 않음
여러 시점의 8C/16C/32C, Session 60m/90m, TPS/VM 값이 존재하므로 버전 충돌 검증 필요
```

## 35.7 Physical / Inventory

```text
서버 1대 = Master Inventory 1 Row
운영/개발/DR, 센터, Hostname, WEB/WAS/AP/DB, CPU/MEM/Disk/tpmC 연결
운영 노드와 DR 노드 매핑
```

## 35.8 Closed Loop

```text
Document → Model → Code → Test → Runtime Evidence → Drift → GAP/ADR → Baseline
```

# 38. 금지사항

```text
1. 확인되지 않은 CPU/MEM/Port/Version/Module 개수를 임의 생성하지 않는다.
2. 과거 성능 숫자를 최신값으로 자동 승격하지 않는다.
3. PDMG/PDMK/PDMP/NSIGHT TCF를 같은 Source Baseline으로 섞지 않는다.
4. 제품명 나열을 Architecture라고 하지 않는다.
5. Logical과 Physical을 한 그림에서 무분별하게 혼합하지 않는다.
6. Tomcat Server/JVM/Container/WAR 개념을 혼용하지 않는다.
7. Session 수를 TPS 또는 동시요청자와 동일시하지 않는다.
8. DB Pool을 CPU 배수나 maxThreads 비율 하나로 결정하지 않는다.
9. Source에 없는 기능을 구현됐다고 쓰지 않는다.
10. 문서에 적혀 있다는 이유만으로 현재 코드보다 우선하지 않는다.
11. Runtime Evidence 없는 항목을 운영검증 완료라고 하지 않는다.
12. 다른 Domain의 내부 DAO/Mapper/Table 호출을 정상 패턴으로 묘사하지 않는다.
13. Timeout 숫자만 적고 Cancel/Transaction/DB 상태를 설명하지 않는 설계를 허용하지 않는다.
14. Architecture Decision의 이유·Trade-off·검증방법을 생략하지 않는다.
15. Source/Evidence를 표시하지 않은 핵심 판단을 확정값으로 제시하지 않는다.
```
