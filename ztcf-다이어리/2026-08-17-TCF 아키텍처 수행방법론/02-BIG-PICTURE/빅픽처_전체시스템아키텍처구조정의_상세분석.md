# 빅픽처 — 전체 시스템 아키텍처 구조 정의 상세 분석

## 1. 문서 개요

본 문서는 원본 장표 **「전체 시스템 아키텍처 구조 정의」**를 기준으로 차세대 정보계의 전체 시스템 구조를 텍스트 아키텍처로 재구성하고, 각 영역의 역할·연계방식·데이터 흐름·런타임 경계를 분석한 자료다.

원본 우측 상단 분류는 다음과 같다.

```text
1.4 시스템 아키텍처 구성
```

이 장표는 앞서 정의된 다음 자료들을 한 화면에서 연결하는 **전체 Big Picture Architecture** 성격을 가진다.

```text
Application Domain
Application Classification
System Group
Data Subject Area
Interface
Runtime
Data Platform
Data Governance
External / Legacy Integration
```

원본에서 시각적으로 강조된 핵심 구축영역은 번호 `1 ~ 4`로 표시되어 있다.

```text
1 : 마케팅플랫폼 / 마케팅 이벤트 처리
2 : 데이터플랫폼
3 : BI포탈
4 : 데이터 거버넌스
```

따라서 이 장표는 차세대 정보계의 핵심 구축영역을 다음과 같이 연결한다.

```text
채널
  ↓
정보계 어플리케이션 서비스
  ├─ ① 마케팅플랫폼
  └─ ③ BI포탈
  ↓
① 마케팅 이벤트 처리
  ↓
② 데이터플랫폼
  ├─ RDW
  └─ ADW
  ↓
④ 데이터 거버넌스

그리고

유관 시스템 / 정보계 유관 / 계정계 / 외부기관
  ↕
API Gateway / MCA / CDC / ETL / FOS / MFT
  ↕
차세대 정보계
```

# 2. 핵심 결론

이 장표에서 확인되는 전체 아키텍처의 핵심은 다음과 같다.

1. **채널과 정보계 애플리케이션을 분리**하고 JSON/MCA 등을 통해 연계한다.
2. 정보계 애플리케이션 서비스는 **마케팅플랫폼과 BI포탈**을 중심으로 구성된다.
3. 고객행동은 별도의 **마케팅 이벤트 처리 영역**에서 수집·처리되고 Kafka/EBM/UMS와 연결된다.
4. 데이터플랫폼은 **RDW(실시간/준실시간)** 와 **ADW(분석)** 로 분리된다.
5. 외부/유관 시스템 연계는 **API Gateway(CruzAPIM), MCA, CDC, ETL, FOS, MFT** 등 다양한 방식으로 구분된다.
6. 데이터 거버넌스는 **비즈메타·데이터품질관리·데이터흐름관리**를 횡단 통제한다.
7. 정보계는 계정계 및 유관 시스템과 단순 API만으로 연결되지 않고 **온라인/API, CDC, 파일, ETL, MFT, JDBC, Agent, Polling**을 함께 사용하는 다중 연계구조다.
8. 실시간 고객행동 처리와 정형 분석 데이터 처리를 별도 런타임으로 분리함으로써 **업무 트랜잭션과 이벤트/분석 부하를 분리**하는 방향을 보인다.

# 4. 전체 아키텍처 영역 구분

원본을 기능영역으로 분리하면 다음 9개 영역으로 볼 수 있다.

```text
1. Channel
2. Channel Integration
3. Information Application Service
4. Marketing Event Processing
5. Data Platform
6. Data Governance
7. Related / Legacy Systems
8. Information-related Systems
9. External Institutions
```

이를 다시 Architecture Layer 관점으로 재구성하면:

```text
Experience Layer
 └─ Channel

Integration Layer
 ├─ MCA
 ├─ API Gateway
 ├─ CDC
 ├─ ETL
 ├─ FOS
 └─ MFT

Business Application Layer
 ├─ Marketing Platform
 └─ BI Portal

Event Processing Layer
 └─ Marketing Event Processing

Data Layer
 ├─ RDW
 └─ ADW

Governance Layer
 └─ BizMeta / Quality / Flow

External / Legacy Layer
 ├─ 계정계 / 유관시스템
 ├─ 정보계 유관
 └─ 외부기관
```

> Layer 명칭은 원본을 구조화한 **ANALYSIS**다.

# 6. 마케팅플랫폼 Web

원본에는 마케팅플랫폼 앞단에 다음 컴포넌트가 별도로 표시된다.

```text
마케팅플랫폼 Web
```

구조:

```text
채널 / JSON
       ↓
Marketing Platform Web
       ↓
Marketing Platform Application
```

이는 화면/채널 접점과 업무 애플리케이션을 분리하는 Web Tier가 존재함을 보여준다.

---

# 7. 채널 → 마케팅플랫폼 연계

원본에서 채널은 다음 방식으로 정보계 애플리케이션과 연결된다.

```text
계정단말
 ├─ 계정거래
 └─ Single View / JSON

정보계단말
 ├─ UI
 └─ Package UI

→ JSON
→ 서비스
→ Marketing Platform Web / BI Portal Web
```

또한 계정거래는:

```text
계정 단말
  ↓
MCA
  ↓
유관/계정 시스템
```

구조를 가진다.

즉 화면업무는 크게 다음 두 종류의 접근경로가 공존한다.

```text
1. JSON 기반 정보계 서비스
2. MCA 기반 계정 거래
```

# 8. Channel Integration 영역

원본의 채널통합 영역에는 다음이 보인다.

```text
MCA
단말거래
```

따라서 Channel Integration은 계정성 거래의 중계 역할을 수행하는 것으로 볼 수 있다.

```text
  ↓

  ↓
```

# 10. BI포탈 Web

원본에는 다음 Web Tier가 별도로 표시된다.

```text
BI포탈 Web
```

구조:


```text
단말관리
단말배포
```

이는 앞선 Application Classification의:

```text
IM-XM : UI/UX Management
IM-XD : UI/UX Deployment
```

와 관계되는 것으로 볼 수 있다.

다만 원본 그림에서 물리적인 직접 연결선의 세부 의미는 명확하지 않으므로 **관련성은 ANALYSIS**로 관리한다.

# 12. ① 마케팅 이벤트 처리 영역

마케팅 이벤트 처리 영역은 정보계 애플리케이션 서비스와 분리된 별도 녹색 영역으로 표시된다.

원본 주요 구성:

```text
마케팅 이벤트 처리
│
├─ 데이터 수집
├─ 행동정보처리서버
├─ 고객행태
├─ Wise Collector 수집
├─ 고객행동데이터 Kafka
├─ KAFKA
├─ 실시간 처리 서버
│   ├─ EBM
│   └─ 이벤트 정보
├─ UMS
└─ 데이터 분석
```

이 영역은 고객 채널에서 발생하는 이벤트를 실시간 또는 준실시간으로 수집해 마케팅 행동으로 연결하는 **Event Processing Architecture**다.

# 13. 고객행동 수집 흐름

원본에서 확인되는 주요 흐름은 다음과 같다.

```text
Web 채널 / Mobile 채널
       │
       ├─ Event
       ▼
Wise Collector Proxy
       │
       ▼
비대면 로그
       │
       ▼
Wise Collector 수집
       │
       ▼

       │
       ▼

       │

       │
       ├─ EBM
       └─ 이벤트 정보
```

# 24. Application → Data Platform JDBC 연계

# 74. Architecture Principle 도출

## SYS-PR-01 Channel Separation

채널 UI와 업무/데이터 처리 계층을 분리한다.

## SYS-PR-02 Integration by Purpose

온라인, 거래, 데이터, 파일, 이벤트 연계를 목적별 기술로 분리한다.

## SYS-PR-03 Real-time / Analytics Separation

RDW와 ADW의 책임을 분리한다.

## SYS-PR-04 Event Processing Isolation

고객행동 이벤트는 Kafka/실시간 처리영역으로 분리한다.

## SYS-PR-05 Governance by Design

메타·품질·흐름 관리를 데이터플랫폼에 횡단 적용한다.

## SYS-PR-06 Legacy Coexistence

기존 유관/Big Data/계정계와 단계적으로 공존·연계한다.

> Principle ID는 문서화 목적의 **ANALYSIS**다.

# 87. 최종 평가

이 장표는 차세대 정보계 전체를 가장 종합적으로 표현하는 **System Architecture Big Picture Baseline**이다.

핵심 아키텍처는 다음 4개의 중심축으로 구성된다.

```text
① Marketing / Event
② Data Platform
③ BI
④ Data Governance
```

그리고 이를 다음의 통합·연계 계층이 연결한다.

```text
MCA
API Gateway
CDC
Kafka
JDBC
Agent
ETL
FOS
MFT
```

전체적인 Architecture Intent는 다음 문장으로 정리할 수 있다.

> **채널에서 발생하는 온라인 거래·정보조회·고객행동 이벤트를 업무 특성에 맞는 인터페이스로 수용하고, 마케팅플랫폼·BI포탈·RDW/ADW·데이터거버넌스를 중심으로 실시간 고객 대응과 데이터 기반 분석을 동시에 지원하며, 기존 계정계·유관 시스템·외부기관과 API/CDC/파일/ETL 방식으로 공존 연계하는 차세대 정보계 구조**

후속 상세설계에서는 본 Big Picture를 기준으로 다음 Traceability를 유지해야 한다.

```text
Business Requirement
      ↓
Application Domain
      ↓
Application Code
      ↓
System Group
      ↓
Runtime Flow
      ↓
Interface Type
      ↓
Data Subject Area
      ↓
Physical Server
      ↓
NFR / Security / Operations
      ↓
Runtime Validation
```

결론적으로 본 장표는 **Application, Interface, Runtime, Data, Governance, Legacy Integration을 하나로 연결하는 차세대 정보계 전체 시스템 아키텍처 기준선**으로 사용할 수 있다.
