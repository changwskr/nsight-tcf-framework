# 빅픽처 — 주요 시스템 대상서버 식별
## 논리적 대상 서버군 중심 TOP-DOWN 상세 아키텍처 분석

> **원본 장표:** 주요 시스템 대상 서버 식별  
> **분류:** 1.4 시스템 아키텍처 구성  
> **문서 성격:** 차세대 정보계 Logical Server Group Identification / Physical Architecture 선행 기준  
> **분석 원칙:** 원본에서 직접 확인되는 내용은 `FACT`, 기존 Big Picture 및 선행 장표와의 구조적 연결은 `ANALYSIS`, 원본만으로 확정할 수 없는 사항은 `확인 필요`로 구분한다.

---

# 1. 핵심 결론

원본 장표의 핵심 문장은 다음과 같다.

> **정보계 차세대 시스템은 주요 시스템 영역에 대해 논리적 대상 서버군을 각각 식별 함**

즉 이 장표는 실제 물리 Hostname, CPU, Memory, IP, Node 수를 확정하는 장표가 아니라, 차세대 정보계의 주요 시스템 영역별로 **어떤 종류의 논리적 서버군이 필요한지 식별하는 상위 Physical/Technical Architecture 기준**이다.

전체 서버 영역은 다음 6개 범주로 정리된다.

```text
차세대 정보계 대상 서버군
│
├─ ① 마케팅플랫폼
├─ ② 데이터플랫폼
├─ ③ BI포탈
├─ ④ 데이터거버넌스
├─ ⑤ IT서비스 및 인프라 지원
└─ 기타(임시)
```

원본에서 식별되는 논리 서버 역할은 다음과 같다.

```text
① 마케팅플랫폼        : 5개
② 데이터플랫폼        : 2개
③ BI포탈              : 4개
④ 데이터거버넌스      : 2개
⑤ IT서비스/인프라지원 : 8개
기타(임시)            : 2개 역할 유형
```

따라서 원본은 **상시 운영 대상 21개 논리 서버 역할 + 임시 이행 2개 역할 유형**을 식별한 것으로 볼 수 있다.

> 단, 이는 "서버 역할/서버군 종류"의 개수이며 실제 물리 서버 대수와 동일하지 않다.

# 5. 마케팅플랫폼 서버 구조

```text
Marketing Platform
│
├─ [일반 업무]
│   └─ 마케팅플랫폼 서버
│
├─ [고객 Single View]
│   └─ 미니 싱글뷰 서버
│

    ├─ 실시간처리 서버
    ├─ 행동정보 처리 서버
```

### ANALYSIS

이 분리는 마케팅플랫폼 내에서도 실행 특성이 다른 업무를 하나의 서버군에 모두 넣지 않는다는 의미를 가진다.

```text
일반 Online 업무
        ≠
Single View
        ≠
Event / Behavior Processing
```

특히 고객행동 처리 영역은 일반 업무 WAS와 분리된 독립 Runtime 영역으로 식별된다.

# 10. RDW와 ADW는 물리 서버 1대라는 의미가 아님

장표에서 `ADW`, `RDW`가 각각 하나의 대상 서버군으로 식별되지만 다음은 정의하지 않는다.

```text
Physical Node Count
CPU
Memory
Disk
Cluster
Active/Active
Active/Standby
DR Node
```

따라서:

```text
"RDW 1개"
≠
"RDW 물리서버 1대"
```

이다.

정확한 해석은:

```text
"RDW라는 논리적 대상 서버군 1개"
```

이다.

# 19. IT 공통 서비스의 Architecture 의미

이 영역은 비즈니스 애플리케이션 서버와 달리 여러 시스템이 공통으로 사용하는 **Cross-Cutting Technical Service**다.

```text

RDW
ADW
Governance
    ▲
    │

```

# 33. 선행 시스템 그룹 정의와의 관계

선행 장표 **시스템 그룹 업무 구분**은 현재 장표보다 한 단계 더 상세한 Mapping을 제공했다.

예:

```text
현재 장표
마케팅플랫폼 서버
        ↓

선행 System Group
마케팅플랫폼 WEB 서버
마케팅플랫폼 WAS 서버
        ↓

Server Base Name
sbmpco
```

즉 두 장표의 관계는:

```text
Target Server Identification
        ↓
System Group Definition
        ↓
Server Naming
        ↓
Physical Inventory
```

이다.

# 50. 최종 평가

이 장표는 차세대 정보계의 물리 아키텍처를 바로 확정하는 장표가 아니라, **전체 Big Picture를 실제 서버 구조로 전환하기 위한 첫 번째 논리 서버 식별 단계**다.

핵심 흐름은 다음과 같다.

```text
Application Architecture
        ↓
System Area
        ↓
Logical Target Server Group
        ↓
System Group / Server Role
        ↓
Physical Server
        ↓
Capacity / HA / DR / Network
```

따라서 이 장표의 가장 중요한 Architecture Intent는 다음과 같이 정리할 수 있다.

> **업무·분석·데이터·거버넌스·공통기술 기능의 실행 특성을 기준으로 논리적 대상 서버군을 먼저 분리하고, 후속 Physical Architecture에서 각 서버군의 실제 노드 수·사양·HA/DR·미들웨어·운영환경을 구체화한다.**

결론적으로 본 장표는 **차세대 정보계의 Application/Runtime Architecture를 Physical Server Architecture로 연결하는 Logical Target Server Baseline**이다.
