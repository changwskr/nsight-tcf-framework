# 빅픽처 — 어플리케이션 도메인 구성 정의 아키텍처 분석

## 1. 핵심 결론

이 장표는 차세대 정보계의 애플리케이션을 **업무/데이터/분석/거버넌스/공통기반 도메인으로 분류하고, 각 도메인의 세부 기능 구성과 구축 성격(신규·고도화·대응개발)을 한 화면에서 정의한 상위 Application Domain Architecture**다.

원본에서 직접 확인되는 최상위 도메인은 다음과 같다.

```text
차세대 정보계
│
├─ 데이터플랫폼 RDW
├─ 데이터플랫폼 ADW
├─ BI 포탈
├─ 마케팅플랫폼
├─ 데이터거버넌스
├─ 빅데이터플랫폼
└─ IT서비스 및 업무지원
```

이 장표의 중요한 특징은 단순 도메인 나열이 아니라 각 영역을 다시 세부 업무 기능으로 분리했다는 점이다.

```text
데이터플랫폼
 ├─ SOR
 ├─ 통합/요약/집계
 ├─ 보고서마트
 ├─ 단위업무마트
 ├─ Feed Back
 └─ 분석지원

BI포탈
 ├─ BI포탈
 ├─ 신용실적
 ├─ OLAP
 ├─ Self-BI
 └─ 대시보드

마케팅플랫폼
 ├─ 마케팅 공통
 ├─ 고객 정보
 ├─ 고객 상담
 ├─ 이벤트
 ├─ 마케팅 지원
 └─ 고객 접촉

데이터거버넌스
 ├─ 비즈 메타
 ├─ 데이터 흐름
 └─ 데이터 품질

IT서비스 및 업무지원
 ├─ 형상관리
 ├─ 데이터 처리
 ├─ 보고서 디자이너
 ├─ 프레임워크 관리
 ├─ 라이브러리
 ├─ 정보단말관리
 ├─ 배치관리
 ├─ 실시간 중계
 └─ 시스템 공통
```

또한 각 영역에 붙은 `신규 / 고도화 / 대응개발` 표식은 단순 설명이 아니라 **구축 범위와 변화 성격을 구분하는 포트폴리오 정보**다.

따라서 이 장표는 후속 Application Architecture에서 다음을 결정하는 기준선으로 사용할 수 있다.

- 어떤 도메인이 존재하는가?
- 각 도메인이 어떤 기능을 소유하는가?
- 어떤 영역은 신규 구축인가?
- 어떤 영역은 고도화인가?
- 기존 빅데이터 영역과 어떻게 공존/대응하는가?
- 공통 IT서비스는 어느 기능을 제공하는가?

# 4. 최상위 도메인 분류

| 도메인 | 구축 성격 | 핵심 역할 |
|---|---|---|
| 데이터플랫폼 RDW | 신규 | 실시간/근실시간 데이터 기반 |
| 데이터플랫폼 ADW | 고도화 | 분석 데이터/마트 기반 |
| BI 포탈 | 신규+고도화 혼합 | 통합 BI/실적/OLAP/Self-BI/대시보드 |
| 마케팅플랫폼 | 신규+고도화 혼합 | 고객·상품·상담·캠페인·이벤트 |
| 데이터거버넌스 | 신규 | 메타/흐름/품질 관리 |
| 빅데이터플랫폼 | 대응개발 표식 | 기존/연계 분석·빅데이터 영역 |
| IT서비스 및 업무지원 | 신규 | 공통 개발·운영·데이터 처리 기반 |

이 분류는 애플리케이션을 업무 시스템 이름이 아니라 **역할 중심 도메인**으로 나눈다는 점에서 중요하다.

# 5. 데이터플랫폼 RDW 도메인 상세

## 5.1 원본 FACT

```text
데이터플랫폼 RDW [신규]

SOR
 ├─ 고객
 ├─ 상품
 ├─ 수신
 ├─ 외환
 ├─ 여신
 └─ ...

통합/요약/집계
보고서 마트
Feed Back
```

---

## 5.2 구조적 의미

RDW는 장표에서 매우 단순한 구조로 표현된다.

```text
Source of Record
      ↓
통합/요약/집계
      ↓
보고서 마트
      ↓
Feed Back
```

### ANALYSIS

이는 RDW가 다음 역할을 갖는 것으로 해석할 수 있다.

- 운영/실시간 정보의 기준 저장
- 고객/상품/계정성 업무 데이터의 최신 정보 확보
- 근실시간 집계
- 보고서 데이터 제공
- 업무/마케팅 결과의 피드백 반영

## 6.2 RDW와 ADW 비교

```text
RDW
 ├─ SOR
 ├─ 통합/요약/집계
 ├─ 보고서마트
 └─ Feed Back

ADW
 ├─ SOR
 ├─ 통합/요약/집계
 ├─ 보고서마트
 ├─ 단위업무마트
 ├─ Feed Back
 └─ 분석지원
```

### 핵심 차이

ADW는 RDW보다 다음 기능이 추가된다.

- 업무별 통합
- 계수
- OLAP 마트
- 단위업무 마트
- 분석 지원

즉 ADW는 **심화 분석 및 업무별 분석 소비를 위한 데이터플랫폼**으로 해석된다.

# 13. 마케팅플랫폼 도메인 전체 구조

```text
마케팅플랫폼
│
├─ 마케팅 공통 [신규]
├─ 고객 정보 [고도화]
├─ 고객 상담 [고도화]
├─ 이벤트 [신규 + 고도화]
├─ 마케팅 지원 [고도화]
└─ 고객 접촉 [신규]
```

이 구조는 마케팅플랫폼을 **공통기능 → 고객정보 → 상담 → 이벤트 → 지원 → 접촉**의 다층 업무 도메인으로 나눈다.


- 각 Application이 ETL/CDC를 개별 구축
- 도메인마다 별도 Artifact Repository 운영
- 마케팅 업무가 빅데이터 플랫폼의 물리 저장구조에 직접 결합

# 51. Architecture Principle 도출

## AD-01 Clear Domain Ownership

```text
각 기능은 하나의 주 도메인에서 소유한다.
```

## AD-02 Shared Platform

```text
ETL/CDC/Framework/Library는 공통기반으로 제공한다.
```

## AD-03 Data Platform Separation

```text
RDW와 ADW의 역할을 분리한다.
```

## AD-04 Governance by Design

```text
메타/흐름/품질은 데이터 구축 이후가 아니라 설계에 내장한다.
```

## AD-05 Analytics Consumer Separation

```text
BI포탈은 Data Platform과 분리된 소비/분석 영역으로 구성한다.
```

## AD-06 Event-driven Marketing

```text
고객 행동과 실시간 이벤트 처리를 마케팅 Capability로 내장한다.
```

> Principle ID는 문서화를 위한 ANALYSIS/제안.

# 61. 최종 평가

이 장표는 차세대 정보계 Application Architecture의 가장 중요한 **도메인 분류 기준선** 중 하나다.

전체 그림을 한 번 더 압축하면 다음과 같다.

```text
┌──────────────────────── 차세대 정보계 ─────────────────────────┐
│                                                               │
│   [데이터플랫폼 RDW]      [데이터플랫폼 ADW]                   │
│        신규                    고도화                          │
│                                                               │
│   [BI 포탈]               [마케팅플랫폼]                       │
│   신규+고도화              신규+고도화                         │
│                                                               │
│   [데이터거버넌스]          [빅데이터플랫폼]                    │
│        신규                 대응개발/연계 대상                 │
│                                                               │
│            [IT서비스 및 업무지원]                              │
│                       신규                                    │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

그리고 각 영역의 책임은 다음처럼 정리된다.

```text
RDW
= 실시간/근실시간 데이터

ADW
= 분석/마트 데이터

BI Portal
= 분석 및 정보 소비

Marketing Platform
= 고객/상품/상담/캠페인 업무 실행

Data Governance
= Meta / Flow / Quality

Big Data
= 대용량/비정형/고급 분석

IT Service
= 개발/배포/ETL/CDC/Batch/Framework 공통 기반
```

이 장표의 아키텍처적 가치가 큰 이유는 다음과 같다.

1. **Application Portfolio의 최상위 Domain Boundary를 정의한다.**
2. **신규/고도화 대상을 동시에 표시하여 구축 범위를 보여준다.**
3. **RDW와 ADW를 분리해 데이터 플랫폼 역할을 명확히 한다.**
4. **BI포탈을 공통포털·실적·OLAP·Self-BI·대시보드로 세분화한다.**
5. **마케팅플랫폼을 고객정보·상담·이벤트·접촉까지 상세 분해한다.**
6. **Data Governance를 Biz Meta / Flow / Quality로 독립 도메인화한다.**
7. **ETL/CDC/Framework/NEXUS/Batch 등을 IT공통 서비스로 분리한다.**
8. **기존 Big Data 영역과 차세대 신규 데이터플랫폼의 역할 재정의 필요성을 보여준다.**

후속 설계에서는 반드시 다음 Traceability가 만들어져야 한다.

```text
Domain
  ↓
Sub-Domain
  ↓
Application
  ↓
Module
  ↓
ServiceId / Interface
  ↓
Data
  ↓
Runtime
  ↓
Physical Deployment
```

결론적으로 이 장표는 **차세대 정보계의 애플리케이션을 어떤 도메인으로 나누고, 어떤 기능을 신규 구축하거나 고도화할 것인지를 정의하는 Application Domain Architecture Baseline**이다.
