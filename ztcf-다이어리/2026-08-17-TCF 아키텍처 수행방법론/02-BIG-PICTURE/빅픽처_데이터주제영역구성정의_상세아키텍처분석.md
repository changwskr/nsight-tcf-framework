# 빅픽처 — 데이터 주제영역 구성 정의 상세 아키텍처 분석

## 1. 문서 개요

본 문서는 원본 장표 **「데이터 주제영역 구성 정의 (1/2) ~ (2/2)」**를 기준으로 차세대 정보계의 데이터 주제영역을 상세 전사하고, 앞서 정의된 Application Domain / Application Classification / System Group과의 관계를 분석한 자료다.

이번 장표에서 사용하는 `주제영역`은 전통적인 엔터프라이즈 데이터 모델의 고객/상품/계약/계정 등 개체 중심 Subject Area라기보다, **차세대 정보계의 주요 플랫폼·업무·관리 영역을 데이터 관리 관점에서 묶은 상위 관리영역**으로 제시된다.

원본이 정의하는 최상위 주제영역은 다음 6개다.

```text
차세대 정보계 데이터 주제영역
│
├─ 데이터플랫폼 RDW
├─ 데이터플랫폼 ADW
├─ BI포탈
├─ 마케팅플랫폼
├─ 데이터 거버넌스
└─ IT서비스 및 업무지원
```

각 주제영역은 다시 해당 영역에서 관리하는 세부 Application/기능 집합으로 구성된다.

# 13. RDW와 ADW 주제영역 비교

| 항목 | RDW | ADW |
|---|---|---|
| 주요 성격 | 실시간/준실시간 | 분석/대용량 |
| SoR | 실시간SoR | 분석SoR |
| 집계 | 준실시간요약집계 | 분석통합요약집계 |
| Mart | 준실시간보고서마트 | 단위업무마트 + 분석보고서마트 |
| Feedback | 있음 | 있음 |
| 분석지원 | 없음 | 있음 |

즉 두 영역은 유사한 계층구조를 가지지만 처리 목적과 소비 패턴이 다르다.

# 16. BI포탈 주제영역의 의미

BI 영역은 데이터를 저장하는 Source/Mart 계층이 아니라 **분석정보를 사용자에게 소비시키는 정보 활용 영역**으로 해석할 수 있다.

```text
RDW / ADW
    ↓
BI Subject Area
    ├─ BI Portal
    ├─ Credit Result
    ├─ OLAP
    ├─ Self BI
    └─ UI/UX
```

이 관점에서 BI포탈은 `Data Producer`보다 `Data Consumer / Analysis Consumer` 역할이 중심이다.

# 20. 마케팅 데이터와 업무 데이터의 경계

이번 장표는 `데이터 주제영역`이라는 제목 아래 마케팅 업무기능도 포함한다.

따라서 마케팅 주제영역은 순수한 데이터 Subject Area보다 다음의 혼합적 성격을 가진다.

```text
Business Capability
      +
Business Data Domain
```

예:

```text
통합고객
= 고객 업무기능 + 고객 데이터

캠페인
= 캠페인 업무기능 + 캠페인 데이터

고객행동데이터
= 이벤트 데이터 도메인
```

이 점은 향후 Logical Data Model의 전통적 Subject Area와 구분해야 한다.

# 49. Subject Area 정의의 장점

현재 구조는 다음 장점이 있다.

1. Application Group과 직접 연결된다.
2. 시스템/업무 책임영역이 명확하다.
3. Data Governance 적용 범위를 도메인별로 구분하기 쉽다.
4. 데이터플랫폼/BI/마케팅의 책임 경계가 보인다.
5. System Group과 연결하여 운영 Traceability를 만들 수 있다.

---

# 50. Subject Area 정의의 주의점

다만 다음 위험이 있다.

```text
Subject Area
=
Application Group
```

처럼 너무 밀접하게 정의되면 데이터 자체의 비즈니스 소유관점이 약해질 수 있다.

예를 들어 고객 데이터가:

```text
RDW 고객
ADW 고객
Marketing 통합고객
BI 고객분석
```

처럼 여러 플랫폼에 흩어져도, 상위 Business Subject Area `고객`이 없으면 전사 데이터 Ownership이 불명확할 수 있다.

따라서 후속 Data Architecture에서는 다음 이중 분류를 권고할 수 있다.

```text
Platform Subject Area
+
Business Data Subject Area
```

# 62. 최종 평가

이번 2개 장표는 차세대 정보계의 데이터 관리 범위를 다음 6개 상위 주제영역으로 고정한다.

```text
데이터플랫폼 RDW
데이터플랫폼 ADW
BI포탈
마케팅플랫폼
데이터 거버넌스
IT서비스 및 업무지원
```

이 장표의 중요한 의미는 단순 데이터 모델링이 아니라 다음과 같다.

```text
Application Classification
        ↓
Data Subject Area
        ↓
System Group
        ↓
Data / Runtime / Governance
```

특히 다음 구조적 특징이 확인된다.

1. **RDW와 ADW를 별도 주제영역으로 분리한다.**
2. **BI포탈을 분석 소비 영역으로 독립한다.**
3. **마케팅플랫폼의 16개 Application 전체를 하나의 주제영역으로 묶는다.**
4. **데이터거버넌스는 비즈메타/품질/흐름 세 축으로 정의한다.**
5. **IT서비스도 데이터/정보 처리 생태계의 관리 주제영역으로 포함한다.**
6. **Application Classification과 대부분 1:1로 정합되지만 DG-CO, IM-IG는 누락/제외 상태다.**
7. **현재 Subject Area는 전통적인 고객/상품/거래 중심 데이터 주제영역보다 플랫폼/업무 중심 성격이 강하다.**

따라서 후속 Data Architecture에서는 다음 Traceability를 확보하는 것이 중요하다.

```text
Business Data Subject
        ↓
Platform Subject Area
        ↓
Application
        ↓
Dataset / Table
        ↓
Interface / ETL / CDC
        ↓
System Group
        ↓
Physical DB / Server
        ↓
Metadata / Quality / Lineage
```

결론적으로 본 장표는 **차세대 정보계의 플랫폼별 데이터 관리 책임과 업무/정보 관리범위를 정의하는 Data Subject Area Architecture Baseline**으로 활용할 수 있다.
