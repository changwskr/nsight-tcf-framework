## 본문

채널·대외 연계에서 MCI/대외EAI를 거쳐 상품처리·플랫폼 업무, 인터페이스 통합(CDC·ETL·EAI·MFT·MMI)을 경유해 DW·경영관리·대외보고로 이어지는 전행 인터페이스 논리 구성도이다. 송수신 타입(F2F, D2D 등)과 프로토콜이 함께 표기된다.

## TEXT 구성도

```
[범례] MCI | 대외EAI | EAI | ETL | N.NDM | F2F | D2D 등

[좌측: 채널·대외]
  통합단말/SSO/EAM → EPS(권한), 통합단말관리, 자동화기기관리
    (http/https/xml, http/tcp/flat)
  인뱅 WEB, 모바일/스마트뱅킹 → 인뱅 Quics (F/W, WAS)
    (http/html, http/json)
  ClickStream, 발송서버
  IP Phone / IP PBX → 콜센터 IVR
  대외: 통신사, 대외기관, 국민카드, 로이터, SWIFT
    (X.25, 로이터 회선, SWIFT, EDI)

[연계 계층]
  채널통합(MCI) ── 전문 / FILE
  대외통합(대외 EAI) ── 전문 / FILE
  OFFAC / SWIFT / EDI

[중앙: 업무]
  상품처리 AP (Z-KESA, NDM, CICS)
  상품처리 DB (DBMS + CDC)
  마케팅플랫폼 (NDM, EBM, u-KESA)
  고객통지(UMS), 금융복합플랫폼(n-KESA)
  무인공과금·이미지콜드(n-KESA)
  방카/PPR/퇴직연금/국외점포(u-KESA)
  CMBS·통합로그·TAS(pkg), 배치작업관리(ctrlM)

[인터페이스 통합]
  CDC | ETL | EAI | 전문 | FILE | DB | MFT | MMI

[우측: 데이터·경영]
  종합자산, 리스크관리(u-KESA), OLAP(pkg), 경영관리(u-KESA·레포팅)
  ADW (DBMS, ETL) | RDW (DBMS, CDC) | BIG (DBMS, python)
  IFRS, 연결결산, 인사정보, 메타관리, 형상관리, FDS
```

## 핵심 포인트

- MCI·EAI·ETL·CDC·NDM·MFT·MMI 등 다중 연계 방식을 한 논리도로 통합 표현
- 업무별 z/n/u-KESA 프레임워크 차별 적용
- 상품처리 DB → CDC → RDW, ETL → ADW·빅데이터 파이프라인
- SSO/EAM·메타/형상으로 권한·거버넌스 확보
