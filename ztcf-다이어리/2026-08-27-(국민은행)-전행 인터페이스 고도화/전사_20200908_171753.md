## 본문

금융복합 플랫폼(n-KESA)을 중심으로 채널·MCI·통합인증과 대내 EAI·마케팅·고객통지·DW가 연결되는 Interface Needs이다. MCI↔플랫폼은 http(s)/json, 데이터계는 ETL/CDC, 마케팅과는 실시간 EVT·CDC, 고객통지는 JDBC로 연계된다.

## TEXT 구성도

```
[좌측: 채널]
  EPS(권한) / 통합단말관리 ── http(s)/xml ──► MCI
  통합단말 / 자동화기기 ── http(s)/flat ──► MCI·자동화기기관리
  CTI ── tcp/ip ──► 콜센터 IVR
  통신사 ── HTTP GW
  인뱅 WEB ── http/html ──► 인터넷뱅킹(Quics) ── http(s)/json ──► MCI
  연계채널(SMS/DM/FAX) → 발송서버
  대외기관 / X.25 / 국민카드 ── tcp/ip/flat ──► 대외 EAI (대외·공동·일괄·DMZ)
  (클릭스트림 등) ── log / 실시간 EVT(빨강) ──► 마케팅플랫폼

[중앙]
  MCI ── n-KESA · http(s)/json ──► 금융복합 플랫폼 ★
  통합인증 (MCI ↔ 플랫폼 사이)
  대외 EAI (하단)

[우측]
  대내 EAI (내부)
    └ 상품서비스, 무인공과금, 신용리스크, 이미지코드, 인사, 국외점포
  경영관리 및 지원 / RDW / ADW / 빅데이터 (ETL, CDC)
  마케팅플랫폼 ← CDC · 실시간 EVT
  고객통지 ← JDBC
  발송서버 ↔ 마케팅·고객통지 (JDBC, Direct)
  배치작업관리 / FDS / 통합로그 (Direct)

[선 구분]
  청/흑: 서비스 I/F (MCI·EAI, http/json·xml·flat·tcp)
  보라: ETL · CDC · JDBC · Direct
  빨강: 실시간 EVT · Offer
```

## 핵심 포인트

- 금융복합 플랫폼이 옴니채널(MCI·통합인증)과 내부 EAI의 교차점
- n-KESA / http(s)/json으로 채널 표준 연계
- 마케팅과는 실시간 EVT·CDC, 통지·발송은 JDBC·Direct
- 대외는 대외 EAI, 내부 단위업무는 대내 EAI로 분리
