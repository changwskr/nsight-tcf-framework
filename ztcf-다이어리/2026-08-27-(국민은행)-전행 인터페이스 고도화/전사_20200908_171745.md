## 본문

상품처리서비스(z-KESA·NDM·CICS)를 중심으로, 좌측 채널은 MCI·대외 EAI로 유입되고 우측은 대내 EAI를 통해 마케팅·금융복합·고객통지·DW·리스크·운영계와 연계되는 Interface Needs 다이어그램이다. 코어 구간은 SNA/SNA Flat, 채널은 Http/Xml·Json·Flat, 데이터계는 ETL·CDC가 주 경로이다.

## TEXT 구성도

```
[좌측: 채널·게이트]
  연계채널(SMS/DM/FAX) → EPS·발송서버 (F2F, Http)
  통합단말 → 통합단말관리 → MCI (Http/Xml)
  자동화기기 → 자동화기기관리 → MCI (Http/Flat)
  인뱅 WEB → 인터넷뱅킹 → MCI (Http/Json)
    └ log → 클릭스트림 / Offer
  CTI → 콜센터 IVR → MCI (Http/Flat, TCP/IP Flat)
  통신사 / 대외기관 / X.25 / 국민카드 → 대외 EAI (대외·공동·일괄·DMZ)

[중앙]
  MCI ── SNA/SNA Flat ──► [z-KESA] 상품처리서비스 (NDM, CICS)

[우측: 대내 EAI · 백엔드]
  대내 EAI (내부)
    ├─ 경영관리 및 지원
    ├─ RDW / ADW (ETL, CDC) → 빅데이터 (ETL)
    ├─ 마케팅플랫폼 (실시간 EVT, CDC)
    ├─ 금융복합서비스
    ├─ 고객통지 → 발송서버
    ├─ 무인공과금, 신용리스크, 이미지코드, 인사, 국외점포
    └─ 배치작업관리, FDS, 통합로그 (Direct)

[주요 프로토콜]
  Http/Xml · Http/Json · Http/Flat · SNA/SNA Flat
  TCP/IP Flat · ETL · CDC · JDBC · Direct · F2F
```

## 핵심 포인트

- 채널 유입은 MCI, 내부 확산은 대내 EAI로 역할 분리
- 상품코어는 Mainframe 계열(SNA Flat, z-KESA, CICS, NDM)
- 마케팅·DW는 실시간 EVT·CDC·ETL로 상품계와 동기화
- 대외는 대외 EAI(대외·공동·일괄·DMZ)로 일원화
