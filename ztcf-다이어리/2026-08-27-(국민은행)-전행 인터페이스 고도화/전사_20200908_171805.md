## 본문

글로벌 뱅킹 코어를 중심으로 내부 채널(MCI), 외부 채널·모행(EAI), 계정계 DB, 전일자 배치, 정보계(ODS/DM/RDW/ADW) 연계를 정의한 Interface Needs 다이어그램이다. 채널 통합(내)=MCI, 채널 통합(외)=EAI로 구분하고, 계정계→정보계는 BCV·ETL·CDC로 적재한다.

## TEXT 구성도

```
[내부 채널]                    [코어]                    [배치·정보계]
통합단말관리 ──http(xml)──┐
자동화기기관리 ──http(flat)─┼─► MCI(채널통합 내)
인터넷뱅킹                  │     http(json)
  연행 WEB / 디지털뱅킹      │
  / 캡뱅크 ──http(json)────┘
                              ▼
                         글로벌 뱅킹
                           (n-KESA)
                              │ JDBC
                              ▼
                         계정계 DB ◄──BCV──► 전일자 배치(배치 AP/DB)
                              │                    │ ETL
                              │ CDC                ▼
                              └──────────► 정보계 DB
                                           ODS / DM / RDW / ADW
                                           (상호 ETL)
                                              ▲ JDBC
                                         정보계 AP

[외부·하류]
외부채널(현지보고서·자금결제·펌뱅킹업체)
  ──► EAI(채널통합 외) ◄──► 글로벌 뱅킹 / 정보계 / 통합정보
통합정보 AP/DB ── FILE / JDBC
모행 ── MDI ──► 통합정보 AP
ROC(MCI·계정계·정보계·배치) ── FILE ──► EAI
```

### 프로토콜·연계 방식

| 구분 | 방식 |
|------|------|
| 통신 | http(xml), http(flat), http(json) |
| DB | JDBC |
| 데이터 적재 | ETL, CDC, BCV |
| 파일 | FILE |
| 모행 | MDI |

## 핵심 포인트

- **MCI=내부채널, EAI=외부·정보공유** 로 Global Banking 인터페이스를 이원화.
- 계정계 DB가 실시간(JDBC)·배치(BCV)·CDC로 정보계(ODS/RDW/ADW)와 연결되는 이중 경로.
- 모행은 MDI, ROC·통합정보는 FILE로 EAI에 붙어 해외·보고 흐름을 분리.
- n-KESA가 글로벌 뱅킹 처리 엔진으로 MCI와 계정계 사이에 위치.
